# 14.3.5 HTTP Streaming：首块、已发送头、取消与恢复：代码与观察

## 类型与运行条件

代码入口为相邻runtime-lab，Node>=22，无额外依赖。Node请求作用域/调度模型与真实HTTP传输实验分开，不冒充Nuxt框架执行。主Nuxt验证见综合项目。

## 操作与真实预期

runtime-lab 用真实 node:http 在随机 loopback端口提供 /stream、/partial、/before-error、/cancel。测试读取 first chunk 时断言已有 start 而没有 done，随后再读 done；partial 路径保持HTTP200并发送协议error；before-error在提交头前返回503；cancel在首块后关闭客户端连接，断言服务器活动请求归零且未发送第二块。

每次 reader.read 的 value 都只是字节分片。测试专门用 text()收集完整partial再按行解析，不把一次read当一条NDJSON。真正的浏览器增量客户端还需 TextDecoder 的流式解码、半行缓冲、错误/完成状态与取消按钮，这些列为扩展任务，不声称lab已有UI。

从本目录进入runtime-lab执行：

~~~sh
node --test test.mjs
~~~

本轮六项测试通过：交错请求局部状态、上游白名单、独立任务同时启动、真实首块/终结块、提交头前后错误、断开取消清理。测试临时监听127.0.0.1随机端口并自动关闭。受限执行器需要允许loopback；不能把EPERM当代码逻辑成功。Next的观察结论不在六项运行覆盖中。

## 变体与排错

故障：在 /partial 已 flushHeaders 后调用 setHeader 或 writeHead(500)，会违反已提交响应头状态。保留测试夹具的协议error分支；客户端把error显示成可重试失败。如果错误破坏字节流，应中断并呈现不完整状态，不能假补done。

## 范围

Flutter/RN的Stream可帮助理解连续事件和取消订阅，但HTTP状态码已发不可修改、代理缓冲、浏览器断开和服务器资源清理是额外协议责任。界面进度使用独立role=status文本；不将整块动态数据设为live region反复播报，焦点保持在用户操作处。
