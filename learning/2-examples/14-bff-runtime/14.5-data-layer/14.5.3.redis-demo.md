# 14.5.3 Redis 的协作边界：会话、TTL、原子限流与故障策略：可运行实验与观察

## 运行条件

进入[data-lab](./data-lab/README.md)，Node26/pnpm11，先pnpm install --frozen-lockfile，再pnpm test。运行全部8项便于交叉比较，测试名称标明本点机制；无真实账户、Redis、数据库或云端。第八项仅临时回环端口，退出清理。

## 操作与实际预期

第五项实际运行ExpiringStoreModel，在可控时钟100/109/110验证session过期、撤销；同一A限流key前2次通过第3次拒绝，B不受A计数影响，窗口到期恢复。这是明确的单进程模型，不发送Redis命令，也不能证明脚本原子性、故障转移或集群行为。

## 证据边界

没有安装或连接Redis，不依赖Docker/Colima，不宣称跨进程限流实测。生产选型需要由维护服务的一方给出版本、集群和持久化/SLA，再运行集成/故障测试；这里只要求前端/BFF开发者能读懂角色和失效边界。 参考实现位于lab.mjs，测试在test.mjs。先预测结果，再读断言核对；修改只能在隔离副本，避免破坏其他知识点。不要把assert数量当性能或生产可靠性证明。
