# 14.5.2 Apollo / urql：规范化缓存、SSR 隔离与登出清理：可运行实验与观察

## 运行条件

进入[data-lab](./data-lab/README.md)，Node26/pnpm11，先pnpm install --frozen-lockfile，再pnpm test。运行全部8项便于交叉比较，测试名称标明本点机制；无真实账户、Redis、数据库或云端。第八项仅临时回环端口，退出清理。

## 操作与实际预期

第四项测试使用真实@apollo/client/core的InMemoryCache/gql，A/B分别写入id=1的Person并读取自己的name；extract只含本身份。将A快照restore到新浏览器cache后可读，restore({})后原查询变null。这里没有实际发送GraphQL HTTP，也没有执行React SSR。

## 证据边界

测试覆盖缓存核心和手工状态转移，不代表Apollo Vue / urql插件、HTML序列化、登录切换请求竞态已经集成完成。新项目先按现有REST与useFetch需求决定是否需要GraphQL客户端，避免为缓存概念重复引入库。 参考实现位于lab.mjs，测试在test.mjs。先预测结果，再读断言核对；修改只能在隔离副本，避免破坏其他知识点。不要把assert数量当性能或生产可靠性证明。
