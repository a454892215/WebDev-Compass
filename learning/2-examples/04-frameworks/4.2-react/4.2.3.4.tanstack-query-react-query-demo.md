# 4.2.3.4 示例：TanStack Query：服务端缓存、失效与乐观更新

类型：真实React/生态机制实验；不是伪终端。

## 运行条件与步骤

先读[共享实验说明](./react-lab/README.md)，在react-lab安装锁定依赖。Node26.0.0、pnpm11.4.0；没有全局安装。

```bash
# 从仓库根目录进入
cd learning/2-examples/04-frameworks/4.2-react/react-lab
pnpm install --frozen-lockfile
pnpm exec vitest run -t "4.2.3.4"
```

真实QueryClient测试相同key新鲜缓存只调用queryFn一次，保存/恢复旧值后显式失效，再取发生第二次调用。无真实网络/乐观mutation UI。

完整源码：[Core.tsx](./react-lab/src/Core.tsx)、[路由](./react-lab/src/RoutesDemo.tsx)、[数据工具](./react-lab/src/stores.ts)、[表单](./react-lab/src/FormDemo.tsx)、[编号测试](./react-lab/tests/mechanisms.test.tsx)。

新增受控失败实验：optimisticAppend先取消冲突查询、保存旧值并写临时数据，save Promise失败时恢复快照，最后失效；另用retry:1/retryDelay:0验证一次重试后恢复。仍未实现React useMutation并发UI或真实服务端。

## 预期与对照

- 查询输入变化映射到不同key。
- 失败回滚与最终重新校验可解释，不把本例等同完整并发乐观更新。

先预测，再运行并解释差异。在自己的副本重现：列表A/B共用["tasks"]导致串数据；把筛选/用户放key，分别读取并断言缓存隔离。
