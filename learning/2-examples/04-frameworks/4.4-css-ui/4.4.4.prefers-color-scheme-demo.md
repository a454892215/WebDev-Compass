# 4.4.4 实验：浅深主题：系统偏好、手动覆盖与SSR初始一致

类型：真实Tailwind CLI构建 + 本地静态页面/后台Chrome；四点共享theme-lab。

## 运行条件

在本章`theme-lab/`目录执行：

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm preview
# 另一个终端：pnpm verify
```

预览仅 http://127.0.0.1:4306 。verify自动启停自己的服务器，运行前关闭手动preview。固定Node/pnpm条件见[实验README](./theme-lab/README.md)，需要已有Chrome或按Playwright官方方式准备浏览器。

## 操作与真实预期

1. 先不选主题，在浏览器模拟浅/深系统偏好，查看背景与原生select的color-scheme。
2. 选择浅色后把系统改深色，应保持浅色；选择深色后把系统改浅色，应保持深色。
3. 回跟随系统后覆盖属性消失；关闭JS重新加载，CSS仍能随系统变深色，选择控件的增强行为不被冒称仍存在。

## 验收

- [ ] 系统默认、两种手动覆盖及回system行为明确，颜色和color-scheme一致。
- [ ] 无脚本初始内容可读；明确本例不保存偏好，也未声称Nuxt已实现持久化。

## 故障对照

把:root写死color-scheme:light而只更新meta，观察原生UI不随预期变化；修正CSS覆盖关系再验证两系统偏好。

## 范围说明

只改meta可能被作者CSS的color-scheme覆盖；手动覆盖应与CSS保持一致。深色不等于颜色反转滤镜，必须检查文本/边框/焦点与信息图标。不承诺单个meta完全消除所有闪白，也不把浏览器模拟主题称为系统全平台验证。
