# 4.4.2 实验：设计令牌与组件规范：颜色、间距和行为契约

类型：真实Tailwind CLI构建 + 本地静态页面/后台Chrome；四点共享theme-lab。

## 运行条件

在本章`theme-lab/`目录执行：

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm preview
# 另一个终端：pnpm verify
```

预览仅 http://127.0.0.1:4306 。verify自动启停自己的服务器，运行前关闭手动preview。固定Node/pnpm条件见[实验README](./theme-lab/README.md)，需要已有Chrome或按Playwright官方方式准备浏览器。

## 关键源码

- [src/theme.css](./theme-lab/src/theme.css)
- [src/index.html](./theme-lab/src/index.html)

## 操作与真实预期

1. 定位surface/ink/edge与space-control的定义和.control消费位置。
2. 切换浅/深主题，比较两个卡片及原生select；改一个令牌观察受影响范围。
3. Tab进入按钮，核对焦点有独立可见样式；不要用颜色独自表示收藏状态。

## 验收

- [ ] 相同语义由同一令牌驱动，切换主题时文本、背景、边框成组变化。
- [ ] 按钮有明确名称、焦点与aria-pressed，说明规范包含行为而非只含颜色。

## 故障对照

给第二张卡片硬编码白底而继承深色文字，切换主题重现不匹配；改回语义变量并复核两主题。

## 范围说明

设计系统还包括文档、行为与演进约束，不能仅有几种颜色就称完整设计系统。组件外观一致也不保证键盘、焦点和错误提示正确。令牌、产品布局与业务状态应各自有职责。
