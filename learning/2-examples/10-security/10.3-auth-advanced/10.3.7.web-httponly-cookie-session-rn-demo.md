# 10.3.7 Web Cookie与原生安全存储：迁移威胁模型，不照搬API：操作示例

## 条件与类型

Node26/pnpm11.4，按[auth-lab说明](./auth-lab/README.md)安装与运行。Passkey为明确官方流程观察，OAuth为受控内存模型，其余使用真实库/HTTP/Web机制；不接真实用户或外部IdP。

## 操作与预期

对照本lab HttpOnly不可读但fetch成功、logout后旧Cookie401，与主Nuxt将来的每会话owner-only notes源码核对。此处只执行Web本地fixture，不安装Android/Flutter/RN、不测试Keychain/Keystore，也不把原生安全存储称能抵御所有XSS或服务端越权。

应保留：

- 按读取、自动请求、每请求隔离、持久化和服务端授权列具体差异，不能只替换库名。
- 复用真实Web证据与明确未测原生范围；主Nuxt匿名教学会话不被写成真实用户身份系统。

## 故障与定位

故障：将原生进程单例直接变成Node模块currentUser，让匿名SSR回退上个用户。仅在隔离副本新增确定性lastUser反例并复现，恢复请求内读取与明确401；原主工程不存在此功能时必须先说明新增。

不要硬抄Flutter第三方库或底层框架；用平台适配生命周期与威胁边界，保留高层规范、契约和最小充分验证。
