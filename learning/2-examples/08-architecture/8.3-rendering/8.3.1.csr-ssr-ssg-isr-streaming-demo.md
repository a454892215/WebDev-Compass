# 8.3.1 CSR、SSR、SSG、ISR与Streaming：按约束比较而非排名：操作与观察

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 条件、类型与操作

比较阶段7已保存的三profile产物与本阶段Node SSR；先核对原始HTML/JS依赖/数据更新方式，再列TTFB、FCP、成本与故障维度。阶段7的真实历史记录可引用来源，不说本轮重跑三profile。Streaming/ISR只作官方观察，未测代理与平台不写吞吐收益。

主Nuxt从[综合README](../../../4-practice/08-architecture/README.md)安装/构建；本独立lab与主工程协议不同，先看各自说明。官方观察型不需要安装全部框架，未运行不写通过。

## 应保留的结果

- 每个决定列内容新鲜度、身份、路由与托管约束，不以一个分数决定所有页面。
- 标明真实测量/历史证据/官方观察；Streaming与ISR未运行不记已通过。

记录源码/命令/原始HTTP或官方原文依据，再解释原因。历史证据注明原日期与来源；未测真实生产/Edge/第三方框架性能不编数字。

## 排查与回退

故障：方案把静态public上传后期待运行时Cookie聚合和SSR。先查看有无server入口，再选择Node/API或改变需求；恢复后直接访问详情并核对HTTP状态。
