# 8.3.3 Islands、Partial与Selective Hydration：减少接管范围的不同机制：操作与观察

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 条件、类型与操作

类型：Astro与Nuxt官方观察。把课程介绍、搜索、结算分别划为静态/可延后/立即交互，记录触发、无JS行为、共享状态与失败回退。本轮不安装Astro，不把主Nuxt普通SSR组件称岛。

主Nuxt从[综合README](../../../4-practice/08-architecture/README.md)安装/构建；本独立lab与主工程协议不同，先看各自说明。官方观察型不需要安装全部框架，未运行不写通过。

## 应保留的结果

- 静态内容与真实链接不因JS未就绪消失，关键操作有明确就绪/失败路径。
- 记录跨岛通信成本，不将所有部件都延后以追分。

记录源码/命令/原始HTTP或官方原文依据，再解释原因。历史证据注明原日期与来源；未测真实生产/Edge/第三方框架性能不编数字。

## 排查与回退

故障：关键按钮只在永远没进入视口的祖先事件后接管。用键盘路径推演并改为立即就绪或原生导航，不用spinner掩盖永久不可用。
