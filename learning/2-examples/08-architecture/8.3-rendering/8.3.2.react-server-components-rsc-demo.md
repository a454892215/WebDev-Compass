# 8.3.2 React Server Components与Server Functions：可见输出与远程入口：操作与观察

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 条件、类型与操作

类型：React官方文档观察。分别读Server Components与use server，标出执行位置、发送数据和可调用边界；对主Nuxt把server/api、payload及Vue组件对应到职责而非API名字。不装Next/RSC，不声称编译通过。

主Nuxt从[综合README](../../../4-practice/08-architecture/README.md)安装/构建；本独立lab与主工程协议不同，先看各自说明。官方观察型不需要安装全部框架，未运行不写通过。

## 应保留的结果

- 授权必须在每次服务端写调用按资源检查，不能只在React组件分支检查。
- 区分RSC、SSR、Client Components及Server Functions，明确这是选修观察。

记录源码/命令/原始HTTP或官方原文依据，再解释原因。历史证据注明原日期与来源；未测真实生产/Edge/第三方框架性能不编数字。

## 排查与回退

故障：把数据库token作为Client Component prop，认为父组件在server所以保密。追踪输出/props，改为最小公开DTO；真正泄露过的token另需撤销/轮换，不能只删UI。
