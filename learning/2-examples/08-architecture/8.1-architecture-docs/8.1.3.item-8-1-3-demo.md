# 8.1.3 C4架构图：区分系统、运行单元与代码组件：代码与观察

类型：真实本地源码/文档观察，配合主项目执行；不是生产架构认证。

## 条件与操作

先按[主项目README](../../../4-practice/08-architecture/README.md)安装、运行检查并构建。

读docs/ARCHITECTURE.md的Context/Container/Component三视图。浏览器通过HTTP访问Nuxt；Nuxt进程内adapter是合成数据，不画成真实远程微服务；不存在的数据库或消息队列不得画成已部署。

## 预期与应留证据

- 关系标注请求/响应协议、公开与服务端边界，图与对应代码一致。
- 解释C4 Container与Docker区别；用文字提供图的等价说明，不只靠颜色。

保存实际源码、命令和结果，再说明判断依据；不能以模板已生成替代设计审查。

## 排错与参考

故障：把shared/contracts画成独立服务，声称网络调用。沿API入口与service注入查看真实调用，改为代码组件；若另建服务，需新的实际接口与部署证据。

只画对读者有用的层级，避免一张图混入所有文件、机器和用户。
