# 8.1.2 非功能需求：把性能、安全与演进目标变成验收：代码与观察

类型：真实本地源码/文档观察，配合主项目执行；不是生产架构认证。

## 条件与操作

先按[主项目README](../../../4-practice/08-architecture/README.md)安装、运行检查并构建。

读docs/NFR.md：本例先要求四并发scope不混用、必需DTO不合法就失败、可选进度失败显示未知而非0、边界违规构建前失败、键盘可操作。每个指标对应unit/HTTP/浏览器或人工检查，而不是只写“高可用”。

## 预期与应留证据

- 至少三项可观察响应或状态，记录环境、输入、采样范围和未测生产限制。
- 质量冲突有取舍：安全/一致性要求不能为页面始终200而静默吞掉错误。

保存实际源码、命令和结果，再说明判断依据；不能以模板已生成替代设计审查。

## 排错与参考

故障：接口失败时返回completed:0使业务看似正常。检查null/warnings与真实零值区别，恢复失败状态并用同一输入复验。

先提出实际风险和证据，再选技术；不编造生产预算或固定“所有接口100ms”。
