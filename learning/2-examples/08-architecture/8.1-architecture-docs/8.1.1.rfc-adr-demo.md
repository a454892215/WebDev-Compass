# 8.1.1 RFC与ADR：记录可检验的取舍和决策后果：代码与观察

类型：真实本地源码/文档观察，配合主项目执行；不是生产架构认证。

## 条件与操作

先按[主项目README](../../../4-practice/08-architecture/README.md)安装、运行检查并构建。

读综合docs/RFC.md与ADR-001.md，逐项对照server/api组装、端口接口、app/features公共入口和真实测试。选择Nuxt单体不是因为其永远最好，而是本教学场景只有一个交付单元，没有团队自治或多运行时约束。

## 预期与应留证据

- 至少两备选按同一约束比较，决策后果含复杂度、验证和撤回条件。
- 说清已有与要求新增；用实际文件/请求/行为证据支撑，不把打分矩阵当客观科学。

保存实际源码、命令和结果，再说明判断依据；不能以模板已生成替代设计审查。

## 排错与参考

故障：RFC宣称方案支持独立发布，但仍要求宿主/子应用同构建上线。追踪真实产物与发布边界，修正能力声明或重新设计独立契约，不以分文件夹当独立发布。

ADR聚焦一个重要决定；后续改变写supersedes而非改旧决定，不把大量模板当设计质量。
