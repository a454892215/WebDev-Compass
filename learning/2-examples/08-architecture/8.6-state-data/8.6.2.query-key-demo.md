# 8.6.2 查询Key、缓存层级与作用域失效：操作与预期

## 条件与运行类型

先按[state-lab运行说明](./state-lab/README.md)安装，Node26/pnpm11.4/Chrome；也可对照[Nuxt主实践](../../../4-practice/08-architecture/README.md)。没有真实用户、外网上报或生产凭据。

## 操作

pnpm test验证不同scope或query生成不同key，旧epoch响应被拒；主Nuxt查询scope实际由URL传入，公开fixture不是登录，不能把scope参数当访问控制。

## 应保留的结果

- 相同filter但不同scope结果不共用，key不包含令牌。
- 切换后旧响应不能回写新scope，说明HTTP/CDN/Nitro是否另有缓存。

记录实际命令、状态与原始值；控制模型/官方观察/真实HTTP和浏览器存储分开。

## 反例与参考

故障：只clearNuxtData后仍给服务端/account套公开swr。检查实际响应与所有缓存层，敏感路径旁路并重测并发；不要宣称清客户端解决所有层。

缓存key维度要与真实数据依赖对应，不能无脑加入随机时间破坏复用；身份授权始终由服务端真实协议完成。
