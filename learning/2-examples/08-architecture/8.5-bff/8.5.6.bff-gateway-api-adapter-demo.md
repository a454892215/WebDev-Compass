# 8.5.6 BFF与移动Gateway/API Adapter：职责相似但信任位置不同：操作与观察

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 条件、类型与操作

把主Nuxt的页面/composable、server workspace、进程内adapter标在调用图；把lab的真实HTTP上游另画，不把两张图混为主项目已联网。说明真实用户进入系统时授权应在哪里，以及本轮未实现部分。

## 应保留的结果

- 图中每个组件的运行位置与信任边界明确，客户端不含服务凭据。
- 不把UI独立等同业务/权限逻辑复制，明确fixture演示与真实认证差距。

记录源码/命令/原始HTTP或官方原文依据，再解释原因。历史证据注明原日期与来源；未测真实生产/Edge/第三方框架性能不编数字。

## 排查与回退

故障：把Android拦截器中的服务secret搬入Nuxt public配置，认为BFF相同架构。追踪浏览器payload，改在server持有受限凭据并最小化返回，真实泄露需轮换。
