# 8.5.4 API版本与废弃：并行兼容、Deprecation与Sunset：操作与观察

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 条件、类型与操作

真实lab /api/v1/workspace保留原DTO并返回Deprecation、Sunset、successor-version链接；/api/v2/workspace保留旧字段并增加meta.schemaVersion。检查旧调用仍工作，不把教学日期当真实服务停用计划。

[BFF HTTP实验入口](./bff-lab/README.md)

主Nuxt从[综合README](../../../4-practice/08-architecture/README.md)安装/构建；本独立lab与主工程协议不同，先看各自说明。官方观察型不需要安装全部框架，未运行不写通过。

## 应保留的结果

- v1消费者原字段/类型/语义保持，v2有明确契约和回滚。
- Deprecation是@秒结构日期，Sunset是可解析HTTP-date；公告不等于自动关服。

记录源码/命令/原始HTTP或官方原文依据，再解释原因。历史证据注明原日期与来源；未测真实生产/Edge/第三方框架性能不编数字。

## 排查与回退

故障：返回Deprecation:true并次日直接删除v1。依据RFC修正格式，补真实消费者迁移/观察窗口；不能只改header掩盖破坏性下线。
