# 8.5.2 BFF还是直连API：用网络与职责收益抵偿运维成本：操作与观察

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 条件、类型与操作

真实lab给/api/v1/workspace增加url=https://example.com输入，返回400且上游请求计数不变；所有真实请求只到本实验固定127.0.0.1端口。没有向外部或内网地址做攻击。主项目进程内adapter不是独立微服务。

[BFF HTTP实验入口](./bff-lab/README.md)

主Nuxt从[综合README](../../../4-practice/08-architecture/README.md)安装/构建；本独立lab与主工程协议不同，先看各自说明。官方观察型不需要安装全部框架，未运行不写通过。

## 应保留的结果

- 方案有新增故障/运维成本与可验证收益，不以层数多当成熟。
- 任意URL/未知scope输入被拒且不会产生上游请求，授权责任仍在服务端。

记录源码/命令/原始HTTP或官方原文依据，再解释原因。历史证据注明原日期与来源；未测真实生产/Edge/第三方框架性能不编数字。

## 排查与回退

故障：写/api/proxy?url=任意输入并自动跟随重定向。改固定服务映射、参数白名单和redirect:error，生产再核对DNS/网络出口；不要在真实私网演示。
