# 3.1.4 实验：锁文件：解析图与冻结安装

[理论](../../../1-notes/03-engineering/3.1-package-management/3.1.4.package-lock.json.md) · [独立练习](../../../3-exercises/03-engineering/3.1-package-management/3.1.4.package-lock.json.md) · [示例目录](./README.md)

类型：真实本地CLI／构建实验，含适用浏览器观察。

## 环境和入口

前置：3.1.1与3.1.3。 本机验证Node26.0.0、pnpm11.4.0，工具固定版本见manifest。

本点复用[package-lab项目](./package-lab/README.md)，重点阅读[pnpm-lock.yaml](./package-lab/pnpm-lock.yaml)。先阅读命令和源码，使用演示数据；不真实publish、不上传凭据。

## 操作与预期

先冻结安装现有package-lab，再在独立临时副本改变semver版本验证冻结拒绝；复跑脚本不会破坏本仓库锁。

1. 原工程冻结安装退出0且锁文件未被改写。
2. 临时副本manifest不一致时冻结命令非0，能指出修复路径。

## 排错观察

制造依赖声明/锁不一致，定位ERR_PNPM_OUTDATED_LOCKFILE；按明确升级目标重生成锁，不用关闭冻结掩盖问题。

## 证据边界

本轮实际执行和可复跑命令以组内[验证报告](../../../../docs/audits/stage-3-build-review.md)为准。静态阅读、CLI、浏览器HMR与产物断言分别记录；不把Webpack阅读、预览、source map存在称完整部署或GPU/性能验证。不要提交node_modules、dist或本地.env。
