# 7.1.6 Docker 多阶段构建：构建工具与 Node 运行镜像分离 — 操作与预期

## 条件与运行类型

Node26.0.0；本地HTTP实验无需第三方依赖。Nginx专项本轮1.31.8，可设置NGINX_PATH；命令在[lab说明](./release-lab/README.md)。涉及主工程从[综合README](../../../4-practice/07-deployment/README.md)进入。真实云平台、容器、远端Actions未执行，不把模板检查写成发布成功。

## 操作

阅读release-lab/templates/Dockerfile.example和.dockerignore.example，按说明以主Nuxt目录为构建上下文。此轮只核对模板，不启动Docker daemon/Colima、不下载镜像、不宣称容器构建运行通过。

先读[理论](../../../1-notes/07-deployment/7.1-build-deploy/7.1.6.docker-dockerfile.md)，预测请求路径、状态和缓存，再运行。对照源码server.mjs/verify.mjs的断言；lab合成资产不是Nuxt真实bundle。

## 应保留的结果

- 构建上下文/锁文件/构建命令/输出匹配，最终镜像不含.env与开发缓存；静态和SSR入口不混。
- 运行用户、端口、启动环境、信号与检查步骤完整；未实际运行明确记录。

## 反例与排查

COPY本机.output到不同平台后原生模块加载失败：定位Node/架构/libc与产物来源，在目标平台构建；不通过复制更多秘密文件解决。

## 本轮边界

镜像tag、平台架构、libc、Node版本及原生依赖会影响可运行性；不盲目跨平台拷node_modules。用非root运行、明确工作目录和环境、通过exec形式CMD接收信号。秘密不放ARG/ENV构建层，.dockerignore排除.env/缓存/本机输出；生产按审核过digest固定镜像并更新。
