# 7.1.7 GitHub Actions：验证门禁、产物和受控发布 — 操作与预期

## 条件与运行类型

Node26.0.0；本地HTTP实验无需第三方依赖。Nginx专项本轮1.31.8，可设置NGINX_PATH；命令在[lab说明](./release-lab/README.md)。涉及主工程从[综合README](../../../4-practice/07-deployment/README.md)进入。真实云平台、容器、远端Actions未执行，不把模板检查写成发布成功。

## 操作

查看templates/quality.yml.example：固定官方Action SHA、contents:read、pnpm11.4锁文件、主工程门禁和三profile构建；模板不在.github/workflows，未推送/运行真实GitHub任务，也没有自动发布凭据。

先读[理论](../../../1-notes/07-deployment/7.1-build-deploy/7.1.7.github-actions.md)，预测请求路径、状态和缓存，再运行。对照源码server.mjs/verify.mjs的断言；lab合成资产不是Nuxt真实bundle。

## 应保留的结果

- 失败停止推广，产物与提交/profile可追溯；缓存与产物职责分开。
- 权限最小、可信代码边界与固定Action SHA明确；未运行远端不记通过。

## 反例与排查

工作流忽略测试退出码或使用continue-on-error后仍部署：删掉该旁路，用真实非零检查验证后续推广不执行；不可只在说明文档写“会阻止”。

## 本轮边界

工作流遵循最小权限、受保护环境和可信分支；不要给不可信PR代码生产凭据，尤其不把pull_request_target当普通PR构建。第三方Action固定完整审核SHA，定期升级；SHA固定降低漂移但不替代审阅。发布并发控制防止旧流水线覆盖新版本，失败有明确回滚入口。
