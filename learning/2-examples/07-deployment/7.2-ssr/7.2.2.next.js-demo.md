# 7.2.2 操作卡：Next.js选修：Pages/App路由、组件边界与部署模型

类型：官方文档观察；本轮未安装Next或执行其构建。

## 运行条件与入口

按[阶段7综合README](../../../4-practice/07-deployment/README.md)安装锁定依赖，用pnpm build、pnpm build:ssg、pnpm build:csr分别构建，依README启动；不要同时覆盖同一输出目录。本组不复制另一套Nuxt。Node/框架精确版本及最终结果见阶段验收和runtime记录。

## 操作与预期

本点为官方文档观察型：分别打开Pages getServerSideProps、App Server and Client Components、App静态export、当前Caching文档。记录各页面对应路由/模型，给同一“登录后账户页”标出服务端凭据、浏览器DTO、不可公开缓存部分。不声称Next安装或构建通过。

## 可复核步骤

1. 阅读本理论引用的四份Next官方正文，记录Pages/App标识和缓存模型。
2. 在Pages文档定位getServerSideProps；在App文档定位Server/Client Components与客户端边界。
3. 在静态export文档定位不支持的请求时功能；对照账户页为什么不能把身份HTML生成给所有访问者。
4. 写出观察结论，明确“未实装Next”；不执行主项目中的不存在Next命令。

## 结果与限制

本轮已读取官方文档并完成边界比较，没有Next安装/构建/部署证据。 CDN/ISR、外网部署、生产认证、多浏览器、真机与搜索收录不由这些本地操作证明。
