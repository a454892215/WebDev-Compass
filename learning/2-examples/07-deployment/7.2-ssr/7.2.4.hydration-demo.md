# 7.2.4 操作卡：Hydration生产排查：原始HTML、payload与重复请求

类型：共享Nuxt生产产物、HTTP与后台浏览器实际操作。

## 运行条件与入口

按[阶段7综合README](../../../4-practice/07-deployment/README.md)安装锁定依赖，用pnpm build、pnpm build:ssg、pnpm build:csr分别构建，依README启动；不要同时覆盖同一输出目录。本组不复制另一套Nuxt。Node/框架精确版本及最终结果见阶段验收和runtime记录。

## 操作与预期

在综合项目公开详情保存原始HTML，监听页面error/console和API请求，再执行一次计数交互、链接导航与刷新。SSR内容被接管且事件有效；初始取数没有无原因重复。对同一输入比较初始数据与payload，不用最终DOM截图代替原始响应。

## 可复核步骤

1. 主首页useAsyncData("public-courses", () => Promise.resolve(courses))从shared常量建立payload，详情按slug同步查常量，不存在默认HTTP取数。保存首页/详情原始HTML和初始数据，不能用浏览器Elements代替HTTP响应。
2. 在加载前开始记录pageerror、console和API请求；加载后等待接管并点击实际交互控件。
3. 导航另一详情再刷新深链，判断每个请求由初始接管、参数变化还是用户动作触发。
4. 在SSR副本才把首页读取改为现有/api/catalog的HTTP读取，比较useFetch与setup裸$fetch；静态profile不运行该server端点变体。另按独立练习制造浏览器API故障，修复后复测相同链路，不改默认正确示例。

## 结果与限制

本轮主代理已完成三profile构建、HTTP组与6项后台Chrome测试；本组已核读脚本、日志、产物和JSON，范围见stage-7-rendering-runtime.json。 CDN/ISR、外网部署、生产认证、多浏览器、真机与搜索收录不由这些本地操作证明。
