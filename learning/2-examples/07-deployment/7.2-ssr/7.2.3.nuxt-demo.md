# 7.2.3 操作卡：Nuxt生产部署：Node SSR、静态托管与身份缓存

类型：共享Nuxt生产产物、HTTP与后台浏览器实际操作。

## 运行条件与入口

按[阶段7综合README](../../../4-practice/07-deployment/README.md)安装锁定依赖，用pnpm build、pnpm build:ssg、pnpm build:csr分别构建，依README启动；不要同时覆盖同一输出目录。本组不复制另一套Nuxt。Node/框架精确版本及最终结果见阶段验收和runtime记录。

## 操作与预期

用综合项目SSR profile启动同一构建，改变公开runtime配置并检查原始响应；合成私有标记只在server使用，不进入HTML/payload/客户端资源。对公开和私有路径分别核对Cache-Control，再到SSG静态托管确认server-only端点不存在。

## 可复核步骤

1. 阅读nuxt.config.ts的profile、runtimeConfig与routeRules（STAGE7_PROFILE是构建选择，public.renderProfile记录该结果）；画出公开配置、server配置及DTO去向。
2. 用SSR产物按README启动，检查/api/health和公开详情，NUXT_PUBLIC_RELEASE_ID与NUXT_PUBLIC_SITE_LABEL按需在Node启动时覆盖；runtime公开值应按实际命令读取，私有标记不进payload。
3. 对/account、/api/private按主项目合成身份契约请求，核对状态、当前用户DTO、Cache-Control与不共享缓存。
4. 用纯静态托管启动SSG产物，确认没有运行中的Nitro能力；预渲染路由与缺失资源不能只靠SPA fallback判断。

## 结果与限制

本轮主代理已完成三profile构建、HTTP组与6项后台Chrome测试；本组已核读脚本、日志、产物和JSON，范围见stage-7-rendering-runtime.json。 CDN/ISR、外网部署、生产认证、多浏览器、真机与搜索收录不由这些本地操作证明。
