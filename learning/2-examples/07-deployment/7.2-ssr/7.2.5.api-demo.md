# 7.2.5 操作卡：同构部署验收：依赖兼容、请求隔离与静态边界

类型：共享Nuxt生产产物、HTTP与后台浏览器实际操作。

## 运行条件与入口

按[阶段7综合README](../../../4-practice/07-deployment/README.md)安装锁定依赖，用pnpm build、pnpm build:ssg、pnpm build:csr分别构建，依README启动；不要同时覆盖同一输出目录。本组不复制另一套Nuxt。Node/框架精确版本及最终结果见阶段验收和runtime记录。

## 操作与预期

在主SSR同一个进程并发发送Alice/Bob/匿名合成身份请求，核对各自正文/状态和no-store；匿名不得得到上一身份DTO。静态产物扫描私有路径/标记，且用静态托管实际请求server-only端点。客户端依赖导入与视口读取另验证SSR构建、真实导航及错误恢复。

## 可复核步骤

1. 查server身份读取与/account代码，确认没有模块级可变currentUser。
2. 按README定义的合成Cookie（stage7-demo=alice或bob，缺失为匿名）同时发Alice、Bob和匿名请求，检查每个原始响应，不只检查状态码。/api/private匿名401；/account页面显示解释而非他人资料，不把内嵌取数401等同页面HTTP必然401。
3. 检查身份HTTP缓存头与routeRules，确认没有匹配到公开共享缓存。
4. 检查SSG/CSR的public目录，搜索私有标记/账户payload；静态HTTP请求/api/private不能得到主Node数据。

## 结果与限制

本轮主代理已完成三profile构建、HTTP组与6项后台Chrome测试；本组已核读脚本、日志、产物和JSON，范围见stage-7-rendering-runtime.json。 CDN/ISR、外网部署、生产认证、多浏览器、真机与搜索收录不由这些本地操作证明。
