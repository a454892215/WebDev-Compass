# 13.2.2 内部npm包交付：scope、registry、权限与可回退产物：操作与观察

## 类型与前置

官方观察/配置审查型；Bot政策另有本地Node测试。模板不等于registry/Bot平台已接入。 Node26.0.0/pnpm11.4.0，CLI3.0.3；无真实token、不publish或控制前台。

[实验说明](./release-lab/README.md)

## 操作与预期

本地真实pnpm pack已验证widget归档内workspace:^转为^2.0.0，但没有上传服务器。templates/npmrc.example只给特定scope的GitHub Packages地址和环境变量令牌占位；publish-package.json.example指出显式publishConfig.registry。模板仅官方观察/评审，需替换组织与权限，不读取或写入真实token。

GitHub Packages当前npm认证文档列PAT classic及Actions中GITHUB_TOKEN适用条件；npmjs trusted publishing/OIDC不能直接当作所有registry通用能力。读取别的私有repo还需授予包访问，安装token不应默认拥有发布权限。不要把.npmrc实际令牌、CI日志、缓存归档或tarball当秘密存储。

[源码](./release-lab/verify.mjs)与[模板目录](./release-lab/templates/)可核对范围。保存实际版本/锁差异/归档结果，不把包数量当质量。
