# 15.6.2 Navigation API：拦截边界、历史与框架路由所有权：操作卡

## 类型与入口

[独立navigation-lab](./navigation-lab/README.md)使用原生页面及真实Chrome；先在该目录pnpm install --frozen-lockfile，再pnpm test。Node26、pnpm11、固定Playwright1.65.1，Chrome路径可用CHROME_PATH覆盖。不会接管主Nuxt路由，不调用云服务或真实用户数据。

## 操作与实际预期

真实navigate拦截跳到/nav/two，保持window内同文档marker、更新标题，再后退回视图一。测试等待页面标题状态，不把goBack调用返回当渲染已完成；强制回退使用普通链接整页加载仍可用。

先看app.mjs对应函数与verify.mjs断言，再预测后运行。浏览器异步导航需等待内容完成，网络块、URL变更、动画完成和业务成功不是同一事件。

## 独立变体与排错

在原生lab新增/nav/three并为直接深链、后退、未知路径、锚点及下载列测试；对主Nuxt只写路由owner评审，不另装全局拦截器。

故障：只检查URL已到/nav/two就立即断言异步内容，会偶发看到旧标题；等待导航finished或页面完成标记。另一故障是无条件intercept把下载吞掉，恢复明确筛选并验证普通行为。

## 证据边界

仅本地后台Chrome，非真机/多引擎/辅助技术/真实音视频或生产网络。能力不支持有回退；这不是强制所有Web项目引入的新框架。
