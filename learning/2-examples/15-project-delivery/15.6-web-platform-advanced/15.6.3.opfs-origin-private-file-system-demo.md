# 15.6.3 OPFS：源私有草稿、配额和可恢复边界：操作卡

## 类型与入口

[独立navigation-lab](./navigation-lab/README.md)使用原生页面及真实Chrome；先在该目录pnpm install --frozen-lockfile，再pnpm test。Node26、pnpm11、固定Playwright1.65.1，Chrome路径可用CHROME_PATH覆盖。不会接管主Nuxt路由，不调用云服务或真实用户数据。

## 操作与实际预期

真实Chrome执行getDirectory→唯一文件createWritable/write/close→getFile/text→finally removeEntry；返回合成正文且测试确认没有残留compass-fixture文件。强制缺失路径返回supported:false，不假称已持久化。

先看app.mjs对应函数与verify.mjs断言，再预测后运行。浏览器异步导航需等待内容完成，网络块、URL变更、动画完成和业务成功不是同一事件。

## 独立变体与排错

新增可导出的版本化草稿格式，测试未知版本拒绝、正文读取失败和存储不可用回退；只清理由本练习创建的唯一文件。

故障：写后不await close就立即显示保存成功，错误晚到导致UI与实际内容不符；把成功状态移到完整close之后。若catch所有错误仍返回supported:true，应改为可见失败/显式回退，并保留旧草稿或导出入口。

## 证据边界

仅本地后台Chrome，非真机/多引擎/辅助技术/真实音视频或生产网络。能力不支持有回退；这不是强制所有Web项目引入的新框架。
