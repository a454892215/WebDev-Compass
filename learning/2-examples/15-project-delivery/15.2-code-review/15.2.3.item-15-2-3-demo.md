# 15.2.3 技术债与Hotspot：历史线索、业务风险及偿还验证：操作与观察

类型：真实本地Node纯函数/清单实验；15.2.3另有隔离临时Git历史。没有真实PR审批、浏览器渲染、生产事故或团队能力测评。先读对应理论，再预测结果。

## 运行入口

Node22+、Git可执行文件，无第三方依赖；本轮Node26.0.0/Git2.54.0。从仓库根目录执行：

~~~sh
node learning/2-examples/15-project-delivery/15.2-code-review/review-lab/verify.mjs
~~~

实现review.mjs，断言verify.mjs；[评审fixture与实验边界](./review-lab/fixture-review.md)。5项有不同机制的检查实际通过，安全报告写在忽略目录dist/runtime.json。临时history-*只在本lab dist内创建/删除，不操作用户仓库历史或发网络请求。

## 对应操作与预期

运行verify.mjs的isolated Git项。它在自己的dist/history-*新建临时仓库，仅本地配置fixture身份、生成六提交、读取真实历史，再在finally删除该目录；不读取主仓库历史或改任何用户提交。报告列3/1/2、排除生成文件、9/1候选排序和改变权重后排序变更。

## 变体

在隔离历史fixture中给catalog增加一次真实提交，再分别报告touches与增删行数；新增一条低频但高安全影响的债务，写清为何不按教学乘积排序。

真实历史计数由输出复算，生成文件/重命名/样本窗口等偏差有说明，不把人工权重称静态复杂度实测；偿还条目包含用户影响、范围、最小变更、回归及复查条件，不用候选榜评价个人。本段变体和综合任务由学习者新增，不等于已在主Nuxt接入。UI安全/a11y的观察清单不能用纯函数结果替代。
