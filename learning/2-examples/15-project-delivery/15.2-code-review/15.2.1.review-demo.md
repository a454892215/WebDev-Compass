# 15.2.1 代码评审：从用户行为到可复现缺陷：操作与观察

类型：真实本地Node纯函数/清单实验；15.2.3另有隔离临时Git历史。没有真实PR审批、浏览器渲染、生产事故或团队能力测评。先读对应理论，再预测结果。

## 运行入口

Node22+、Git可执行文件，无第三方依赖；本轮Node26.0.0/Git2.54.0。从仓库根目录执行：

~~~sh
node learning/2-examples/15-project-delivery/15.2-code-review/review-lab/verify.mjs
~~~

实现review.mjs，断言verify.mjs；[评审fixture与实验边界](./review-lab/fixture-review.md)。5项有不同机制的检查实际通过，安全报告写在忽略目录dist/runtime.json。临时history-*只在本lab dist内创建/删除，不操作用户仓库历史或发网络请求。

## 对应操作与预期

运行verify.mjs第一、二项。负例子进程对badTotal(-2)期待拒绝，真实以AssertionError退出1；主验证器确认这是预期失败。修复lineTotal拒绝负数、0、分数、字符串、100、NaN和错误价格；正常返回398，内部字段不出DTO。证据清单在blocking未关闭时false，关闭后即使nit未处理也true。true只代表这个小型清单满足，不是人工LGTM或自动合并。

## 主迁移项目的实际评审入口

已读主项目shared/catalog.ts、server/routes/legacy/catalog.get.ts、server/api/catalog.get.ts与app/pages及route-focus.client.ts。可沿“旧形状→normalizeLegacy→公开Product→页面文本”追踪契约，再检查固定入口、只读双源、查询状态和焦点。主项目没有本lab的badTotal函数；不能把独立反例当主项目已存在Bug。关于skip位置/可聚焦目标、详情503与404映射、导航移焦和后退输入的专项反馈，已再次核源码修复并有对应测试；最终实际运行结论见主项目和阶段验收记录。本组复核不是又一次浏览器运行。

## 变体

给商品行增加最大100字符标题与缺失title的变体，写两条blocking评审意见和一条明确可选的Nit；另按主Nuxt真实数据流选一个UI或SSR边界检查。

坏输入实际被拒绝，正常398与公开字段不变；测试包含缺失、错误类型及长度边界；意见包含触发输入、用户影响和复验方法，区分函数测试与真实UI/SSR证据。本段变体和综合任务由学习者新增，不等于已在主Nuxt接入。UI安全/a11y的观察清单不能用纯函数结果替代。
