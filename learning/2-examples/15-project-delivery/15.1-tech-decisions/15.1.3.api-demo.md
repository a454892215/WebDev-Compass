# 15.1.3 跨团队API契约：Mock先行、兼容窗口与联调：操作与观察

## 类型与运行条件

本点使用[交付依赖实验](../15.1-tech-decisions/delivery-lab/README.md)的合成数据/文档卡；Node22+，本轮26.0.0，零第三方依赖。代码模型与组织流程观察分开，不虚构会议、采购、生产发布或人类试学。

## 运行与预期

从仓库根运行：

~~~sh
node --test learning/2-examples/15-project-delivery/15.1-tech-decisions/delivery-lab/test.mjs
~~~

六测实际覆盖依赖路径/环路/输入边界、成本敏感性、旧消费者与适配。六测中的两契约测试真实执行可选字段/私有字段投影、必需字段改名、类型漂移和兼容适配；无真实HTTP联调。

本点入口：[对应文件](./delivery-lab/model.mjs)。流程卡是阅读/填写任务；没有为每个人类活动制造一个“有标题就通过”的脚本。

## 变体与排错

把title改name却仅重生成TypeScript，旧消费者仍报CATALOG_CONTRACT。用固定输入复现，增加兼容适配与旧客户端测试，再决定移除窗口；不能用as断言掩盖。

变体是[独立练习](../../../3-exercises/15-project-delivery/15.1-tech-decisions/15.1.3.api.md)要求新增的内容；只记录自己实际运行的结果。

## 主项目实际契约对照

已读主实践shared/catalog.ts：主DTO为id/title/cents，normalizeLegacy把product_code/product_name/十进制price转为该DTO；本独立lab字段叫priceCents，不能直接替换主类型。主server/api/shadow.get.ts做只读双源比较，server/routes/entry.get.ts使用合成bucket/percent/rollback控制跳转，不是真实组织审批或生产分流服务。综合任务须按主实际契约增加变体，不能借本lab证据冒称主API已经联调。

## 验证范围

主Nuxt为另一共享实践项目，以上lab未直接调用其API/操作生产开关。主代码事实需读其README/源码后再写；成本/任务区间均非真实报价或团队承诺，观察不等于已获批准。
