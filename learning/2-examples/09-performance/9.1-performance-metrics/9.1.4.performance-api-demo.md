# 9.1.4 Performance API：时间原点、缓冲区与跨源限制：操作与证据

## 类型与条件

本地真实采集/产物实验与明确官方观察。先按[metrics-lab](../9.1-performance-metrics/metrics-lab/README.md)安装构建，Node26/pnpm11.4、web-vitals6.2.3、Vite8.3.8、后台Chrome；主Nuxt从[综合README](../../../4-practice/09-performance/README.md)进入。

## 操作

lab按能力注册navigation/resource/longtask/measure，原始条目只保留type/duration/startTime并上限30。两视口实测有导航、资源、90ms longtask；没有观测跨源真实CDN或TAO。

## 应观察/保留的证据

- supportedEntryTypes与条目存在性明确，unsupported不假装计时0。
- 不将startTime当UNIX时间，Observer与记录有上限/销毁，跨源字段限制有说明。

## 排错

故障：从getEntriesByType一次快照推断整个长会话，或把0 transferSize断言必命中缓存。改Observer并记录头/请求上下文，保留不确定性。

工具用于定位，不按一个字段推断因果；原始entry.name通常含URL，上传前必须最小化。

本轮真实范围：4组Node、Vite真实构建/预算、两视口web-vitals/原生条目/手动本地collector；无Lighthouse/LHCI/WebPageTest远端/Partytown运行。合成访问不叫RUM，原始目标/URL不上传。
