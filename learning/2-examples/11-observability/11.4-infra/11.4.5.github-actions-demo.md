# 11.4.5 GitHub Actions矩阵、缓存与受保护部署：实验与观察

## 类型与运行条件

配置审查与官方观察型。阅读infra-lab/templates对应文件及README，不需要新建云资源。占位符与平台条件未满足不能直接宣称可部署。

## 操作与预期

quality.yml.example定义2个OS×2个Node共4格质量，main push且needs质量成功才进入production environment。部署job仅打印说明，没有云动作；需在仓库设置required reviewers/分支规则，YAML中写environment不会自动创建审批制度。三个action SHA仍需核验替换。

请记录输入、具体状态、解释与未测条件，不只截图绿色状态。PR代码不拿生产secrets，避免pull_request_target检出并执行不可信分支。GITHUB_TOKEN最小权限，OIDC只在需要发布的job启用并由云端限定repo/ref/environment；id-token:write本身不是授权成功。平台secret遮罩不能保证所有变换都脱敏。部署concurrency/审批与回滚要另核。
