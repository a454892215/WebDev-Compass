# 事件响应桌面推演

类型：**合成情景与角色练习**，不是本轮发生的真实生产故障，不表示发送过通知。

场景：reader-v1新模块出现错误，页面其余区域仍可用；发布owner尚在25%观察。无真实用户/数据库。

| 推演节点 | 角色/检查             | 动作与失败分支                                                                                   | 需学员填写的证据                    |
| -------- | --------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------- |
| T0       | 指挥确认影响与release | 区分局部模块失败/全站不可达；暂停扩量并指定操作owner                                             | 实际本地页面/指标，不捏造生产用户数 |
| T1       | 操作止损              | 核对kill优先白名单与百分比，运行第一组Node；若配置服务不可用，按预定默认回旧路径                 | 自己执行时间与输出                  |
| T2       | 操作恢复              | pnpm rollback验证manifest回stable，两hash保留；若数据库不兼容则停止应用直接回退并升级给后端owner | 输出与剩余边界                      |
| T3       | 沟通                  | 写当前影响/已做/未确认/下次更新时间，不发送任何真实消息                                          | 练习文本                            |
| T4       | 指挥验收              | 原业务路径、资源可读、分release错误/延迟恢复才结束；静音不算修复                                 | 实际检查与未测项                    |
| T5       | 复盘                  | 分事实/推断/未知，给改进owner/期限/验收方法                                                      | 自己填写的复盘                      |

## Runbook骨架

触发/影响与分母 → 可用权限和owner → 当前release/配置 → 最小诊断（不含Cookie/完整URL） → 停止扩量 → kill/产物回退条件 → 失败升级 → 业务和指标恢复 → 继续观察。

## Postmortem骨架

事件摘要与用户影响；事实时间线（实际操作时间）；触发与促成条件；检测/沟通/缓解有效与无效；未确认假设；行动项（owner/期限/成功标准）；复验链接。不要把角色模板当真实值班记录，不以“开发粗心”替代系统原因。
