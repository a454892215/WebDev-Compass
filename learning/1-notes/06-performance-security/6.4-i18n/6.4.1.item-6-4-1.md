# 6.4.1 文案管理：语义键、参数、复数与回退

前置：阶段3工程工具、阶段4Vue/Nuxt和阶段5请求/会话边界。先机制、再本地实验、最后副本变体，不把这些基础质量要求延后到上线。

## 机制与使用场景

把文案作为有上下文的数据管理，键表达用途而非简单用中文句子拼接。参数应由翻译模板决定位置，避免“前缀+名字+后缀”固定语序；同一英文词在不同场景不一定同译。语言、地区、货币与时区分开，不从一种推断另一种。

数量规则因语言而异，不能统一count===1否则复数。Vue-i18n支持消息选择与自定义pluralRules，本lab用Intl.PluralRules映射阿语zero/one/two/few/many/other；真实产品文案仍需母语/上下文审校。回退使缺项有可解释结果，但不应隐藏持续遗漏；翻译完整性可以加入检查。

动态参数作为文本输出，不能因为字符串来自翻译文件就随意v-html。主Nuxt样例阿语采用中性数量标签，避免把简化英语复数机制误套成阿语语法。

## 最小例子

```javascript
const messages = { en: { greeting: 'Hello, {name}', count: 'No courses | One course | {count} courses' } }
// t('greeting', { name: 'Ada' })；t('count', 3, { count: 3 })
// 阿语的6种plural category不能用英语两分支代替。
```

片段按注释提供上下文；完整导入与运行入口见操作卡，不是独立工程。

## 运行与边界

真实Vue-i18n参数Ada、英语0/1/3、中文缺项回退英语、阿语2分支与Intl many分类均测试；不存在的locale被拒绝。

## 移动开发经验对照

迁移的是信任边界、状态所有权与失败恢复方法；浏览器脚本/Cookie/DOM/SSR和原生宿主机制不同。国际化同样需区分语言、时间与排版，不能照搬字符串替换或平台存储假设。
