# 6.4.4 RTL：方向语义、逻辑属性与混排

前置：阶段3工程工具、阶段4Vue/Nuxt和阶段5请求/会话边界。先机制、再本地实验、最后副本变体，不把这些基础质量要求延后到上线。

## 机制与使用场景

dir=rtl是文档/区域的文字方向语义，lang是内容语言，不是同一属性。阿语/希伯来语等场景需要方向与排版一起验证；不要对整页scaleX(-1)，那会镜像文字和非方向图标。

用margin-inline/padding-inline/inset-inline等逻辑属性表达起止边，与必要的方向性图标配合；品牌、照片、数字/代码不应机械镜像。混排账号/URL可用bdi或合适dir隔离，不能把字符串字符顺序反转来“支持RTL”。

视觉顺序和DOM/键盘顺序要同时考虑。direction影响flex起始侧不表示所有自定义组件已可用；表单、菜单、焦点、溢出和长文案应实测，屏幕阅读器/母语审校仍是独立验证。

## 最小例子

```css
html[dir='rtl'] { /* 使用方向语义，不反转字符串 */ }
.card { padding-inline: 1rem; margin-inline-start: .5rem; }
/* 混排示例：<bdi dir="auto">user@example.test</bdi> */
```

片段按注释提供上下文；完整导入与运行入口见操作卡，不是独立工程。

## 运行与边界

独立浏览器实验en→ar后html lang/dir同时更新，START实际盒子位于END右侧；390/1440无横向溢出，再切英文恢复。

## 移动开发经验对照

迁移的是信任边界、状态所有权与失败恢复方法；浏览器脚本/Cookie/DOM/SSR和原生宿主机制不同。国际化同样需区分语言、时间与排版，不能照搬字符串替换或平台存储假设。
