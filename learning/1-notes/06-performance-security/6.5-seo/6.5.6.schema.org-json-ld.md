# 6.5.6 JSON-LD：内容一致、结构和script注入边界

前置：阶段1语义/样式、阶段3工程工具、阶段4Vue/Nuxt；本章是在已有能力上深化，不是首次才考虑质量。

## 解决什么问题

用机器可读结构表达页面已有内容，同时避免在script上下文直接拼接不可信文本。

## 机制与边界

Schema.org提供词汇，JSON-LD是数据表达方式；能JSON.parse不等于符合某个搜索功能资格，也不保证富结果。类型/属性必须与真实可见内容一致，不能造评分、认证或课程事实。

JSON-LD嵌在script type=application/ld+json时，HTML解析器仍会识别结束script标签。把用户文本直接JSON.stringify后塞innerHTML并非完整上下文防护；可将<转义为\u003c等，或使用框架验证过的安全序列化。

只纳入允许公开的数据，避免把会话、内部ID或诊断信息顺手输出；CSP、XSS和内容校验仍各有边界。结构验证/富结果测试与真实收录要分别说明。

## 最小机制片段

```typescript
export function serializeJsonLd(value: unknown): string {
  const json = JSON.stringify(value)
  if (typeof json !== 'string') throw new TypeError('JSON-LD必须可序列化')
  return json.replace(/</g, '\\u003c')
}
// 含 </script> 的文本仍不能结束数据script；此函数不验证schema资格。
```

片段按注释提供上下文，完整可运行文件及操作条件见示例；不能把片段或观察清单当完整生产实现。

## 实际观察与适用场景

Nuxt shared/utils/seo.ts提供转义，首页ItemList/详情Course与可见内容对应；单元和原始响应检查恶意形状字符串不能结束script。未向外部富结果工具上传私有内容。

## 移动经验对照

移动端也要管理内容与分享，但Web还有可抓取URL、HTTP状态、HTML元信息和搜索索引生命周期，不能套用原生页面路由或商店排名机制。
