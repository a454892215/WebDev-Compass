# 6.5.3 title、description、canonical与多语言对应URL

前置：阶段1语义/样式、阶段3工程工具、阶段4Vue/Nuxt；本章是在已有能力上深化，不是首次才考虑质量。

## 解决什么问题

让每个可索引页面拥有明确身份，避免查询和多语种页面互相混淆。

## 机制与边界

title应准确描述页面，description提供有用摘要；搜索系统可能重写展示内容，并非写了就必定原样显示。Nuxt用响应式useHead/useSeoMeta同时考虑SSR和客户端导航更新，不能只在mounted修改document.title。

canonical指示偏好URL，是信号而非访问重定向或绝对命令。应由可信配置构造绝对地址，不信任任意Host/query拼接；同一语言页面一般自指canonical，语言替代用hreflang并提供互返关系。

查询/筛选页若选择noindex需与robots抓取策略配合，避免禁止抓取导致机器人看不到noindex。canonical去q是本项目明确取舍，不代表所有网站过滤参数都可无条件删除。

## 最小机制片段

```javascript
// 主工程课程页script setup上下文：course为已加载课程ref，canonicalUrl为computed绝对URL。
// 获取course见courses/[slug].vue；可信基址生成见shared/utils/seo.ts。
// 下面保留响应式getter，不能复制到普通Node脚本独立运行。
useHead(() => ({
  title: course.value.title,
  link: [{ rel: "canonical", href: canonicalUrl.value }],
}))
useSeoMeta({ description: () => course.value.summary })
```

片段按注释提供上下文，完整可运行文件及操作条件见示例；不能把片段或观察清单当完整生产实现。

## 实际观察与适用场景

Nuxt原始HTML和客户端详情切换核对title/description，canonical以https://compass.example为保留域名占位且无q，hreflang覆盖三语与x-default；不外网请求占位域名。

## 移动经验对照

移动端也要管理内容与分享，但Web还有可抓取URL、HTTP状态、HTML元信息和搜索索引生命周期，不能套用原生页面路由或商店排名机制。
