# 6.5.4 Open Graph与Twitter Card：分享元信息和验证边界

前置：阶段1语义/样式、阶段3工程工具、阶段4Vue/Nuxt；本章是在已有能力上深化，不是首次才考虑质量。

## 解决什么问题

为分享消费者提供可解释的标题、摘要和图片，不把标签存在当真实平台预览已通过。

## 机制与边界

Open Graph常用og:title/type/url/description/image；Twitter Card元信息仍使用twitter:等协议字段，不因平台品牌变化随意改字段名。不同消费者的抓取/缓存/支持不同，需按目标平台文档验证。

图片应可被目标消费者访问，使用合适绝对URL、尺寸和内容；本地127.0.0.1或保留域名无法成为真实公网分享认证。元信息应在目标爬虫能获取的初始响应，且与公开可见页面一致。

分享缓存可能滞后，测试时区分响应标签、图片资源可达和平台缓存刷新。不要为了预览暴露私人页面或在URL中放凭证。

## 最小机制片段

```javascript
// Nuxt script setup片段，useSeoMeta由Nuxt自动导入。
const title = "Web学习目录"
const imageUrl = "https://compass.example/images/og-cover.png" // 保留域名，占位不上网请求。
useSeoMeta({ ogTitle: title, ogType: "website", ogImage: imageUrl, twitterCard: "summary_large_image" })
```

片段按注释提供上下文，完整可运行文件及操作条件见示例；不能把片段或观察清单当完整生产实现。

## 实际观察与适用场景

检查Nuxt初始响应中的og/twitter字段和图片本地资产；这是标签/资源验证，不代表真实社交平台已抓取。

## 移动经验对照

移动端也要管理内容与分享，但Web还有可抓取URL、HTTP状态、HTML元信息和搜索索引生命周期，不能套用原生页面路由或商店排名机制。
