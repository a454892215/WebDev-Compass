# 6.3.7 axe与Lighthouse：自动发现、人工验证和回归边界

前置：阶段1语义/样式、阶段3工程工具、阶段4Vue/Nuxt；本章是在已有能力上深化，不是首次才考虑质量。

## 解决什么问题

用工具发现可重复的缺陷，同时避免将自动化当完整无障碍认证。

## 机制与边界

axe-core可在浏览器页面运行规则，结果含violations/incomplete/passes等；incomplete需要进一步检查，不等于通过。工具的标签/规则覆盖随版本变化，应记录版本、页面、状态与选用规则。

Lighthouse无障碍评分由部分审计组成，不能覆盖所有WCAG或真实用户任务。axe DevTools扩展、axe-core自动引擎、Lighthouse是不同工具入口，运行某一个不能声称全部已操作。

先用受控坏样本证明检查真的会失败，再修复并回归。键盘、缩放、dialog动态状态、真实辅助技术需组合证据；不要为提高分数删除业务内容或忽略真实问题。

## 最小机制片段

```javascript
// Node ESM上下文：page是已打开lab页面的Playwright Page，完整见lab/verify.mjs。
import { createRequire } from "node:module"
const require = createRequire(import.meta.url)
await page.addScriptTag({ path: require.resolve("axe-core/axe.min.js") })
const result = await page.evaluate(() => axe.run(document, {
  runOnly: { type: "tag", values: ["wcag2a", "wcag2aa", "wcag21aa", "wcag22aa"] },
}))
// violations为空只描述该次检测；incomplete仍需复核。
```

片段按注释提供上下文，完整可运行文件及操作条件见示例；不能把片段或观察清单当完整生产实现。

## 实际观察与适用场景

本轮真实axe-core4.14.1：正确页两视口零违规；坏样本检测button-name/image-alt/label。未操作axe扩展UI，不以此冒称Lighthouse也已运行。

## 移动经验对照

类似移动自动无障碍扫描，但工具规则、可见树与Web场景不同；跨平台分数不能等价比较。
