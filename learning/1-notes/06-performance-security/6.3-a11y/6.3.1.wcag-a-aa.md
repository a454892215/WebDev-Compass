# 6.3.1 WCAG 2.2：等级、范围与验收证据

前置：阶段1语义/样式、阶段3工程工具、阶段4Vue/Nuxt；本章是在已有能力上深化，不是首次才考虑质量。

## 解决什么问题

把“页面看起来能用”转成具体可验证准则，避免拿一次自动扫描结果直接宣称符合WCAG。

## 机制与边界

WCAG 2.2按可感知、可操作、可理解、健壮组织，成功准则分A/AA/AAA。宣称AA需满足该范围内所有适用A与AA，不是只满足若干常见规则或axe得分。WCAG标准与Understanding/APG技术说明用途不同，后者帮助解释而非另立强制规则。

验收先列页面、流程、状态和适用准则，再选择自动/键盘/视觉/辅助技术等证据。登录失败、弹窗、动态错误、窄屏和语言切换都可能暴露初始页面扫描看不到的问题。

本地lab只给特定页面和交互的部分证据：axe、焦点、受控文字放大等。没有真实屏幕阅读器/残障用户测试，不给完整符合性认证。

## 最小机制片段

```javascript
// 验收记录示意：不是程序判断整个站点已AA。
// 范围: 课程表单；准则: 3.3.2标签、2.1.1键盘、1.4.10重排。
// 证据: 标签关联/键盘实测/320CSSpx；未测:真实辅助技术。
```

片段按注释提供上下文，完整可运行文件及操作条件见示例；不能把片段或观察清单当完整生产实现。

## 实际观察与适用场景

独立lab正确页面axe零违规，坏样本仍报button-name/image-alt/label；比较两类结果，说明“零检测”不等于所有准则已审。

## 移动经验对照

可迁移移动端无障碍验收意识，但WCAG网页成功准则与Android/Flutter检查工具的结果不能直接互认。
