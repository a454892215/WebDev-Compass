# 6.1.2.4 Web Worker：移出主线程与协议清理

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

把可独立计算的CPU任务移出界面线程，保留即时交互。

## 原理与选择

Worker有独立执行上下文，不能直接操作DOM。通过消息传数据/结果，序列化与传输也有成本；小任务不一定值得创建Worker。

协议需校验输入、任务id、取消/过时结果和错误；terminate结束当前worker但不保证远程业务回滚。使用transferable可减少部分复制但会转移所有权。

lab是固定2000000项数值求和，结果确定；主线程按钮可继续操作，pagehide停止Worker。它不证明任意业务加Worker就更快，也未实现通用任务池。

## 最小机制片段

```javascript
const worker = new Worker(new URL('./worker.js', import.meta.url), { type: 'module' })
worker.onmessage = event => { showResult(event.data); worker.terminate() }
worker.postMessage(2000000)
// 生命周期结束也terminate；真实协议还需任务id/输入与错误校验。
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

Chrome验证Worker返回1999999000000，同时响应计数能点击；构建产生实际worker资产，完成后terminate。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
