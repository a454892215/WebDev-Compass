# 6.1.1.1 Core Web Vitals：场数据与实验数据

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

把“这台电脑一次很快”与“真实用户体验达标”分开，才能选对优化目标。

## 原理与选择

当前核心指标为LCP、INP、CLS。良好阈值分别为LCP≤2.5秒、INP≤200毫秒、CLS≤0.1；场数据通常按页面访问分布的第75百分位判断，并区分移动/桌面。没有足够真实会话，不能从单次自动化数据算出生产p75。

LCP描述主要内容呈现；INP覆盖访问中的交互响应，受输入延迟、处理和呈现影响；CLS关注非预期视觉位移并按会话窗口聚合。不能把原始entry简单求和/取最大就等同正式指标算法。

本lab用PerformanceObserver读取原生候选/长任务/位移条目，Lighthouse给一次lab LCP/CLS/TBT；TBT不是INP。真实线上测量可用官方web-vitals并按隐私/采样/清理要求设计，这里不上传遥测。

## 最小机制片段

```javascript
const observer = new PerformanceObserver(list => console.log(list.getEntries()))
if (PerformanceObserver.supportedEntryTypes.includes('largest-contentful-paint')) {
  observer.observe({ type: 'largest-contentful-paint', buffered: true })
}
// 原始候选用于诊断，不是生产p75；离开时observer.disconnect()。
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

进入lab先不交互，再读取观测；点击可控阻塞后看longtask。Lighthouse JSON的TBT/LCP只代表本次本地环境，没有用户访问分布。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
