# 6.1.2.2 虚拟列表：DOM窗口与可访问内容

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

长列表滚动时只保留一个可控DOM窗口，但同时设计完整阅读与定位。

## 原理与选择

虚拟列表维护总高度、可见范围和overscan，将数据索引映射到渲染窗口；它减少DOM数量，不减少所有数据/网络成本。可变行高、动态内容、缩放和焦点需要更复杂估计。

窗口外节点不存在，浏览器查找、屏幕阅读、打印、锚点及键盘焦点都受影响。不能只看滚动顺滑就称无障碍完成；可提供分页或完整模式。

lab用固定36px/1000条fixture，窗口12条，明确不适合任意多行动态业务。稳定业务key/身份在框架版仍重要，不用滚动位置代替数据ID。

## 最小机制片段

```javascript
const start = Math.max(0, Math.floor(viewport.scrollTop / 36) - 2)
const end = Math.min(1000, start + 12)
// spacer表示总高度；只渲染[start,end)，并平移到start*36。
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

真实Chrome检查初始12/1000，scrollTop18000后首项498；切完整模式1000条，再切回12。没有把完整无障碍/动态行高宣称已实现。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
