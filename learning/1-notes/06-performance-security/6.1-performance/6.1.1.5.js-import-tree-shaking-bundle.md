# 6.1.1.5 JS：动态加载、摇树与产物证据

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

把不需要立即执行的能力移出首屏，并验证构建确实按预期处理。

## 原理与选择

动态import建立可按需加载的模块边界；它返回Promise，需要处理加载失败。切分并不保证任何场景更快，过多chunk可能产生额外请求与依赖瀑布。

Tree Shaking依赖模块可分析性和副作用信息；未使用纯导出可以消除，模块初始化副作用不能为缩包随意删除。package sideEffects:false错误声明会破坏行为。

压缩/摇树/分包是不同步骤。看实际产物和真实网络消费，不凭源码用了import()就宣布首包或交互改善。

## 最小机制片段

```javascript
document.querySelector('#lazy').onclick = async () => {
  const { summary } = await import('./statistics.js')
  document.querySelector('#lazy-result').textContent = summary()
}
// 完整lab同时验证唯一unused标记未进入运行JS。
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

Vite真实构建包含statistics和third-party独立dynamic entry；check-artifacts检查纯unused唯一标记不在运行JS。Chrome点击前无模块请求，点击后显示真实返回值。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
