# 6.1.2.3 防抖与节流：频率、尾调用与清理

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

限制高频副作用，同时保留用户最终意图与正确的生命周期。

## 原理与选择

防抖等待一段安静时间，适合搜索提交等最后意图；节流限制最大频率，可选leading/trailing。两者不相同，参数和取消需要明确。

延迟输入处理不应阻止原生输入显示；请求仍需取消/迟到保护，减少发起次数不等于解决竞态。离开页面或依赖改变时清理计时器。

测试用可控时钟验证时间边界，避免固定真实sleep造成偶发通过。用户需要立即执行时可设计flush，而不是所有事件统一延迟。

## 最小机制片段

```javascript
const search = debounce(value => showResult(value), 100)
input.addEventListener('input', event => search(event.target.value))
// pagehide / unmount: search.cancel()；完整lab提供可控clock注入。
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

Node控制时钟验证最后输入、trailing与cancel；Chrome快速fill两次只呈现latest，页面离开取消计时器。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
