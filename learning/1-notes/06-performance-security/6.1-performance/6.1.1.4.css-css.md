# 6.1.1.4 关键CSS、非关键样式与闪烁边界

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

减少首屏渲染依赖，同时保留稳定样式与缓存能力。

## 原理与选择

样式表通常参与渲染阻塞；关键CSS提取要覆盖真实首屏，不只是把所有CSS塞进HTML。内联会增加HTML并降低跨页缓存复用，过量内联不是通用优化。

非关键样式可按媒体/路由/组件拆分；print媒体不应阻塞屏幕首屏，但仍可能被浏览器低优先级下载。异步preload/onload切换需考虑JS失败、CSP和FOUC，不盲抄内联onload。

SSR框架可能已有CSS提取和组件拆分，应先查看真实生成HTML和资源。延迟样式不能让重要信息、焦点或布局在交互时突然变化。

## 最小机制片段

```html
<style>/* 仅实际首屏必要规则 */ body{margin:0;font-family:system-ui} </style>
<link rel="stylesheet" href="./print.css" media="print">
<!-- print.css为lab public目录提供的可选观察fixture；页面默认仍正常加载主样式。 -->
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

在lab产物index.html检查Vite提取的CSS与加载顺序，操作卡提供首屏/print清单；本例没有声称自动关键CSS提取器已运行。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
