# 6.1.1.8 CDN：缓存键、版本与部署边界

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

把可公开复用资源放到靠近用户的位置，同时避免缓存错人或发布新旧不一致。

## 原理与选择

CDN收益取决于用户距离、命中、回源和网络，不是换个域名就保证快。哈希资源可长缓存，入口文档与个性化响应需不同策略。

缓存键要考虑路径、查询、编码与明确允许的变体；带身份数据不能因“静态站”标签被公共缓存。清理/版本切换需与HTML引用和保留旧资产协调。

本课程不部署外部CDN、不压测第三方；用具体官方检查清单评估目标profile。源站正确头不等于所有中间层配置已被验证。

## 最小机制片段

```javascript
// 适用条件不同的示意响应：
// public hashed /assets/app.abcd.js: public,max-age=31536000,immutable
// personalized /account: private,no-store
// HTML入口: 依时效协商或短缓存；不能无脑套同一条头。
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

阅读本地公开cache与mockPrivate no-store响应，对照官方CDN检查清单；没有真实边缘节点/命中率/跨地域时延数据。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
