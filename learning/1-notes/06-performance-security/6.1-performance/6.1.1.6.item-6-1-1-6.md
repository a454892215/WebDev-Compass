# 6.1.1.6 第三方脚本：加载时机、隐私与降级

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

第三方脚本可能占网络/主线程，还可能接触页面数据，不能只看功能是否出现。

## 原理与选择

先盘点来源、业务必要性、数据访问和用户同意，再决定是否加载。async适合独立脚本，defer/module对解析时序不同；延迟并不会让不可信脚本自动安全。

按用户动作加载可以避免未使用能力首屏执行，但要处理失败、重复点击与撤销/清理。不可用应让核心内容继续工作，不把关键业务藏在不透明第三方执行里。

本地替身用于观察时序，无真实analytics、上报或第三方Cookie。生产还需CSP/来源、供应链、隐私和预算专项。

## 最小机制片段

```javascript
document.querySelector('#third').onclick = async () => {
  const module = await import('./third-party.js')
  document.querySelector('#third-result').textContent = module.loaded
}
// 仅本地替身，不连接外部统计服务。
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

Chrome确认允许动作前未加载替身chunk/global标记，动作后模块执行；它不代表真实服务的同意/隐私流程已经实现。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
