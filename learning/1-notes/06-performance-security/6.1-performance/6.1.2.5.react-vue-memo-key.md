# 6.1.2.5 Vue/React性能：先测量再选择机制

前置：阶段2浏览器/模块、阶段3工程工具与阶段4Vue/Nuxt；先明确测量目标，再读机制和实验。

## 解决什么问题

利用框架实际的更新模型，而不是把某生态规则机械套到所有组件。

## 原理与选择

Vue基于响应式依赖和编译优化，computed缓存派生计算；Props稳定与组件边界可减少更新，但要先确认实际成本。不要为了“性能”复制第二份事实状态或过度响应化巨大不可变数据。

React的memo/useMemo/useCallback与Vuecomputed不是同义词；编译器、上下文、依赖和版本也会影响优化方式。缓存不是正确性的基础，删掉后结果仍应正确。

本lab真实测试Vuecomputed在依赖不变时只算一次、变化后重新计算；不运行Vue/React渲染性能基准，不宣称某框架总更快。主线仍Vue/Nuxt，React选修。

## 最小机制片段

```javascript
import { ref, computed } from 'vue'
const source=ref(2)
const doubled=computed(()=>source.value*2)
console.log(doubled.value) // 4
source.value=3
console.log(doubled.value) // 6
```

片段按注释说明DOM/模块/框架上下文，完整导入与运行工程在操作卡；不把独立片段冒充完整可执行项目。

## 实际观察与边界

pnpm check用真实Vue3.5.46检查调用次数与结果。浏览器lab为原生模块，不把它冒充Vue组件重渲染计数。

## 移动开发对照

共同目标是减少等待、主线程工作和资源成本；浏览器渲染、HTTP/页面生命周期、DOM与缓存层不同于移动框架，不能按API名字套底层方案。测试只覆盖本次Web环境。
