# 6.2.7 移动经验迁移：Web、原生UI与WebView脚本边界

前置：阶段3工程工具、阶段4Vue/Nuxt和阶段5请求/会话边界。先机制、再本地实验、最后副本变体，不把这些基础质量要求延后到上线。

## 机制与使用场景

XSS是Web可执行上下文中的信任边界问题，不能用“React Native较少”推出原生应用没有注入风险。浏览器DOM、React Native原生宿主与Flutter渲染机制不同；但WebView里运行网页会重新引入Web脚本、导航、来源和存储边界。

如果WebView暴露原生bridge，不可信页面或脚本可能调用更高权限能力；因此导航/资源来源、消息schema、允许操作、会话与最低权限都要单独设计。不要把任意字符串eval、任意消息当命令，postMessage本身不是认证。

本阶段只运行浏览器安全fixture，未构建Android/iOS/WebView或真实原生桥；对照用于分析，不能冒称移动安全认证或按名字直接搬库。

## 最小例子

```javascript
// Web侧接收跨文档消息的机制示意，仍需校验业务schema。
if (event.origin !== expectedOrigin || event.source !== expectedWindow) return
if (!isAllowedMessage(event.data)) return
// 不执行event.data里的代码；原生bridge还需平台自己的限制。
```

片段按注释提供上下文；完整导入与运行入口见操作卡，不是独立工程。

## 移动开发经验对照

迁移的是信任边界、状态所有权与失败恢复方法；浏览器脚本/Cookie/DOM/SSR和原生宿主机制不同。国际化同样需区分语言、时间与排版，不能照搬字符串替换或平台存储假设。
