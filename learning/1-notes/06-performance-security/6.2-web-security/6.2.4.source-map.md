# 6.2.4 前端秘密与Source Map：构建、发布和读取边界

前置：阶段3工程工具、阶段4Vue/Nuxt和阶段5请求/会话边界。先机制、再本地实验、最后副本变体，不把这些基础质量要求延后到上线。

## 机制与使用场景

客户端可下载的JS、HTML、payload和公开配置都由用户控制，不能把API私钥、长期服务凭据或可信授权判断放进去。VITE_或Nuxt public是公开约定，不是加密；混淆、压缩和把字符串拆开也不是保密措施。

Source Map帮助错误定位，hidden通常只是生成外部map而不写sourceMappingURL；文件如果公开托管仍可下载，sourcesContent可能含被摇掉代码和注释。生成、上传私有错误平台、静态托管路径和访问控制需分开决定，不能用hidden等同私有。

本例合成server-only canary只演示导入边界和资产检查，不是真密钥；扫描未命中仅覆盖定义的检查，不能证明整个应用没有秘密。生产泄露还需撤销/轮换凭据并处理缓存，不只删当前文件。

## 最小例子

```javascript
// vite.config.mjs
export default defineConfig({ build: { sourcemap: 'hidden' } })
// 实际dist中仍有.map；不能据此宣称源码不可读。
```

片段按注释提供上下文；完整导入与运行入口见操作卡，不是独立工程。

## 运行与边界

实际构建JS没有sourceMappingURL，但map里仍能找到SOURCE_ONLY_PUBLIC_DEMO注释；未导入的server-only合成canary没有进入JS/map。两项产物检查均实际执行。

## 移动开发经验对照

迁移的是信任边界、状态所有权与失败恢复方法；浏览器脚本/Cookie/DOM/SSR和原生宿主机制不同。国际化同样需区分语言、时间与排版，不能照搬字符串替换或平台存储假设。
