# 6.2.3 点击劫持：frame-ancestors与嵌入需求

前置：阶段3工程工具、阶段4Vue/Nuxt和阶段5请求/会话边界。先机制、再本地实验、最后副本变体，不把这些基础质量要求延后到上线。

## 机制与使用场景

点击劫持利用页面被嵌入后对UI的遮挡/诱导，不要求窃取DOM读取权限。默认不允许嵌入的页面可以发送CSP frame-ancestors none，并按目标兼容用X-Frame-Options DENY；确需伙伴嵌入时按明确祖先来源设计，不把所有站点放行。

frame-ancestors控制谁能嵌入当前文档，frame-src控制当前文档能加载谁，不是同一方向。frame-ancestors必须以HTTP响应头部署，meta不能替代；多层祖先和实际代理响应也需核对。X-Frame-Options旧式ALLOW-FROM不作为现代跨浏览器伙伴白名单方案。

本例只在本地两端口测试允许/拒绝嵌入，不改浏览器安全设置，不声称支付/登录UI已通过完整攻防评审。

## 最小例子

```http
Content-Security-Policy: frame-ancestors 'none'
X-Frame-Options: DENY


```

## 移动开发经验对照

迁移的是信任边界、状态所有权与失败恢复方法；浏览器脚本/Cookie/DOM/SSR和原生宿主机制不同。国际化同样需区分语言、时间与排版，不能照搬字符串替换或平台存储假设。
