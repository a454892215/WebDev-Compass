# 2.2.9 Service Worker：作用域、生命周期与离线回退

[本章目录](./README.md) · [阶段地图](../../../../knowledge-map/01-foundation-stages-0-2.md#22-浏览器原理)

## 解决什么问题

离线能力需要拦截请求并明确更新/失效策略。Service Worker不是一直运行的页面线程，也不等于安装一个PWA就完成了所有离线体验。

## 原理与关键规则

Service Worker运行在独立于页面的worker环境，没有直接DOM访问。注册需安全上下文（本机loopback可用），脚本URL和scope限定它能控制的客户端范围；生命周期有install、activate及后续事件，浏览器可终止空闲实例。

新注册不意味着当前页面立刻由它控制。clients.claim可在激活后接管范围内客户端；更新可能等待旧客户端关闭。skipWaiting会改变更新切换时机，生产应用应处理旧页面/新资源兼容，不能无条件复制教学捷径。

fetch事件可选择网络和Cache Storage；缓存API与HTTP缓存不同，离线回退需自己设计。不要缓存敏感认证数据、所有跨源opaque响应或无限积累版本；Cache.put仅适用于合规请求/响应，不是POST队列。

本例仅拦截本组的sw-sample.json：联网时请求并更新缓存，断网时返回自己的已缓存数据。它不缓存整个站点、不提供安装清单和后台同步，也不声称完整PWA通过。清理只移除本例registration及命名缓存。

## 最小例子

以下JavaScript在配套浏览器页面的模块环境或Console中观察，元素由该页面提供；HTML片段中的资源名是说明用占位，完整实验使用本地真实文件，不要求在空白Node文件直接运行。

```javascript
// 位于本组目录下的页面；注册范围不会跨到其他教材。
const registration = await navigator.serviceWorker.register('./sw.js', {scope:'./'});
console.log(registration.scope);
// 进入受控状态后，再测试联网/离线请求；结束只清理本例。
```

片段用于解释本节关键机制；完整运行环境和真实资源见[本节实验](../../../2-examples/02-javascript-browser/2.2-browser-internals/2.2.9.service-worker-pwa-demo.html)，不把占位资源名视为仓库已有文件。

## 移动端对照与边界

类似离线资源策略与后台事件概念，但浏览器决定worker生命周期；不能把它当Android长期前台服务，也不能把全局变量当持久数据库。

## 常见误区

注册成功不等于页面已受控；service worker不是Web Worker；缓存旧壳未配更新可让用户长期拿到旧内容。离线实验必须真断开该测试上下文网络，不能只切换UI标签。

## 实验与独立实践

1. 注册后等待页面controller就绪，在线请求本例JSON，观察网络来源。
2. 只对这个测试浏览器上下文设离线，再请求同一路径，应由Service Worker缓存回退；不停止整个电脑网络。
3. 恢复在线并清理本例，确认controller/缓存范围；刷新后不再假定仍受控。
