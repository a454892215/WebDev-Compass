# 2.2.3 布局与绘制失效：避免交错读写造成布局抖动

[本章目录](./README.md) · [阶段地图](../../../../knowledge-map/01-foundation-stages-0-2.md#22-浏览器原理)

## 解决什么问题

循环中“写样式→读尺寸→再写”可能反复迫使浏览器同步计算布局。优化的目标是减少不必要的工作，而不是让所有布局永远不发生。

## 原理与关键规则

布局相关属性、内容、字体或视口变化可能使几何失效。仅改变颜色通常不改变几何，但仍可能需要绘制；浏览器也会按影响范围增量处理。

写入使样式/布局失效后，offsetWidth、getBoundingClientRect等读取可能迫使浏览器同步更新。是否真的产生强制布局取决于此前状态，不能把任何读取都说成慢。

先批量读取所需尺寸，再批量写入，通常有助于避免循环里的读写往返。更好的布局模型、CSS能力和减少节点也可能比手工微调更有效。

performance.now测得一段脚本的耗时，不等于完整一帧，也不直接给出布局次数或用户INP。应在相同环境用Performance跟踪确认瓶颈，避免一次快慢偶然值下定论。

## 最小例子

以下JavaScript在配套浏览器页面的模块环境或Console中观察，元素由该页面提供；HTML片段中的资源名是说明用占位，完整实验使用本地真实文件，不要求在空白Node文件直接运行。

```javascript
const cards = [...document.querySelectorAll('.card')];
const widths = cards.map(card => card.offsetWidth); // 读阶段
cards.forEach((card, i) => {
  card.style.width = `${widths[i] + 1}px`; // 写阶段
});
```

片段用于解释本节关键机制；完整运行环境和真实资源见[本节实验](../../../2-examples/02-javascript-browser/2.2-browser-internals/2.2.3.reflow-repaint-demo.html)，不把占位资源名视为仓库已有文件。

## 移动端对照与边界

与移动端避免布局阶段反复触发测量的思路相通；浏览器这里还受CSS失效与同步几何API影响，不等同于Flutter setState调用次数。

## 常见误区

“所有DOM操作都重排”“transform绝不需要绘制”“脚本耗时低就代表没有布局抖动”都过于绝对。

## 实验与独立实践

1. 分别执行交错模式与批量模式，确认两者最终宽度变化相同。
2. 读取页面实际输出的脚本耗时，但不据此宣称布局次数或性能排名。
3. 在Performance里为两种模式各录一次，核对Layout及强制重排线索；同轮不额外做真机基准。
