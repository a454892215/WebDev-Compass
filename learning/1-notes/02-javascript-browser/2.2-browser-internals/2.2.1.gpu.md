# 2.2.1 浏览器多进程：页面、渲染器与GPU的职责

[本章目录](./README.md) · [阶段地图](../../../../knowledge-map/01-foundation-stages-0-2.md#22-浏览器原理)

## 解决什么问题

页面中的JavaScript不是浏览器的全部。遇到页面卡顿、崩溃或隔离问题，需要区分进程与线程，而不是一概称为“JS线程”。

## 原理与关键规则

浏览器进程管理窗口、导航、权限等浏览器级功能；渲染进程负责页面内容，内部又有主线程、合成等不同职责。GPU、网络等工作可分到其他进程或服务，具体划分随浏览器与平台变化。

进程有独立地址空间，线程是进程内的执行单元。进程间通信与共享内存方案存在，不表示所有状态自动共用；不能从window对象看到浏览器全部内部状态。

标签、站点、frame和进程不是固定一对一关系。站点隔离可能让跨站iframe位于其他渲染进程；同站页面也可能复用进程。实际数量受隔离策略、资源及实现影响。

navigator.hardwareConcurrency给出浏览器报告的逻辑处理器数量提示，可能为隐私或策略降低；它既不是当前页面线程数，也不是浏览器进程数。

## 最小例子

以下JavaScript在配套浏览器页面的模块环境或Console中观察，元素由该页面提供；HTML片段中的资源名是说明用占位，完整实验使用本地真实文件，不要求在空白Node文件直接运行。

```javascript
const report = {
  logicalProcessorHint: navigator.hardwareConcurrency,
  crossOriginIsolated: window.crossOriginIsolated,
};
console.log(report); // 只报告页面可见能力，不报告PID。
```

片段用于解释本节关键机制；完整运行环境和真实资源见[本节实验](../../../2-examples/02-javascript-browser/2.2-browser-internals/2.2.1.gpu-demo.html)，不把占位资源名视为仓库已有文件。

## 移动端对照与边界

可以借助Android进程/线程概念理解隔离，但Web页面不能像原生应用一样自行决定浏览器渲染进程拓扑。Flutter isolate与浏览器进程也不是可直接互换的单位。

## 常见误区

“开三个标签一定有三个渲染进程”“GPU进程存在就代表页面全部在GPU执行”都不成立。页面API返回的CPU提示不应伪装成内部进程枚举。

## 实验与独立实践

1. 打开页面读取能力提示，说明每个字段能证明什么、不能证明什么。
2. 在Chrome任务管理器中找到浏览器、页面与GPU相关条目，再打开同站/跨站页面观察；不同浏览器可用自己的任务工具。
3. 保存实际截图或文字记录并标明浏览器版本；若未操作任务管理器，明确此步骤未验证。

再完成[独立练习](../../../3-exercises/02-javascript-browser/2.2-browser-internals/2.2.1.gpu.md)。综合任务见[阶段项目任务](../../../4-practice/02-javascript-browser/tasks.md#p-2-2-1)；其中副本新增能力不等于参考项目已有实现。
