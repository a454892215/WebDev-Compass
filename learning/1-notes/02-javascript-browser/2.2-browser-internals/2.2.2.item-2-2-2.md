# 2.2.2 渲染流水线：从DOM/CSSOM到布局、绘制与合成

[本章目录](./README.md) · [阶段地图](../../../../knowledge-map/01-foundation-stages-0-2.md#22-浏览器原理)

## 解决什么问题

DOM已经更新不等于像素已经显示。需要理解结构、样式、几何与像素的不同阶段，才能解释读取尺寸、下一帧与视觉变化。

## 原理与关键规则

浏览器解析HTML形成DOM，解析样式形成CSSOM相关结构，通过样式计算得到节点使用的样式，再构建参与布局的结构。布局计算几何；绘制产生绘制记录/栅格化相关工作；合成把适当的层组织为最终图像。

这是一张心智模型，不是所有浏览器内部结构的逐字名称。display:none节点仍在DOM中但不参与正常布局；可见性、伪元素和匿名盒又使布局结构并非简单DOM复制。

后续更新从失效的阶段开始，不是每帧重新下载HTML并完整解析。文字颜色改变可能只需样式和绘制，尺寸改变通常还需布局；部分transform/opacity动画在满足条件时可主要由合成处理。

JavaScript修改样式后读取getBoundingClientRect等几何值，浏览器可能为了给出当前值提前刷新样式/布局。返回值不是“屏幕已经绘制完成”的凭证。requestAnimationFrame回调也不是绘制完成通知。

## 最小例子

以下JavaScript在配套浏览器页面的模块环境或Console中观察，元素由该页面提供；HTML片段中的资源名是说明用占位，完整实验使用本地真实文件，不要求在空白Node文件直接运行。

```javascript
const card = document.querySelector('#card');
card.style.width = '260px';
const box = card.getBoundingClientRect();
console.log(box.width); // 当前几何读数，不是绘制结束事件。
```

片段用于解释本节关键机制；完整运行环境和真实资源见[本节实验](../../../2-examples/02-javascript-browser/2.2-browser-internals/2.2.2.item-2-2-2-demo.html)，不把占位资源名视为仓库已有文件。

## 移动端对照与边界

可对照Android测量/布局/绘制或Flutter布局/绘制/合成的分工，但具体失效传播、样式计算和DOM解析属于浏览器机制。不能把CSSOM当Widget树。

## 常见误区

流程图不意味着每个CSS属性都触发相同阶段；“JS执行完屏幕必定更新”“rAF就是after paint”都是错误简化。

## 实验与独立实践

1. 切换卡片宽度与颜色，比较DOM内容、计算样式及几何读数。
2. 用Rendering面板的Paint flashing与Performance录制区分样式、布局和绘制；没有录制时只报告几何结果。
3. 隐藏卡片后确认DOM节点仍存在，再说明为什么宽度/布局参与发生变化。
