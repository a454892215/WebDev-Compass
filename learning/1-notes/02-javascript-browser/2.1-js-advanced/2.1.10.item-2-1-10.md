[返回章节](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md#21-javascript-进阶)

## 解决什么问题与前置

移除页面节点后，为什么监听器或定时任务仍可能保存旧状态并继续工作？

前置：阶段1闭包、事件订阅、定时器、AbortController；2.1.3执行环境。

## 工作机制

1. 可达性是理解自动回收的基本模型：从运行环境根仍可到达的对象不能仅因“不再显示”就假定释放。循环引用本身不必然泄漏；现代GC不是只做简单引用计数。

2. 闭包不是天然泄漏，问题在于长期存活引用把不再需要的数据/DOM保留下来。事件监听器、定时器、订阅、Observer、Worker和Object URL各有对应清理责任。

3. addEventListener可使用AbortSignal批量撤销；定时器用clearTimeout/clearInterval，Observer断开、Worker终止。重复装配前先销毁旧实例，确保一次事件只处理一次。

4. GC何时发生不确定，WeakRef/FinalizationRegistry不能承担关键清理或业务正确性。实验用回调是否停止、监听是否重复等可观察行为验收，不声称直接证明回收完成。

## 最小示例

```javascript
function mount(target, onPing) {
  const controller = new AbortController();
  const timer = setInterval(() => {}, 1000);
  target.addEventListener("ping", onPing, { signal: controller.signal });
  return () => { controller.abort(); clearInterval(timer); };
}
const target = new EventTarget();
let calls = 0;
const dispose = mount(target, () => calls++);
target.dispatchEvent(new Event("ping"));
dispose();
target.dispatchEvent(new Event("ping"));
console.log(calls); // 1
```

## 场景、边界与误区

把DOM从页面移除不等于取消挂在window上的监听器。pagehide中释放资源后若从bfcache恢复，需在pageshow或重新装配流程恢复，不能假定已卸载。

## 移动端经验对照

可联系Flutter dispose、Android lifecycle等资源责任，但Web页面、组件、bfcache及Worker有自己的生命周期；浏览器销毁时机不能直接套Activity。
