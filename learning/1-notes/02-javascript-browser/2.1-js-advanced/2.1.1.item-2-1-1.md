# 2.1.1 原型链：对象委托与属性遮蔽

[返回章节](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md#21-javascript-进阶)

## 解决什么问题与前置

多个对象需要共享方法，如何解释一个对象上不存在却可以读取的属性？

前置：阶段1对象、属性、函数与class；这里先理解对象查找，再读this。

## 工作机制

1. 每个普通对象有内部[[Prototype]]链接。读取自身没有的属性时沿链查找，直到null；写入通常先在接收对象创建/修改自身属性，并非自动改原型。访问器和不可写属性另有规则。

2. 构造函数的prototype是实例默认原型来源；Object.getPrototypeOf(instance)取得实际原型。函数自己的[[Prototype]]与函数.prototype不是同一条关系。

3. Object.create(proto)指定新对象的原型，Object.hasOwn区分自身属性和继承属性。Object.create(null)没有Object.prototype方法，应直接用Object.hasOwn而非obj.hasOwnProperty。

4. __proto__是历史访问器，不建议作为业务接口；优先Object.create/getPrototypeOf。不要修改Object.prototype给全部对象加业务状态，解析外部配置还应防止原型污染。

## 最小示例

```javascript
const shared = { kind: "article" };
const item = Object.create(shared);
item.title = "原型实验";
console.log(item.kind, Object.hasOwn(item, "kind")); // article false
item.kind = "draft";
console.log(shared.kind, item.kind); // article draft
delete item.kind;
console.log(item.kind); // article
```

## 场景、边界与误区

Object.create不是深复制；继承来的数组/对象仍可能共享。修改原型会影响依赖它的对象，也可能损害性能和安全。

## 移动端经验对照

可类比“复用行为”的目的，但Java/Kotlin类继承、Dart类系统与JS运行期对象委托不同；不要把prototype当成静态类型声明。
