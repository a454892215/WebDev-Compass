# 2.1.3 执行上下文、调用栈与异常展开

[返回章节](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md#21-javascript-进阶)

## 解决什么问题与前置

一层函数失败时，后面的语句为何不再执行，而外层finally仍运行？

前置：阶段1函数、作用域、try/catch/finally。

## 工作机制

1. 执行上下文保存执行函数或脚本所需的词法环境、变量与this等信息；调用栈是当前活跃调用的LIFO结构。两者不是“每个文件一个永远存在的栈”。

2. 普通函数调用压入新的执行上下文，return返回到调用者；抛出异常则沿调用链寻找匹配catch，并执行经过的finally。

3. 词法作用域由定义嵌套决定，不等于调用栈顺序。闭包可在调用结束后继续引用环境，因此“函数返回”不代表其所有数据都立刻回收。

4. await会暂停当前异步函数并把恢复工作安排到后续job；它不会把同步调用栈卡住等网络。栈追踪文本是诊断工具，格式和异步栈拼接随引擎不同。

## 最小示例

```javascript
const trace = [];
function inner() { trace.push("inner"); throw new Error("演示故障"); }
function outer() {
  trace.push("outer:start");
  try { inner(); trace.push("unreachable"); }
  finally { trace.push("outer:finally"); }
}
try { outer(); } catch { trace.push("caught"); }
console.log(trace); // outer:start, inner, outer:finally, caught
```

## 场景、边界与误区

递归深度有限且上限依引擎/环境，不要用固定次数验收。finally中return可能覆盖原返回或异常，清理逻辑通常不应吞错。
