# 2.1.5 浅复制、structuredClone与JSON序列化边界

[返回章节](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md#21-javascript-进阶)

## 解决什么问题与前置

复制草稿后修改嵌套内容，为什么原稿也改变？什么时候需要复制，什么时候应该共享？

前置：阶段1对象共享、展开、JSON、Map及Date。

## 工作机制

1. 展开对象只复制可枚举自身属性的值；嵌套引用仍共享。复制数组也不会自动克隆其中的对象。冻结外层对象不等于深冻结。

2. structuredClone按结构化克隆算法复制支持的数据，包括循环引用、Date、Map等；函数、DOM节点等不受支持，会抛DataCloneError。自定义原型、访问器和属性描述符也不能当作完整保真复制。

3. JSON stringify/parse用于JSON兼容数据的序列化，不是通用深复制；Date变字符串、对象中的undefined字段会消失、循环引用会抛错，BigInt默认也不可直接JSON序列化。

4. transfer选项将可转移资源的所有权转移而非复制，原ArrayBuffer会分离。为了撤销/草稿复制应先定义数据模型，避免每次渲染无差别深复制。

## 最小示例

```javascript
const original = { meta: { title: "初稿" }, when: new Date("2026-01-01") };
const shallow = { ...original };
const deep = structuredClone(original);
shallow.meta.title = "被浅复制修改";
console.log(original.meta.title); // 被浅复制修改
console.log(deep.meta.title); // 初稿
console.log(deep.when instanceof Date); // true
console.log(typeof JSON.parse(JSON.stringify(original)).when); // string
```

## 场景、边界与误区

JSON变换可能有意改变数据格式，不能把它的限制一概叫bug；structuredClone不是复制业务对象所有行为的方法。缺API时应按模型选择替代，不偷偷用JSON声称同等能力。

## 移动端经验对照

类似移动端数据模型的浅复制/序列化区别，但Dart模型copyWith、Kotlin data class.copy也通常不是深复制；最终按字段引用关系解释，而非依方法名称判断。
