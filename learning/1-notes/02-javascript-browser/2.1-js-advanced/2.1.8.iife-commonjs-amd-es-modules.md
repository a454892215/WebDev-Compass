## 工作机制

1. IIFE用函数作用域封装变量，不是模块加载协议；仍可能手动挂全局入口。CommonJS的require/module.exports来自对应运行时或打包器，不是浏览器原生全局。

2. AMD使用define等加载约定，主要用于理解旧项目；本课不安装模拟加载器。发展顺序是历史线索，不表示今天必须依次采用全部格式。

3. ESM有静态import/export、模块图、live binding和模块作用域，默认严格。相同环境中同一解析模块URL通常只求值一次并复用模块记录；URL查询不同可形成不同模块实例。

4. 动态import返回Promise，用于按需加载；浏览器需正确JavaScript MIME与CORS。Node中.cjs/.mjs和package.json的type共同影响解释模式，不能只靠文件里有没有export判断。

## 最小示例

```javascript
// counter.mjs（独立文件）
export let value = 0;
export function increment() { value += 1; return value; }

// main.mjs（另一个文件，通过HTTP加载）
const first = await import("./counter.mjs");
const second = await import("./counter.mjs");
console.log(first === second); // true
first.increment();
console.log(second.value); // 1：live binding
```

## 场景、边界与误区

浏览器原生ESM不自动识别裸包名，除非有import map或工具转换。导入绑定只读不意味着导出对象不可变；模块级状态也是共享状态，SSR还需请求隔离设计。
