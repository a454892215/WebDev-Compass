# 2.1.9 严格模式：把隐式错误转为明确失败

[返回章节](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md#21-javascript-进阶)

## 解决什么问题与前置

为什么模块中的漏写变量、失去接收者或写只读属性更容易暴露错误？

前置：阶段1变量、函数、模块、try/catch；结合2.1.2理解this。

## 工作机制

1. 经典脚本/函数可通过有效指令序言中的"use strict"开启严格模式；ES模块和class体自动严格，不需要重复写。严格模式不是TypeScript，也不提供静态类型检查。

2. 严格模式中给未声明标识符赋值会抛ReferenceError，不再隐式建立全局属性；写不可写属性等失败会抛TypeError。部分语法错误发生在解析期，不能用同一脚本后面的try/catch挽救。

3. 普通函数无接收者调用的this为undefined；非严格经典函数可能把它替换为globalThis。箭头捕获this规则不因此变成另一套。

4. 严格模式作用于对应脚本/函数，不会自动改变被调用的外部非严格函数。生产代码优先模块化和lint，不用开启严格模式替代权限、输入校验或沙箱。

## 最小示例

```javascript
// 本片段保存为ES模块。
function receiver() { return this; }
console.log(receiver()); // undefined
try { stage2UnDeclaredName = 1; } catch (error) {
  console.log(error.name); // ReferenceError
}
const fixed = Object.freeze({ value: 1 });
try { fixed.value = 2; } catch (error) {
  console.log(error.name); // TypeError
}
```

## 场景、边界与误区

在非简单参数列表函数体中放use strict会产生语法问题；初学直接使用ESM更清楚。不要为了让旧脚本“能跑”删掉严格模式并掩盖隐式全局。
