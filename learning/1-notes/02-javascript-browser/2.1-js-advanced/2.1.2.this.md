# 2.1.2 this：由调用方式决定的接收者

[返回章节](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md#21-javascript-进阶)

## 解决什么问题与前置

同一方法通过对象调用正常，传给回调后却读不到状态，原因在哪里？

前置：阶段1普通/箭头函数、对象方法；先完成2.1.1。

## 工作机制

1. 普通函数的this由调用方式决定，不由定义位置自动绑定。obj.method()以obj为接收者；先取出method再单独调用会丢失该接收者。

2. 严格模式普通调用的this为undefined；非严格经典脚本还存在全局替换和基本值装箱。模块自动严格，不能把经典脚本控制台现象当模块规则。

3. call逐个传参，apply用参数数组；bind返回固定this及可选前置参数的新函数。保存绑定后的函数引用，才能正确removeEventListener。

4. new调用会创建实例并作为this；用new调用已bind函数时构造接收者规则优先，绑定参数仍保留。箭头函数没有自己的this，只捕获外层this，也不能new。

## 最小示例

```javascript
const counter = { value: 2, add(n) { return this.value + n; } };
console.log(counter.add(3)); // 5
const detached = counter.add;
console.log(detached.call({ value: 10 }, 3)); // 13
const bound = detached.bind(counter);
console.log(bound(4)); // 6
function makeReader() { return () => this.value; }
const read = makeReader.call(counter);
console.log(read.call({ value: 99 })); // 2
```

## 场景、边界与误区

箭头函数不是“永远指向当前组件”；它捕获哪层this取决于定义位置。不要为了修复回调给所有方法盲目改成箭头。

## 移动端经验对照

Kotlin/Dart对象方法与JS回调的接收者规则不同。迁移时显式检查回调绑定，不能假定传递对象方法就自动保留实例。
