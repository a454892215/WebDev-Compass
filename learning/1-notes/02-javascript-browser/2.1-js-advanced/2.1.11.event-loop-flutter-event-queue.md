## 解决什么问题与前置

有移动开发经验时，哪些异步直觉能复用，哪些不能直接搬到Web？

前置：2.1.4事件循环、2.1.10生命周期；此处是概念对照，不要求先搭移动工程。

## 工作机制

1. 一个浏览器执行代理内的同步JS会阻塞该代理，Promise不是线程。Dedicated Worker运行在另一个执行环境，通过消息通信，不能直接读取页面DOM。

2. Dart isolate拥有自己的内存与事件循环；isolate之间通常通过消息通信。浏览器Worker与它有相似隔离目标，但宿主API、数据传递、部署和平台支持不同，不是同一个实现。

3. React Native的JS运行环境与原生渲染/线程协作依架构和版本而定。旧Bridge不能代表全部现代RN；新架构的JSI/Fabric模型也不能据此推导浏览器任务顺序。

4. 可迁移的是“避免阻塞负责交互的执行环境、明确状态归属与清理”；需要重新学习的是浏览器task/微任务、渲染时机、DOM、权限、安全源及页面生命周期。

## 最小示例

```javascript
// worker.mjs（Worker文件，不在主页面执行）
self.onmessage = event => {
  const total = event.data.reduce((sum, n) => sum + n, 0);
  self.postMessage({ total, hasDOM: typeof document !== "undefined" });
};

// main.mjs（通过HTTP加载；worker.mjs在同目录）
const worker = new Worker(new URL("./worker.mjs", import.meta.url), { type: "module" });
worker.onmessage = event => { console.log(event.data); worker.terminate(); };
worker.postMessage([1, 2, 3]); // {total:6, hasDOM:false}
```

## 场景、边界与误区

Worker数据通常通过结构化克隆传递，不会自动共享普通对象；SharedArrayBuffer是另一个有安全前提的主题，不在本最小实验范围。工作结束或离开视图时要终止Worker。
