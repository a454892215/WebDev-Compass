# 2.4.6 File API：用户提供文件、异步读取与安全展示

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

HTML file输入、Blob、Promise、JSON解析与文本输出。按需选学。

## 解决什么问题

导入用户主动选择的本地文本，不扫描磁盘，不因选择文件就上传。File是Blob的扩展，包含名称、大小、类型和修改时间。

## 原理与使用规则

input.files或拖放提供File对象；现代File.text可异步读取文本，FileReader适合需要事件/进度或abort的读取。检查size以避免一次加载过大，accept/type只作提示不能当安全验证。解析JSON后还需检查字段协议。

读取是异步的，用户可能在旧读取结束前清空选择或换选新文件；用递增版本号标记每次选择，在await后和错误分支核对归属，页面离开时也令旧版本失效，防止迟到结果覆盖新状态。

文件名和内容均不可信，使用textContent输出，不插入innerHTML。Blob URL用于预览时需在替换/结束时revokeObjectURL；读取文件不等于持久保存，也不等于文件系统任意读写。

## 最小例子

```javascript
async function readSelected(file) {
  if (!file || file.size > 64 * 1024) throw new Error("请选择64KiB内文本");
  const text = await file.text();
  document.querySelector("#preview").textContent = text;
} // 页面change事件传入input.files[0]，这里不上传
```

## 移动端对照

类似移动文档选择器交回URI/文件句柄，而非App获得整个磁盘访问权；浏览器只读用户给出的File。

## 边界与常见误区

例子仅处理64KiB内文本，选择清空/读取失败需有提示；网页不能靠accept证明文件内容安全。
