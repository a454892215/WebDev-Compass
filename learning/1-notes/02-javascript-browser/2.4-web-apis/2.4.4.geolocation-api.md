# 2.4.4 Geolocation：安全上下文、授权与失败体验

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

事件回调/Promise错误、用户主动操作与隐私边界。按需选学。

## 解决什么问题

用户主动选择附近资源时才请求位置。浏览器返回坐标与accuracy等估计值，不保证GPS硬件或精确定位。

## 原理与使用规则

需要安全上下文与用户授权，还可能受Permissions-Policy限制。getCurrentPosition是一次请求；watchPosition持续观察，要用返回ID调用clearWatch清理。权限拒绝、位置不可用、超时是不同错误，页面应保留手工选择地区。

enableHighAccuracy只是偏好，可能耗电并延迟，不保证精度；maximumAge允许用多旧缓存位置，timeout约束获取等待。Permissions API查询并非各浏览器同等支持，更不能代替实际调用和错误处理。

## 最小例子

```javascript
// 仅绑定到用户主动点击的按钮，不在页面加载时调用。
function locate() {
  if (!navigator.geolocation) return console.warn("请手动选择地区");
  navigator.geolocation.getCurrentPosition(
    position => console.log(position.coords.accuracy),
    error => console.warn("定位失败，改手动选择", error.code),
    { timeout: 5000, maximumAge: 0, enableHighAccuracy: false }
  );
}
```

## 移动端对照

类似移动定位服务用途，但权限、提供者和策略受浏览器/站点约束，不能假定获得Android定位权限就能让网页定位。

## 边界与常见误区

例子仅用户点击后调用，不保存或上传坐标；测试用虚拟坐标，不读取当前设备真实位置。
