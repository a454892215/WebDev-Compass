# 2.4.2 ResizeObserver：组件尺寸变化与反馈环

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

CSS盒模型、DOM回调与2.2布局基础。

## 解决什么问题

容器被侧栏、父布局或内容改变宽度时，window.resize不一定触发；ResizeObserver直接报告元素尺寸。

## 原理与使用规则

可观察content-box/border-box等尺寸；contentRect、boxSize等值的口径不同，阅读时说明单位与盒范围。只改变不影响被观察尺寸的展示区域可避免自激循环。若回调持续写回目标尺寸，可能形成ResizeObserver loop，浏览器可能延后并报告未交付通知。

能用CSS container query完成的纯布局优先交给CSS；需要计算图表缓冲区或与第三方组件协作时再使用Observer。销毁时disconnect，不把Observer当成布局立即同步完成的保证。

## 最小例子

```javascript
const panel = document.querySelector("#panel");
const output = document.querySelector("#size"); // 放在被测元素之外
const observer = new ResizeObserver(entries => {
  output.textContent = Math.round(entries[0].contentRect.width) + " CSS px";
});
observer.observe(panel);
// 销毁：observer.disconnect();
```

## 移动端对照

用途近似LayoutBuilder/尺寸监听，但回调时机、CSS盒口径与反馈循环由浏览器规则决定，不能直接按Widget重建理解。

## 边界与常见误区

CSS负责排版，Observer负责需要尺寸的数据逻辑；不要为了每次改字号再改变同一目标宽度。
