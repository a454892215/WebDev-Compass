# 2.4.3 MutationObserver：观察DOM变化而非业务状态

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

DOM节点、属性与事件循环微任务基础。

## 解决什么问题

为第三方DOM适配或调试记录结构变化。它观察DOM树变更，不应代替自己可直接管理的业务数据流。

## 原理与使用规则

observe指定childList、attributes、subtree等范围，attributeFilter可缩小属性监听。变更记录在异步回调批量交付，不是每次赋值立刻同步执行。输入的value属性和运行期value property不同，不应期待所有用户输入都变成attributes记录。

若回调又写入同一被测树会反复触发；把日志放在树外，或只处理特定类型并做去重。takeRecords取走待交付记录，disconnect停止并丢弃未交付通知；根据场景先取记录再断开。

## 最小例子

```javascript
const root = document.querySelector("#watched");
const log = document.querySelector("#log"); // root外
const observer = new MutationObserver(records => {
  log.textContent = records.map(r => r.type).join(", ");
});
observer.observe(root, { childList: true, attributes: true, attributeFilter: ["data-state"] });
// 销毁：observer.disconnect();
```

## 移动端对照

不同于Flutter状态通知或Android数据订阅；这里观察已发生的DOM变更，业务状态通常应由状态/事件源直接管理。

## 边界与常见误区

谨慎观察document整棵树；阴影树边界与第三方节点生命周期需要额外处理，不默认观察任意所有内容。
