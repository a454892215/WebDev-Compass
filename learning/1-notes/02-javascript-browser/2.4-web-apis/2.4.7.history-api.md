# 2.4.7 History API：URL、状态、后退与刷新

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

URLSearchParams、DOM渲染、事件；是后续Vue Router前置。

## 解决什么问题

把阅读筛选条件保存在可分享URL里，前进后退恢复界面。pushState/replaceState修改历史，不会自动发请求或渲染页面。

## 原理与使用规则

进入页面先从location解析当前状态，再replaceState补齐初始条目的状态；显式导航用pushState并主动渲染，popstate读取URL/state恢复。调用pushState本身不触发popstate。URL必须同源，state需可序列化，避免存大对象和秘密。

刷新和直接访问路径仍会请求服务器，所以真实路径路由需服务端fallback；查询参数示例保留同一个静态HTML路径，不需要伪装服务器路由已配置。应保留原生链接语义，处理修饰键和新标签页行为，而不拦截所有点击。

## 最小例子

```javascript
function readPage() { return new URL(location.href).searchParams.get("page") ?? "home"; }
function render() { document.querySelector("#view").textContent = readPage(); }
history.replaceState({ page: readPage() }, "", location.href);
function go(page) {
  const url = new URL(location.href); url.searchParams.set("page", page);
  history.pushState({ page }, "", url); render();
}
addEventListener("popstate", render); render();
```

## 移动端对照

类似移动路由历史，但Web地址可复制、直接访问和刷新；运行时栈正确不代表服务器深链接可用。

## 边界与常见误区

本例仅用page查询参数，不保证完整产品路由；未知page回到home并说明错误，不把hash与popstate混为一谈。
