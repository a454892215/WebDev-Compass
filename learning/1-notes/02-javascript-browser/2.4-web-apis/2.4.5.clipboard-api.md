# 2.4.5 Clipboard：用户动作、权限与拒绝回退

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

Promise、用户事件与安全上下文。按需选学。

## 解决什么问题

复制当前阅读链接，不在加载时悄悄读取用户剪贴板。写入固定的本页演示文本，失败时提供可选择文本。

## 原理与使用规则

navigator.clipboard是异步API，通常要求安全上下文；读取/写入的权限、用户激活和提示规则在浏览器间不同。Permissions API中的clipboard-read/write并非统一可用，不应硬编码“授权一次就永远成功”。

writeText成功后再提示已复制；捕获NotAllowedError等失败，保留手动选择复制。旧execCommand已不推荐作为新设计默认，降级可给可选文本而不是假报成功。

## 最小例子

```javascript
async function copyLink() { // 从click处理器调用
  const text = location.href;
  try {
    if (!navigator.clipboard) throw new Error("剪贴板API不可用");
    await navigator.clipboard.writeText(text);
    console.log("写入成功");
  } catch { console.warn("请手动选择并复制", text); }
}
```

## 移动端对照

和移动系统剪贴板用途相近，但网页受用户激活与站点权限限制；不能照搬后台读取系统内容的行为。

## 边界与常见误区

示例只写固定演示文本、不读取剪贴板；本轮QA用受控适配器模拟写入/拒绝，不触碰用户真实系统剪贴板。
