# 2.4.9 Notification：权限与站内提示的边界

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

用户动作、权限失败、安全上下文；按业务选学，不是所有Web项目必需。

## 解决什么问题

系统通知是用户主动选择的增强能力，默认保留站内状态提示。Notification API与服务器Push不是同一个东西。

## 原理与使用规则

Notification.permission有default/granted/denied；在明确用户动作里requestPermission，拒绝后不能反复骚扰。安全上下文、浏览器/系统设置、平台支持都会影响行为。桌面new Notification不适用于所有移动浏览器，移动平台通常需ServiceWorkerRegistration.showNotification，Web Push另需订阅与服务端。

授予通知权限不保证OS最终展示，页面关闭后普通脚本也不会自动持续运行。真实发送须用户明确选择且内容不泄露敏感信息；本示例不自动显示系统通知，只核对权限和站内回退，构造通知的代码作为进一步手工实验。

## 最小例子

```javascript
async function requestNotifications() { // 从用户click触发
  if (!("Notification" in window) || !isSecureContext) return "使用站内提示";
  const permission = await Notification.requestPermission();
  return permission === "granted" ? "已授权，是否展示仍由平台决定" : "使用站内提示";
}
// 只有用户另外明确点击“发送测试”且支持时才考虑new Notification；
// 手机环境应评估SW showNotification，不把本片段当完整Push实现。
```

## 移动端对照

类似移动通知权限，但浏览器权限、站点、ServiceWorker与系统设置叠加；不能用App通知权限推导网页一定送达。

## 边界与常见误区

本例不创建OS通知；自动化检查默认/拒绝/缺API的站内分支，明确不能证明通知真正送达。
