# 2.3.2 Cookie：传输属性、脚本可见性与认证边界

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

阶段0的origin/site、HTTP头与CORS；阶段1Fetch和服务端/客户端职责。

## 解决什么问题

Cookie用于浏览器与服务器按作用域自动携带少量信息。属性不是一组万能安全开关；理解作用域与威胁后再用于真实会话。

## 原理与使用规则

服务器通过Set-Cookie设置值。HttpOnly阻止document.cookie读取，但浏览器仍可在符合条件的请求里发送；这不能消除XSS全部影响，也不能替代CSRF防护。Secure要求安全传输，SameSite控制跨站发送情景，不等同于同源；SameSite=None通常须配Secure。

省略Domain得到host-only Cookie；Domain不能任意指向其他网站，端口不参与Cookie隔离。Path选择发送路径，不能当作同源脚本的保密边界。Max-Age以秒计、优先于Expires，删除要匹配名称和作用域。浏览器隐私/第三方Cookie策略会增加限制。

## 最小例子

```javascript
// 服务端响应示意；值必须是演示值。
// Set-Cookie: demo_session=opaque; HttpOnly; Secure; SameSite=Lax; Path=/
// 浏览器页面不能通过document.cookie创建HttpOnly Cookie。
console.log(document.cookie); // 只看得到允许脚本读取的Cookie
// 真实认证还需服务端授权、会话轮换、失效与CSRF策略。
```

## 移动端对照

类似原生HTTP Cookie Jar自动携带，但浏览器还有站点、第三方、SameSite及脚本访问限制；不能照搬移动端明文token存储方案。

## 边界与常见误区

本地HTTP演示仅比较HttpOnly与普通Cookie，不声称测试了生产HTTPS、Secure、真实跨站SameSite或登录安全。
