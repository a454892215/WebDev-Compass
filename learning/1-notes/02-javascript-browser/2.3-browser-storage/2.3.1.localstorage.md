# 2.3.1 localStorage / sessionStorage：作用域、序列化与失败

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

阶段1的对象、JSON、异常处理和DOM事件。先学本节的小量字符串存储，再比较Cookie和IndexedDB。

## 解决什么问题

保存不敏感的主题偏好与当前标签草稿。localStorage按origin共享；sessionStorage还按顶层标签会话分区，带opener的新标签可能先复制一份，随后独立变化。它们都不是账号数据库。

## 原理与使用规则

两套API同步读写字符串，复杂值要序列化并校验解析结果；JSON格式正确也不等于符合字段协议。读取或写入可能因隐私策略、配额等失败，捕获异常并保留内存回退。localStorage跨会话保留不等于永久保证，用户清理、私密模式和存储回收都可能影响数据。

同源其他文档可收到storage事件，写入者本身不会因此收到自己的storage事件。sessionStorage不等同于服务端Session，也不能直接替代HttpOnly Cookie。

## 最小例子

```javascript
const key = "stage2:theme";
try {
  localStorage.setItem(key, JSON.stringify({ theme: "dark" }));
  const value = JSON.parse(localStorage.getItem(key) ?? "null");
  if (!value || !["dark", "light"].includes(value.theme)) throw new Error("偏好格式无效");
  console.log(value.theme);
} catch (error) { console.warn("使用内存默认主题", error.message); }
```

## 移动端对照

像SharedPreferences的小量配置用途，但浏览器按origin而非App沙箱归属；同步API不适合频繁写入大文本，更不是原生安全存储。

## 边界与常见误区

不要将令牌或秘密放这里：同源脚本可读取，XSS会影响它；跨设备同步、身份认证与权限由其他系统处理。
