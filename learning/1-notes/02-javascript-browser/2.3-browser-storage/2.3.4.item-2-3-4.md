# 2.3.4 浏览器存储选型：按数据与访问需求选择

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

2.3.1–2.3.3；知道HTTP缓存不等同于业务数据持久化。

## 解决什么问题

主题偏好、当前标签草稿、服务端会话和大量记录属于不同需求。先问数据敏感度、访问方式、体量与离线/同步要求，再选API。

## 原理与使用规则

内存适合短期状态；sessionStorage适合当前标签的少量字符串；localStorage适合少量非敏感偏好；IndexedDB适合较多结构化数据与事务；Cookie适合服务器需随请求接收的信息，但大小与传输开销要克制。Cache Storage缓存Request/Response，不是任意业务对象库，HTTP缓存又由HTTP头和浏览器策略管理。

本地存储不是授权来源，保存失败必须有恢复或回退。容量不应背诵为跨浏览器固定数字；估算、配额、逐出和持久化权限依环境。真正跨设备同步需要服务端协议。

## 最小例子

```javascript
const requirements = { structured: true, manyRecords: true, serverNeedsEachRequest: false };
const choice = requirements.serverNeedsEachRequest ? "Cookie协议需安全评审"
  : requirements.structured && requirements.manyRecords ? "IndexedDB"
  : "先比较内存与少量Web Storage";
console.log(choice); // 决策示意，不自动搬运数据
```

## 移动端对照

类似移动端区分内存状态、偏好、数据库和HTTP缓存；Web还须考虑origin、脚本可见性、用户清理和浏览器逐出。

## 边界与常见误区

示例是输入需求后的决策说明，不是浏览器自动测试所有配额/安全性；选择结果必须能解释取舍。
