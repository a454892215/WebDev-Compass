# 2.3.3 IndexedDB：对象仓库、事务与失败恢复

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 前置与目标

Promise、事件回调、结构化数据；先理解2.3.1及数据协议校验。

## 解决什么问题

为阅读草稿保存结构化记录。IndexedDB是异步、按origin隔离的本地数据库；不是关系数据库，也不是服务端同步或永久备份。

## 原理与使用规则

open(name, version)在首次创建或升级时触发upgradeneeded，可建立objectStore和索引；普通数据操作使用readonly/readwrite事务。request成功只说明一次请求完成，不能先于transaction.complete宣称整批写入已提交；abort会回滚该事务。

事务生命周期与事件循环有关，不要在创建事务后等待无关fetch/长计时器再写数据。版本升级遇旧连接可能blocked；旧连接收到versionchange时应close，页面提示用户关闭其他标签。数据可能受配额/清理/回收影响，关键资料需另行备份。

## 最小例子

```javascript
const request = indexedDB.open("stage2-example", 1);
request.onupgradeneeded = () => request.result.createObjectStore("drafts", { keyPath: "id" });
request.onerror = () => console.error(request.error);
request.onblocked = () => console.warn("请关闭旧版本标签");
request.onsuccess = () => {
  const db = request.result;
  db.onversionchange = () => db.close();
  const tx = db.transaction("drafts", "readwrite");
  tx.objectStore("drafts").put({ id: "one", text: "草稿" });
  tx.oncomplete = () => { console.log("事务完成"); db.close(); };
  tx.onabort = () => { console.warn("已回滚", tx.error); db.close(); };
};
```

## 移动端对照

可类比异步本地数据库事务，但API是对象仓库与请求事件，不是直接把Room/SQLite SQL拷过来；结构化克隆也不支持任意函数与DOM节点。

## 边界与常见误区

最小片段只展示首次创建单仓库；正式升级需要按旧版本条件迁移，不能重复无条件createObjectStore。complete也不等于承诺抗断电永久落盘。
