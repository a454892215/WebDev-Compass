# 1.3.1.8 函数：声明、表达式、箭头函数、`this` 绑定基础

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

函数是可传递的值；普通函数的 this 取决于调用方式，箭头函数捕获外层 this。

前置与顺序：先学变量、表达式与对象字段读取；从函数参数、返回值开始，再比较普通方法/箭头与 this。bind 用于观察接收者，不要求先学 class。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

函数声明、函数表达式和箭头函数的创建时机与 this 行为不同。普通函数作为对象方法调用可取得接收者；提取为独立函数后接收者会丢失。模块处于严格模式，普通独立调用的 this 是 undefined。

## 使用规则

1. 使用返回值表达结果，避免让函数同时隐式修改过多外部状态。

2. 箭头适合保留词法 this 的回调，不适合作为依赖动态接收者的方法。

3. 需要固定接收者时使用 bind 或显式包装调用，不能只复制方法引用。

## 最小代码

```javascript
const counter = {
  count: 2,
  read() {
    return this.count;
  },
};
const bound = counter.read.bind(counter);
console.log(bound()); // 2
const add = (a, b) => a + b;
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Kotlin/Dart 的函数闭包也可传递，但 JavaScript 普通方法提取后的 this 丢失更容易发生；不要把语法相似当成接收者规则相同。

## 常见误区

- “箭头函数只是短写法”：它没有自己的 this。

- “对象中的函数永远绑定该对象”：接收者由调用表达式决定。
