# 1.3.3.6 尺寸与位置：`offsetWidth/Height`、`clientWidth/Height`、`getBoundingClientRect()`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

不同尺寸API测量不同盒子；选对坐标系比记住数字更重要。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

offsetWidth/Height通常给布局边框盒整数尺寸；clientWidth/Height包含padding、不含border和滚动条；getBoundingClientRect返回相对视口的边界矩形，可包含transform影响并具有小数精度。

## 使用规则

1. 需要文档坐标时可结合scrollX/scrollY，而不是假设rect.top固定不变。

2. 频繁交错写样式与同步读布局可能触发额外布局，集中读写并基于测量优化。

3. display:none元素没有正常布局尺寸；缩放和设备像素比也不能简单等同CSS像素。

## 最小代码

```javascript
const box = document.querySelector(".box");
console.log(box.offsetWidth); // 布局边框盒
console.log(box.clientWidth); // 内边距区域
console.log(box.getBoundingClientRect().width); // 受变换影响
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Android测量/布局坐标和FlutterRenderBox有类似区别；Web CSS像素、viewport坐标、滚动和transform需要分别理解。

## 常见误区

- “所有width API相同”：它们测量区域和精度不同。

- “rect.top是页面绝对位置”：它相对当前视口。
