# 1.3.3.2 查询：`getElementById`、`querySelector`、`querySelectorAll`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

按范围查询节点并处理找不到的结果；不要依赖ID自动变成全局变量。

前置与顺序：先学 1.3.3.1 DOM 节点与 CSS 选择器；最小代码需先有 id=items 的列表，配套 HTML 已提供该根节点。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

getElementById按文档唯一ID取元素或null；querySelector按CSS选择器取第一个匹配；querySelectorAll返回静态NodeList。某些getElementsBy*返回实时HTMLCollection，会随DOM变化更新。

## 使用规则

1. 优先在当前组件/区域根节点上查询，减少跨页面碰撞。

2. 外部字符串进入CSS选择器前需转义或避免拼接；无效选择器会抛SyntaxError。

3. 保存查询结果后DOM可能改变，静态NodeList不会自动增加新元素。

## 最小代码

```javascript
const root = document.querySelector("#items");
if (!root) throw new Error("缺少列表根节点");
const snapshot = root.querySelectorAll(".item");
const live = root.getElementsByClassName("item");
root.append(Object.assign(document.createElement("li"), { className: "item" }));
console.log(snapshot.length, live.length);
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

类似Android在指定View树查找控件，但DOM有静态/实时集合差异；Vue/RN/Flutter中应优先用框架引用而非到处全局查询。

## 常见误区

- “querySelectorAll总是实时”：它返回快照式NodeList。

- “找不到节点就得到undefined”：querySelector/getElementById返回null。
