# 1.3.2.4 `async` / `await`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

async 函数总返回Promise；await暂停当前async函数的后续执行，不阻塞整个浏览器。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

await把值按Promise语义处理，恢复步骤排入后续微任务。两个独立请求逐个await会串行；需要并发时先启动任务再等待Promise.all，并决定任一失败时的行为。

## 使用规则

1. async返回普通值也会被包装成Promise。

2. try/catch只能捕获作用域内实际await或同步抛出的错误，漏await可能产生未处理拒绝。

3. Promise.all不自动取消其他任务，取消需另外传递AbortSignal等契约。

## 最小代码

```javascript
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
async function task(value) {
  await wait(20);
  return value * 2;
}
const results = await Promise.all([task(2), task(3)]);
console.log(results); // [4, 6]
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Dart async/await更接近这套语义；Kotlin suspend函数与协程取消有不同运行契约，JS async没有自动提供结构化并发。

## 常见误区

- “await会卡住整个页面”：它暂停当前函数，主线程仍可处理其他工作。

- “Promise.all失败会取消其余请求”：默认不会。
