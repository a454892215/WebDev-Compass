# 1.3.5.1 回调函数与回调地狱问题

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

回调是函数作为后续处理传入；嵌套会增加依赖和错误路径的阅读成本。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

回调可能同步调用，也可能由定时器、事件或I/O稍后调用；不能仅从“是回调”推断异步。串行依赖的多层回调需要约定错误、返回值与取消行为，Promise可帮助组合但不会自动纠正逻辑。

## 使用规则

1. 给回调命名和定义输入输出，比盲目把所有函数套成async更重要。

2. Node风格error-first与DOM事件回调不是同一种参数约定，需按API文档读取。

3. 分离请求、数据转换和UI反馈，减少层层匿名函数与重复错误处理。

## 最小代码

```javascript
function load(callback) {
  setTimeout(() => callback(null, { name: "Ada" }), 20);
}
load((error, user) => {
  if (error) return console.log(error.message);
  console.log(user.name);
});
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Android Listener、Dart回调和JS回调都只是传递函数的契约；不能把每个回调都理解成某条后台线程返回。

## 常见误区

- “回调一定异步”：数组map回调通常同步。

- “外层try能抓到以后回调抛错”：后续调用栈的错误需要自身处理或Promise传播。
