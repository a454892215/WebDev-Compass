# 1.3.5.6 JSON：`JSON.parse`、`JSON.stringify`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

JSON是受限的数据交换格式；可解析不代表符合业务模型，也不等于JS对象的完整复制。

前置与顺序：先学对象、数组、类型判断和同步 try/catch；建议在 Fetch 前先读本节。只接受语法正确仍不足以确认协议字段正确。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

JSON.parse把合法JSON文本变成JS值；JSON.stringify按序列化规则输出文本。对象中的undefined属性通常被忽略，数组中的对应值会变成null；BigInt和循环引用默认会导致错误。

## 使用规则

1. 外部JSON解析后仍需验证类型、必需字段和范围，再映射到领域模型。

2. 日期通常变成字符串，Map/Set、函数、原型和undefined不会按原语义保留。

3. 不要用JSON往返作为通用深拷贝；按数据类型选择显式映射或structuredClone并处理其限制。

## 最小代码

```javascript
const raw = '{"quantity":2}';
const value = JSON.parse(raw);
if (!Number.isInteger(value.quantity)) throw new Error("数量必须是整数");
console.log(JSON.stringify({ missing: undefined, empty: null }));
try {
  JSON.parse("{bad}");
} catch (error) {
  console.log(error.name);
}
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

与Dart jsonDecode/编码、Kotlin序列化同样需要协议模型；JS解析结果不会自动获得业务类实例或静态类型保证。

## 常见误区

- “有效JSON就是正确数据”：数组、null或错误字段仍可合法解析。

- “JSON.stringify能保存任何对象”：BigInt、循环引用等需特殊处理。
