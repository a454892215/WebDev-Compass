# 1.3.3.1 DOM 树概念：Document、Element、Node、Text

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

DOM把HTML解析为节点树；Element只是Node的一类，文本也有自己的节点。

前置与顺序：先学 HTML 结构、函数和对象；从 Document/Element/Text 分类开始，创建 API 的完整操作在 1.3.3.3 展开。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

Document是文档入口，Element表达元素，Text表达文本内容。children只包含元素节点，childNodes还包含文本、注释等；源代码中的空白也可能成为Text节点。

## 使用规则

1. 不能假设firstChild一定是元素，按目标选择firstElementChild或明确查询。

2. textContent汇总后代文本；修改它会替换该节点的子节点。

3. 浏览器会修复不合法HTML结构，Elements里实际DOM可能与源码不完全相同。

## 最小代码

```javascript
const paragraph = document.createElement("p");
paragraph.append("正文", document.createElement("strong"));
console.log(paragraph.children.length); // 1
console.log(paragraph.childNodes.length); // 2
console.log(paragraph.firstChild.nodeType); // Node.TEXT_NODE
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Flutter Widget是声明描述，DOM Node是浏览器可读写的实际文档对象；不要把构建配置对象与运行期节点混为一谈。

## 常见误区

- “所有DOM节点都是标签”：文本和注释也属于节点。

- “children和childNodes一样”：两者对非元素节点的处理不同。
