# 1.3.4.6 事件委托（Event Delegation）

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

事件委托把处理器放在稳定容器上，再按命中目标识别动态子项。

前置与顺序：先学事件流、target/currentTarget 与动态节点创建；list 是查询得到的稳定列表，未知点击不执行动作。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

可冒泡事件到达容器后，通过target.closest找到实际操作按钮；新增子节点不必分别重新绑定。委托的边界、可访问控件和动作白名单要明确。

## 使用规则

1. 只接受已知data-action，不把任意字符串当函数名或可执行代码。

2. closest可能找到容器之外的祖先，应结合contains或明确结构检查。

3. 委托不是所有事件的通用替代，非冒泡事件或复杂Shadow DOM需要适当策略。

## 最小代码

```javascript
list.addEventListener("click", (event) => {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest('button[data-action="remove"]');
  if (!button || !list.contains(button)) return;
  button.closest("li")?.remove();
});
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

可类比列表复用中的统一点击处理，但DOM委托依赖事件传播路径；Vue模板事件仍通常应优先遵循框架约定。

## 常见误区

- “每个新增按钮都要重新绑定”：可冒泡动作可委托给稳定父层。

- “data-action可直接eval”：只映射到明确允许的动作。
