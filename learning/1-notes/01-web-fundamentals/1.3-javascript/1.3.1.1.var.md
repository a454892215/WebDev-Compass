# 1.3.1.1 变量：`var`、`let`、`const` 与暂时性死区（TDZ）

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

let/const 是块级绑定；const 限制重新赋值，不冻结对象。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

进入作用域时词法绑定已经创建，但声明初始化之前仍不可读取，形成暂时性死区。var 是函数或全局作用域，声明被提升并初始化为 undefined。

## 使用规则

1. 默认使用 const；确需重新赋值才用 let，维护旧代码时认识 var。

2. 同一块内重复 let 声明是语法错误；读取 TDZ 中的绑定是 ReferenceError。

3. const 对象的属性仍可修改；需要不可变更新时复制对象并管理嵌套引用。

## 最小代码

```javascript
const profile = { name: "Ada" };
profile.name = "Lin"; // 允许，绑定没有改变
let attempts = 0;
attempts += 1;
try {
  console.log(later); // ReferenceError，不是 undefined
  let later = 1;
} catch (error) {
  console.log(error.name);
}
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Kotlin val/Dart final 也约束绑定，但 JS let/const 没有静态类型保护；不能将 const 当作 Dart 编译期 const。

## 常见误区

- “const 对象不可变”：它只阻止绑定指向新值。

- “提升等于可以提前访问”：var 和 let/const 的初始化行为不同。
