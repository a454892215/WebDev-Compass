# 1.3.5.5 定时器：`setTimeout`、`setInterval`、`requestAnimationFrame`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

定时器给出最早调度机会而非精确时钟；动画用requestAnimationFrame并显式清理。

前置与顺序：先学函数回调；setTimeout 基础可在 Promise 前阅读。interval/rAF 需理解订阅清理，实验外壳的 Promise/AbortSignal 在异步章节后回读。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

setTimeout安排一次回调，setInterval重复安排；延迟受任务队列、页面可见性与浏览器节流影响。requestAnimationFrame在渲染前回调，应根据时间戳计算动画进度而非假定每帧固定间隔。

## 使用规则

1. 组件卸载或任务失效时clearTimeout/clearInterval/cancelAnimationFrame。

2. 频繁异步请求不宜无边界setInterval堆叠，可在上次结束后再调度。

3. 后台节流、设备刷新率和CPU负载会改变间隔，测试断言应验证行为而非固定毫秒精度。

## 最小代码

```javascript
let count = 0;
const timer = setInterval(() => {
  count += 1;
  if (count === 3) clearInterval(timer);
}, 20);
const frame = requestAnimationFrame((timestamp) => console.log(timestamp));
// 页面/组件结束：clearInterval(timer); cancelAnimationFrame(frame);
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

可类比Dart Timer和Flutter帧调度，但Web页面后台节流及rAF暂停策略不同；不要以定时器替代真实媒体或业务时间源。

## 常见误区

- “setTimeout(0)立即执行”：它仍需等待当前任务结束。

- “setInterval保证每20ms执行”：延迟不是实时保证。
