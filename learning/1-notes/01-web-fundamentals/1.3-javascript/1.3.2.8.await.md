# 1.3.2.8 顶层 `await`（了解）

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

顶层await允许模块在初始化时等待异步结果；它只在模块等支持的上下文中成立。

前置与顺序：先学 1.3.2.2 模块和 1.3.2.4 async/await；本节为初始化依赖选读，不是运行普通原生页面的前提。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

依赖模块含顶层await时，其导入者需要等待该模块求值完成后才能继续访问结果。它可以简化初始化，也会把初始化延迟传播到依赖图；并不意味着所有模块都串行阻塞。

## 使用规则

1. 浏览器代码必须使用type=module；经典script里直接写await会语法错误。

2. 启动关键路径不要无边界等待远程服务，超时、失败回退和依赖关系要明确。

3. 动态import返回Promise，重复导入同一模块通常复用模块实例；不要把缓存误认作每次重新执行。

## 最小代码

```javascript
// ready.mjs
const result = await Promise.resolve({ ready: true });
export const ready = result.ready;
// main.mjs
import { ready } from "./ready.mjs";
console.log(ready);
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Dart顶层初始化与async函数不能机械对应到JS顶层await；重点是浏览器模块依赖求值和启动失败边界。

## 常见误区

- “任意script都能顶层await”：需要模块环境。

- “import每次都会重跑初始化”：同一模块URL通常复用已加载模块实例。
