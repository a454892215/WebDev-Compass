# 1.3.4.1 事件监听：`addEventListener`、`removeEventListener`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

监听器是需要管理生命周期的订阅；添加与移除需要同一个回调身份和匹配的capture。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

addEventListener为目标注册回调；removeEventListener按类型、回调引用和capture识别要移除的注册。once适合一次性事件，AbortSignal可组织多个监听器的共同清理。

## 使用规则

1. 重复创建的箭头函数不是同一个引用，无法靠相同源码正确remove。

2. 组件卸载、页面切换或实验重跑时清理监听器。

3. passive监听器承诺不调用preventDefault；不能把它用于需要取消默认行为的处理器。

## 最小代码

```javascript
const controller = new AbortController();
button.addEventListener("click", onClick, { signal: controller.signal });
function onClick() {
  console.log("点击");
}
controller.abort(); // 清除此信号管理的监听器
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

类似Android解除Listener或Flutter dispose中的订阅清理；JS DOM的回调身份与capture参数需要一致。

## 常见误区

- “再写一遍()=>run()就能移除”：它是新函数。

- “离开界面所有监听都会自动消失”：被全局对象引用的监听可能保留对象。
