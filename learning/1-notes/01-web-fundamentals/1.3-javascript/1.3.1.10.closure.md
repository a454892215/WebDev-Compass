# 1.3.1.10 闭包（Closure）概念与应用场景

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

闭包让函数在离开定义环境后，仍能访问那个环境中的绑定。

前置与顺序：先学 1.3.1.8 函数和 1.3.1.9 词法作用域；先做独立计数器，DOM 引用清理在事件章节后回读。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

外层函数返回时，闭包引用的词法环境不会因为函数调用结束就失效。它保留的是绑定及其当前值，而不是自动生成的历史快照；每次工厂调用可形成独立环境。

## 使用规则

1. 闭包适合私有计数器、参数化回调与组合式逻辑，但不是安全隔离边界。

2. 长期保存回调可能同时保留 DOM 或大对象，清理订阅仍然必要。

3. 使用 let 的循环绑定与单个 var 共享绑定不同，是回调值问题的常见来源。

## 最小代码

```javascript
function createCounter() {
  let count = 0;
  return () => ++count;
}
const a = createCounter();
const b = createCounter();
console.log(a(), a(), b()); // 1 2 1
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Flutter 回调捕获 State 或 Kotlin lambda 捕获对象也会延长可达生命周期；JS 闭包不是自动免清理的状态容器。

## 常见误区

- “闭包冻结创建时的值”：它通常读取同一个绑定的新值。

- “返回函数共享所有调用的局部变量”：不同工厂调用有不同环境。
