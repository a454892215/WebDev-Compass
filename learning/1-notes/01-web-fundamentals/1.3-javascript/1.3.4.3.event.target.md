# 1.3.4.3 `event.target` vs `event.currentTarget`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

target是事件起点（可能重定向），currentTarget是当前正在执行监听器的节点。

前置与顺序：先学捕获/目标/冒泡；container 是已查询的稳定父容器。closest 在本节只识别按钮，完整受限委托在 1.3.4.6 完成。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

事件从子元素冒泡到父元素时，target通常仍是最初命中的后代，currentTarget则变为当前父监听器。异步回调中不要依赖事件对象仍保留当前监听上下文，应先保存所需值。

## 使用规则

1. 委托处理时用target.closest寻找业务按钮，再校验它确属当前容器。

2. target可能不是Element，调用closest前需判断类型。

3. 按钮内图标、span被点击时target可能是后代，不能直接假定target就是button。

## 最小代码

```javascript
container.addEventListener("click", (event) => {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest("button");
  console.log(event.target.tagName, event.currentTarget.id);
});
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

类似点击嵌套View时区分实际命中对象与注册处理器的容器；Web委托常用currentTarget表达操作边界。

## 常见误区

- “target总是注册监听的元素”：那个角色是currentTarget。

- “按钮内部点击的target一定是button”：图标和文本span可能成为target。
