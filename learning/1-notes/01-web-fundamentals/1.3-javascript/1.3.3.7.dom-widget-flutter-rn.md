# 1.3.3.7 📱 移动端对照：DOM 节点、原生 View 与声明式 UI 的区别

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

原生DOM操作帮助理解浏览器，但声明式框架里应让状态成为界面更新的主要来源。

前置与顺序：先学查询、修改与函数；页面提供 id=count。Vue 响应式只作后续对照，现在用显式 render 区分模型和 DOM 即可。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

DOM节点是浏览器维护的可变对象；Vue把响应式状态映射到DOM。若同时让框架与手写代码控制同一子树，就可能发生状态与画面不一致、节点被覆盖或监听器遗留。

## 使用规则

1. 以DOM实验认识底层机制，不把手写查询散落到每个Vue组件。

2. 第三方图表、焦点和测量等场景可通过明确引用适配，并在卸载时清理。

3. 区分模型状态、已渲染DOM和临时输入，不能把读取标签文本作为唯一业务数据源。

## 最小代码

```javascript
let count = 0;
const output = document.querySelector("#count");
function render() {
  output.textContent = String(count);
}
function increment() {
  count += 1;
  render();
}
render(); // 后续Vue会帮助自动追踪与更新
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Flutter setState、RN state和Vue响应式都强调状态驱动；直接操作DOM更接近操作原生View对象，适配层有用但不应替代状态模型。

## 常见误区

- “理解DOM后不需要响应式状态”：手动同步在复杂页面容易漏。

- “框架不允许任何DOM”：焦点、测量等明确边界仍需要。
