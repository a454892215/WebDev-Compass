# 1.3.3.5 内容：`textContent` vs `innerHTML`（及 XSS 风险）

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

显示不可信文本用textContent；innerHTML会解析HTML，属于需要严格控制的注入入口。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

textContent把字符串作为文本节点内容；innerHTML把字符串交给HTML解析器，能生成元素和危险行为。即使script标签不按预期直接执行，事件属性、URL等仍可能造成XSS。

## 使用规则

1. 用户输入、接口错误消息和日志默认走textContent。

2. 确需富文本时使用可信的净化方案与明确允许列表，并配合安全策略，而不是自写正则过滤。

3. 转义规则随HTML文本、属性、URL、脚本等上下文不同，不存在一个万能replace。

## 最小代码

```javascript
const input = "<strong>用户文本</strong>";
const output = document.querySelector("#safe-output");
output.textContent = input; // 显示尖括号，不创建strong
// 只有确定可信的静态模板才可按需要解析HTML。
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

类似把任意字符串交给WebView执行与普通Text控件显示的区别；RN/Flutter普通文本安全不能迁移成Web innerHTML天然安全。

## 常见误区

- “只拦script就没有XSS”：HTML还存在其他执行入口。

- “模板字符串会自动转义”：字符串插值本身不会。
