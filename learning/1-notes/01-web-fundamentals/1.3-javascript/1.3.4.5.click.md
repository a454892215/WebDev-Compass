# 1.3.4.5 常见事件：`click`、`input`、`change`、`submit`、`keydown/keyup`、`focus/blur`、`scroll`、`resize`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

按用户意图选择事件：输入过程、值确认、表单提交、键盘与焦点各有不同语义。

前置与顺序：先学原生表单与监听器；input/form 是查询结果，onResize 需自行定义。先用 input/submit，IME 与高频事件只要求认识边界并设计验证。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

input通常在编辑值时持续触发，change在控件确认变化时触发；submit属于表单。focus/blur与focusin/focusout的冒泡规则不同，scroll/resize应避免高频重工作。

## 使用规则

1. 文本输入与中文输入法组合过程需考虑isComposing等状态，不应只用keydown推断文本。

2. 按钮用click支持鼠标与键盘激活，避免只监听mousedown/touchstart。

3. 程序给input.value赋值通常不会自动触发用户input事件；需要明确的状态更新或事件契约。

## 最小代码

```javascript
input.addEventListener("input", (event) => {
  console.log(event.currentTarget.value);
});
form.addEventListener("submit", (event) => event.preventDefault());
function onResize() {
  console.log(window.innerWidth);
}
window.addEventListener("resize", onResize);
// 该视图结束时：window.removeEventListener("resize", onResize);
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Flutter onChanged/onSubmitted有相似职责，但Web控件的change、提交、IME和浏览器默认行为需要分别测试。

## 常见误区

- “keydown等于文本变化”：粘贴、语音和输入法不一定对应简单按键。

- “给value赋值会自动触发input”：脚本赋值与用户事件不同。
