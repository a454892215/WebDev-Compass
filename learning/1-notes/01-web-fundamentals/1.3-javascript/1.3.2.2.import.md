# 1.3.2.2 模块（ES Modules）：`import` / `export`（default vs named）

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

ES Module 用显式导出与导入建立依赖；模块作用域和加载机制不同于经典 script。

前置与顺序：先学函数与作用域；先用两个文件练习静态 import/export。动态 import() 的返回值在 Promise/await 后回读；配套点击外壳由课程提供，不要求先重写它。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

静态 import 只写在模块顶层，浏览器通过 URL 加载并解析依赖图；模块默认严格模式。default 与 named exports 是不同导出契约，导入绑定通常是指向导出绑定的只读实时视图。

## 使用规则

1. HTML 用 script type="module"；浏览器模块路径须是正确URL，裸包名需要构建工具或import map。

2. 浏览器跨源模块需要合适CORS；本地教学用HTTP同源服务，避免file URL限制。

3. 动态 import() 返回Promise，可在操作发生时加载；它不是把模块源码当字符串执行。

## 最小代码

```javascript
// math.mjs
export const double = (value) => value * 2;
export default "本地数学模块";
// main.mjs（模块顶层）
import label, { double } from "./math.mjs";
console.log(label, double(4));
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Dart import 的静态依赖思想可复用，但浏览器ESM按URL加载，Node包解析和Vite构建解析并不完全相同；不要把import等同于网络下载npm包。

## 常见误区

- “default 导入名字必须与原名相同”：本地名字可自定义。

- “script里写import就能运行”：必须是模块上下文或支持的工具链。
