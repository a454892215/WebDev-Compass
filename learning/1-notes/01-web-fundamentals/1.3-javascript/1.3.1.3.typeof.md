# 1.3.1.3 类型判断：`typeof`、`instanceof`、`Array.isArray()`、`Object.prototype.toString`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

类型判断要针对目标能力：判断数组用 Array.isArray，判断原始类型用 typeof。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

typeof 返回字符串并有历史特殊情况：null 为 object，函数为 function；instanceof 检查原型链，不是通用类型标签。跨 iframe/realm 时构造函数身份不同，会影响 instanceof。

## 使用规则

1. Array.isArray 比 value instanceof Array 更适合跨 realm 数组。

2. typeof x === "object" 仍需排除 null，不能据此直接读取属性。

3. Object.prototype.toString 可观察内建标签，但 Symbol.toStringTag 可改变标签，不能作为安全校验。

## 最小代码

```javascript
const values = [null, [], {}, () => {}];
for (const value of values) {
  console.log(typeof value);
}
console.log(Array.isArray([]));
console.log(Object.prototype.toString.call(new Date()));
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Kotlin is / Dart is 与 JS instanceof 并不等价：JS 侧还涉及运行时原型和跨文档环境，网络 JSON 更需要字段结构校验。

## 常见误区

- “typeof null 等于 null”：实际返回 object。

- “能 instanceof 就能验证接口 DTO”：普通 JSON 对象通常没有业务类原型。
