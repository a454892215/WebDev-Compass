# 1.3.1.13 字符串：模板字面量、常用方法（`slice`、`split`、`includes`、`replace` 等）

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

字符串不可变；方法返回处理后的值，Unicode 字符不一定对应一个索引。

前置与顺序：先学 1.3.1.2 字符串类型与循环；码点/字素区别用于发现截断边界，Intl.Segmenter 属目标兼容范围内的扩展。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

模板字面量用反引号插入表达式；slice 按 UTF-16 代码单元取片段。length 是代码单元数，展开或 for...of 按 Unicode 码点迭代，但仍不等同于用户感知的字素簇。

## 使用规则

1. 用户可见文本截断要考虑 emoji、组合音标与字素分割，不能盲按 length 切。

2. replace 的字符串模式只替换首个匹配；全替换可用 replaceAll 或合适的全局正则。

3. 模板字面量仅拼接字符串，不自动 HTML 转义；显示到页面仍应使用 textContent。

## 最小代码

```javascript
const label = `Hello ${"Web"}`;
const normalized = "  Vue,Nuxt  ".trim().split(",");
console.log("A😀".length); // 3
console.log([..."A😀"].length); // 2
console.log("a-a".replaceAll("a", "b"));
console.log(label.slice(0, 5), label.includes("Web")); // Hello, true
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Dart String 也基于 UTF-16；Flutter characters 处理字素簇的经验可迁移，但 Web 侧要按目标浏览器选择 Intl.Segmenter 等能力。

## 常见误区

- “一个emoji长度总是1”：JS length 不是字素数。

- “模板字符串可以安全塞innerHTML”：仍然会形成HTML注入风险。
