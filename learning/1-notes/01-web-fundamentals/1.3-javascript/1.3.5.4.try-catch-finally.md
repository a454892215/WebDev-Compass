# 1.3.5.4 错误处理：`try/catch/finally`、`throw`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

在能解释和处理错误的边界捕获异常；finally用于恢复状态和清理资源。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

throw可抛任意值，但使用Error及其子类更有利于诊断。try/catch只覆盖当前同步流程和实际await的拒绝；finally无论成功失败通常都会执行，return/throw写在finally会覆盖原结果。

## 使用规则

1. 不要空catch吞掉失败；区分用户可重试错误、程序错误与主动取消。

2. 错误消息显示到页面要用textContent，不直接展示凭据、堆栈或服务器敏感内容。

3. async流程在finally中恢复loading，在资源拥有者生命周期内解除监听和定时器。

## 最小代码

```javascript
let loading = true;
try {
  throw new TypeError("字段格式不正确");
} catch (error) {
  console.log(error.name, error.message);
} finally {
  loading = false;
}
console.log(loading);
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Dart try/finally、Kotlin try表达式有相似思想；JS异步拒绝是否被await会影响捕获位置，不能忽略Promise返回值。

## 常见误区

- “catch后就不需要处理状态”：loading仍可能悬挂。

- “finally中return最安全”：它可能覆盖原来的错误或返回值。
