# 1.3.1.4 类型转换：隐式转换、显式转换（`Number()`、`String()`、`Boolean()`）

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

边界处显式转换输入，再验证转换结果，避免依赖隐式强制转换。

前置与顺序：先学 1.3.1.2 值类型与 1.3.1.3 基础判断；本节先用字符串常量实验，读取 HTML input 的代码在 1.3.3 查询节点后再实现。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

加号既可能做数值加法也可能连接字符串；比较、布尔上下文和其他运算会采用不同转换规则。HTML input.value 是字符串，即使输入类型为 number。

## 使用规则

1. Number("") 和 Number(" ") 为 0，空输入需要先单独判断。

2. Boolean("false") 为 true，非空字符串不按单词含义转换。

3. Number.isFinite 用于验证已转换的有限数；parseInt 会接受部分数字前缀，不能替代完整输入校验。

## 最小代码

```javascript
const inputText = " 2 "; // 暂用常量；DOM 章节再改为已查询 input 的 value
const raw = inputText.trim();
if (raw === "") throw new Error("请输入数量");
const amount = Number(raw);
if (!Number.isFinite(amount)) throw new Error("数量无效");
console.log("2" + 1); // '21'
console.log(Number("2") + 1); // 3
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Android EditText/Flutter TextEditingController 的文本也需解析；JS 的 + 更容易隐式转字符串，应该明确领域输入的空值和精度规则。

## 常见误区

- “Boolean("false") 是 false”：它是非空字符串，结果为 true。

- “Number 成功就可用于金额”：还需检查范围、整数/小数策略与业务精度。
