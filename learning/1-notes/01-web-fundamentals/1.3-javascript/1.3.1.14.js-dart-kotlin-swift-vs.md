## 学习目标与前置

移动端经验能帮助理解控制流，但 Web 的动态类型、对象共享与浏览器边界仍需单独验证。

前置与顺序：先完成本组语言核心；移动端只作经验对照，TypeScript、SSR 生命周期是后续导航，不要求现在搭框架。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

JS 在运行时对值执行操作；字符串与数字的自动转换、undefined 与 null、方法接收者和原型系统，是从静态语言迁移时的高频差异。TypeScript 在后续阶段补静态约束，但不自动改变运行时行为。

## 使用规则

1. 把网络数据视为 unknown 语义并校验，而不是靠强制断言跳过解析。

2. 区分 undefined 的缺失和业务协议中的 null；JSON 不会保留所有 JS 值。

3. 函数和对象可变性要独立管理，类型系统不替代资源清理、取消和生命周期。

## 最小代码

```javascript
const raw = { quantity: "2" };
const quantity = Number(raw.quantity);
if (!Number.isFinite(quantity)) throw new Error("bad quantity");
console.log(quantity + 1); // 3
console.log("2" + 1); // '21'
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Dart/Kotlin 的工程习惯可复用，但不要机械寻找每个API的一一对应：浏览器有 DOM、源、导航和页面生命周期，SSR 还有请求边界。

## 常见误区

- “熟悉RN就可以跳过浏览器基础”：RN宿主不是DOM浏览器。

- “用了TS就没有运行时类型问题”：API响应与存储值仍需验证。
