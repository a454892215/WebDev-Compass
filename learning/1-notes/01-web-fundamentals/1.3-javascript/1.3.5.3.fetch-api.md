# 1.3.5.3 Fetch API：GET/POST 请求、请求头、响应处理、`response.ok`、解析失败与 `response.json()`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

Fetch把传输、HTTP状态、响应解析和业务数据校验分成不同步骤。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

fetch通常在收到响应头后履行为Response；404/500不会自动使Promise拒绝，必须检查ok/status。response.json异步读取并解析正文，正文只能按相应流语义消费；有效JSON仍可能不符合业务模型。

## 使用规则

1. 网络失败、主动取消、HTTP错误、JSON解析错误与业务错误应分别识别。

2. POST JSON需序列化body并声明Content-Type；FormData则不要手写multipart boundary。

3. 使用AbortController取消已不需要的请求，查询场景还需防止迟到结果覆盖新状态；服务端处理可能已发生，取消不等于回滚。

## 最小代码

```javascript
async function loadUsers(signal) {
  const response = await fetch("./users.json", { signal });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const value = await response.json();
  if (!Array.isArray(value.users)) throw new Error("数据结构不符");
  return value.users;
}
// POST: fetch(url, {method:'POST',headers:{'Content-Type':'application/json'},
//   body:JSON.stringify({title:'演示'})})
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

与Dio/Retrofit统一错误拦截的经验有关，但原生Fetch不会自动把HTTP 404归为Promise失败；浏览器Cookie、CORS和取消边界也需独立设计。

## 常见误区

- “await fetch没报错就成功”：还要检查HTTP、解析和领域数据。

- “abort撤销服务器修改”：它终止客户端继续等待，并不保证服务端回滚。
