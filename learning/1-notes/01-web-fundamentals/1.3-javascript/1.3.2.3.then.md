# 1.3.2.3 Promise 基础：`then`、`catch`、`finally`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

Promise 表示将来完成或失败的一次结果；then 返回新的Promise，用于组合后续步骤。

前置与顺序：先学函数，再提前阅读 1.3.5.1 回调、1.3.5.4 同步错误与 1.3.5.5 一次性定时器；本节首次引入 Promise，微任务与事件循环在阶段 2 深化。 适用场景是原生页面、组件逻辑与浏览器排障；不要求先搭 Vue/Nuxt。

## 工作机制

Promise 状态从pending走向fulfilled或rejected后不再变。then回调进入微任务，不会在当前同步栈中直接执行；回调返回值、返回的Promise与抛出错误分别影响后续链。

## 使用规则

1. 在then内启动异步步骤时return它，否则外层链不会等待该步骤。

2. catch处理前面链上的拒绝；catch正常返回值会把链恢复成fulfilled。

3. finally适合清理，不接受业务结果；除非自身抛错/返回拒绝，否则通常透传原结果。

## 最小代码

```javascript
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
wait(20)
  .then(() => 2)
  .then((value) => value * 3)
  .then(console.log)
  .catch((error) => console.log(error.message))
  .finally(() => console.log("结束"));
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Dart Future 与Promise的组合思想相似，但浏览器微任务顺序要实际观察；Promise不是独立线程，也不是默认可取消任务。

## 常见误区

- “Promise会让CPU计算自动并行”：执行器和同步代码仍在当前线程。

- “finally可以替代catch”：它负责结束阶段，默认不消除拒绝。
