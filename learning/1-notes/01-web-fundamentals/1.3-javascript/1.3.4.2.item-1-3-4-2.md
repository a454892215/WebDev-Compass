# 1.3.4.2 事件流：捕获阶段、目标阶段、冒泡阶段

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

事件沿传播路径经历捕获、目标和冒泡，监听器所处阶段影响执行顺序。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

捕获从祖先向目标前进，目标阶段运行目标上的监听器，能冒泡的事件再向祖先返回。eventPhase用1/2/3表达当前阶段；并非所有事件都冒泡。

## 使用规则

1. 用capture:true订阅捕获阶段，默认通常在冒泡阶段处理。

2. 注册顺序会影响同一节点同阶段监听器顺序，目标阶段仍需区分capture注册。

3. 事件路径在Shadow DOM等场景可能重定向；基础实验先理解普通DOM。

## 最小代码

```javascript
outer.addEventListener("click", handler, { capture: true });
inner.addEventListener("click", handler);
outer.addEventListener("click", handler);
function handler(event) {
  console.log(event.currentTarget.id, event.eventPhase);
}
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Android触摸分发的拦截/消费可做概念对照，但浏览器DOM的捕获/目标/冒泡模型有独立规则，不等同Flutter手势竞技场。

## 常见误区

- “所有事件都冒泡”：如原生focus不冒泡，focusin可冒泡。

- “捕获与冒泡只发生在按钮上”：它们描述整条祖先路径。
