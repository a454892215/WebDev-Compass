# 1.3.5.2 `XMLHttpRequest` 基础（了解即可，现代用 fetch）

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

XMLHttpRequest是旧项目常见的异步HTTP API；认识其状态和失败边界，现代新代码通常先选Fetch。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

open设置方法和URL，send发出请求；load表示传输完成，不代表HTTP成功。网络错误、超时、主动abort与HTTP非2xx需要分别处理。responseType影响读取的响应形式。

## 使用规则

1. 使用异步XHR，避免同步请求阻塞页面。

2. load中检查status范围，不能见到onload就当业务成功。

3. 需要上传进度时区分xhr.upload的progress与下载progress；生产还需来源、凭据及大小策略。

## 最小代码

```javascript
const xhr = new XMLHttpRequest();
xhr.open("GET", "./users.json");
xhr.timeout = 3000;
xhr.onload = () => {
  if (xhr.status >= 200 && xhr.status < 300) console.log(xhr.responseText);
  else console.log("HTTP", xhr.status);
};
xhr.onerror = () => console.log("网络错误");
xhr.send();
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

可类比OkHttp/Dio异步请求的完成与错误回调，但浏览器XHR受同源/CORS约束；上传/下载进度和取消是明确的API行为。

## 常见误区

- “onload代表200”：404等HTTP响应也可触发load。

- “XHR请求不受浏览器安全规则”：它与Fetch一样受Web安全模型约束。
