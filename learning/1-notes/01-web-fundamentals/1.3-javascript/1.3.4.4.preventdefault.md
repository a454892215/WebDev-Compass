# 1.3.4.4 阻止默认行为与冒泡：`preventDefault()`、`stopPropagation()`

[返回 JavaScript 目录](./README.md) · [阶段知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

取消默认动作和阻止事件传播是两件事，需要分别表达。

前置：能阅读变量、函数与基础 HTML。语言核心按顺序学习；DOM 需要先理解函数和对象，异步示例建议先学 Promise。适用场景：原生练习、Vue/Nuxt 组件逻辑与浏览器排障；框架不会改变这些语言规则。

## 工作机制

preventDefault请求取消可取消事件的默认行为，例如表单导航；stopPropagation阻止继续向其他节点传播，但不自动取消默认动作，也不阻止当前节点其他监听器。stopImmediatePropagation影响同节点后续监听器。

## 使用规则

1. 先看event.cancelable和具体浏览器默认行为；不能取消的事件调用preventDefault无效。

2. 表单本地预览可取消submit默认导航，但仍应保留原生输入验证。

3. 少用广泛stopPropagation，以免破坏父层委托、统计或复合控件的事件协作。

## 最小代码

```javascript
form.addEventListener("submit", (event) => {
  event.preventDefault(); // 阻止导航式提交
  console.log(event.defaultPrevented);
});
button.addEventListener("click", (event) => event.stopPropagation());
```

这段代码用于观察本节规则。浏览器 DOM、事件、网络与模块代码需要在对应的环境运行；配套实验把预期错误捕获并展示，不制造未处理的页面异常。

## 移动开发对照与边界

Android事件消费也影响后续分发，但Web取消默认导航与DOM传播是两个维度，需要分别验证。

## 常见误区

- “stopPropagation防止链接跳转”：它不取消默认动作。

- “preventDefault阻止父级监听”：事件仍可能继续冒泡。
