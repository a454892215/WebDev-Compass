# 1.1.2.5 原生验证与自定义提示

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

先使用浏览器约束表达单字段规则，再用 Constraint Validation API 补充跨字段规则和可理解的反馈。

## 工作方式与使用规则

原生验证先于 submit：required、email 等不满足时，浏览器会阻止提交，因此 submit 监听器不一定执行。`checkValidity()` 返回是否通过；`reportValidity()` 还会请求显示浏览器提示。浏览器提示的语言和样式因环境而异。

跨字段比较可调用 `input.setCustomValidity('说明')`，非空字符串使控件持续无效；解决后必须传空字符串清除。自定义错误配可见文字、`aria-describedby` 和 `aria-invalid="true"`，修复后清除状态。不要仅用红色区分，也不要每输入一个字符就打断用户。

本示例保留原生必填/邮箱校验，在 submit 中检查两次邮箱，并在任一相关字段 input 时清除旧的自定义错误。使用 novalidate 接管全部流程时，需要自己收集无效字段、显示摘要并移动焦点；入门示例不走这条复杂路线。

前端验证只帮助用户，不能防止伪造请求。服务器需要再次验证、返回字段错误，并在真实项目中避免回显敏感字段。

## 最小示例

```html
<label for="confirmation">再次输入邮箱</label>
<input id="confirmation" type="email" name="confirmation" required />
<script>
  const input = document.querySelector("#confirmation");
  input.setCustomValidity("两次邮箱不一致。");
  input.reportValidity();
  // 用户修复相关字段后：
  input.setCustomValidity("");
</script>
```

## 📱 移动端对照

相当于 Flutter Form/validator 加焦点管理，但浏览器的 validity 和 submit 生命周期由平台参与；不能简单把点击按钮当作唯一提交入口。

## 常见误区

- setCustomValidity 后从不清除：内容正确也会一直不能提交。
- 在 submit 监听器中期待收到所有无效输入：原生约束可能已拦截事件。
- 只在客户端校验或依赖按钮 disabled：可被绕过。
