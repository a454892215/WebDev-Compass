# 1.1.2.1 表单与 input 类型

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

form 定义一次数据提交；input 的 type 描述输入语义，name 才是提交字段名。

## 工作方式与使用规则

`id` 用于 label 关联和 DOM 定位，`name` 用于数据协议。一个 form 不能嵌套另一个 form。按 Enter 或点击提交按钮都会进入原生提交生命周期。

| 类型            | 用途与边界                                                         |
| --------------- | ------------------------------------------------------------------ |
| text / password | 单行文字；password 仅遮挡显示，不提供传输加密                      |
| email / url     | 基本格式约束；不证明邮箱存在或链接可信                             |
| number          | 数值数量，配 min/max/step；电话号码、邮编用 text/tel，避免丢前导零 |
| checkbox        | 独立开关；未勾选通常没有对应字段；未写 value 时默认值为 on         |
| radio           | 同 name 的选项构成一组，提交选中项                                 |
| file            | 用户主动选本地文件，accept 只是选择提示，服务器仍需检查文件        |
| hidden          | 隐藏但可被查看修改，不能存可信权限或秘密                           |

只有符合提交条件的控件参与数据集；通常需要 name，且不能 disabled。多选字段有重复键，使用 `FormData.getAll()`。POST 配 HTTPS 仍需服务端认证、授权与校验。

## 最小示例

```html
<form action="/preferences" method="post">
  <label for="email">邮箱</label>
  <input id="email" name="email" type="email" autocomplete="email" required />
  <label><input name="notice" type="checkbox" value="yes" />接收通知</label>
  <button type="submit">保存偏好</button>
</form>
```

## 📱 移动端对照

类似 Android 的输入类型、Flutter TextInputType，但浏览器还原生提供表单提交协议与约束；UI 输入类型不能替代后端数据模型验证。

## 常见误区

- 把 id 当提交字段名：没有 name 的普通输入不会被 FormData 自动收集。
- 用 password 或 hidden 当安全边界：开发者工具可读取，生产仍需 HTTPS 和权限验证。
- 把 FormData 直接转为对象保存多选值：重复键会丢失，先用 getAll 或保留 entries。
