# 1.1.3.6 SEO 基础与 JSON-LD

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

SEO 的基础是让用户和搜索引擎理解真实内容；元信息和结构化数据提供线索，不保证收录、排名或富媒体结果。

## 工作方式与使用规则

每个页面提供描述主题的 title、清晰的主标题与层级、可理解的链接文字和有意义的图片替代文本。meta description 可作为摘要线索，但搜索引擎可能根据查询自行生成摘要。语义结构同样改善可访问性，不应只为爬虫编写。

JSON-LD 在 script type="application/ld+json" 中描述结构化事实，通常使用 Schema.org 词汇。内容应与页面可见正文一致，不能虚构评分、作者或商品。Google 支持的富媒体类型与必需字段有独立要求；仅写 @type=Article 不表示已经符合所有展示资格。

抓取还受 HTTP 状态、robots、canonical、链接发现、渲染和站点质量等影响。框架页面需要确认爬虫能取得主要内容，不能把 SSR 当作排名保证。正式上线后才可通过 Search Console、URL Inspection 或对应结构化数据工具核对，本地页面无法证明收录。

用户输入注入 JSON-LD 仍需安全序列化，尤其避免未转义的结束 script 片段；不要直接用字符串拼 HTML。示例使用固定演示数据。

## 最小示例

```html
<title>HTML 表单入门 · WebDev Compass</title>
<meta name="description" content="学习 label、name 与原生表单验证。" />
<script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Article",
    "headline": "HTML 表单入门",
    "author": { "@type": "Organization", "name": "WebDev Compass 编辑组" }
  }
</script>
<!-- 正文中同样可见文章名称和作者，不能只在 JSON-LD 虚构事实。 -->
```

## 📱 移动端对照

类似应用商店元信息帮助理解产品，但 Web 还有页面抓取、链接和渲染链路。SEO 与 App 内路由、Deep Link 相关但不是同一件事。

## 常见误区

- 加几个 meta/JSON-LD 就能保证排名：平台不作此承诺。
- 用 h1/h2 仅调整字号：应表达信息层级，字号交给 CSS。
- 结构化数据可以写页面没有的评分：应与可见内容和类型规则一致。
