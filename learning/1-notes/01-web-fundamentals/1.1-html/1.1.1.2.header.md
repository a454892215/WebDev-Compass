# 1.1.1.2 语义化区域：header、nav、main、section、article、aside、footer

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

语义化元素描述内容在文档中的职责，让浏览器、搜索工具和辅助技术理解区域关系。

## 核心机制与选择

| 元素                | 适用内容                                         |
| ------------------- | ------------------------------------------------ |
| `header` / `footer` | 页面或文章的介绍、结尾信息；含义取决于所在上下文 |
| `nav`               | 主要导航集合，不是所有链接的通用包装             |
| `main`              | 当前页面的主要内容；常规页面保留一个可见 main    |
| `section`           | 按主题组织的章节，通常有可识别标题               |
| `article`           | 可独立理解、分发或复用的完整内容，如文章或评论   |
| `aside`             | 与主内容相关但可分离的补充内容                   |
| `div`               | 没有更合适语义时的通用结构容器                   |

同一页面可以有多篇 article，每篇有自己的 header/footer；它们不是额外的页面级 banner/contentinfo。标签不规定视觉位置，aside 也可以位于正文下方。

## 最小示例

```html
<header>
  <nav aria-label="主导航"><a href="/">首页</a></nav>
</header>
<main>
  <h1>学习日志</h1>
  <article>
    <header><h2>初识 HTML</h2></header>
    <section>
      <h3>今日收获</h3>
      <p>结构可以表达意义。</p>
    </section>
  </article>
  <aside aria-labelledby="tip">
    <h2 id="tip">相关提示</h2>
    <p>先写内容。</p>
  </aside>
</main>
<footer>站点说明</footer>
```

## 实际使用与边界

页面结构应从内容和导航需求推导。若只是为了 CSS 网格分组，用 div 即可；不要给每个装饰盒子加 section。多个 nav 可分别命名，例如“主导航”“目录导航”。

为键盘用户提供指向 main 的跳转链接。原生语义已存在时，不重复添加 `role="button"` 等不相关角色。

## 📱 移动端对照

Android/Flutter 的 Row、Column、Container 主要控制布局。Web 的 main、article 等首先表达内容关系；其布局由 CSS 决定，因此不能按“Column 就对应 section”机械映射。

## 常见误区

- 全部使用 div 并加 class，视觉可用，但丢失文档区域语义。
- 全部替换成 section，同样不能自动得到合理语义。
- aria-label 不是给任意元素补全设计的万能工具，优先用可见标题。
