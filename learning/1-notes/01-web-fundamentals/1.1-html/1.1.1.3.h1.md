# 1.1.1.3 标题与文本：h1–h6、p、span、strong、em、br、hr

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

标题组织文档层级，文本元素表达段落、重要性与语气；字体大小和颜色交给 CSS。

## 核心机制与选择

| 元素      | 表达的含义                                 |
| --------- | ------------------------------------------ |
| `h1`–`h6` | 从页面主题到下级章节，按内容逻辑逐层组织   |
| `p`       | 一个段落，不能装入 section、div 或另一个 p |
| `span`    | 没有额外语义的短语级容器                   |
| `strong`  | 内容的重要性、严重性或紧迫性               |
| `em`      | 语气重音，可能改变一句话的强调重点         |
| `br`      | 内容中本来存在的换行，如地址或诗行         |
| `hr`      | 同一内容中的主题转折，不只是装饰线         |

本项目采用一个主要 h1、逐级组织 h2/h3 的教学约定。不要为了字号选择级别，也不要假定嵌套 section 会自动把 h1 变成 h2。

## 最小示例

```html
<main>
  <h1>学习记录</h1>
  <section>
    <h2>HTML</h2>
    <h3>文本语义</h3>
    <p><strong>请保留备份。</strong>建议<em>先</em>阅读说明。</p>
    <p>讨论地址：<br />线上学习室</p>
  </section>
</main>
```

## 实际使用与边界

标题常被辅助技术用于快速导航；只把普通文字放大无法代替标题。strong 默认常显示为粗体，em 默认常显示为斜体，但这些样式可以覆盖，语义仍保留。

浏览器会折叠大多数普通空白。要增加段间距，使用 margin 等 CSS，不要连续堆叠 br 或空 p。展示原样多行代码时使用 pre 和 code。

## 📱 移动端对照

Flutter Text 的 fontWeight 或 Android TextAppearance 主要描述样式；Web 的 heading 与 strong 额外提供文档意义。字体样式相同的两个节点，辅助技术读取方式仍可能不同。

## 常见误区

- h3 不是“中号字体组件”；调整字号不该改变大纲。
- strong 不是所有粗体字的统一包装，em 也不是任意斜体。
- 不把 hr 用作每张卡片之间的纯装饰边框。
