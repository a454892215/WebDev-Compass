# 1.4.4 慢网、失败与无 JavaScript 时仍可理解的页面

> [返回质量目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学什么，先会什么

会 HTML 内容结构与 Promise/async 基础后实践。理解概念可先阅读，异步代码在 1.3 后回读。目标是能解释核心内容、增强功能、失败回退和数据采集边界，后续在实际宿主应用中验证真实服务。

## 一句话理解

渐进增强先提供可阅读或可操作的基础，再按环境增加体验；每个增强都要考虑失败时用户还能知道什么、做什么。

## 选择核心能力和增强能力

静态说明、商品介绍和主要导航通常可以先通过 HTML 交付。搜索、账户操作、支付等任务可能确实依赖 JavaScript 或服务端，无法支持时要清楚说明替代方式；不能声称所有应用关掉 JavaScript 后都必须保持全部功能。

```html
<section id="reading">
  <h2>入门步骤</h2>
  <ol>
    <li>阅读原理</li>
    <li>运行示例</li>
    <li>验证结果</li>
  </ol>
</section>
<section id="enhanced" hidden><!-- JS 初始化成功后再显示增强控件 --></section>
<noscript><p>当前未启用脚本，仍可阅读入门步骤。</p></noscript>
```

hidden 在此避免展示无法操作的增强按钮，不用于隐藏唯一的正文。脚本初始化失败时，基础内容仍存在。关键 CSS 失效时，应保留合理的 HTML 阅读顺序，而不是依赖绝对定位排列出意义。

## 网络与异步失败

| 情况               | 处理方式                                                         |
| ------------------ | ---------------------------------------------------------------- |
| 慢响应             | 明确加载、必要时允许取消或退出；不要无期限只转圈                 |
| HTTP 非成功状态    | 先检查 response.ok，再解析适当错误；fetch 不会因 404 自动 reject |
| JSON 解析/协议失败 | 与传输失败区分，保留用户输入并提供适当重试                       |
| 用户取消           | 作为可识别的终止，不把它统一提示为服务崩溃                       |
| 迟到响应           | 用请求标识或会话版本检查，避免覆盖新的查询/账号状态              |
| 图片或媒体不可用   | 保留对应说明/替代文本，必要时给明确错误，不永久空白              |

AbortController 可向支持的 API 传递取消信号，但取消不等于后端未执行。对写操作，是否重试需依据幂等和业务协议判断，不能看到错误就自动重复付款或提交。

## 最小数据原则

只收集完成任务所需的数据。日志与错误提示不直接输出 token、密码或完整敏感正文。浏览器网络缓存、URL 参数、localStorage 和分析上报都有各自可见范围，不能把“只是前端”当作没有隐私责任。

## 配套实验与验收

[打开渐进增强示例](../../../2-examples/01-web-fundamentals/1.4-quality-basics/1.4.4.progressive-enhancement-demo.html)，建议经本机 HTTP 访问。

1. 关闭 JavaScript 后重新打开：基础步骤、导航和说明仍可阅读；增强控件不展示，noscript 说明可见。
2. 开启 JavaScript：加载本地 JSON；人为增加等待时间后可取消，取消后不能被迟到结果覆盖。
3. 选择本地故障注入，再重试成功，观察错误与恢复信息。故障注入不是实际断网、真实后端或手机弱网验证。
4. 本例没有输入上传、持久化或分析上报；真实项目需要另行确定采集目的、保留与访问规则。

## 📱 移动开发对照

可复用移动端的离线/弱网和取消设计经验，但 Web 文档可能先于脚本交互到达，链接、表单和服务端 HTML 能构成独立基础。SSR 只是输出方式之一，不自动保证所有增强失败后可用。

## 常见误区

- 把 navigator.onLine 当真实 API 可达：网络接口连通不证明业务服务器可用。
- try/catch 后只 console.error：用户仍需要可理解反馈与恢复路径。
- 取消一定撤销服务端写操作：需要业务协议支持。
- 为了统计运行情况默认上报全部输入：先做数据最小化和授权判断。
