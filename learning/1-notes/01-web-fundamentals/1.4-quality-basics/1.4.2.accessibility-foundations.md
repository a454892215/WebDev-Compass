# 1.4.2 语义、键盘、焦点、缩放与对比度

> [返回质量目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学什么，先会什么

会使用原生 HTML 表单和链接即可开始。目标是让同一个小页面能被键盘、放大界面和辅助技术理解；深入的 WCAG 审计、复杂组件和读屏器兼容放在阶段 6/12 深化。

## 一句话理解

无障碍是让用户能够感知内容、操作控件、理解反馈并完成任务，不是给元素批量添加 ARIA。

## 基础检查顺序

| 层面      | 最小做法                                 | 实际检查                              |
| --------- | ---------------------------------------- | ------------------------------------- |
| 结构      | 合理的 main、标题层级、列表与表头        | 只看标题和区域能否理解页面            |
| 控件      | 导航用 a，动作使用 button，输入有 label  | 可访问名称与可见用途是否一致          |
| 键盘      | 采用原生 Tab 顺序，不用正 tabindex 重排  | Tab/Shift+Tab、Enter/空格可否完成流程 |
| 焦点      | 清楚的 focus-visible，弹窗关闭回到触发点 | 不被遮挡，不意外丢到页面开头          |
| 反馈      | 错误有文字并关联字段，必要时用状态区域   | 不只靠红色，不在每个按键都打断朗读    |
| 缩放/重排 | 不禁缩放、相对字号、内容可重排           | 放大后不丢内容或按钮，长内容不掩盖    |
| 替代内容  | 信息图像有合适 alt，媒体有适当文字替代   | 替代内容与上下文传递同样信息          |

对比度可按 WCAG 的相应成功标准检查：AA 下普通文本通常至少 4.5:1，大文本通常 3:1；必要的控件边界/图形信息也有非文本对比要求和例外。不能把某个比值当作整个页面“通过 WCAG”的证明。文本大小、状态、背景透明度、图像以及禁用项例外都影响判断。

## 最小可访问表单

```html
<label for="nickname">昵称</label>
<input
  id="nickname"
  name="nickname"
  autocomplete="nickname"
  aria-describedby="nickname-help"
  required
/>
<p id="nickname-help">使用演示昵称，不输入真实个人资料。</p>
<button type="submit">生成预览</button>
<p id="status" role="status"></p>
```

原生 required 已具有相应语义，不必重复 aria-required。ARIA 不增加点击、键盘或焦点行为；一个 div 加 role=button 仍需开发者实现全部行为，因此能用原生按钮就不重造。不要对可聚焦元素或其祖先加 aria-hidden。

错误处理要把文字、字段和焦点连起来。示例主动点击时调用原生 reportValidity，并在错误时设置 aria-invalid 和关联错误；用户修正后同步清除。重要错误不应只保存在控制台或自动消失的 Toast 中。

## 配套实验与验收

[打开键盘与对比度示例](../../../2-examples/01-web-fundamentals/1.4-quality-basics/1.4.2.accessibility-foundations-demo.html)。

1. 仅用键盘从跳转链接进入主标题，Tab 到昵称并提交空值，观察错误、焦点和字段状态。
2. 输入演示昵称后再次提交，确认输出存在且错误状态清除。
3. 切换高对比配色，确认控件用途仍通过文字表达；配色切换不是完整对比度审计器。
4. 用浏览器缩放检查 200% 文字和窄视口内容。若需要 WCAG 2.2 AA 等正式声明，应按完整适用标准和目标辅助技术进一步验收。

## 📱 移动开发对照

可对照 Android contentDescription、Flutter Semantics 和焦点遍历，但 Web 的标签、文档区域、链接与键盘导航由 HTML/浏览器共同提供。触屏能点中不意味着键盘和读屏器也能完成任务。

## 常见误区

- 自动扫描零告警意味着完全无障碍：扫描只能覆盖部分问题，需人工任务走查和适用的辅助技术验证。
- 把 outline 去掉就算设计一致：会让键盘用户失去当前位置。
- 用 disabled 替代所有不可用状态：disabled 影响焦点和提交，aria-disabled 又需要自己阻止操作，应按交互目的选择。
- 把放大视口当成真实手机：缩放、触控、屏幕阅读器和软键盘分别有验证边界。
