# 1.2.5.2 keyframes 与 animation 生命周期

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：独立写一次性keyframes淡入，区分动画播放状态和真实请求成功/失败文本。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

关键帧定义样式随时间的序列，animation控制播放、次数、方向和填充。

## 工作机制与使用规则

1. @keyframes按百分比描述各阶段；animation-name绑定序列，duration与iteration-count控制时长和次数。
2. fill-mode控制动画前后采用何种样式，不等于修改真实业务状态；动画结束后的语义状态要由逻辑维护。
3. 尽量避免无限自动动画；允许停止并支持减少动态效果，不能让信息只在一闪而过的帧中出现。
4. 同一个元素的多个动画可能竞争同一属性；应简化合成关系并通过浏览器检查。

## 最小代码与阅读顺序

```css
@keyframes reveal {
  from {
    opacity: 0.3;
  }
  to {
    opacity: 1;
  }
}
.badge {
  animation: reveal 180ms ease 1 both;
}
@media (prefers-reduced-motion: reduce) {
  .badge {
    animation: none;
  }
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

接近AnimationController/关键帧序列，但CSS填充模式不会替代Widget状态或业务事件。

## 常见误区与修正

- 动画结束等于业务完成，忽略失败/取消。
- 无限闪烁内容且没有停止路径。

## 示例观察

打开[对应离线实验](../../../2-examples/01-web-fundamentals/1.2-css/1.2.5.2.keyframes-demo.html)，操作“切换对照状态”，再用“读取实际样式”观察计算值。目标规则保留在页面 style 中，公共外壳在 assets/lab.css，便于逐条检查。

减少动态效果环境下animation会禁用；此时应验证静态信息而非强制要求动画播放。

1. 初始暂停关键帧，观察animation-play-state。
2. 切换为播放并等待一次结束。
3. 模拟reduced-motion，确认内容仍完整可读。

## 关联综合实践

为 #status 增加一次性、可关闭的请求结果淡入，加载/错误文字本身不依赖动画。

综合验收：没有无限闪烁且不把动画结束当接口完成；取消或失败状态有真实文本，偏好reduce时保留结果。
