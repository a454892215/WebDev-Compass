# 1.2.4.6 把移动布局经验迁移到 CSS

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：用CSS重建一个熟悉的Row/Wrap布局，写出默认收缩、自动最小尺寸及DOM顺序三个差异。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

复用“约束、内容、对齐”的思维，但需重新学习浏览器的文本流和最小尺寸规则。

## 工作机制与使用规则

1. Row/Column/RN Flexbox与CSS Flex有共同轴模型；CSS默认收缩、内在最小尺寸和书写方向不能直接照搬。
2. Wrap可类比flex-wrap，多维对齐常用Grid；列表虚拟化是另一层能力，不由Grid自动实现。
3. rem是根字号单位，em是字体参照，不与设备dp/逻辑像素存在固定换算。
4. Web保留DOM阅读和键盘顺序；不能仅为了布局美观用order打乱交互顺序。

## 最小代码与阅读顺序

```css
.row {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}
.row > .content {
  flex: 1 1 12rem;
  min-inline-size: 0;
}
.column {
  flex-direction: column;
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

已有移动开发经验可以帮助判断布局目的，但不能把CSS当另一套Widget属性字典；应测量实际盒模型。

## 常见误区与修正

- rem永远等于16px或某个dp。
- 页面只要看起来像设计稿，就忽略焦点和文字缩放。

## 关联综合实践

将 .fields/.actions/.cards 分别映射到熟悉的Row/Wrap/Grid思维，再写出CSS不等价之处。

综合验收：实际解释一个min-inline-size或正常流差异；不改DOM源顺序来追求视觉排列。
