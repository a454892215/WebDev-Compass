## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

CSS 多列把同一连续内容流排入若干列，适合文章而非任意交互卡片网格。

## 工作机制与使用规则

1. column-count 给出列数目标，column-width 给出理想宽度；浏览器结合可用空间决定实际列。
2. column-gap 和 column-rule 控制列间距与分隔线，不创造新的语义结构。
3. break-inside:avoid 可减少卡片内部断开，但不是任意内容都保证不分段；列高和平衡有影响。
4. 交互内容的视觉跨列顺序可能难于理解；长文阅读注意窄屏回到单列。

## 最小代码与阅读顺序

```css
.prose {
  column-count: 2;
  column-gap: 2rem;
}
.prose figure {
  break-inside: avoid;
}
@media (max-width: 40rem) {
  .prose {
    column-count: 1;
  }
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与多列正文排版相近，不等价于Flutter GridView；一段内容会被浏览器分割到多个列。

## 常见误区与修正

- 用columns构建复杂表单，造成阅读/焦点跳转难以理解。
- 把column-count当保证固定列宽。
