# 1.2.6.3 Sass/SCSS：构建变量、嵌套与混入

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

Sass将扩展语法编译为CSS；运行期浏览器不会执行SCSS变量或mixin。

## 工作机制与使用规则

1. $变量和mixin在编译时展开，CSS自定义属性留在浏览器运行期，两者解决不同问题。
2. 嵌套减少重复书写但过深会生成高耦合选择器；@extend会合并选择器，需检查输出体积和意外匹配。
3. 优先明确依赖的@use/@forward模块机制；旧@import属于迁移知识，不把过时全局加载方式当默认。
4. 只有SCSS源码和浏览器成功展示不代表编译成功；必须运行选定编译器并比较产物。

## 最小代码与阅读顺序

```css
$accent: #006464;
@mixin ring($color) {
  border: 2px solid $color;
}
.card {
  @include ring($accent);
  &__title {
    font-weight: 700;
  }
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与构建时代码生成相似；SCSS不是新的浏览器运行时，不能类比为实时修改Theme对象。

## 常见误区与修正

- 把.scss当普通link样式直接加载。
- 把Sass编译变量当可由浏览器style.setProperty修改的token。
