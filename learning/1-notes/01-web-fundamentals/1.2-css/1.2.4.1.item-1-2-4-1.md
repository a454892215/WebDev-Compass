# 1.2.4.1 媒体查询与内容驱动的断点

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：创建单列基础与宽屏多列布局，以长内容失效位置确定断点并记录390/700/1440px结果。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

媒体查询判断视口或环境条件，断点应来自内容无法合理排布的位置，而不是设备型号列表。

## 工作机制与使用规则

1. 移动优先通常先写单列基础，再用min-width增强宽布局；桌面优先用max-width收敛也可，需团队一致。
2. width媒体查询以CSS视口判断，不等于物理屏幕像素或操作系统窗口的外边框。
3. 不要只测两端尺寸；中间宽度、文本放大、长文案也可能触发布局问题。
4. 查询可以关注hover、pointer和用户偏好；不能把宽屏等同于鼠标，把窄屏等同于触控。

## 最小代码与阅读顺序

```css
.cards {
  display: grid;
  grid-template-columns: 1fr;
}
@media (min-width: 50rem) {
  .cards {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与LayoutBuilder断点布局相近；CSS视口、浏览器缩放与用户根字号会共同影响实际结果。

## 常见误区与修正

- 为每款手机写一个固定宽度断点。
- 只测390和1440，忽略700px时的长标题。
