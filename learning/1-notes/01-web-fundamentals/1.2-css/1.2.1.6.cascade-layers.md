# 1.2.1.6 完整层叠：来源、重要性、层与权重

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：创建base/theme两个命名层，分别预测普通声明和!important声明的获胜层并保留对照记录。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

先决定声明属于哪一优先级区间，再比较该区间内的特异性和顺序。

## 工作机制与使用规则

1. 先过滤选择器/媒体条件，再比较来源及 important、层、特异性，必要时比较作用域接近程度和出现顺序。
2. 普通作者样式中，后声明的层优于早层，未分层普通规则优于已分层普通规则；内联普通声明另有更高位置。
3. important 会反转层顺序：早层重要声明优于晚层，已分层重要声明优于未分层重要声明。
4. 用户 important 可优于作者 important；CSS 动画、过渡也有层叠位置，不能简化为“important 永远最大”。
5. 提前声明 @layer 顺序可稳定第三方和本地样式关系，不要以引入 BEM 代替理解层叠。

### 来源与重要性的总顺序

先忽略各来源内部的层与内联细分，下列从低到高排列：

| 顺序 | 候选声明或运行值 |
| --- | --- |
| 1 | 浏览器普通样式 |
| 2 | 用户普通样式 |
| 3 | 作者普通样式 |
| 4 | 正在生效的关键帧动画值 |
| 5 | 作者重要声明 |
| 6 | 用户重要声明 |
| 7 | 浏览器重要声明 |
| 8 | 正在生效的过渡值 |

作者来源内部，内联普通声明高于普通样式规则；内联重要声明高于作者样式表中的重要声明，但仍不能压过用户/浏览器重要声明或正在生效的过渡值。同一来源、重要性和层区间内才继续比较特异性、作用域接近程度与顺序。此表解释规则，不意味着应该用动画争抢优先级。

## 最小代码与阅读顺序

```css
@layer base, theme;
@layer base {
  .note {
    color: firebrick !important;
  }
}
@layer theme {
  .note {
    color: teal !important;
  }
}
/* important 时 base 获胜；普通声明则 theme 获胜 */
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

类似配置来源的优先级，而不是进程级样式单例；CSS 的重要性和层反转在移动主题系统中没有直接等价物。

## 常见误区与修正

- 把未分层样式视为永远最低。
- 给所有规则加 important；会使用户偏好和覆盖关系更难推理。

把综合页主题、组件与工具样式按明确 @layer 顺序组织，单独制作一次!important层序反转对照后移除冲突。

综合验收：普通层与important层序分别能解释；最终页不依赖全局!important争抢状态。
