# 1.2.4.5 容器查询：组件根据可用空间变化

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：同一视口并排放窄侧栏和宽主体，两张卡片按各自祖先容器调整布局并保留基础样式。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

容器查询让组件根据祖先容器尺寸调整布局，而不只根据整个视口。

## 工作机制与使用规则

1. 尺寸查询需要在祖先声明container-type:inline-size或size，并可用container-name命名。
2. @container通常查询祖先容器；不能让同一个盒子简单地根据自己的尺寸查询再改变自己造成循环。
3. inline-size保留块向内容尺寸，通常更适合卡片；size可能需要显式块尺寸以避免意外塌陷。
4. 先提供可用基础布局，再用@supports/容器查询增强；组件在窄侧栏与宽主体应分别验证。

## 最小代码与阅读顺序

```css
.slot {
  container-type: inline-size;
  container-name: card-slot;
}
.card {
  display: block;
}
@container card-slot (min-width:240px) {
  .card {
    display: flex;
  }
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

接近对局部LayoutBuilder constraints做响应，而非只看MediaQuery屏幕尺寸；查询对象必须正确选择祖先。

## 常见误区与修正

- 给卡片自己写container-type，然后期待它查询自己。
- 为了启用size容器导致内容高度丢失。

## 关联综合实践

让一个资源卡片根据自身容器而不是整页宽度改变封面/正文排列，对照窄侧栏与宽列表。

综合验收：祖先声明inline-size容器而非错误地查询自身；基础布局可用，不支持查询时有合理回退。
