# 1.2.6.2 CSS Modules：构建时类名映射

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：在已提供Vite构建实验中分别修改两个同名.card模块，核对生成类与组件引用。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

CSS Modules通过构建工具生成局部类名映射；浏览器最终接收的仍是普通HTML和CSS。

## 工作机制与使用规则

1. 常见*.module.css约定由构建工具识别；import styles后以styles.title取实际类名，映射命名由工具决定。
2. 局部类避免名称碰撞，但不是Shadow DOM；继承、全局选择器和显式global声明仍可能影响。
3. Vite/Vue/Nuxt有各自接入约定，不能把<script import CSS对象>直接放进无构建HTML并期待原生支持。
4. 测试应包含构建输出和组件引用一致性；静态演示只能解释编译后行为。

## 最小代码与阅读顺序

```css
/* Card.module.css */
.title {
  color: teal;
}
/* 组件中：import styles from "./Card.module.css" */
/* 编译后可能：class="Card_title_x7"；具体名称由工具决定 */
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与代码生成的资源名称映射相似，但不等于Dart库私有或Widget树隔离；必须验证宿主构建链。

## 常见误区与修正

- 浏览器原生理解.module.css导出对象。
- 以为所有全局样式从此无法穿透组件。
