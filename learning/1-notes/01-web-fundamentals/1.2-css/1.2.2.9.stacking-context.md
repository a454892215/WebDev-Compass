# 1.2.2.9 层叠上下文与 z-index

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

z-index 只在所属层叠环境内比较，子元素不能靠一个巨大数字逃出父上下文。

## 工作机制与使用规则

1. 定位元素的非auto z-index、transform、opacity小于1等可建立新的层叠上下文，条件需按规范核对。
2. 每个上下文在父上下文中作为整体排序，内部z-index只影响内部，不能直接与外部同级比较。
3. position:relative 并非必然建立上下文，通常还要非auto的z-index；flex/grid item有自己的规则。
4. dialog等顶层元素与普通文档层叠不同；不要用全站z-index递增代替正确浮层/焦点策略。

## 最小代码与阅读顺序

```css
.panel {
  position: relative;
  z-index: 1;
}
.panel .badge {
  position: absolute;
  z-index: 999;
}
.neighbor {
  position: relative;
  z-index: 2;
}
/* badge 仍不能压过 neighbor 所在的父级排序 */
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与Stack绘制顺序相关，但CSS嵌套上下文、合成和顶层行为有独立规则；不是所有“层”都是GPU层。

## 常见误区与修正

- z-index:999999可以解决所有遮挡。
- 把overflow裁剪、层叠顺序和包含块混成同一问题。
