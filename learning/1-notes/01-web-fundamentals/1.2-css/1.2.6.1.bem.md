# 1.2.6.1 BEM 命名：识别结构与状态

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

BEM 是一种团队命名约定，不是浏览器隔离机制，也不决定层叠优先级。

## 工作机制与使用规则

1. block表示独立组件，element常用双下划线表示内部部分，modifier常用双连字符表示变体。
2. 命名帮助读者识别职责，浏览器只把它们当普通类；不要靠命名推断不可覆盖或天然低特异性。
3. 现代项目可结合局部样式、@layer和:where降低耦合；MWG更倾向原生层叠/作用域能力，不要求新项目一律BEM。
4. 状态可以由原生属性、aria或data表达；避免为了命名重复存多份同一业务状态。

## 最小代码与阅读顺序

```css
.lesson-card {
  padding: 1rem;
}
.lesson-card__title {
  font-weight: 700;
}
.lesson-card--highlighted {
  border-color: teal;
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

类似组件文件/样式命名约定，不能替代Flutter组件作用域；CSS类仍可被全局选择器匹配。

## 常见误区与修正

- 双下划线会让浏览器自动隔离。
- 给每一层DOM都创建长链名称，耦合页面结构。

## 示例观察

打开[对应离线实验](../../../2-examples/01-web-fundamentals/1.2-css/1.2.6.1.bem-demo.html)，操作“切换对照状态”，再用“读取实际样式”观察计算值。目标规则保留在页面 style 中，公共外壳在 assets/lab.css，便于逐条检查。

这是维护/团队约定示例，不宣称BEM优于所有原生层叠或局部样式方案。

1. 观察block、element和modifier三个角色。
2. 切换modifier，确认只是新增普通class。
3. 用相同属性的全局规则测试命名并不免疫层叠。
