# 1.2.6.4 原子化 CSS 与 Tailwind 的构建边界

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

工具类用小而明确的样式组合表达界面；Tailwind通过工具链按源码生成这些规则。

## 工作机制与使用规则

1. 原子类通常表达单一属性或职责，优点是组合与局部修改直观，代价是模板更长且需统一token。
2. Tailwind的响应式、状态和主题变体由构建工具处理；不是浏览器原生理解md:或hover:前缀。
3. 动态拼接类名可能让构建扫描找不到完整类，需按实际版本的源码检测规则提供完整候选。
4. 语义HTML、无障碍、布局约束不会因换用工具类而自动解决；不把工具类系统当UI设计本身。

## 最小代码与阅读顺序

```html
<!-- 构建后这些类对应生成CSS -->
<div class="lesson-flex lesson-gap lesson-rounded">内容</div>
/* 示例原子规则：.lesson-flex{display:flex} .lesson-gap{gap:1rem} */
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

类似把常用Style token组合到Widget参数，但类扫描、响应式变体和CSS层叠是Web构建链特有问题。

## 常见误区与修正

- 引入不存在的类就期待浏览器生成CSS。
- 通过字符串拼接任意颜色类，构建结果却缺失。
