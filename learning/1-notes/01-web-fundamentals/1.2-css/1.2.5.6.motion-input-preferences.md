# 1.2.5.6 用户动效偏好与不同输入方式

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

交互样式应尊重减少动态效果、键盘焦点和触控能力，而不只优化鼠标hover。

## 工作机制与使用规则

1. prefers-reduced-motion:reduce表示用户希望减少非必要动态效果；可直接取消位移/缩放，同时保留明确状态。
2. 用:focus-visible表达键盘焦点，不为美观删除outline；焦点提示不能只依赖颜色。
3. hover/pointer媒体特征描述主要输入能力，any-hover/any-pointer描述任意输入；设备可同时拥有触控和鼠标。
4. 触控目标、按钮标签和文本放大同样需要检查；CSS媒体查询不能判断人的全部需求。

## 最小代码与阅读顺序

```css
.control:focus-visible {
  outline: 3px solid #994900;
  outline-offset: 3px;
}
@media (hover: hover) and (pointer: fine) {
  .control:hover {
    filter: brightness(0.9);
  }
}
@media (prefers-reduced-motion: reduce) {
  .preview {
    transition: none;
    animation: none;
  }
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与系统动画偏好、FocusNode和触控尺寸关联；浏览器环境需显式保留键盘路径和用户缩放。

## 常见误区与修正

- 手机一定没有hover，桌面一定没有触控。
- reduced-motion就隐藏所有交互结果。

打开[对应离线实验](../../../2-examples/01-web-fundamentals/1.2-css/1.2.5.6.motion-input-preferences-demo.html)，操作“切换对照状态”，再用“读取实际样式”观察计算值。目标规则保留在页面 style 中，公共外壳在 assets/lab.css，便于逐条检查。

1. 切换目标状态，确认无需动画也能理解。
2. DevTools模拟reduced-motion后检查transition-duration为0。
