# 1.2.1.3 特异性：比较 ID、类与元素权重

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

只有先进入同一层叠竞争区间的声明，才需要比较选择器的特异性。

## 工作机制与使用规则

1. 一般选择器以 ID、类/属性/伪类、元素/伪元素三组权重逐组比较，不把三组当十进制相加。
2. :where() 及其参数为零特异性；:is()、:not()、:has() 的参数采用选择器参数列表中的最大特异性。
3. 继承值不是与子元素直接声明进行同一场竞赛；直接给子元素的普通声明可覆盖继承值。
4. 避免用 ID、长祖先链和 !important 争抢样式；先定位所属层、来源和生效条件。

## 最小代码与阅读顺序

```css
#message {
  color: firebrick;
} /* 1-0-0 */
.card .message {
  color: teal;
} /* 0-2-0 */
:where(.card) .message {
  color: navy;
} /* 0-1-0 */
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

可类比多个配置同时匹配时的决策规则，但与 Theme 合并不同；层优先级先于选择器权重。

## 常见误区与修正

- 认为十个 class 就能压过一个 ID。
- 只记 important 最大，忽略过渡、用户重要样式和层次顺序。
