# 1.2.3.1 颜色语法、透明度与可读性

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：为成功/错误提示设计等值HEX、RGB、HSL颜色，并记录文字与最终背景对比及文字状态。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

不同语法可以表达相同颜色；真正的UI决策还需考虑背景、对比和非颜色提示。

## 工作机制与使用规则

1. 命名色、HEX、rgb()/rgba()、hsl()/hsla() 都能表达颜色；现代rgb/hsl可用空格和斜线alpha语法。
2. alpha是颜色透明度，不同于把整个元素opacity降低；后者会影响文字、后代与层叠上下文。
3. HSL的lightness不是感知亮度，不能仅比较L值就断言满足可读性。
4. 状态不要只用红绿区分，还需文字/图标/结构说明；生产主题应验证文字与实际背景的对比。

## 最小代码与阅读顺序

```css
.notice {
  color: rgb(0 100 100);
}
.overlay {
  background: hsl(180 50% 30% / 0.2);
}
/* rgba(0,100,100,1) 与 rgb(0 100 100) 可表达同一色 */
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与Color、ARGB颜色值相似；CSS alpha合成依赖底层背景，主题对比不能只看单一色值。

## 常见误区与修正

- 透明背景意味着文字也透明。
- 把颜色编码转换当作无障碍对比验证。
