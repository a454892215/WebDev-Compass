# 1.2.5.4 cursor、user-select 与 pointer-events

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：用原生按钮测试pointer-events、disabled与键盘激活，另保留可复制的错误文本。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

指针样式和命中测试改变交互细节，不会自动改变控件语义、禁用状态或键盘行为。

## 工作机制与使用规则

1. cursor只改变指针外观，不让div自动成为按钮；动作应使用button，导航用a。
2. user-select控制文本选择，避免对正文和错误信息全局禁选，用户可能需要复制。
3. pointer-events:none使指针命中穿透，但键盘焦点和脚本点击不一定被禁用；真正禁用表单控件使用disabled并解释状态。
4. 触控没有传统鼠标光标，hover策略必须有键盘/触控等效路径。

## 最小代码与阅读顺序

```css
.decoration {
  pointer-events: none;
}
button:disabled {
  cursor: not-allowed;
}
.copyable {
  user-select: text;
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与IgnorePointer有相关性，但CSS pointer-events不是完整的输入禁用模型，也不等价于按钮enabled=false。

## 常见误区与修正

- pointer-events:none之后就认为键盘不能触发。
- cursor:pointer给静态文字造成可点击的错误暗示。
