# 1.2.4.7 移动视口、safe-area 与软键盘

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

手机浏览器的可见区域会变化，安全区和软键盘需要按真实设备行为验收。

## 工作机制与使用规则

1. svh/lvh/dvh分别基于小、大和动态视口尺寸；100dvh能响应浏览器UI变化，但不是保证键盘处理正确的万能公式。
2. env(safe-area-inset-*)表示设备安全区，需与viewport-fit=cover及产品布局协调；桌面常得到0。
3. visualViewport可观察可见区域变化，但布局修复仍应优先CSS流与滚动，不用任意JS改整页高度。
4. 固定底栏与输入框容易被键盘遮挡；缩放、横竖屏、焦点滚动和浏览器差异需要目标真机专项。

## 最小代码与阅读顺序

```css
.screen {
  min-block-size: 100svh;
}
.bar {
  padding-block-end: max(1rem, env(safe-area-inset-bottom));
}
@supports (height: 100dvh) {
  .screen {
    min-block-size: 100dvh;
  }
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

类似SafeArea和键盘insets，但浏览器地址栏、visualViewport及宿主WebView策略有额外变化，不能把移动模拟当真机结果。

## 常见误区与修正

- 所有vh都等价于当前可见高度。
- 模拟器中safe-area=0就删掉产品安全区处理。
