# 1.2.4.2 viewport、CSS 像素与浏览器缩放

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：写允许缩放的最小页面，分别记录innerWidth、devicePixelRatio与visualViewport读数及含义。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

viewport元信息让移动布局使用设备宽度的CSS视口；CSS像素不等于一个物理像素。

## 工作机制与使用规则

1. 常用meta viewport为width=device-width, initial-scale=1.0；不能用user-scalable=no阻止读者放大。
2. devicePixelRatio描述设备像素与CSS像素的比例，仍受浏览器/缩放环境影响，不是业务布局断点。
3. layout viewport与visual viewport在放大或软键盘出现时可能不同，需要按交互选择观察对象。
4. Web页面应通过流动布局适配，而不是把整张固定设计稿按比例缩成不可读小字。

## 最小代码与阅读顺序

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
<!-- 保留用户缩放，布局尺寸用CSS像素与相对单位表达 -->
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

类似逻辑像素概念，但浏览器缩放、地址栏和visualViewport是移动App常规布局以外的边界。

## 常见误区与修正

- CSS width=390意味着物理屏幕390像素。
- 用maximum-scale=1掩盖页面在缩放后的布局缺陷。
