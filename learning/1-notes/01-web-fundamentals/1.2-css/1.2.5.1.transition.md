# 1.2.5.1 transition：在状态变化之间插值

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

transition描述两个可动画状态间的插值，不创造状态，也不保证所有属性都能平滑变化。

## 工作机制与使用规则

1. 需有实际起始/结束值和属性变化；transition-property、duration、timing-function、delay分别控制范围和时间。
2. 优先明确属性而不是transition:all，避免未来新增布局属性也意外动画。
3. 布局尺寸变化可能触发布局，transform/opacity更常适合移动或淡入，但仍需测量实际合成和绘制成本。
4. 保留prefers-reduced-motion路径，并确保动画不是传达结果的唯一方式。

## 最小代码与阅读顺序

```css
.badge {
  transform: translateX(0);
  transition: transform 180ms ease;
}
.badge[data-open] {
  transform: translateX(40px);
}
@media (prefers-reduced-motion: reduce) {
  .badge {
    transition: none;
  }
}
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

类似隐式动画，但CSS监听的是样式状态差异；Web还需考虑动画偏好和主线程布局代价。

## 常见误区与修正

- 有transition就会自动播放，不改变值。
- transition:all覆盖所有属性，导致尺寸和颜色也意外延迟。
