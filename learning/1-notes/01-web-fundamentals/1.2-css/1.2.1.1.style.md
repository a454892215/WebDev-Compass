# 1.2.1.1 CSS 的三种引入方式与来源顺序

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

学完应能解释此规则、在 DevTools 中找到获胜声明或计算值，并对照内容变化判断是否适用。工程化选修项需区分源码与浏览器产物。

## 一句话理解

浏览器把外部表、style 标签和内联声明一起参与层叠；“放在哪里”不等于完整优先级。

## 工作机制与使用规则

1. link rel=stylesheet 加载独立资源，便于缓存和复用；style 适合页面级实验，style 属性只影响当前元素。
2. 外部表和 style 都是作者样式，同一层叠条件下再比较特异性与出现顺序，外部 CSS 不天然低于内部 CSS。
3. 内联普通声明优先于普通作者规则；important、层、来源及动画需要另看 1.2.1.6。
4. HTML 先能表达内容，再把样式抽到独立文件；生产禁止把凭据塞进 style 或 CSS。

## 最小代码与阅读顺序

```html
<link rel="stylesheet" href="./assets/lab.css" />
<style>
  .notice {
    color: teal;
  }
</style>
<p class="notice" style="color: tomato">观察层叠</p>
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

与 Android XML 样式或 Flutter Theme 的复用目标相似，但 CSS 不是简单的最后一次赋值：继承与层叠会共同选值。

## 常见误区与修正

- 认为内联、内部、外部是一条不变的三档顺序。
- 为了压过一个规则不断追加 style；先用 DevTools 看最终获胜声明。

## 示例观察

打开[对应离线实验](../../../2-examples/01-web-fundamentals/1.2-css/1.2.1.1.style-demo.html)，操作“切换对照状态”，再用“读取实际样式”观察计算值。目标规则保留在页面 style 中，公共外壳在 assets/lab.css，便于逐条检查。

本页外部 lab.css 提供公共样式；当前目标的内部规则与内联声明可在 Elements 核对。

1. 初始检查目标颜色，预判内联声明是否获胜。
2. 点击切换移除内联 color，观察内部规则开始生效。
3. 在 Elements 恢复内联声明，再观察，而不是只读输出。
