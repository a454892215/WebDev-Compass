# 1.2.3.7 overflow、滚动容器与可达性

[返回 CSS 目录](./README.md) · [知识地图](../../../../knowledge-map/01-foundation-stages-0-2.md)

## 学习目标与前置

前置：HTML 元素、属性与基本页面结构；含切换按钮的脚本仅用于观察，不要求此时掌握完整 JavaScript。

本点产出：独立实现有名称和键盘入口的长代码滚动区，整页保持正常流。 验收时需解释实际规则与适用边界，不能仅复述界面输出。

## 一句话理解

溢出策略决定超出盒子的内容如何显示或访问，也可能改变定位与格式化行为。

## 工作机制与使用规则

1. visible显示溢出，hidden裁剪但可能仍可程序滚动，clip裁剪且不创建滚动容器，auto按需滚动。
2. overflow-x/y并非总能彼此独立，某些组合会使另一轴的计算值变化；以Computed结果验证。
3. 滚动区域必须有实际尺寸约束；只有overflow:auto而没有受限尺寸可能不会形成预期滚动。
4. 窄屏优先修正布局，必要的代码/表格局部滚动须能键盘聚焦，并提供可访问名称。

## 最小代码与阅读顺序

```css
.code-region {
  max-inline-size: 100%;
  overflow: auto;
}
/* 对必要滚动区域加 tabindex="0"、role="region" 与可访问名称 */
```

先读匹配目标与参照条件，再读计算结果。不要把一份截图当作所有内容、浏览器和字号均正确的证据。

## 移动开发经验对照

类似ScrollView/裁剪设置，但Web滚动容器还影响sticky、滚轮传播和键盘可达性。

## 常见误区与修正

- 全局overflow-x:hidden掩盖意外溢出。
- 滚动面板没有焦点入口，键盘用户无法操作。
