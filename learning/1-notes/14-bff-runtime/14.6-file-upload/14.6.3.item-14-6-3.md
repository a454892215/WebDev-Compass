# 14.6.3 上传安全：类型、大小、隔离与扫描完成态

## 前置与目标

先掌握阶段5 HTTP/鉴权与阶段10安全，以及14.2 BFF身份和请求校验；本组按14.6.1 → 14.6.2 → 14.6.3阅读。能解释机制、运行反例并为Nuxt上传模块制定可验证边界。无需为普通小文件强制引入分片或云平台。

## 核心原理

文件名扩展、客户端File.type和Content-Type均由不受信输入影响，只能作为声明。服务端先限制请求/任务/用户资源，再按允许类型检查字节特征并使用受控解析器验证内容；完成传输与允许公开是不同状态。扫描失败、超时或未知应留在quarantine，只有受信扫描结果才能迁移到ready。

## 按风险排列检查

先鉴权和对象归属，再限制总长度、片长、片数、并发、速率、存储配额与任务期限；不能等全部读进内存才检查上限。上传正文的网络接收限制需同时在代理/框架和流读取层设置；本地实验只有Buffer方法入参，不能称已经抗慢速上传或HTTP超大body。压缩包须限制解压后大小、文件数和路径穿越，图片/视频解析须限制像素、时长、内存/CPU；为“支持所有格式”放开任意类型会扩大攻击面。

## 声明、签名、解析与扫描各解决什么

image/png声明与PNG前8字节签名相符，只通过一个粗类型门槛。攻击者可造带正确头部的任意数据或polyglot，因此还需可信解析器/重新编码、适用的恶意内容扫描与资源限制。SHA-256证明接收字节与预期一致，不证明内容无害；客户端自报摘要也不是身份授权。SVG/HTML有主动内容，不能因为是图片扩展就与应用同源内联展示。

实验fixture是“PNG签名字节+合成文本”，并非可解码图片。UploadStore.complete检查声明和8字节后只进入quarantine；scan接受的是受信扫描适配器结果模型，测试中的clean/infected字符串不执行病毒识别。真实接口绝不能让浏览器POST一个clean来发布文件，回调需认证、关联对象版本/摘要、幂等处理，并防止扫描后覆盖再发布旧结果。

## 状态机与失败关闭

uploading → quarantine → ready或rejected。未完成/扫描未决时read始终not-ready；感染则拒绝读取且清理对象，扫描不可用留在quarantine并由有界重试/人工处理恢复。若允许重复签名覆盖同key，应绑定不可变版本或重新进入隔离，不能沿用旧clean状态。本例complete后拒绝put，防止已扫描内容被替换；生产还需在存储权限、版本和业务引用上维持这个不变量。

## 发布与移动端对照

下载仍按业务权限；公开资源宜使用隔离域和正确Content-Type、nosniff，附件按需要Content-Disposition: attachment，不能用上传文件名直接拼响应头或磁盘路径。应用UI显示文件名采用文本插值，不把文件名当HTML。原生客户端的“上传完成回调”同样不能代表服务器审核，但浏览器同源主动内容会引入额外脚本执行风险。

## 最小排查顺序

先看任务owner和state，再核对已确认字节、整体摘要、类型/解析错误、扫描requestId/结果和对象版本。日志保存分类、长度、状态、关联ID即可，避免原始文件、完整预签名URL和凭据。当前实验无HTTP下载、解析器、真实杀毒、持久化和生产配额；这些是接入计划的明确缺项，不以11个单元测试代替上线安全验收。

## 自足最小调用

在示例的upload-lab目录以node --input-type=module运行下列代码；命令路径见配套示例。不需要浏览器或云账号。

~~~js
import { UploadStore, uploadMissing, digest } from './upload.mjs'
const bytes = Buffer.from([137,80,78,71,13,10,26,10])
const store = new UploadStore()
const id = store.create('alice', bytes.length, 8, digest(bytes))
await uploadMissing(store, 'alice', id, bytes, 8, 1,
  async (i, part, hash) => store.put('alice', id, i, part, hash))
store.complete('alice', id, 'image/png')
console.log(store.scan('alice', id, 'timeout')) // quarantine
// store.read('alice', id) 抛not-ready，粗类型通过不等于可发布。
~~~
