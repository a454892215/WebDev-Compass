# 14.6.2 预签名URL：S3/OSS直传与最小授权

## 前置与目标

先掌握阶段5 HTTP/鉴权与阶段10安全，以及14.2 BFF身份和请求校验；本组按14.6.1 → 14.6.2 → 14.6.3阅读。能解释机制、运行反例并为Nuxt上传模块制定可验证边界。无需为普通小文件强制引入分片或云平台。

## 核心原理

直传拆成控制通道和数据通道：浏览器先向受信BFF申请指定对象/分片的限时权限，再把原始文件字节PUT到对象存储，最后向BFF确认完成。服务端保存长期凭据并验证用户和对象归属；浏览器只拿短期能力。预签名URL通常是持有即有权限的bearer能力，并不天然绑定当前登录用户或一次性使用。

## 为什么直传

文件字节经过BFF会占用带宽和连接；直传把数据发送给对象存储，但BFF仍负责业务授权、任务归属、对象key生成、完成态验证和发布。客户端不得自行要求任意bucket/key或把他人的key传来覆盖。用服务端生成的不可预测key并绑定业务记录；上传成功的200不等于“当前账户的附件已审核发布”。

## 一次完整的协作顺序

1. BFF校验会话、CSRF策略、用户配额和文件声明，为当前用户生成受控key或multipart uploadId。
2. 使用平台官方SDK和服务端角色凭据签发指定PUT或UploadPart；设置短有效期并绑定所需的Content-Type/checksum等签名字段。
3. 浏览器按返回的method、headers和原始Blob发送；PUT不是FormData封装，不能随意改method、host、region或签名字段。
4. BFF以自身凭据查对象元数据/part列表、长度和校验结果，核对业务归属；不得仅相信客户端回传的ETag或成功标志。完成后进入隔离检查，再发布。

多分片需要分别签名每片和服务端控制complete，过期只更新缺片授权，不重建整个已完成部分。长时间未完成任务应清理；S3未完成Multipart不会自动按本例内存生命周期消失，需设置存储生命周期策略或主动abort。

## 浏览器CORS与凭据

Bucket CORS按真实前端Origin、PUT/GET等必要方法和签名请求头配置；JS需读取ETag等非简单响应头时设置Expose-Headers。CORS决定浏览器能否发出/读取跨域请求，不能代替存储权限或阻止持有URL的非浏览器调用。向存储PUT时通常不转发BFF的Cookie/Authorization，而按签名契约发送；不要把所有请求都设credentials:include。

## 最小模型与生产差异

LocalGrants用每进程随机HMAC密钥对{id,part,checksum,size,method,expires}签名；verify拒绝过期和修改字段。它只演示“授权范围必须被完整性保护”，并没有AWS SigV4的规范请求、区域/服务密钥推导或OSS协议，不能拿本token请求云存储。size字段的强制匹配是本模型行为，不保证任意S3 PUT预签名都自动限制长度；生产需按官方API/策略选择适用约束并在完成前核验实际长度。

## 易错处与移动端对照

与原生SDK类似，前端不能保存长期云密钥。浏览器多出CORS约束，而原生调用成功不代表H5成功。URL可在有效期内重复使用，同key上传还可能覆盖对象；不能称一次性凭据。实际期限受临时凭据到期、撤权和平台规则约束，不能一律认为“写了1小时就必定有效1小时”。不要记录完整URL查询参数或放进分析上报；生产用HTTPS，签名过期后重申请而非改URL时间。

## 自足最小调用

在示例的upload-lab目录以node --input-type=module运行下列代码；命令路径见配套示例。不需要浏览器或云账号。

~~~js
import { LocalGrants, digest } from './upload.mjs'
const signer = new LocalGrants()
const request = { id: 'fixture', part: 0, size: 4, checksum: digest(Buffer.from('demo')), method: 'PUT' }
const now = Date.now()
const token = signer.issue({ ...request, expires: now + 1000 }, now)
console.log(signer.verify(token, request, now).method) // PUT
// signer.verify(token, { ...request, method: 'GET' }, now) 会抛scope错误
// token不打印、不上报；它不是AWS/OSS签名URL。
~~~
