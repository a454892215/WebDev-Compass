## 机制、场景与边界

BFF（Backend for Frontend）是服务于特定前端体验的接口层，不是所有 Web 项目必备。已有适用 API 的静态站可以直接调用，不为目录分层新增网络跳数。需要隐藏服务凭据、聚合多服务、输出适合页面的 DTO 时，Nuxt 已有 Nitro server 能力；只有独立部署、独立团队或运行时要求成立时才选独立 Fastify/Hono/Express 服务。

Nuxt 的 server/api/dashboard.get.ts 对应 GET /api/dashboard，文件后缀约束方法；server/middleware/context.ts 在处理请求时建立追踪上下文。中间件应做短小的通用工作，不对所有静态资源执行昂贵认证，也不误把中间件 return 当所有框架统一的 next() 语义。插件是进程/运行时生命周期；event.context 是当前请求的数据承载处。两者范围不同。

最小机制：context 中生成 randomUUID，再由 handler 返回 DTO 的 traceId；它与 x-request-id 对应。不要直接信任来自浏览器的任意追踪头或转发头。反向代理的可信链必须另行配置。本项目使用 Node preset，可访问 event.node；这不能移植成所有 Edge 平台的通用写法。

Android 的拦截器链可以帮助理解横切关注点，但 Nuxt SSR 会在同一进程并行处理不同访问者，不能把当前用户放模块级单例。路由、中间件、身份校验、DTO投影各有职责；目录数量不等于架构质量。
