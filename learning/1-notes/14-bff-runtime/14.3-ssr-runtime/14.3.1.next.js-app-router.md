# 14.3.1 Next.js App Router：Server Components 与路由边界（选修）

## 目标与前置

本节衔接阶段4 Nuxt数据获取、阶段5身份/API和本阶段14.1–14.2；读后应能解释边界、复现具体故障，并把结论用于实际BFF审查。Next为选修，其余按14.3.2→14.3.3→14.3.4→14.3.5学习。

## 原理与取舍

本点是 React/Next.js 分支选修。主线读者先完成阶段4的 Vue 3/Nuxt 和本节14.3.2–14.3.5，再作机制对照，不要求为了学 Nitro 安装 React。Next App Router 的 layout/page 默认是 Server Component；Server Component 的代码执行和输出协议不等同于 Vue 的通用组件 SSR。需要事件、状态或浏览器 API 的交互边界使用 Client Component。

Server Component 可以在服务端读数据，但其输出、传入 Client Component 的 props 和响应仍可能被浏览器看到。服务端运行不代表返回值自动保密。`'use client'` 标记客户端模块边界，会影响其依赖图；不宜把整个根布局都标成 client。Client Component 初次加载也可能参与服务端预渲染，不能因名字而在模块顶层随意访问 window。

Route Handler 是 HTTP 接口边界，负责方法、输入校验、身份、权限、状态码和响应。页面能调用数据库不代表所有外部调用都应先绕回自己的 Route Handler；服务端内部可复用数据访问函数。敏感接口仍必须独立鉴权，不能只依赖页面隐藏按钮。框架缓存默认行为会随版本变化，个性化数据先核具体版本的缓存/动态策略，并以双用户请求验证隔离。

## 最小例子与观察

官方观察步骤：阅读 Server and Client Components 的 first load、subsequent navigation 和 composition；画出“数据访问→Server Component→可序列化 DTO→Client Component”。在已有 Next 项目中再检查 app/api 下 Route Handler 的独立鉴权。本仓库没有安装或执行 Next，以下是静态边界示意，不是可直接运行项目：

~~~text
server data function -> page (Server Component)
                    -> {title, likes} -> LikeButton (Client Component)
external HTTP       -> Route Handler -> authenticate + authorize + data function
~~~

观察结果应指出 props 属于可见输出；服务端密钥留在数据访问边界。Nuxt 通用组件与 Next RSC 不能只替换目录名互迁。

## 移动开发对照与误区

Android/Flutter 可以用 repository/UI 层来理解职责分离，但 RSC payload、服务端路由和客户端模块边界是 Web 框架机制，不等于 isolate 或 Activity。SSR/Server Components/静态生成/缓存是不同维度；不能把任何一次服务端 HTML 都称为 RSC。
