# 14.3.5 HTTP Streaming：首块、已发送头、取消与恢复

## 目标与前置

## 原理与取舍

Streaming 是逐段交付响应；HTTP数据流、框架组件的HTML流和 RSC 是不同协议。Nuxt/Nitro 能提供流式 API，不代表本仓库使用的 Nuxt 版本自动拥有 Next式组件分段流。MWG 的原生 out-of-order HTML方案属于 volatile 能力，本项目未启用；本节采用稳定的 HTTP/NDJSON教学实验，不能把它称为该新HTML能力的实现。

响应头在 writeHead/flushHeaders/首次发送正文时提交。提交前可以返回503等状态与完整错误DTO；提交后不能再把已经发送的200改成500，也不能把第二个JSON对象直接接进原JSON文档。NDJSON按行 framing，每行独立JSON，客户端必须缓冲跨chunk的半行；网络chunk不保证与一次write或一行对应。协议要定义 start/data/done/error，只有收到终结消息才能知道应用层成功，HTTP200并不足够。

客户端主动离开时取消读取并中止请求；服务器监听响应提前 close 并取消待执行的上游/计时器。正常 finish 与提前 close 区分，不把请求body读完触发的事件误当断连。生产代理/CDN可能缓冲，压缩也会改变首块时机；本地首块通过不能代替整条部署链路验证。恢复仅对可重试、幂等操作进行，必要时携带受服务端校验的游标；写操作没有幂等键不能盲目重放。

## 最小例子与观察

runtime-lab 用真实 node:http 在随机 loopback端口提供 /stream、/partial、/before-error、/cancel。测试读取 first chunk 时断言已有 start 而没有 done，随后再读 done；partial 路径保持HTTP200并发送协议error；before-error在提交头前返回503；cancel在首块后关闭客户端连接，断言服务器活动请求归零且未发送第二块。

每次 reader.read 的 value 都只是字节分片。测试专门用 text()收集完整partial再按行解析，不把一次read当一条NDJSON。真正的浏览器增量客户端还需 TextDecoder 的流式解码、半行缓冲、错误/完成状态与取消按钮，这些列为扩展任务，不声称lab已有UI。

## 移动开发对照与误区

Flutter/RN的Stream可帮助理解连续事件和取消订阅，但HTTP状态码已发不可修改、代理缓冲、浏览器断开和服务器资源清理是额外协议责任。界面进度使用独立role=status文本；不将整块动态数据设为live region反复播报，焦点保持在用户操作处。
