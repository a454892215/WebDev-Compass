# 14.1.4 环境变量与配置：字符串校验、加载优先级和公开边界

前置：阶段2的异步/事件循环、阶段3的模块与测试。先完成14.1.1，再学习Stream与Worker；配置和进程管理用于运行边界，之后进入14.2的Nitro接口。目标是能解释调度、实现有界工作并判断哪些状态能跨请求/进程共享。

## 解决的问题与机制

环境变量在Node里以字符串形式读取。Boolean("false")为true、parseInt("12x")为12，都不适合严格配置验证。启动时把未知字符串转换为经过范围校验的配置，再传给使用者；缺少必需项应尽早失败，不在日志里打印秘密值。配置与代码分离是12-factor的一项原则，不意味着所有环境变量都适合送入浏览器。

Node内建--env-file可加载dotenv格式；dotenv包是另一种可选加载器，要核其版本与override选项，不能默认两者语义完全一致。本lab使用Node内建功能，不安装dotenv。已有进程环境优先于同名env-file值，多个文件的覆盖细节按所用Node版本核对。Nuxt runtimeConfig私有键和public子树有明确边界，生产运行读取环境也不同于构建期替换；不能因为键名含TOKEN就假设框架会自动保密。

## 最小例子与实际观察

下面片段以操作卡中的node-lab目录为运行上下文；导入模块、输入与完整清理代码均随该目录提供。

~~~js
import { readConfig, publicConfig } from './config.mjs'
const config = readConfig({ LAB_PORT: '4562', LAB_DEBUG: 'false', LAB_TOKEN: 'public-fixture' })
console.log(publicConfig(config)) // { port: 4562, debug: false }
// token仍只在私有config中，公开对象主动投影字段
~~~

verify临时生成dist/config-fixture.env，内容明确为公开fixture，调用node --env-file加载后得到port4562/debugfalse；同名宿主LAB_PORT=4569覆盖文件。配置函数拒绝12x、0、65536、yes和缺token；publicConfig不含token。临时文件验证后删除，报告只保存公开投影。没有读取、输出或修改用户真实凭据。

## 场景、边界与误区

适用于上游origin、超时、开关和私有凭据。解析数字还要明确单位，URL要验证协议和允许目标。冻结对象只是浅冻结，不等于秘密加密或权限控制。CI、部署平台和本地env有不同注入时机，需分别记录。

## 移动开发对照

Android BuildConfig或Flutter --dart-define常参与构建，并可能被打进客户端产物；Nuxt服务器运行期配置有另一条私有边界。任何发送到HTML、payload或浏览器bundle中的值都应按公开信息对待，不能照搬客户端常量作为服务端秘密管理。
