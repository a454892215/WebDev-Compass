# 14.4.5 CDN 缓存与 SWR：公开内容、键和过期边界

前置：阶段6HTTP缓存、14.2错误与鉴权、14.4.4一致性。目标是在允许短暂旧读的公开数据上降低上游请求，同时证明不会泄露私有响应。

## 机制

HTTP Cache-Control的max-age面向客户端/共享缓存，s-maxage专门控制共享缓存；stale-while-revalidate允许在指定过期窗口内先返回旧值并后台更新。它不是“永远返回旧值”，过了fresh+stale边界仍需获取或按明确失败策略报错。no-cache表示可存但使用前需要验证，no-store表示不存；private阻止共享缓存存储，并非加密。CDN供应商可能覆盖/忽略某些指令，必须核对具体路由规则与响应头。

应用层缓存、浏览器缓存、Service Worker、Cloudflare Cache API和CDN自动缓存是不同层。Cloudflare Cache API内容限于写入的数据中心，cache.put不使用tiered cache；cache.put/cache.match明确不支持stale-while-revalidate与stale-if-error，不能把HTTP SWR语法原封不动当Cache API的自动后台刷新。自定义Worker策略需自己协调fetch、waitUntil和错误，并验证实际部署。

## 本地实验

createPublicCache用注入时钟，实现10秒fresh、随后20秒stale窗口，后台刷新同键合并，超过窗口则等待上游；失败时不无限延长旧值时间戳。缓存最多8个已完成条目（测试用2），键只允许zh/en语言；生产仍需限制并发pending/请求速率和实例资源，不能把该教学Map当全球缓存。

handler在有Cookie或Authorization时绕过共享缓存并给private,no-store；/private也始终不共享。公开目录的语言进入缓存键，未知查询维度拒绝，防止不受控键膨胀。对真实业务还要审核tenant、locale、货币、实验组、Vary与Set-Cookie，不能只靠URL去掉query就共用。

## 对照与边界

移动HTTP客户端缓存通常只服务本机用户；CDN会跨用户，因此错误的缓存键可能变成数据泄漏。MWG建议区分私有与普通动态资源，不把no-store机械加到所有静态内容。本实验的私有fixture使用no-store，公开目录使用明确HTTP策略；没有跑真实CDN、缓存命中率或bfcache测试。
