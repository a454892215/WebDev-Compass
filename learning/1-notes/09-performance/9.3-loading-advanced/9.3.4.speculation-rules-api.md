# 9.3.4 推测加载：预取、预渲染与无副作用边界

前置：阶段3构建、阶段6资源/缓存基础与阶段7托管；先读机制再跑操作卡。性能进阶以真实资源发现、协议和缓存维度为重点，不重复只看一张优化截图。

## 解决什么问题与原理

preload供当前页面，prefetch给未来资源，prerender会加载并执行未来页面，成本和副作用不同。SpeculationRules是浏览器可忽略的提示，不是确定调度承诺；支持、用户设置、Save-Data和内存会影响执行。只选择高概率安全只读目标；预渲染可能提前触发脚本、API和遥测，需激活检测与延迟副作用。正常链接始终保留。

## 最小机制片段

```javascript
const supported = HTMLScriptElement.supports?.("speculationrules") === true;
// 支持不代表会执行；完整lab仅对固定只读next.html添加prefetch，不预渲染账户。
```

## 实际实验与边界

lab仅在用户动作后探测HTMLScriptElement.supports(speculationrules)，Save-Data跳过，插入固定公开next.html的prefetch建议并保留正常链接；单测验证不支持/节流回退。浏览器验证规则与导航，没有声称实际prefetch/prerender、命中或带宽收益。

## 误区与移动端对照

把节省等待与额外网络/内存/隐私成本一起纳入预算，不以“API存在”默认全站开启。

移动端也关注资源字节与缓存；Web还受HTML发现链、CSS阻塞、字体/图片选择、共享HTTP缓存和浏览器提示策略影响，不能把App资源打包或原生图片缓存经验直接等同。
