# 9.3.6 边缘缓存键：输出维度、凭据旁路与失效

前置：阶段3构建、阶段6资源/缓存基础与阶段7托管；先读机制再跑操作卡。性能进阶以真实资源发现、协议和缓存维度为重点，不重复只看一张优化截图。

## 解决什么问题与原理

缓存键必须包含实际影响可共享输出的维度，且在查缓存前决定是否能共享。只规范化已明确语义的query，不随意删除语言/分页/版本。Vary表达响应受哪些请求头影响，但不能替代CDN实际key/旁路配置；Cookie/Authorization/用户数据通常需旁路公共缓存，私有响应no-store，服务端内部缓存也要独立管理。失效、容量与部署版本是设计一部分。

## 最小机制片段

```javascript
function key(url, headers) {
  if (headers.cookie !== undefined || headers.authorization !== undefined) return null;
  return JSON.stringify(["public-data:v1", url.searchParams.get("q") || "", url.searchParams.get("lang") || "zh-CN"]);
}
// 精简机制；完整lab还拒绝未知参数、限制值与容量并归一化头名。
```

## 实际实验与边界

lab公开key为v1/q/lang，参数顺序不影响相同结果，未知维度不缓存；最多32项。Cookie/Authorization任意存在即旁路、private/no-store；四并发alice/bob合成请求各自读取，公开缓存保持public。scope可伪造，非真实认证；此内存模型不是实际CDN部署。

## 误区与移动端对照

HTTP头、Nitro、CDN、浏览器、SW是独立层；隐私和身份边界不能为命中率让步。

移动端也关注资源字节与缓存；Web还受HTML发现链、CSS阻塞、字体/图片选择、共享HTTP缓存和浏览器提示策略影响，不能把App资源打包或原生图片缓存经验直接等同。
