# 9.3.2 字体加载：子集、swap与匹配的preload

前置：阶段3构建、阶段6资源/缓存基础与阶段7托管；先读机制再跑操作卡。性能进阶以真实资源发现、协议和缓存维度为重点，不重复只看一张优化截图。

## 解决什么问题与原理

字体有发现链、下载、解析与字形覆盖。WOFF2/子集能减少字节，但语言覆盖和license先满足；unicode-range选择哪些资源需要下载，不是对已下载字体自动做本地子集。font-display控制阻塞/交换窗口，swap可能产生FOUT与布局变化，optional等策略有不同取舍；指标需看真实字体与回退度量。

## 最小机制片段

```html
<link rel="preload" href="./assets/roboto-latin-400.woff2" as="font" type="font/woff2" crossorigin>
<!-- CSS @font-face使用相同URL/font-weight400/font-display:swap。 -->
```

## 实际实验与边界

lab携官方Roboto Latin400 WOFF2与OFL许可证，font-display:swap；相同URL的preload/as/type/crossorigin与CSS匹配，真实一个资源请求、FontFace loaded。中文由系统字体回退。本轮没有运行subset工具，也未做慢网FOIT/FOUT视觉持续时间/跨语言审校。

## 误区与移动端对照

预加载只给当前确需字体；子集、语言回退与字体度量应一起设计。

移动端也关注资源字节与缓存；Web还受HTML发现链、CSS阻塞、字体/图片选择、共享HTTP缓存和浏览器提示策略影响，不能把App资源打包或原生图片缓存经验直接等同。
