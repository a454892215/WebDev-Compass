# 9.3.3 图片管线：真实候选、占位与CDN变换契约

前置：阶段3构建、阶段6资源/缓存基础与阶段7托管；先读机制再跑操作卡。性能进阶以真实资源发现、协议和缓存维度为重点，不重复只看一张优化截图。

## 解决什么问题与原理

图片管线从源图、编码、尺寸变体到HTML选择和缓存。AVIF/WebP可能减少字节，但质量/解码/支持/业务图像决定取舍；picture类型回退和srcset/sizes分别负责格式与尺寸。LQIP必须与最终固有比例一致，不能用模糊图代替可访问描述，也不能为“懒加载”推迟LCP候选。CDN变换还需有限参数、缓存键、原图权限和失效策略。

## 最小机制片段

```html
<picture>
  <source type="image/avif" srcset="./assets/hero-320.avif 320w, ./assets/hero-640.avif 640w" sizes="(max-width:672px) calc(100vw - 32px),640px">
  <img src="./assets/hero-640.png" width="640" height="240" fetchpriority="high" alt="课程封面">
</picture>
<!-- 完整lab还含WebP层。 -->
```

## 实际实验与边界

lab以原创几何fixture提供AVIF/WebP/PNG两尺寸，640×240固有尺寸、比例一致LQIP、首屏high非lazy；Chrome实读currentSrc与完成解码。没有CDN服务，源码回退链不等于本轮禁用所有格式后都实测。小几何图压缩比不推业务照片收益。

## 误区与移动端对照

按视觉质量、解码、传输与缓存综合测量，不盲目一律转同一格式。

移动端也关注资源字节与缓存；Web还受HTML发现链、CSS阻塞、字体/图片选择、共享HTTP缓存和浏览器提示策略影响，不能把App资源打包或原生图片缓存经验直接等同。
