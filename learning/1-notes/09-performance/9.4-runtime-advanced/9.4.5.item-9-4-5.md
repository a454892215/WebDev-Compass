# 9.4.5 可变高虚拟列表：前缀定位、锚点与可访问回退

前置阶段2异步/浏览器、阶段3测试和阶段4–8 Vue/Nuxt/状态/边界；先观察真实瓶颈，再选择策略。

## 解决什么问题与机制

固定itemHeight无法表示折行/图片/动态内容。保存已知/估算高度及前缀和，用二分定位scrollTop对应索引；测量变化要更新后续偏移，保留可见项目与项内偏移，否则上方内容变高会跳动。content-visibility保留DOM而跳过部分渲染，不等于虚拟列表移除DOM，不能把两者当完全相同策略。真实动态测量还需ResizeObserver、批处理和避免反馈循环，本lab用真实配置的可变高度演示定位，不假装完整自动测量库。

## 最小片段

```javascript
const heights = [32, 40, 48];
const prefix = [0];
for (const height of heights) prefix.push(prefix.at(-1) + height);
console.log(prefix); // [0,32,72,120]，完整二分/锚点见lab。
```

片段上下文与完整可运行机制见操作卡，不把可选 API 当所有浏览器都支持。

## 实验与使用边界

lab1000项高度32/40/48/56循环，窗口<30 DOM、全量1000 DOM；首行增加20px后scrollTop同步+20且同一可见行相对位置不变。行没有内部可聚焦控件；说明窗口外查找/读屏/打印/交互问题，全量模式是显式回退，不称完整无障碍认证。

不为100条列表机械虚拟化；DOM减少、可访问性和实现成本一起权衡。

## 移动开发对照

移动端也关注UI线程、生命周期和列表窗口；浏览器的task/微任务/DOM/Worker/GC与框架原生线程不同，不能把移动API名字套为同一机制。
