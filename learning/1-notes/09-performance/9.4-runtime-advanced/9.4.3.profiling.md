# 9.4.3 内存定位：用实际Heap快照追踪强引用与Detached DOM

前置阶段2异步/浏览器、阶段3测试和阶段4–8 Vue/Nuxt/状态/边界；先观察真实瓶颈，再选择策略。

## 解决什么问题与机制

移除DOM不代表没有引用；window监听、闭包、数组、timer或缓存可保留已卸载对象和节点。一次heap增大可能是缓存/GC时机，不能只看总MB判泄漏。对可重复进入/退出场景采baseline/操作后/清理后，按构造器与Retainers看谁持有，必要时比较对象数量。Heap snapshot是侵入式诊断，会暂停页面并改变GC，真实项目profile可能含敏感数据，不随意上传。

## 最小片段

```javascript
const controller = new AbortController();
window.addEventListener('resize', () => console.log('resize'), {signal:controller.signal});
// 对应生命周期结束时主动controller.abort()，不是等finalizer。
controller.abort();
```

片段上下文与完整可运行机制见操作卡，不把可选 API 当所有浏览器都支持。

## 实验与使用边界

lab故意new20个Stage9RetainedPanel，把node append后remove却留在数组和window监听；实际CDP HeapProfiler保存三快照，构造器对象0→20→0，泄漏态有Array element强入边。清理既移除监听又清空数组，原始文件可Load到DevTools Memory查看Retainers。

不要把DevTools保留的console对象当业务泄漏；避免记录大对象和不释放调试handle。

## 移动开发对照

移动端也关注UI线程、生命周期和列表窗口；浏览器的task/微任务/DOM/Worker/GC与框架原生线程不同，不能把移动API名字套为同一机制。
