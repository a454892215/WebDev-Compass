# 9.4.7 空闲任务：deadline、timeout与可取消回退

前置阶段2异步/浏览器、阶段3测试和阶段4–8 Vue/Nuxt/状态/边界；先观察真实瓶颈，再选择策略。

## 解决什么问题与机制

requestIdleCallback让非关键工作在空闲预算中分片；timeRemaining只是当前回调预算，didTimeout为true不代表获得无限空闲时间。timeout让任务最终有机会运行，却可能在忙碌时执行，仍要限制每批工作。支持不全面，setTimeout回退是普通任务，不应伪造真实空闲预算。不能把首次交互、必要内容或关键持久化完全依赖空闲调度；pagehide时取消或可靠保存另设计。

## 最小片段

```javascript
let cancelled = false;
const id = setTimeout(() => { if (!cancelled) console.log('bounded fallback work'); }, 0);
// timer是回退任务，不是真正idle预算
cancelled = true; clearTimeout(id);
```

片段上下文与完整可运行机制见操作卡，不把可选 API 当所有浏览器都支持。

## 实验与使用边界

labqueueIdle使用原生能力与cancelIdleCallback；forceFallback测可取消计时器，回退显式didTimeout:true/timeRemaining:0。取消后不执行；无论idle还是timeout都不做无限循环，本例仅写一条诊断状态。

浏览器后台节流/冻结会推迟工作；需要可靠提交的数据不能只排idle并希望卸载前执行。

## 移动开发对照

移动端也关注UI线程、生命周期和列表窗口；浏览器的task/微任务/DOM/Worker/GC与框架原生线程不同，不能把移动API名字套为同一机制。
