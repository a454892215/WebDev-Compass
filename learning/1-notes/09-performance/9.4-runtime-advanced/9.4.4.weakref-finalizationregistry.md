# 9.4.4 WeakRef与FinalizationRegistry：不依赖GC时机

前置阶段2异步/浏览器、阶段3测试和阶段4–8 Vue/Nuxt/状态/边界；先观察真实瓶颈，再选择策略。

## 解决什么问题与机制

WeakRef不强持有对象，但deref何时为undefined由GC决定；同一job内已取出的目标通常保持可用。FinalizationRegistry回调可能晚到或不执行，不能用于必须释放的Worker、DOM监听、连接、锁或计费资源。heldValue若反向强引用目标会破坏目的。优先明确dispose、缓存容量/TTL与作用域；WeakMap适合附着元数据，也不是可枚举自动清空业务store。

## 最小片段

```javascript
const target = {};
const weak = new WeakRef(target);
const current = weak.deref();
console.log(current !== undefined);
// target仍强可达；不能用等待时长推断其回收时机。
```

片段上下文与完整可运行机制见操作卡，不把可选 API 当所有浏览器都支持。

## 实验与使用边界

本点类型为官方机制阅读与安全最小片段：运行deref只能观察当时对象，lab的清理成功来自显式dispose与heap诊断，而非等待finalizer。没有编造固定延时后GC一定发生的测试。

本例不保证主动触发GC就符合所有引擎；测试控制GC只是定位工具，不是业务依赖。

## 移动开发对照

移动端也关注UI线程、生命周期和列表窗口；浏览器的task/微任务/DOM/Worker/GC与框架原生线程不同，不能把移动API名字套为同一机制。
