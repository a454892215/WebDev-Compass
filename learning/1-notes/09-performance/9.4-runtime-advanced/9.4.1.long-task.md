# 9.4.1 长任务与分片：让出主线程、取消和框架更新

前置阶段2异步/浏览器、阶段3测试和阶段4–8 Vue/Nuxt/状态/边界；先观察真实瓶颈，再选择策略。

## 解决什么问题与机制

Long Task按整个任务占用而非单个函数名判断，超过50ms的任务可能延迟输入与绘制。Vue nextTick等待DOM刷新，不等于浏览器已经绘制，也不保证耗时计算已经分片。采用时间预算分片、scheduler.yield能力检测和setTimeout回退；scheduler.postTask是按优先级安排新任务，不和yield连续任务语义完全等同。任务更新UI后还应让出，取消/离开用epoch或signal阻止旧工作写回。50ms是longtask定义阈值，不是所有操作应恰好跑50ms的产品目标。

## 最小片段

```javascript
const yieldMain = () => typeof globalThis.scheduler?.yield === 'function'
  ? globalThis.scheduler.yield()
  : new Promise(resolve => setTimeout(resolve, 0));
// 每个有界批次后await yieldMain()；完整epoch与取消见lab。
```

片段上下文与完整可运行机制见操作卡，不把可选 API 当所有浏览器都支持。

## 实验与使用边界

先点同步阻塞90ms，观察反馈文字赋值不能保证阻塞期间已呈现；再点分片工作，真实6×12ms合成工作在yield间分开。PerformanceObserver读取原始longtask，取消测试同一轮启动后立即取消，旧结果不回写。没有声称分片总时长更短。

React并发为选修对照，不把它称Vue调度器或Web Worker；优先明确取消和有界工作。

## 移动开发对照

移动端也关注UI线程、生命周期和列表窗口；浏览器的task/微任务/DOM/Worker/GC与框架原生线程不同，不能把移动API名字套为同一机制。
