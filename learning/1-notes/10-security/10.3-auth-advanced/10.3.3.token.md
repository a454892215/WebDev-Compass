# 10.3.3 令牌存储与BFF Cookie：读取、请求和生命周期是不同风险

前置：阶段0同源/HTTP、3类型与测试、5会话/授权、6安全基础、8请求/状态边界；先解释机制，再进入实验与独立变体。

## 解决什么问题与原理

HttpOnly限制页面JavaScript读取Cookie，不阻止浏览器携带它发请求，也不阻止XSS以用户身份调用API。Secure约束HTTPS传输，SameSite按站点而非端口源判断，Path不是权限边界。Cookie+BFF把access/refresh保留在服务端，仍需服务端身份/对象授权和适用CSRF防线。

localStorage/sessionStorage能被同源脚本读取；内存减少持久化残留却仍可被活动XSS利用。没有一种客户端存储自动解决整站安全。选择应依据威胁、刷新与跨标签/退出行为；不要把原生Keystore/Keychain等同浏览器Storage或承诺HttpOnly永不泄漏。

## 最小上下文片段

```javascript
// 上下文：server.mjs的createServer((req,res)=>...)处理器内部。
// lab仅HTTP loopback：没有Secure，上线必须HTTPS并调整cookie策略。
res.setHeader('Set-Cookie',
  'stage10-auth=<random>; HttpOnly; SameSite=Strict; Path=/; Max-Age=60');
// 本例不把token放入document.cookie、localStorage或URL。
```

片段中的helper来自[auth-lab完整源码](../../../2-examples/10-security/10.3-auth-advanced/auth-lab/README.md)，不是任意项目可直接粘贴的全套认证。

## 场景、观察与边界

运行verify，浏览器创建公开Alice fixture会话后，context.cookies可见httpOnly=true而document.cookie为空；随后fetch仍能读取合成资料200，撤销后同一旧Cookie401。Node实际核对恶意Origin403。localhost不同端口可同站，不用此实验冒充真实跨站SameSite全矩阵或HTTPS Secure验证。

内存/BFF/HttpOnly都是降低某一风险的措施，不是替代CSRF、CSP或授权。不要为了演示把真实bearer或个人资料写到测试结果。

## 移动开发对照

Web页面、SSR、Cookie请求与原生存储的生命周期不同；只借鉴规范/契约，不能将移动API或进程单例直接视为Web安全方案。
