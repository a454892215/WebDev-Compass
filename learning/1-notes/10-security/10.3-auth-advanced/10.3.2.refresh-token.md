# 10.3.2 Refresh轮换与复用检测：原子消费、族撤销和并发策略

前置：阶段0同源/HTTP、3类型与测试、5会话/授权、6安全基础、8请求/状态边界；先解释机制，再进入实验与独立变体。

## 解决什么问题与原理

刷新令牌通常比access token长寿，需要绑定客户端/会话、限制作用域与保留窗口。轮换令牌只能用一次；检测旧令牌再次出现时，严格策略撤销相关family，不能仅返回错误却让攻击者持有的新token继续有效。刷新令牌是高价值bearer，存储/日志不可随意暴露；本模型存哈希索引、过期时间和历史used状态。

并发刷新和网络超时会使合法请求看似复用。客户端single-flight降低竞争，服务端共享store仍需事务/CAS和明确定义的幂等/短宽限策略，不能靠前端锁保护所有实例。本lab采用严格策略：第二个并发请求触发family撤销，第一个已返回的新token也失效；这是一项教学取舍，不是所有系统唯一做法。

## 最小上下文片段

```javascript
const store = createRefreshStore();
const first = store.issue('alice');
const next = store.rotate(first.refreshToken);
// 再用 first.refreshToken 会撤销整个family；next随后也不能刷新。
```

片段中的helper来自[auth-lab完整源码](../../../2-examples/10-security/10.3-auth-advanced/auth-lab/README.md)，不是任意项目可直接粘贴的全套认证。

## 场景、观察与边界

第二组Node测试真实执行轮换、旧令牌复用、family撤销、两个Promise并发刷新与时钟过期；断言并发一个成功/一个拒绝后family已撤销。compare-and-consume在单Node同步函数内没有await，仅表示本进程原子顺序；不构成Redis/数据库跨进程事务或完整OAuth token endpoint。

历史used记录不能在有效family仍活动时随意删除，否则丢失复用检测。lab最多32族/每族16次、1小时过期清理，仅内存，不证明耐久、撤销传播或高可用。

## 移动开发对照

Web页面、SSR、Cookie请求与原生存储的生命周期不同；只借鉴规范/契约，不能将移动API或进程单例直接视为Web安全方案。
