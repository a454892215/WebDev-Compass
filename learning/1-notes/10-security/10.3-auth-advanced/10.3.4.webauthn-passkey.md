# 10.3.4 WebAuthn与Passkey：浏览器仪式和服务端验签职责

前置：阶段0同源/HTTP、3类型与测试、5会话/授权、6安全基础、8请求/状态边界；先解释机制，再进入实验与独立变体。

## 解决什么问题与原理

WebAuthn使用绑定Relying Party范围的公钥凭据。注册时服务端生成短期一次challenge并发送可信RP/user参数，浏览器/认证器在用户介入下创建凭据，服务端验证clientData、challenge、origin、RP ID hash、适用flags和attestation政策后存公钥；认证时再用新challenge验证assertion签名和用户验证要求。私钥不应由网页导出。

Passkey是围绕可发现公钥凭据的产品/生态概念，不等于任何页面调用get()就完成安全登录。同步凭据、设备绑定、备份状态、计数器行为和账户恢复需按实际认证器与策略处理，不能把signCount不增加一概称克隆。WebAuthn Level3在本轮已是W3C Recommendation，但支持仍按目标浏览器与认证器核对。

## 最小上下文片段

```javascript
// 官方流程观察：challenge必须来自服务端并与当前事务绑定。
// 不在此教材代码中调用用户真实凭据，也不把随机本地对象当验签结果。
const ceremony = { create: '注册并存公钥', get: '验证新challenge的assertion' };
console.log(ceremony.get);
```

片段中的helper来自[auth-lab完整源码](../../../2-examples/10-security/10.3-auth-advanced/auth-lab/README.md)，不是任意项目可直接粘贴的全套认证。

## 场景、观察与边界

类型：W3C/MDN官方流程与服务器契约观察，不调用navigator.credentials、不使用用户passkey，也未建立CDP virtual authenticator。按注册/认证列出挑战存储与一次性、origin/RP ID/flags/签名和恢复路径；真正集成应使用成熟服务端WebAuthn验证库及专用测试账号。

HTTPS/可信上下文、RP ID和origin不是任意可换的字符串；allowCredentials空列表与discoverable credential行为需官方流程核对。不要自己解析CBOR/签名代替维护中的库。

## 移动开发对照

Web页面、SSR、Cookie请求与原生存储的生命周期不同；只借鉴规范/契约，不能将移动API或进程单例直接视为Web安全方案。
