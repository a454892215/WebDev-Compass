# 15.6.3 OPFS：源私有草稿、配额和可恢复边界

前置：阶段2浏览器API/取消、阶段4Vue/Nuxt路由与生命周期、阶段6无障碍和阶段10安全。本组按业务选修，先讲机制再运行独立实验，不作为主线迁移前置。

## 原理、最小上下文与边界

Origin Private File System是浏览器按源隔离的私有存储端点，不是用户“下载”目录，也不是把任意本机路径交给网页。navigator.storage.getDirectory返回该源根句柄；通常无需文件选择授权，但需要安全上下文和浏览器能力。loopback作为可信本地上下文可供实验，生产使用HTTPS。

主线程可用异步getFileHandle、createWritable、write、close；文件关闭完成后再读取。同步访问句柄的同步I/O用于Dedicated Worker，createSyncAccessHandle本身仍返回Promise；不能为了快就在主线程调用。OPFS受配额、站点清理、私密模式与浏览器回收策略影响，浏览器本地草稿不能承诺永久存储。storage.estimate是估计值，persist请求也非一定批准；仍需导出/同步/恢复策略和可解释错误。

lab.opfsRoundTrip每次使用compass-fixture-加randomUUID的唯一文件，只写synthetic-local-draft，读取核对后finally删除这个文件。它不遍历删除用户源目录，不把测试清理写成清空整个OPFS。真实测试进一步确认合成前缀条目不存在。最小调用在lab上下文：
~~~js
const result = await opfsRoundTrip()
// 完整writer.close与仅本文件的finally清理见app.mjs
~~~

能力缺失时返回显式“内存草稿/导出”策略说明，不伪装相同持久保证；QuotaExceededError、权限/安全与I/O错误要区分，不能吞异常显示已保存。将OPFS用作离线数据层时还需Schema版本、并发写锁和损坏恢复，非本例一写一读就等于SQLite数据库方案。

和移动App私有目录相似的是不直接展示给文件管理器，但浏览器源/存储分区与站点清理生命周期不同，不能把Android私有文件的持久策略原封不动搬过来。用户敏感数据仍需要访问控制、最少保存和退出清理；源私有不是防同源恶意脚本的加密边界。

## 预测与验证

真实Chrome执行getDirectory→唯一文件createWritable/write/close→getFile/text→finally removeEntry；返回合成正文且测试确认没有残留compass-fixture文件。强制缺失路径返回supported:false，不假称已持久化。
