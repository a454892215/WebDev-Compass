# 15.6.2 Navigation API：拦截边界、历史与框架路由所有权

前置：阶段2浏览器API/取消、阶段4Vue/Nuxt路由与生命周期、阶段6无障碍和阶段10安全。本组按业务选修，先讲机制再运行独立实验，不作为主线迁移前置。

## 原理、最小上下文与边界

Navigation API用window.navigation集中表示导航与当前上下文内同源历史条目，navigate事件描述目标、类型、表单、下载和可拦截性。它不是给History.pushState换个名字；finished代表导航处理完成，不能看到URL变了就认为异步UI也已更新。

独立lab只在有API且未强制回退时注册一个navigate处理器。先判断canIntercept、同源、目标路径允许列表，并放过hash、下载与表单，再event.intercept。handler更新文字和document.title，使用focusReset:manual后自己把焦点落到标题；滚动仍由浏览器默认处理，本lab不实现自定义滚动位置数据库。别拦所有地址再把未知链接吞掉，服务端也必须能直接返回深链。

最小模式的上下文是原生lab，不应粘到Nuxt app全局插件中：
~~~js
navigation.addEventListener('navigate', event => {
  // 完整可拦截性/来源/路径/表单/下载筛选见app.mjs
  if (!event.canIntercept) return
})
~~~

没有能力时普通a href直接整页导航，服务器为/nav/one和/nav/two返回入口并按URL渲染。回退不需要手工伪造新的路由器。真实框架迁移时先确认Vue Router/Nuxt是否已经负责历史、取消、数据与滚动；同一导航应有一个owner，不同时注册两套拦截器。更复杂加载需用事件的取消信号避免迟到结果覆盖新页面。本阶段主实践app/app.vue实际使用NuxtLink、NuxtPage与NuxtRouteAnnouncer；本lab不向该宿主注册第二个导航处理器。

和Android返回栈相似的是有位置与返回操作，但浏览器还有地址栏、深链、跨源、下载、辅助技术、历史遍历和多标签页；不是Activity栈的等价物。官方当前标Baseline2026不意味着旧WebView都支持，应检测并测试目标浏览器。

## 预测与验证

真实navigate拦截跳到/nav/two，保持window内同文档marker、更新标题，再后退回视图一。测试等待页面标题状态，不把goBack调用返回当渲染已完成；强制回退使用普通链接整页加载仍可用。
