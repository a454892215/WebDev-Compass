# 15.6.1 View Transitions：内容先可用，动画渐进增强

前置：阶段2浏览器API/取消、阶段4Vue/Nuxt路由与生命周期、阶段6无障碍和阶段10安全。本组按业务选修，先讲机制再运行独立实验，不作为主线迁移前置。

## 原理、最小上下文与边界

视图转场在DOM更新前后捕获快照，再把两张状态图衔接；它不是路由器、数据加载器，也不自动管理业务状态或焦点。先保证普通链接/内容切换正确，再在确有连续性收益时增加动画；不为了浏览器新能力给每次交互加特效。

同文档document.startViewTransition(update)包住DOM更新，返回ready/updateCallbackDone/finished等不同阶段的Promise。一个view-transition-name在每一侧必须唯一，多个元素同名会导致转场跳过；DOM更新成功与动画成功要分开。lab只有标题一个route-title，不对所有卡片复制同名。正常等待finished后把焦点放在新标题tabindex=-1；动画跳过仍应保留内容与可达焦点，错误不应用来回滚正确数据。

lab.transitionView先检测API和prefers-reduced-motion。无支持、强制回退或减弱动画时直接update并聚焦；原生路径才调用startViewTransition。CSS也对减弱动画关闭快照动画。网络/数据加载不包含在快照动画里，不能用转场遮住永久等待；请求错误仍需明确可恢复状态。

下面最小调用在navigation-lab/app.mjs上下文，heading为页面现有h2：
~~~js
await transitionView(() => { heading.textContent = '局部详情' })
~~~

Android共享元素动画可帮助理解视觉连续性，但DOM快照、CSS命名、浏览器渲染和路由焦点是不同机制；不等于Flutter Hero自动移植。Nuxt已有路由器，若接入应使用其匹配版本能力和单一更新入口，不再叠一套通用navigate拦截。

## 预测与验证

点击“切换局部视图”，内容变为局部详情、标题获焦；本轮Chrome走真实native分支。?fallback=1和reduced-motion分别走直接更新，内容和焦点仍正确。
