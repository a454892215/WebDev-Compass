# 15.4.2 旧 MPA / jQuery 到 Vue 3：DOM所有权与兼容窗口

前置：阶段4Vue/Nuxt、阶段5接口、阶段7部署、阶段8边界与阶段10/12安全测试；先完成15.1决策与15.2评审，再按本组1→6推进。目标：能定义接缝、保持行为、复现变体并说明回退边界。

## 机制、选择与实际边界

先确认旧系统怎样工作：完整页面导航还是局部Ajax、全局事件如何绑定/清理、插件怎样改DOM、路由/表单由谁拥有。Vue可以在旧页挂一个有边界的小组件，也可按路由替换页面。主项目选择路由级并存，旧文档不加载Vue，避免旧脚本和Vue同时修改同一DOM子树。Vue组件接管后不要再让jQuery append/remove那些节点。

模板迁移不只是把HTML复制进SFC。表单默认提交、按钮类型、标签和焦点、错误/空/加载状态、URL查询、浏览器后退、SEO和SSR状态都需确认。主旧MPA使用GET表单完整导航；新Nuxt使用router.push更新q，useFetch读取响应并保留SSR数据。只有真实路径切换后才把焦点移到主标题，同路径搜索不抢输入焦点；NuxtRouteAnnouncer负责通知，不代替焦点管理。

本例旧页面是原生HTML/服务端字符串，不安装或运行jQuery。jQuery插件拆除属于官方观察与新增练习，不能把没有调用jQuery的迁移称真实jQuery版本升级。真实局部迁移先列插件事件、data缓存、定时器、外部监听的销毁方法，再卸载旧实例，框架unmount不会自动清理所有第三方全局副作用。

React是可选分支，思路可对照但本主线用Vue3/Nuxt。Android/Flutter的View/Widget拥有关系有助于理解边界，浏览器还额外有默认表单、历史记录和DOM外部可变性。主项目不共享两套渲染器的DOM，因此不能借本例证明任意旧插件与Vue混挂都安全。

## 最小项目与操作

对照旧GET表单与新catalog.vue：过滤、空结果、详情路径与错误退回。确认初始加载不抢焦点，路径切换后标题获焦，搜索更新不强移焦。 完整自足源码及运行环境见[迁移项目](../../../4-practice/15-project-delivery/README.md)，不需要创建第二套后台系统。
