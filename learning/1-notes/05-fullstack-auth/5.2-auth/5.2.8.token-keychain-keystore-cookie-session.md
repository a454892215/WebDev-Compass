# 5.2.8 浏览器凭证存储与移动安全存储的差异

前置：阶段0同源/HTTP、阶段2异步、阶段3TS与阶段4Nuxt。推荐先5.2.1/5.2.3再5.2.7/5.2.9；JWT/Bearer和OAuth/SSO按后台契约选读。

## 解决什么问题

用移动开发经验帮助分析威胁，同时避免把localStorage当作浏览器版Keychain/Keystore。

## 原理与选择

localStorage/sessionStorage面向同源脚本，主要区别包括生命周期与作用域，不提供“脚本无法读”的秘密容器；XSS可读取其中凭证。IndexedDB也不是凭证保险箱。内存降低持久化暴露，但恶意页面脚本仍可能调用应用能力，刷新恢复也需设计。

HttpOnly Cookie不给document.cookie读取，但浏览器会按规则自动发送，需处理CSRF和请求授权；Secure不是防XSS的开关。浏览器保存密码或WebAuthn凭证是另一类平台能力，不能与应用自存Bearer字符串混同。移动OS安全存储具备不同进程/硬件/访问控制边界，也不是能消除所有恶意代码和授权问题的保证。

本路线默认按后端会话契约选择，不能统一规定“token永远放localStorage”或“所有应用只能Cookie”。区分同源脚本、第三方嵌入、服务端渲染、网络传输、设备丢失和撤销需求，再决定最小暴露方案。桌面/手机Web都仍是浏览器安全模型，H5不因手机运行就自动获得原生Keychain。

## 最小机制片段

```typescript
// 浏览器控制台只用教学值做观察，不存真实凭据。
sessionStorage.setItem('storage-observation', 'public-demo')
console.log(sessionStorage.getItem('storage-observation')) // 脚本可读
sessionStorage.removeItem('storage-observation')
// HttpOnly session在服务器响应设置，不能用document.cookie创建HttpOnly。

```

片段按注释提供HTTP/页面或实验上下文；完整可运行文件与导入在[操作卡](../../../2-examples/05-fullstack-auth/5.2-auth/5.2.8.token-keychain-keystore-cookie-session-demo.md)，不能把协议示意当生产认证实现。

## 观察、场景与边界

浏览器观察脚本存储可读与服务端HttpOnly cookie不可通过document.cookie直接获取的区别；本轮移动比较不运行Android/iOS存储API，不声称硬件安全认证。

## 移动端对照

可迁移会话生命周期、权限最小化和失败恢复分析；浏览器的Cookie自动携带、脚本读取和SSR作用域须单独理解，不按Keychain/Keystore关键词类推。
