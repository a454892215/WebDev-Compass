# 5.3.5 HTTPS与安全响应头：按部署能力逐步收紧

前置：阶段2浏览器/HTTP、阶段3模块与测试；认证边界参见5.2。先理解协议，再运行本地实验，不需要生产凭据。

## 解决什么问题

TLS保护传输，响应头约束浏览器行为。它们有不同作用和部署条件，不能用某一个头代替输入校验、授权或全面XSS治理。

## 机制与选择

HTTPS需要有效证书、正确主机与链、HTTP到HTTPS策略及混合内容检查。已用HTTP发送的敏感数据不能靠随后重定向收回。HSTS只应在确定有效HTTPS覆盖后部署，预加载和includeSubDomains会影响所有相应域，不是本地教程随意开启的开关。

CSP需结合实际脚本/样式/接口来源设计，通常先Report-Only核对合法资源，再使用nonce/hash等适合架构的策略。frame-ancestors防嵌入策略必须通过响应头发送；X-Frame-Options只能表达DENY/SAMEORIGIN等有限策略，不能使用过时ALLOW-FROM表示跨源允许列表。nosniff和Referrer-Policy解决其他边界。

本lab的严格script-src 'self'只是无内联应用的对照，会阻止本地内联script；不能原样粘进Nuxt造成payload/接管脚本失效后宣称“更安全”。完整生产CSP、TLS和权限策略在阶段6/7/10深化。

## 最小例子

```http
// 本地/csp响应头示意，真实代码在server.mjs：
Content-Security-Policy: default-src 'self'; script-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
// 本轮HTTP对照不设置HSTS，不声称验证证书或公网TLS。
```

这是有明确上下文的机制片段，完整导入/服务器/页面代码见操作卡，不作为孤立可运行文件。

## 实际观察与边界

进入4404/csp：同源外部allowed.js设置externalRan，内联inlineRan被阻止；自动检查真实CSP响应头。HTTPS证书、混合内容、HSTS按部署观察清单另核对，本轮未做公网验证。

## 移动端对照

与移动网络层一样要分析超时、身份和失败恢复；浏览器额外受源/站点、CORS及受限请求API影响，不把Cookie或页面连接当系统安全存储/推送。
