# 5.1.3 FormData上传、XHR进度与Blob下载生命周期

## 前置与目标

阶段2异步/HTTP、阶段3TS/模块、阶段4Vue/Nuxt。能正确提交multipart并解释进度含义，下载后管理对象URL。

## 机制与场景

FormData保存字符串或Blob/File字段；以它作为请求体时让浏览器生成Content-Type和boundary。手填multipart/form-data但漏boundary会让服务端无法正确拆分；客户端accept、文件扩展名和MIME只改善选择体验，不能代替服务端限额、格式及权限校验。

普通浏览器fetch没有可移植的传统上传progress回调；本例需要明确传输进度，因此用XMLHttpRequest.upload的progress，并检查lengthComputable。loaded/total反映传输，不等于服务器校验/存储完成；必须等待最终HTTP响应。上传事件监听在跨域环境还可能影响预检，不能由同源实验推断全部CORS情况。

下载先检查HTTP状态，再读Blob；URL.createObjectURL用于本地引用，不是公网地址或持久化存储。替换资源或离开页面时revokeObjectURL；不要在浏览器消费前立即撤销导致下载失效。服务端Content-Disposition/文件名应符合协议，客户端可提供安全下载名；跨域可读头仍受暴露规则约束。

## 最小例子

```javascript
const body = new FormData()
body.set('file', new File(['hello'], 'note.txt', { type: 'text/plain' }))
await fetch('/api/upload', { method: 'POST', body })
// 不手写Content-Type；browser.mjs的XHR版本额外观察upload.progress。
```

片段用于说明机制，完整上下文与运行条件见操作卡；不要把注释中的占位URL/变量当可直接粘贴的完整工程。

## 运行与观察

浏览器上传5字节note.txt，观察传输进度100及最终201；换1025字节文件得到413。准备下载后真实blob:链接触发sample.txt下载，pagehide释放对象URL。

## 移动经验对照与边界

可复用移动端的分层、状态所有者和失败恢复方法；浏览器凭据/CORS/对象URL及Nuxt服务端上下文必须按Web机制验证，不等同于移动网络库或安全存储。
