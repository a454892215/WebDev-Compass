# 5.1.7 安全重试与幂等：限额、退避和重复写入边界

## 前置与目标

阶段2异步/HTTP、阶段3TS/模块、阶段4Vue/Nuxt。能设计有上限的读取重试，并解释取消/超时后写操作为什么不能随意重发。

## 机制与场景

幂等描述同一请求重复执行的预期效果，不是每次返回完全相同，也不等于服务端实际实现一定正确。GET/HEAD按HTTP语义应安全读取；PUT/DELETE有幂等语义但本实验为了保守只自动重试GET/HEAD。POST不能仅因超时就认定未执行，取消也不能证明回滚。

只重试协议允许的暂时失败，明确次数、总时间预算、退避和取消。Retry-After可以是秒数或HTTP日期；本例若服务端要求超过本地等待预算，就返回给调用方稍后处理，不把长等待强行缩短造成更早重试。生产需要按负载加入抖动和全局预算，本例固定最多3次便于可重复观察，不声称完整重试框架。

写入幂等键要由服务端识别与存储，并绑定主体、路由、请求指纹、期限和事务。客户端随便加Idempotency-Key头不会自动安全。独立lab只展示无用户的内存key+body指纹：相同重放返回同一结果，不同body同key为409；进程重启失效、没有数据库原子性，不可直接移植为支付方案。

## 最小例子

```javascript
const response = await safeRead('/api/retry', { attempts: 3, signal })
// 只允许GET/HEAD；429/503最多3次，Retry-After超预算停止。
// POST /api/create仅演示明确定义的服务端幂等契约，不能交给该读取重试器。
```

片段用于说明机制，完整上下文与运行条件见操作卡；不要把注释中的占位URL/变量当可直接粘贴的完整工程。

## 运行与观察

429+Retry-After:0的真实HTTP在第二次成功；503+120秒只请求一次；403不重试；自动POST被策略拒绝。相同key/body创建返回同id，不同body同key409。

## 移动经验对照与边界

可复用移动端的分层、状态所有者和失败恢复方法；浏览器凭据/CORS/对象URL及Nuxt服务端上下文必须按Web机制验证，不等同于移动网络库或安全存储。
