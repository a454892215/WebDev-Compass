# 5.1.4 阅读OpenAPI：方法、参数、响应与版本兼容

## 前置与目标

阶段2异步/HTTP、阶段3TS/模块、阶段4Vue/Nuxt。能从接口文档找到可执行契约，并把文档与真实响应核对。

## 机制与场景

OpenAPI描述HTTP API的路径、方法、参数位置、请求体、响应与安全方案；Swagger是围绕规范的工具生态，不是所有API的一种固定响应包壳。先确认使用的规范版本和环境，再检查required、可空、范围、枚举、分页和每个状态响应。示例JSON不是约束全集。

本地规范明确固定为OpenAPI3.1.1，不声称该版本是当前最新。路径/api/v1是本实验的版本约定，URL版本、媒体类型版本或兼容演进各有取舍；新增可选字段通常不等于所有客户端都兼容，严格校验器、枚举新增及语义变化仍需契约回归。移除字段或改变含义不能只改文档版本号而不迁移。

生成客户端主要改善静态调用体验，运行时后端仍可能偏离文档。代码生成不完成认证/错误处理或unknown响应校验。契约检查既要检查文档结构，也要请求真实fixture比较范围和返回形状；本例只校验自己用到的几个不变量，不冒充完整OpenAPI验证器。

## 最小例子

```javascript
// openapi.json中的局部约束
{ "name": "size", "in": "query",
  "schema": { "type": "integer", "minimum": 1, "maximum": 3 } }
// 实际请求size=99应400；不能只看页面里写了maximum。
```

片段用于说明机制，完整上下文与运行条件见操作卡；不要把注释中的占位URL/变量当可直接粘贴的完整工程。

## 运行与观察

打开本地/openapi.json，找listItems与multipart上传；测试同时检查size.maximum=3并实际发送size=99得到400。观察201/400/413/415对应不同协议分支。

## 移动经验对照与边界

可复用移动端的分层、状态所有者和失败恢复方法；浏览器凭据/CORS/对象URL及Nuxt服务端上下文必须按Web机制验证，不等同于移动网络库或安全存储。
