# 5.1.6 环境配置与baseURL：公开值、凭据目标和SSR边界

## 前置与目标

阶段2异步/HTTP、阶段3TS/模块、阶段4Vue/Nuxt。能区分构建/运行配置并防止请求或凭据被任意URL带走。

## 机制与场景

dev/staging/production是部署环境约定，不是三个必须复制维护的代码项目。Vite的公开env通常在构建时替换；Nuxt runtimeConfig区分服务端私有与public，Node运行覆盖和静态产物行为不同。环境变量不是自动加密，任何进入浏览器包/payload的值都要当公开。

同源相对路径可让浏览器访问应用BFF，由服务器控制上游地址。确需跨源baseURL时，使用明确origin allowlist、协议和路径规则，禁止URL用户名密码以及用户输入覆盖任意origin；SSR转发Cookie/Authorization更不能跟着不可信目标走。开源演示中的localhost绝不能直接部署成生产地址。

不能把跨环境失败都归咎CORS：先检查请求发到哪里、DNS/TLS、状态、响应体和服务端日志。开发代理只改变本地访问路径，不会给生产自动生成代理或授权。配置读入后也要验证格式和预期，而不只用as string压过类型。

## 最小例子

```javascript
const target = apiURL(configuredOrigin, '/api/v1/items', allowedOrigins)
// apiURL使用URL解析，拒绝非允许origin、userinfo和逃逸绝对路径。
// 配置值可公开；真实服务端凭据从不放public字段。
```

## 运行与观察

测试允许本地origin，拒绝未允许baseURL和把path改成https://other.invalid/steal。没有向这些.invalid目标实际发请求。Nuxt公私运行期边界在主工程另验。

## 移动经验对照与边界

可复用移动端的分层、状态所有者和失败恢复方法；浏览器凭据/CORS/对象URL及Nuxt服务端上下文必须按Web机制验证，不等同于移动网络库或安全存储。
