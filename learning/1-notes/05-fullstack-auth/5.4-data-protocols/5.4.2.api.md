# 5.4.2 分页、排序与筛选：稳定身份和参数边界

## 前置与目标

阶段2异步/HTTP、阶段3TS/模块、阶段4Vue/Nuxt。能定义有界分页参数并解释稳定排序、空页与数据变化的影响。

## 机制与场景

分页先约定页码从0还是1开始、size上限、排序字段/方向、筛选编码和返回total或nextCursor。重复query参数、负数、小数、超限size都要决定拒绝还是规范化；不要让客户端任意指定数据库列或无限size。URLSearchParams负责编码，不手工拼未转义的用户输入。

相同标题/时间会造成排序并列，需要稳定唯一tie-breaker，例如title再id。本例固定fixture的offset分页可比较不重不漏；真实数据并发插入/删除时即使稳定排序仍可能跨页漂移，cursor及一致性策略需按后端协议设计，不能用本例证明生产动态列表无重复。

筛选或排序改变通常应重置页码；空结果与越界空页的反馈应清楚，不能自动把任意错误当第一页。前端key使用业务id，与分页index不同。total与items长度来自不同语义，不把本页2项当全部2项。

## 最小例子

```javascript
const params = new URLSearchParams({ q: query, page: '1', size: '2' })
const page = decodePage(await readJSON(`/api/v1/items?${params}`))
// 服务器按title再id排序，size仅允许1..3。
```

片段用于说明机制，完整上下文与运行条件见操作卡；不要把注释中的占位URL/变量当可直接粘贴的完整工程。

## 运行与观察

测试跨两页合并得到5个不同id；两个同名Vue按a/c排序。size99和重复q被400拒绝，page99得到成功空items，total仍说明匹配总量。

## 移动经验对照与边界

可复用移动端的分层、状态所有者和失败恢复方法；浏览器凭据/CORS/对象URL及Nuxt服务端上下文必须按Web机制验证，不等同于移动网络库或安全存储。
