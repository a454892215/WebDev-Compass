# 5.4.1 JSON契约、unknown解码与DTO映射

## 前置与目标

阶段2异步/HTTP、阶段3TS/模块、阶段4Vue/Nuxt。能把外部unknown解析成明确的内部模型，而不把TS类型当运行校验。

## 机制与场景

JSON只规定数据表示，不规定业务字段一定存在、正确或可信。response.json()返回的结构仍应按unknown处理；as Model只是向检查器作声明，不会检查服务器返回值。还要区分缺失、null、空字符串、0和false，不能用一串truthy判断误删合法值。

运行解码逐字段检查类型、范围、身份唯一等必要不变量，再返回新的内部对象。DTO到UI模型的映射可以重命名、选择公开字段和处理可选值，但不是任意丢掉错误字段后继续伪装成功。错误应保留适当诊断，向用户呈现不含服务器秘密的反馈。

小契约可手写guard/decoder，复杂协议可用成熟schema库并固定版本。类型生成、OpenAPI和运行校验要协同维护；校验的严格度需与可扩展性约定一致，不能无意拒绝所有未来可选字段，也不能忽略必要字段改变。

## 最小例子

```javascript
const value = await readJSON(url) // 外部输入仍需解码
const page = decodePage(value)
// 解码返回{id,title}新记录，拒绝错误id/重复id/无items/负total。
```

片段用于说明机制，完整上下文与运行条件见操作卡；不要把注释中的占位URL/变量当可直接粘贴的完整工程。

## 运行与观察

测试用id:42触发schema错误，合法列表得到只含公开id/title的记录；http404、解析失败不混在同一解码错误里。

## 移动经验对照与边界

可复用移动端的分层、状态所有者和失败恢复方法；浏览器凭据/CORS/对象URL及Nuxt服务端上下文必须按Web机制验证，不等同于移动网络库或安全存储。
