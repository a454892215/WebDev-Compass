# 5.4.5 GraphQL与REST：请求、局部错误和选型边界（选修）

## 前置与目标

阶段2异步/HTTP、阶段3TS/模块、阶段4Vue/Nuxt。能读懂一个查询与data/errors结果，知道HTTP成功不等于每个字段成功。

## 机制与场景

GraphQL用schema描述类型与操作，查询选择字段，variables传参数；REST围绕资源和HTTP语义组织，两者都需要输入验证、授权、缓存和可观测性。GraphQL不自动解决N+1、越权、请求成本或版本演进，选择它应基于客户端聚合与组织需求。

一次执行可能同时返回data和errors，字段可因为失败为null；HTTP请求错误与执行错误的状态处理取决于协议/媒体类型，不能简单规定所有GraphQL结果HTTP200。客户端要决定局部展示、错误反馈和重试，不能只检查response.ok然后无条件读取深层字段。

本点是本地query/JSON样本与官方操作清单，没有安装GraphQL执行器或访问真实服务。可以观察请求形状和局部错误，但不称schema验证、解析器执行、权限或生产性能通过。Vue/Nuxt主线不要求改用GraphQL。

## 最小例子

```graphql
query Resource($id: ID!) {
  resource(id: $id) { id title }
}
# 请求JSON还需variables: { id: 'vue' }；本文件是协议样本，不是已部署服务。
```

片段用于说明机制，完整上下文与运行条件见操作卡；不要把注释中的占位URL/变量当可直接粘贴的完整工程。

## 运行与观察

打开protocol-observations/query.graphql与response.json，指出resource为null以及errors.path的位置，按README追踪HTTP与字段错误两层，不把本地样本叫真实接口。

## 移动经验对照与边界

可复用移动端的分层、状态所有者和失败恢复方法；浏览器凭据/CORS/对象URL及Nuxt服务端上下文必须按Web机制验证，不等同于移动网络库或安全存储。
