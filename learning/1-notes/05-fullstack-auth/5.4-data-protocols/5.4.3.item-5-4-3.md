# 5.4.3 上传接口契约：字段、限额、格式与结果

## 前置与目标

阶段2异步/HTTP、阶段3TS/模块、阶段4Vue/Nuxt。能区分浏览器选文件、传输完成和服务端接受，并写出明确上传协议。

## 机制与场景

接口需说明方法、字段名、单/多文件、总请求限额、单文件限额、允许格式、额外字段、认证/CSRF、成功状态与返回记录。客户端accept与MIME都可伪造；服务器要在合适层限流/限额、识别格式和分配安全存储名，不能直接拼用户文件名写目录。

本例只接收1个file，multipart总量4096字节、单文件1024字节，要求text/plain及.txt，进一步拒绝NUL与非法UTF-8。不存盘、不执行、不声称完整内容安全扫描；PDF/图片/压缩包需要专用解析与安全策略，不能把简单文件头或扩展名当可靠安全认证。

返回201只表示本实验完成校验，stored:false明确没有存储。生产异步扫描/对象存储可能先202并提供状态查询；进度100%并不表示业务可用。失败413/415/400分别为限额/格式/请求体错误，认证与权限仍要在服务端前置执行。

## 最小例子

```javascript
// 实验协议：POST /api/upload，multipart字段file恰好一个。
// 201 { name: 'note.txt', bytes: 5, stored: false }
// 400 malformed/boundary；413 size；415 format。
```

片段用于说明机制，完整上下文与运行条件见操作卡；不要把注释中的占位URL/变量当可直接粘贴的完整工程。

## 运行与观察

真实HTTP上传hello/note.txt返回201；1025字节413；声明text/plain但含NUL的伪装文件415；漏boundary400，浏览器行为也复验合法/超限路径。

## 移动经验对照与边界

可复用移动端的分层、状态所有者和失败恢复方法；浏览器凭据/CORS/对象URL及Nuxt服务端上下文必须按Web机制验证，不等同于移动网络库或安全存储。
