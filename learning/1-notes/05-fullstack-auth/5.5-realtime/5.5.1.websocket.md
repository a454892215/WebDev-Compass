# 5.5.1 原生WebSocket：连接状态、消息、心跳与重连

前置：阶段2浏览器/HTTP、阶段3模块与测试；认证边界参见5.2。先理解协议，再运行本地实验，不需要生产凭据。

## 解决什么问题

WebSocket用于持续双向消息，不会自动替应用完成重连、授权过期处理、消息补偿或移动系统后台推送。

## 机制与选择

浏览器WebSocket有CONNECTING/OPEN/CLOSING/CLOSED，发送前检查readyState；大流量还需关注bufferedAmount与协议层限额，浏览器API没有自动提供业务背压策略。message按约定解码，不能相信任意帧都是合法JSON或已授权业务事件。

浏览器构造器不能像Fetch那样任意设置Authorization头；URL票据、Cookie或连接后认证各有威胁边界，票据不得泄露到普通日志。跨源WebSocket不是普通Fetch的CORS预检流程，服务端应校验Origin并单独认证/逐消息授权；Origin不是非浏览器客户端的身份凭证。

浏览器没有Node ws库的ping()方法；本例用应用字符串ping/pong只验证一次往返，不冒称完整定时心跳。断线重连采用有限指数退避，真实项目还应加入抖动、总预算、可见性/离线判断和消息恢复协议。离开页面需清理连接和定时器。

## 最小例子

```javascript
// 完整可重连封装在client.mjs，以下是其核心调用。
const socket = new WebSocket('ws://127.0.0.1:4405/ws')
socket.addEventListener('open', () => socket.send('ping'))
socket.addEventListener('message', event => console.log(event.data))
// cleanup时socket.close(1000,'leave')；生产HTTPS页面使用wss。
```

这是有明确上下文的机制片段，完整导入/服务器/页面代码见操作卡，不作为孤立可运行文件。

## 实际观察与边界

openSocket真实收到pong，主动发送drop触发1012关闭，有限重连后发送again得到echo:again；stop后服务端活动连接归零，未残留重连。计时器是本地教学短间隔，不是生产调优建议。

## 移动端对照

与移动网络层一样要分析超时、身份和失败恢复；浏览器额外受源/站点、CORS及受限请求API影响，不把Cookie或页面连接当系统安全存储/推送。
