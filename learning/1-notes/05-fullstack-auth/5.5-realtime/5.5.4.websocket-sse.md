# 5.5.4 移动经验迁移：连接、生命周期与系统推送不同

前置：阶段2浏览器/HTTP、阶段3模块与测试；认证边界参见5.2。先理解协议，再运行本地实验，不需要生产凭据。

## 解决什么问题

移动端长连接经验可以帮助分析重连和消息状态，但浏览器页面并不是后台服务，更不是操作系统通知通道。

## 机制与选择

WebSocket双向消息、SSE单向事件和移动系统推送属于不同层。浏览器页面可能被后台节流、冻结或丢弃，电脑休眠/网络切换也会断开；不能假定setInterval在后台持续准时运行。服务端要容忍连接失效，恢复时重新核对会话与数据。

pagehide可用于释放页面所有的连接，BFCache恢复后应按需要重新初始化；组件卸载与退出登录也有各自清理点。多个组件或标签页可能意外创建重复连接，需要明确所有者。跨标签共享、Service Worker或通知权限又是独立设计，不在本节虚构已完成。

原生移动客户端可配置的请求头、安全存储和后台执行能力与浏览器不同。浏览器WS/EventSource的认证入口要按实际API约束选择，不能照搬移动Token拦截器或把Cookie等同Keystore。

## 最小例子

```javascript
// client.mjs实际执行：记录当前页面拥有的控制器。
window.addEventListener('pagehide', () => {
  for (const controller of [...controllers]) controller.stop()
})
// controllers在同模块创建，stop关闭WS/SSE并清除重连定时器。
// 重新进入/从BFCache恢复后由用户显式点击启动，不假称系统后台推送。
```

这是有明确上下文的机制片段，完整导入/服务器/页面代码见操作卡，不作为孤立可运行文件。

## 实际观察与边界

本lab停止按钮关闭连接，WS/SSE服务端active归零；连接控制器同时注册pagehide清理。浏览器模拟视口只证明当前前台页面行为，未做手机后台保活或OS通知测试。

## 移动端对照

与移动网络层一样要分析超时、身份和失败恢复；浏览器额外受源/站点、CORS及受限请求API影响，不把Cookie或页面连接当系统安全存储/推送。
