# 4.1.4 客户端路由、服务端路由与直接访问

前置：阶段1原生DOM/事件、阶段2模块/异步与阶段3TS。这里先建立框架概念；完整SFC语法在4.3.3.1先读。

## 解决什么问题

客户端切换URL和服务端收到一个URL，是两个相关但不同的流程。刷新、分享、前进后退都属于页面能力，不能只测试点击菜单。

## 机制与边界

SPA路由通常监听/使用History并切换组件；服务端直接访问必须有匹配页面或合适回退。Nuxt的页面文件同时参与服务端渲染与客户端路由，Nitro的server/api又是HTTP接口，不等于页面路由。查询参数适合可分享筛选；临时交互不必全塞URL。客户端导航守卫改善流程，不能替代API授权。

## 最小例子

```typescript
// Nuxt约定示意，不是一个可独立运行的JS模块：
// app/pages/resources/[id].vue -> 页面 /resources/vue
// server/api/resources/[id].get.ts -> GET /api/resources/vue
// 页面模板使用 <NuxtLink to="/resources/vue">详情</NuxtLink>。
```

片段的上下文按注释说明，完整可运行工程见操作卡。

## 实际观察与使用场景

直接请求/resources/vue能得到含标题的HTML，再用NuxtLink进入详情。筛选q保留在URL，刷新仍筛选；不存在详情HTTP404由服务端响应，不只是画一个404标题。

## 移动端对照

可迁移的是状态所有权、契约和失败恢复的分析方法；浏览器DOM、URL和SSR执行环境必须按Web机制验证。4.1.7集中比较差异，不能把类比当底层等价。
