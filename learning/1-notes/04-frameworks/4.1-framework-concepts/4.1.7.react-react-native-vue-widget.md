# 4.1.7 从移动开发迁移：组件相似，平台机制不同

前置：阶段1原生DOM/事件、阶段2模块/异步与阶段3TS。这里先建立框架概念；完整SFC语法在4.3.3.1先读。

## 解决什么问题

多年移动经验可以迁移状态所有权、组件契约和异步边界，但不能按“Widget等于DOM”推断运行行为。

## 机制与边界

Vue/React Web最终操作浏览器DOM与CSS布局，React Native使用原生宿主组件，Flutter有自己的渲染/Widget体系。组件组合是共通方法，渲染、输入、样式、生命周期和导航不是同一实现。Web URL、History、刷新、可分享链接、浏览器存储和SSR需要单独理解；Nuxt同一源码可能在服务端与浏览器执行，顶层window/localStorage并不安全。

## 最小例子

```typescript
// 跨平台比较片段：只演示Web侧安全执行位置。
// 在Vue组件setup中注册；onMounted不在SSR执行。
import { onMounted, ref } from 'vue'
const width = ref<number | null>(null)
onMounted(() => { width.value = window.innerWidth })
// 首屏渲染使用稳定的null分支，不能服务端/客户端分别随机初始化。
```

片段的上下文按注释说明，完整可运行工程见操作卡。

## 实际观察与使用场景

对照资料库的SSR原始HTML、浏览器导航和CSR对照页；观察useState在一次应用内共享但新SSR请求独立。这里没有运行Dart或React Native工程，不冒称跨平台测试。

## 移动端对照

可迁移的是状态所有权、契约和失败恢复的分析方法；浏览器DOM、URL和SSR执行环境必须按Web机制验证。4.1.7集中比较差异，不能把类比当底层等价。
