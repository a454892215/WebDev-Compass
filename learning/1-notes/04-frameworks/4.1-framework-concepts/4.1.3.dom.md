# 4.1.3 虚拟DOM、响应式追踪与更新调度

前置：阶段1原生DOM/事件、阶段2模块/异步与阶段3TS。这里先建立框架概念；完整SFC语法在4.3.3.1先读。

## 解决什么问题

虚拟DOM是界面描述，响应式追踪的是读取与依赖关系，两者解决不同问题。了解机制用于排错，不要求先实现框架。

## 机制与边界

Vue把模板编译成渲染函数，执行渲染时读取响应式值并形成依赖；变化触发调度，更新阶段比较/应用必要DOM变更。虚拟DOM不是浏览器DOM的完整副本，也不保证每次都比手写DOM快。computed缓存依赖计算结果，但不能为隐式副作用提供可靠执行时机。React函数重渲染与Vue依赖追踪机制不同，不能仅因都有组件就当作相同。

## 最小例子

```typescript
// Vue组合式API的自足逻辑片段；Node或Vite包需已安装vue。
import { ref, computed, nextTick } from 'vue'
const source = ref(2)
const doubled = computed(() => source.value * 2)
source.value = 3
console.log(doubled.value) // 6
await nextTick() // 组件DOM读取应在更新提交后；此独立片段没有挂载DOM。
```

片段的上下文按注释说明，完整可运行工程见操作卡。

## 实际观察与使用场景

对照useReadingList与模板：ids变化，数量和按钮消费同一事实；E2E用可重试断言等待界面。Vue组实验进一步演示computed缓存、nextTick和解构失响应。

## 移动端对照

可迁移的是状态所有权、契约和失败恢复的分析方法；浏览器DOM、URL和SSR执行环境必须按Web机制验证。4.1.7集中比较差异，不能把类比当底层等价。
