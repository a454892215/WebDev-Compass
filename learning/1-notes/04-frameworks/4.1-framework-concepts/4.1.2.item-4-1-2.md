# 4.1.2 组件组合、复用与单向数据流

前置：阶段1原生DOM/事件、阶段2模块/异步与阶段3TS。这里先建立框架概念；完整SFC语法在4.3.3.1先读。

## 解决什么问题

组件不是按页面截图机械切成小块，而是封装一个可说明的输入、输出与职责。优先稳定契约，再考虑复用。

## 机制与边界

父组件传Props表达当前状态，子组件发事件请求改变，状态所有者处理更新。事件不是“父级必须照办”的命令，子组件也不应改只读Props。默认/具名插槽允许父级提供内容而保留容器结构；插槽内容的词法作用域属于提供它的父组件。组件可有局部草稿，但必须说明何时丢弃以及与后端事实的关系。

## 最小例子

```typescript
// 以下为ResourceCard.vue的script setup契约片段；完整SFC含import和template。
defineProps<{ selected: boolean }>()
const emit = defineEmits<{ toggle: [id: string] }>()
// 点击时 emit('toggle', resource.id)；父级接收后修改自己的书单。
```

片段的上下文按注释说明，完整可运行工程见操作卡。

## 实际观察与使用场景

运行组件测试：点击发出toggle但selected仍为false；父级setProps(true)后才变aria-pressed。页面用具名title插槽插入NuxtLink，卡片本身保持内容容器。

## 移动端对照

可迁移的是状态所有权、契约和失败恢复的分析方法；浏览器DOM、URL和SSR执行环境必须按Web机制验证。4.1.7集中比较差异，不能把类比当底层等价。
