# 4.1.1 声明式UI与命令式DOM操作

前置：阶段1原生DOM/事件、阶段2模块/异步与阶段3TS。这里先建立框架概念；完整SFC语法在4.3.3.1先读。

## 解决什么问题

从阶段1手工查找元素和改textContent，转向描述“状态对应什么界面”。声明式框架负责根据状态安排更新，并不意味着DOM、事件循环或运行成本消失。

## 机制与边界

命令式写法明确指定查找和修改；声明式写法保留数据与界面的关系。两者都由JavaScript运行，选择应围绕局部功能、复杂度与可维护性，而非“框架永远更快”。Vue模板经过编译，运行时仍需调度和提交DOM更新；重复直接操作框架管理的子树会破坏一致性。浏览器原生focus、selection等通常仍需模板引用和生命周期。

## 最小例子

```typescript
// 命令式最小例：把此代码放在含<button id="add">与<output id="count">的页面模块中。
let count = 0
const output = document.querySelector('#count')
document.querySelector('#add')?.addEventListener('click', () => {
  count += 1
  if (output) output.textContent = String(count)
})
// Vue版完整SFC见4.3；核心关系是 ref(0) + @click="count++" + {{ count }}。
```

片段的上下文按注释说明，完整可运行工程见操作卡。

## 实际观察与使用场景

阅读任务板从useReadingList.ids派生数量。点击加入书单后看output变化；不要手工把output改为999作为状态更新。

## 移动端对照

可迁移的是状态所有权、契约和失败恢复的分析方法；浏览器DOM、URL和SSR执行环境必须按Web机制验证。4.1.7集中比较差异，不能把类比当底层等价。
