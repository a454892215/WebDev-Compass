# 4.5.7 Plugins、composables、modules与Layers：选择复用边界

## 前置与目标

先完成阶段3工程与TypeScript；4.4需CSS布局/层叠基础，4.5需Vue组件、组合式API与路由。能解释本点机制、运行对应实验并定位一种失败。4.4可按需要选读，完整SEO与生产部署分别留阶段6、7。

## 解决什么问题

复用框架能力时知道应该在构建期装配、应用启动注入，还是调用时执行逻辑，避免所有代码都塞进“common”。

## 原理与选择

composable是按约定组织的可复用函数，可在适当Nuxt/Vue上下文调用；插件在Nuxt应用创建时执行，可注入工具，.client/.server限定运行环境；Nuxt module在Nuxt开发/构建初始化期间扩展配置、模板或注册运行代码；Layer按Nuxt目录结构复用配置、组件和页面等。它们不能互相当同义词；模块可以注册插件，Layer也可以包含模块。

## 最小机制片段

```typescript
// app/plugins/format.ts的注入形态示意
export default defineNuxtPlugin(() => ({
  provide: { formatCategory: (value: string) => value.toUpperCase() },
}))
// 在setup上下文取工具，不在任意模块顶层调用Nuxt composable
const { $formatCategory } = useNuxtApp()
// 局部Layer通过layers/目录自动登记或extends显式选择，具体以配置为准。
```

片段只解释当前机制；不是可直接替代完整工程的文件。变量、依赖与运行上下文见[代码操作卡](../../../2-examples/04-frameworks/4.5-nuxt/4.5.7.plugins-modules-layers-demo.md)及其源码链接。

## 场景、边界与常见误区

Nuxt composable依赖当前实例时，应在setup、插件或框架支持上下文调用；异步封装要理解上下文恢复，不随意在任意回调调用。插件中创建的可变服务也可能有错误作用域，不能因文件在plugins就认定隔离。Layer的覆盖优先级和目录解析需要查当前版本并实际构建，不能当包发布/版本治理已完成。

## 移动端经验对照

复用移动端的分层、状态所有者和失败恢复经验；Nuxt还要分别考虑服务端请求、浏览器应用与hydration，不能按移动进程生命周期直接等同。
