# 4.5.8 Nuxt中间件、错误页、404与浏览器边界

## 前置与目标

先完成阶段3工程与TypeScript；4.4需CSS布局/层叠基础，4.5需Vue组件、组合式API与路由。能解释本点机制、运行对应实验并定位一种失败。4.4可按需要选读，完整SEO与生产部署分别留阶段6、7。

## 解决什么问题

让导航失败、未知资源和浏览器专属能力有明确反馈，同时避免把客户端检查误当安全保障。

## 原理与选择

Nuxt route middleware在Vue导航上下文运行，可以在SSR首个导航与客户端导航执行；server middleware在Nitro请求上下文运行，两者不相同。导航重定向要return navigateTo等结果并避免循环。找不到资源可通过createError等进入合适错误页；局部读取错误不必全部升级为全屏致命错误。错误页提供恢复路径，并注意恢复后的路由/状态。

## 最小机制片段

```typescript
// app/middleware/study.ts中的机制示意
export default defineNuxtRouteMiddleware((to) => {
  if (to.query.notice === "1") {
    return navigateTo("/about?from=study")
  }
})
// 浏览器特有代码：onMounted(() => { /* 此处才读取DOM */ })
// 资源不存在：throw createError({ statusCode: 404, statusMessage: "Not found" })
```

片段只解释当前机制；不是可直接替代完整工程的文件。变量、依赖与运行上下文见[代码操作卡](../../../2-examples/04-frameworks/4.5-nuxt/4.5.8.middleware-errors-client-boundaries-demo.md)及其源码链接。

## 场景、边界与常见误区

路由守卫不能阻止绕过页面直接请求API。import.meta.client/.client组件适用于实际边界，不能通过隐藏所有SSR内容掩盖数据/HTML不一致。错误消息需适合公开展示，不直接回显秘密、原始堆栈或不可信HTML；clearError恢复要配合正确重定向。

## 移动端经验对照

复用移动端的分层、状态所有者和失败恢复经验；Nuxt还要分别考虑服务端请求、浏览器应用与hydration，不能按移动进程生命周期直接等同。
