# 4.5.9 useHead/useSeoMeta：SSR首屏与导航后的页面标题

## 前置与目标

先完成阶段3工程与TypeScript；4.4需CSS布局/层叠基础，4.5需Vue组件、组合式API与路由。能解释本点机制、运行对应实验并定位一种失败。4.4可按需要选读，完整SEO与生产部署分别留阶段6、7。

## 解决什么问题

让不同路由在浏览器标签、历史和辅助技术中有准确身份；使描述能在初始HTML中被读取，而不依赖挂载后临时改document。

## 原理与选择

Nuxt借助Unhead管理head。useHead适合title、meta、html属性等，useSeoMeta提供较明确的SEO字段契约。数据依赖可以用getter/computed使标题在路由参数或内容变化后更新；页面卸载时框架管理注册项。标题和正文应表达同一资源，布局提供公共模板但不应盖掉所有详情标题。

## 最小机制片段

```typescript
// app/pages/resources/[id].vue的机制片段，假定resource是该页已校验的数据ref
useHead({ title: () => resource.value?.title ?? "资料详情" })
useSeoMeta({
  description: () => resource.value ? `阅读：${resource.value.title}` : "资料读取中",
})
// 完整上下文与实际ref命名以本点链接的页面源码为准。
```

片段只解释当前机制；不是可直接替代完整工程的文件。变量、依赖与运行上下文见[代码操作卡](../../../2-examples/04-frameworks/4.5-nuxt/4.5.9.head-page-metadata-demo.md)及其源码链接。

## 场景、边界与常见误区

不要把不可信输入注入script/innerHTML；head值也应来自允许公开的数据。标题存在不保证搜索排名、索引或完整SEO，canonical、结构化数据、robots和站点地图等按阶段6/真实域名深化。不因模板里有description就称所有爬虫已验证。

## 移动端经验对照

复用移动端的分层、状态所有者和失败恢复经验；Nuxt还要分别考虑服务端请求、浏览器应用与hydration，不能按移动进程生命周期直接等同。
