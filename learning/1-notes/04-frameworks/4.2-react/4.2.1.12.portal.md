# 4.2.1.12 Fragment、Portal与Suspense：三种不同边界

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

Fragment组合多个子节点但不创建额外DOM容器。Portal改变内容在DOM中的放置位置，React父子关系与事件传播仍按React树处理。

Portal不会自动使浮层可访问；模态行为需要焦点、Escape和背景交互管理，简单对话框先考虑原生dialog。本例Portal只放说明文本，不伪装完整模态框。

Suspense为支持挂起的子树提供等待回退；lazy的动态导入会触发，普通Effect里的fetch不会自动触发。代码加载失败还需要错误处理，Suspense不是通用try/catch。

## 最小例子

```tsx
const Note=lazy(()=>import("./LazyNote"))
// <Suspense fallback={<p>加载中</p>}><Note/></Suspense>
// createPortal(<p>说明</p>, target)
```

## 操作、场景与边界

PortalNote文本出现在独立aside而非原host；LazyExample真实动态导入成功后显示懒模块内容。等待回退的网络时序另由浏览器观察，不把jsdom计时当性能测试。

三个API解决不同问题，不能相互替代。

## 移动开发经验对照

已有React Native经验可帮助理解props、state和Hooks；浏览器DOM、表单、history、CSS及服务端执行环境仍需单独验证。Flutter的Widget更新/生命周期不能与本节API按名字一一等同。
