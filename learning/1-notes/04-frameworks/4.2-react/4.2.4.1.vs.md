# 4.2.4.1 展示组件与容器：按职责组合而非机械分层

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

展示组件以props/回调描述界面，容器组织状态、数据获取和业务动作；这是可选设计模式，不是每个组件必须配一个Container文件。

组件大小、复用与变化原因决定是否拆分。Hooks可以复用逻辑而不再依赖额外容器包装，但数据所有权与错误状态仍需明确。

切分应保留可访问名称、loading/empty/error等业务可见状态，不要把类型和技术层级名泄露给产品用户。

## 最小例子

```tsx
function CardView({title,onSelect}:{title:string;onSelect:()=>void}){
 return <button type="button" onClick={onSelect}>{title}</button>
}
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.4.1.vs-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

App.tsx的CardContainer拥有state，CardView发回调；真实DOM测试点击后容器文本更新。

层次服务变化边界，不为目录形式增加转发组件。

## 移动开发经验对照

已有React Native经验可帮助理解props、state和Hooks；浏览器DOM、表单、history、CSS及服务端执行环境仍需单独验证。Flutter的Widget更新/生命周期不能与本节API按名字一一等同。
