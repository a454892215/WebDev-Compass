# 4.2.1.10 自定义Hook：复用有状态逻辑而非共享实例

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

自定义Hook以use开头，通过其他Hooks封装状态逻辑；在组件或其他Hook顶层调用，不能按条件、循环或事件临时调用。

两处调用同一个Hook通常各有独立状态；复用的是逻辑，并不是自动得到进程单例。需要共享时再选择提升状态、Context或专门store。

Hook公开返回值、依赖和清理职责，隐藏实现但不掩盖副作用；不能把任何普通工具函数都冠以use然后违反调用规则。

## 最小例子

```tsx
function useToggle(initial=false){
 const [on,setOn]=useState(initial)
 return {on,toggle:()=>setOn(v=>!v)}
}
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.1.10.hook-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

TogglePair中A/B各调用useToggle；点A后A true而B false，验证状态独立。

React Hook的调用规则不能照抄Vue composable写法。

## 移动开发经验对照

已有React Native经验可帮助理解props、state和Hooks；浏览器DOM、表单、history、CSS及服务端执行环境仍需单独验证。Flutter的Widget更新/生命周期不能与本节API按名字一一等同。
