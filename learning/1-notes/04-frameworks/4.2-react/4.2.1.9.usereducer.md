# 4.2.1.9 useReducer：集中状态转换与纯函数

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

reducer接收当前状态与action，返回下一状态；集中描述多种关联转换，方便独立测试，不负责发请求或执行DOM操作。

dispatch安排更新；当前事件闭包仍持有旧state。action用判别联合明确载荷，避免任意字符串和巨型可选字段对象。

纯reducer不能直接修改输入。Redux Toolkit借助Immer允许草稿写法，而普通useReducer不自动拥有这种能力；两者不可按相似名称混用。

## 最小例子

```tsx
function reducer(tasks:readonly Task[],action:TaskAction):Task[]{
 return action.type==="add"?[...tasks,action.task]
 :tasks.map(t=>t.id===action.id?{...t,done:!t.done}:t)
}
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.1.9.usereducer-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

taskReducer测试切换后旧记录done仍false、新记录true；ReducerCounter真实挂载dispatch增加任务数。

复杂度来自转换关联，而不是状态数量达到某个固定值。
