# 4.2.1.1 JSX：表达式、转义与组件树

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

JSX是描述元素的语法扩展，构建器把它转换成React元素创建调用；不是HTML字符串，也不在运行时解释任意模板。组件名大写，原生标签小写。

花括号放JavaScript表达式；多节点可用Fragment组合。className对应class，事件处理传函数而非立即调用。动态列表需要同级稳定key。

React把普通字符串子节点作为文本处理；dangerouslySetInnerHTML是另一种显式HTML注入接口，未经可信处理的输入不能交给它。JSX转义也不等于URL、服务端授权等风险全被解决。

## 最小例子

```tsx
export function Greeting({name}:{name:string}) {
  return <p>你好，{name}</p>
}
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.1.1.jsx-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

Core.tsx的Greeting与编号测试把<b>输入</b>传为name，断言文本保留尖括号、DOM没有b节点。

JSX是编译语法；浏览器仍接收JS与DOM。

## 移动开发经验对照

已有React Native经验可帮助理解props、state和Hooks；浏览器DOM、表单、history、CSS及服务端执行环境仍需单独验证。Flutter的Widget更新/生命周期不能与本节API按名字一一等同。
