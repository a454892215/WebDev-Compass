# 4.2.1.7 useMemo、useCallback与memo：性能缓存的适用边界

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

useMemo缓存计算结果，useCallback缓存函数引用；memo可在props相同时跳过部分重渲染。这些是性能工具，业务正确性不能依赖缓存永远保留。

依赖缺失会留下旧结果/闭包；每次创建全新对象也可能让缓存失效。先用正确代码与测量找到开销，不给每个值机械加缓存。

React Compiler适用配置可减少手工缓存需求；本实验没有启用Compiler。开发StrictMode重复执行不能直接作为生产性能结论。

## 最小例子

```tsx
const items=useMemo(()=>tasks.filter(t=>t.includes(query)),[tasks,query])
const select=useCallback((id:string)=>setSelected(id),[])
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.1.7.usememo-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

MemoFilter测试修改query后列表由Vue更新为Nuxt，点击后选择正确；不把这个功能断言当性能提升基准。

缓存值不是状态持久化和授权边界。
