# 4.2.4.3 React样式：CSS Modules、CSS-in-JS与工具类

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

CSS Modules按构建规则生成类名映射，避免常见类名冲突，但不是Shadow DOM隔离；全局样式、继承和层叠仍然存在。

Styled Components以组件形式描述样式，具体运行/编译/SSR策略取决于版本；不能把所有CSS-in-JS都描述为同一种性能特征。Tailwind将可识别的工具类生成CSS，动态拼接完整类名需符合扫描规则。

本实验真实编译CSS Modules。Styled Components与Tailwind在React中仅作官方对照；Tailwind主线另由4.4实装，避免为横向比较重复装三套。

## 最小例子

```tsx
import styles from "./Card.module.css"
// <section className={styles.card}>...</section>
// Card.module.css: .card { padding:1rem; }
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.4.3.css-css-modules-styled-components-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

App.tsx实际消费Card.module.css，生产CSS包含转换后的card类；样式方案观察清单.md记录其他两方案的条件。

局部类名不等于完全隔离。
