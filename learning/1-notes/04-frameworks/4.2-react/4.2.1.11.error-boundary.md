# 4.2.1.11 错误边界：渲染失败的局部回退

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

错误边界用于隔离子树渲染等React处理阶段的失败，提供回退UI；可用class的getDerivedStateFromError/componentDidCatch或成熟封装。

它不自动捕获事件处理器、任意setTimeout/Promise回调和服务端渲染中的所有错误。请求失败应由请求状态/try-catch处理，不能一律throw给边界。

重试需要明确恢复机制，例如清除故障输入或重建边界；只把同一个仍会抛错的子树再渲染会再次失败。本例提供安全回退，不宣称完整生产错误平台。

## 最小例子

```tsx
class Boundary extends Component<{children:ReactNode},{failed:boolean}>{
 state={failed:false}
 static getDerivedStateFromError(){return {failed:true}}
 render(){return this.state.failed?<p role="alert">渲染失败</p>:this.props.children}
}
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.1.11.error-boundary-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

RenderBoundary包裹受控BrokenCard并真实显示alert；测试只为该预期故障屏蔽console.error，其他测试仍正常报告错误。

回退UI应可理解且保留离开/恢复路径。
