# 4.2.1.8 Context：跨层依赖与更新范围

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

createContext定义通道，Provider提供值，useContext读取上方最近匹配Provider；没有提供时使用创建时默认值。它避免逐层透传，不自动成为完整状态管理器。

Provider值变化会通知消费方；每次创建新对象可能造成额外更新。先分清共享范围和变化频率，必要时拆Context而不是把整个应用塞入一个对象。

Context用于主题、语言、明确范围的依赖等；认证用户对象只能影响UI，不能代替服务端验证。SSR中用户状态仍需按请求创建。

## 最小例子

```tsx
const Locale=createContext("zh")
function Label(){return <p>{useContext(Locale)}</p>}
// <Locale.Provider value="en"><Label/></Locale.Provider>
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.1.8.createcontext-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

LocaleProvider下的LocaleLabel输出en；默认值和覆盖范围可在独立副本继续实验。

Context是传递机制；state所有者仍要明确。
