# 4.2.2.4 lazy路由：按需代码、等待与失败

**React选修**。前置为阶段1 JavaScript/DOM与阶段3 TypeScript/模块/测试；不阻塞Vue 3 + Nuxt主线。目标：能解释本节机制，完成一个变体并定位指定故障。

## 解决什么问题与原理

React.lazy加载具有default组件导出的模块，Suspense提供等待UI；把lazy定义放组件外，避免每次渲染创建新组件身份。

代码分包解决资源加载时机，不自动优化所有网络、渲染或缓存问题。首次加载失败需要错误边界/恢复路径，不能一直显示加载中。

声明式lazy组件与数据路由的route.lazy不是同一接口；本例只用React.lazy与Suspense，不把数据模式文档直接套进来。

## 最小例子

```tsx
const Report=lazy(()=>import("./LazyNote"))
<Route path="report" element={<Suspense fallback={<p>加载中</p>}><Report/></Suspense>}/>
```

片段只解释本节机制；需要的import、类型和组件上下文以[真实实验与操作](../../../2-examples/04-frameworks/4.2-react/4.2.2.4.react.lazy-demo.md)为准，不能把上下文片段当独立可运行文件。

## 操作、场景与边界

真实MemoryRouter进入/report后显示懒模块；生产build生成独立LazyNote chunk。首次网络请求可在本地浏览器Network中观察，不保证它必然被某预加载策略延后。

加载和错误分别处理。
