# 4.4.2 设计令牌与组件规范：颜色、间距和行为契约

## 前置与目标

先完成阶段3工程与TypeScript；4.4需CSS布局/层叠基础，4.5需Vue组件、组合式API与路由。能解释本点机制、运行对应实验并定位一种失败。4.4可按需要选读，完整SEO与生产部署分别留阶段6、7。

## 解决什么问题

让不同页面的相同语义保持一致，并让桌面/手机端可以共享基础规范、分别定义合适的交互和密度。

## 原理与选择

原始值是具体色值或尺寸；语义令牌说明用途，如surface/ink/edge。组件令牌或规范再说明按钮的尺寸、状态和间距。令牌不仅是复制一套CSS变量：还要规定焦点、禁用、错误、加载和空状态。共享令牌不强制两端布局一致；同名语义应保持可解释的含义，平台密度可以不同。

## 最小机制片段

```css
:root {
  --surface: #ffffff; --ink: #172033;
  --edge: #64748b; --space-control: 0.75rem;
}
.control {
  padding: var(--space-control);
  border: 1px solid var(--edge);
}
/* 主题覆盖变量，控件不复制整套布局规则 */
```

片段只解释当前机制；不是可直接替代完整工程的文件。变量、依赖与运行上下文见[代码操作卡](../../../2-examples/04-frameworks/4.4-css-ui/4.4.2.item-4-4-2-demo.md)及其源码链接。

## 场景、边界与常见误区

设计系统还包括文档、行为与演进约束，不能仅有几种颜色就称完整设计系统。组件外观一致也不保证键盘、焦点和错误提示正确。令牌、产品布局与业务状态应各自有职责。

## 移动端经验对照

可类比Theme、颜色和尺寸资源；CSS变量通过层叠继承，作用域和原生控件行为与Widget主题不是同一种机制。
