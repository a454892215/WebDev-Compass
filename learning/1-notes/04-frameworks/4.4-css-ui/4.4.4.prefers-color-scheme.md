# 4.4.4 浅深主题：系统偏好、手动覆盖与SSR初始一致

## 前置与目标

先完成阶段3工程与TypeScript；4.4需CSS布局/层叠基础，4.5需Vue组件、组合式API与路由。能解释本点机制、运行对应实验并定位一种失败。4.4可按需要选读，完整SEO与生产部署分别留阶段6、7。

## 解决什么问题

页面及原生控件随用户环境保持可读；需要手动偏好时，避免不同来源的主题状态互相冲突。

## 原理与选择

模型分system/light/dark。默认meta与:root声明light dark，CSS媒体查询决定令牌；显式选择通过data-theme覆盖变量和color-scheme，回system时删除覆盖。本实验不持久化，不在SSR期间读取window/localStorage，因此初始HTML与客户端渲染不因浏览器存储而分叉。真实Nuxt持久化可用服务端可读cookie或经过设计的启动脚本，但要处理CSP、无脚本及闪烁边界。

## 最小机制片段

```css
:root { color-scheme: light dark; --surface: white; --ink: #172033; }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme=light]) { --surface: #111827; --ink: #e5e7eb; }
}
:root[data-theme=light] { color-scheme: light; --surface: white; --ink: #172033; }
:root[data-theme=dark] { color-scheme: dark; --surface: #111827; --ink: #e5e7eb; }
```

片段只解释当前机制；不是可直接替代完整工程的文件。变量、依赖与运行上下文见[代码操作卡](../../../2-examples/04-frameworks/4.4-css-ui/4.4.4.prefers-color-scheme-demo.md)及其源码链接。

## 场景、边界与常见误区

只改meta可能被作者CSS的color-scheme覆盖；手动覆盖应与CSS保持一致。深色不等于颜色反转滤镜，必须检查文本/边框/焦点与信息图标。不承诺单个meta完全消除所有闪白，也不把浏览器模拟主题称为系统全平台验证。

## 移动端经验对照

类似跟随系统和应用偏好，但SSR首屏还涉及服务器不知道浏览器本地存储这一边界；不能在模块顶层直接读localStorage。
