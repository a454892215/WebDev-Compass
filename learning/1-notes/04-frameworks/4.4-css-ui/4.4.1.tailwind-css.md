# 4.4.1 Tailwind CSS 4：真实工具类构建与响应式前缀

## 前置与目标

先完成阶段3工程与TypeScript；4.4需CSS布局/层叠基础，4.5需Vue组件、组合式API与路由。能解释本点机制、运行对应实验并定位一种失败。4.4可按需要选读，完整SEO与生产部署分别留阶段6、7。

## 解决什么问题

复用一组可组合的样式能力，减少重复声明，同时保留对实际CSS产物、断点和原生布局的理解。Tailwind是生成CSS的工具，不会自动决定产品UI或组件行为。

## 原理与选择

本实验固定Tailwind与官方CLI 4.3.5。v4入口使用CSS的@import、@theme和@source；不要把旧版tailwind.config.js/content配置直接当成当前必需骨架。CLI扫描源文件中的完整类名并生成需要的规则。md:不是“识别桌面设备”，而是从断点起覆盖样式；默认类适用于全部尺寸。运行时拼接text-${color}-600可能无法被扫描，应使用完整类名映射或明确的来源规则。

## 最小机制片段

```css
/* theme-lab/src/theme.css，完整上下文在本点实验 */
@import "tailwindcss";
@source "./index.html";
@theme { --color-brand: #1d4ed8; }
/* HTML: class="grid grid-cols-1 gap-4 md:grid-cols-2" */
```

片段只解释当前机制；不是可直接替代完整工程的文件。变量、依赖与运行上下文见[代码操作卡](../../../2-examples/04-frameworks/4.4-css-ui/4.4.1.tailwind-css-demo.md)及其源码链接。

## 场景、边界与常见误区

构建成功不保证设计一致、可访问性或所有浏览器支持。v4依赖较现代浏览器能力，兼容要求应查官方Compatibility并按项目目标决定；不把本机Chrome通过当全平台认证。样式引擎与业务组件库是不同层，Nuxt UI/Vant不要求一起装。

## 移动端经验对照

类似共享尺寸/颜色资源与样式复用；Web类名最终进入CSS层叠与浏览器布局，断点也不等同Android的设备类型或Flutter Widget分支。
