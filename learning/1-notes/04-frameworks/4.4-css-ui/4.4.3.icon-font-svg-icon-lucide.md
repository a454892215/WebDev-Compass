# 4.4.3 本地SVG图标：装饰、名称与外部资源边界

## 前置与目标

先完成阶段3工程与TypeScript；4.4需CSS布局/层叠基础，4.5需Vue组件、组合式API与路由。能解释本点机制、运行对应实验并定位一种失败。4.4可按需要选读，完整SEO与生产部署分别留阶段6、7。

## 解决什么问题

为动作和状态提供视觉线索，同时确保没有图标字体、图片或颜色时，用户仍能理解和操作。

## 原理与选择

图标字体用字形承载形状，可能受字体加载和替代字体影响。SVG可以内联、作为img或sprite使用；内联currentColor可跟随文字色，img加载的独立SVG不会直接继承宿主CSS的currentColor。带可见文字的图标常是装饰，应避免重复朗读；纯图标按钮的名称放在按钮上；独立信息图应有自己的可访问名称。

## 最小机制片段

```html
<!-- 装饰图标不重复按钮文字 -->
<button type="button">
  <svg aria-hidden="true" focusable="false" viewBox="0 0 24 24">
    <path fill="currentColor" d="M6 3h12v18l-6-4-6 4z"/>
  </svg>收藏
</button>
<!-- 纯图标按钮：名称属于动作，空alt避免再读一次 -->
<button type="button" aria-label="查看说明"><img src="./info.svg" alt=""></button>
```

片段只解释当前机制；不是可直接替代完整工程的文件。变量、依赖与运行上下文见[代码操作卡](../../../2-examples/04-frameworks/4.4-css-ui/4.4.3.icon-font-svg-icon-lucide-demo.md)及其源码链接。

## 场景、边界与常见误区

Lucide/Heroicons是可选图标资源，不是无障碍机制；本实验使用自有本地SVG，没有安装或验证这两套库。外部不可信SVG不能未经审查作为HTML注入，v-html不是图标消毒器。SVG标题id在重复组件内应避免冲突。

## 移动端经验对照

类似区分装饰图标和语义动作说明；Web名称由DOM/ARIA和可见文字共同决定，不能只照搬移动端图标资源的文件名。
