# 4.3.1.2 Vue响应式：ref、reactive、computed与composables

## 前置与目标

SFC与模板基础；侦听副作用随后在4.3.1.8单独学习。

目标：能解释本节机制，运行对应实验，独立定位下述故障并说明边界。

## 解决什么问题与原理

ref保存可替换的值，脚本通过.value读写；reactive为对象提供深层代理，跟踪属性访问。应操作代理而非原始对象；把reactive对象里的数字解构成普通变量会断开属性连接，可用toRefs或getter。Vue3.5的defineProps同一script setup内解构有编译处理，是特定例外，不代表所有解构都响应式。

computed用于基于依赖的派生值并缓存结果；getter保持纯净，不在里面发请求、改依赖或写存储。业务源状态留在ref/reactive，派生筛选和计数不再复制一份手工同步。数组/Map中的ref等解包规则不能从普通模板插值一概类推。

状态写入立即改变JS值，DOM更新按批次调度；需要读取更新后的DOM时await nextTick，不把固定setTimeout当更新保证。composable是复用有状态逻辑的函数，通常以use开头，在合法setup上下文同步调用以绑定生命周期；两个调用默认拥有各自局部状态，不自动是全局单例。

## 最小例子

```typescript
import { computed, reactive, toRefs } from 'vue'
const state = reactive({ count: 1 })
const { count } = toRefs(state)
const double = computed(() => count.value * 2)
state.count++
console.log(double.value) // 4
```

片段用于解释本节规则；标注为setup或模板的代码需放进对应SFC。完整导入、类型与运行入口见[示例操作卡](../../../2-examples/04-frameworks/4.3-vue/4.3.1.2.setup-demo.md)。

## 运行与观察

筛选由computed派生；测试实际对比reactive普通解构的旧值与toRefs新值，验证computed结果4。模板引用实验在nextTick后聚焦。

## 场景、边界与移动开发对照

可迁移状态/派生值分离经验；Vue基于ref/Proxy和依赖追踪，不等同Flutter setState或React函数每次执行的闭包模型。

composable定义本身可在模块顶层，实例状态与生命周期调用要看创建位置；SSR状态边界在Nuxt4.5另行验证。
