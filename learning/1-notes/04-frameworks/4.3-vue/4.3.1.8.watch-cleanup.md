# 4.3.1.8 Vue侦听副作用：watch、watchEffect、取消与迟到结果

## 前置与目标

ref/computed、异步Promise、AbortController和生命周期。

目标：能解释本节机制，运行对应实验，独立定位下述故障并说明边界。

## 解决什么问题与原理

computed负责纯派生，watch负责明确数据源变化后的副作用。watch(ref/getter/源数组)跟踪声明的源，不因为回调读了别的ref就自动依赖它；不能把reactive对象的数字属性求值后直接传作有效响应源。watchEffect立即运行并跟踪同步读到的响应依赖，async函数第一个await之后才读取的值不会被这次自动追踪。

查询变更可让旧请求失效。每次创建AbortController并在等待前注册清理，取消旧操作；再用序号/有效标志防止不遵守abort的异步结果回写。Vue3.5+的onWatcherCleanup必须在同步执行阶段调用，不能await后才注册；watch回调第三参数onCleanup绑定本次侦听，仍应尽早注册避免竞态。

默认watch回调通常在父更新后、所属组件DOM更新前；需要更新后DOM可选flush:post，sync只在确有必要时用，避免高频同步开销。同步setup创建的watch会随实例停止；本lab在effect scope结束时显式stop，清理也使迟到任务失效。空态、失败和恢复应有独立状态，不把捕获所有异常写成成功。

## 最小例子

```typescript
// useLatestSearch.ts的核心；完整状态/类型见源码
watch(query, async (q, _old, onCleanup) => {
  const controller = new AbortController()
  let valid = true
  onCleanup(() => { valid = false; controller.abort() })
  const data = await loader(q, controller.signal)
  if (valid) results.value = data
})
// 片段需在setup/composable内，生产版还要catch与空/错状态。
```

片段用于解释本节规则；标注为setup或模板的代码需放进对应SFC。完整导入、类型与运行入口见[示例操作卡](../../../2-examples/04-frameworks/4.3-vue/4.3.1.8.watch-cleanup-demo.md)。

## 运行与观察

输入error/empty/recovered观察失败、空和恢复；真正的迟到保护由deferred单测控制：旧loader故意忽略abort，后返回也不能覆盖新结果；scope停止后结果不回写。watchEffect测试还核对依赖变化与清理次数。

## 场景、边界与移动开发对照

与订阅取消及请求代次检查目标相似，但Vue依赖追踪/flush调度与移动Flow/Stream监听不同，需按浏览器和框架执行时机验证。

搜索数据是内存延迟fixture，明确不是HTTP服务；HTTP请求与Nuxtpayload由阶段4.5/5另行处理。
