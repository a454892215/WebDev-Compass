# 4.3.3.1 Vue单文件组件：template、script setup与scoped CSS

## 前置与目标

阶段3的TS、ESM和Vite。先读本节再读4.3.1各节；编号不等于先修顺序。

目标：能解释本节机制，运行对应实验，独立定位下述故障并说明边界。

## 解决什么问题与原理

SFC将一个组件的模板、实例逻辑和样式集中在.vue文件。浏览器不能原样执行.vue；本实验用Vite和@vitejs/plugin-vue转换，vue-tsc负责类型检查。build转换与类型检查是不同步骤。

<script setup lang="ts">是编译语法：顶层导入/变量可在模板使用，主体通常按组件实例执行。defineProps/defineEmits/defineModel是编译宏，不需要从vue导入，不能粘到任意普通.ts文件当运行函数。需要模块级逻辑时明确其是否会跨实例/请求共享。

<style scoped>通过生成属性选择器限制样式匹配，不是Shadow DOM或安全隔离。父组件scoped可影响子组件根元素；深层子树要用明确的:deep等机制。应用主题令牌可保留全局，不能靠scoped隔绝所有继承。

## 最小例子

```vue
<script setup lang="ts">
import { ref } from 'vue'
const count = ref(0)
</script>
<template><button type="button" @click="count++">{{ count }}</button></template>
<style scoped>button { min-height: 44px }</style>
```

片段用于解释本节规则；标注为setup或模板的代码需放进对应SFC。完整导入、类型与运行入口见[示例操作卡](../../../2-examples/04-frameworks/4.3-vue/4.3.3.1..vue-demo.md)。

## 运行与观察

运行lab，点击缓存计数；查看源码的template/script setup，再运行typecheck/build，产物已变成JS/CSS而非浏览器直接解释.vue。

## 场景、边界与移动开发对照

类似把界面、逻辑与局部样式放在同一组件文件，但编译后仍由DOM/CSS和浏览器执行，非Widget渲染管线。

主实验是客户端Vite SFC，不据此声称已验证Nuxt SSR、每请求隔离或生产部署。
