# 4.3.1.6 Vue模板引用：DOM可用时机、nextTick与组件公开接口

## 前置与目标

生命周期、响应式更新与v-if。

目标：能解释本节机制，运行对应实验，独立定位下述故障并说明边界。

## 解决什么问题与原理

useTemplateRef在Vue3.5+根据模板ref取得元素或组件引用；挂载前、v-if移除后可以为空。模板里的ref标记不是普通HTML id，不能依赖它作为浏览器全局变量。

修改shown=true后，DOM不一定已更新。先await nextTick再检查引用并focus；只做聚焦等必要命令式操作，通常不通过ref改框架正在维护的DOM文本。浏览器测焦点才有真实布局/交互证据，jsdom只能提供一部分DOM行为。

获取子组件ref会增加耦合。script setup组件默认私有，需要时用defineExpose公开很小的命令接口；父级通常优先用Props/事件。v-for引用集合的顺序也不能不加验证地当业务id索引。

## 最小例子

```typescript
// FocusInput.vue的script setup
import { nextTick, ref, useTemplateRef } from 'vue'
const shown = ref(false)
const field = useTemplateRef<HTMLInputElement>('field')
async function show() { shown.value = true; await nextTick(); field.value?.focus() }
// template内：<input v-if="shown" ref="field">
```

片段用于解释本节规则；标注为setup或模板的代码需放进对应SFC。完整导入、类型与运行入口见[示例操作卡](../../../2-examples/04-frameworks/4.3-vue/4.3.1.6.ref-demo.md)。

## 运行与观察

初始没有目标input，点击后创建并获得焦点。VTU断言document.activeElement，Chrome用toBeFocused核对实际焦点；没有固定sleep。

## 场景、边界与移动开发对照

与拿到原生控件句柄操作焦点有相似目标，但Vue模板引用和Flutter GlobalKey/FocusNode的生命周期并不相同。

本实验未验证屏幕阅读器焦点公告或移动键盘弹出；模拟手机视口不等于真实键盘测试。
