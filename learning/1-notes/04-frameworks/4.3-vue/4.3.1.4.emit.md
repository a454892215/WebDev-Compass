# 4.3.1.4 Vue组件契约：Props、事件、v-model与插槽

## 前置与目标

模板和ref；已会阶段3 TS函数/对象契约。

目标：能解释本节机制，运行对应实验，独立定位下述故障并说明边界。

## 解决什么问题与原理

父级通过props传输入，子级用emit表达事件。props只读约束是浅层的；传入对象的嵌套字段仍可能被子组件写到，但这会隐藏数据流，通常应发事件由状态所有者修改。组件emit不会像原生DOM事件那样自动跨所有祖先冒泡。

defineModel在Vue3.4+提供组件v-model宏，默认对应modelValue与update:modelValue；带名称如draft则对应draft/update:draft。它是显式prop/事件契约的语法便利，不是共享对象魔法。父级应初始化模型；子级默认值而父级未传值可能造成不同步。

默认/具名插槽由父级提供内容，作用域插槽让子级向这段内容传数据。父模板表达式在父作用域求值，不能直接读取子级所有局部变量。Props、emits和slot类型改善检查，但外部JSON仍需运行时校验。

## 最小例子

```typescript
// ReadingCard.vue的script setup内
const emit = defineEmits<{ toggle: [id: string] }>()
const draft = defineModel<string>('draft', { required: true })
// 父级：<ReadingCard v-model:draft="draft" @toggle="toggle" ... />
```

片段用于解释本节规则；标注为setup或模板的代码需放进对应SFC。完整导入、类型与运行入口见[示例操作卡](../../../2-examples/04-frameworks/4.3-vue/4.3.1.4.emit-demo.md)。

## 运行与观察

编辑草稿使父级drafts与插槽文字同步；点击切换只emit合法id，由Pinia action改状态。VTU分别检查update:draft、toggle以及父级新props导致aria-pressed更新。

## 场景、边界与移动开发对照

类似父状态下发和回调上报，但Vue slot是渲染内容契约，DOM事件与组件事件也有不同传播机制。

类型通过不等于权限校验；HTML字符串不作为slot/模板源码执行。
