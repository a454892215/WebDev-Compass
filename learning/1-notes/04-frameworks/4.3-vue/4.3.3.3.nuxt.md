# 4.3.3.3 Nuxt概览：Vue应用框架与4.5的学习入口

## 前置与目标

已能独立运行Vue SFC、路由与状态实验，再进入4.5。

目标：能解释本节机制，运行对应实验，独立定位下述故障并说明边界。

## 解决什么问题与原理

Vue提供组件和响应式能力，Nuxt在其上组织应用：约定目录、文件路由、布局、数据获取、插件、运行配置及Nitro服务端能力。Nuxt仍运行Vue组件，但不是把每项Vue API简单换名。Nuxt4主应用目录为app/，具体版本以官方骨架和项目配置为准。

Nuxt可按需求采用SSR、CSR或预渲染/静态生成。SSR部署要有能执行服务端产物的运行环境；纯静态产物可由静态托管提供，但不再有随请求执行的server/API能力。选择取决于首屏、SEO、数据新鲜度、认证和运维，不能说Nuxt一定需要自建Node服务器，也不能说所有模式功能相同。

从Vite实验迁移时先区分哪些由Nuxt接管：不重复手工创建router，不把客户端VITE_配置当服务端秘密配置，不把模块级ref当每请求状态。useFetch/useState必须在合法Nuxt上下文调用，payload/hydration和SSR隔离在4.5逐项展开，本节只建立职责地图。

## 场景、边界与移动开发对照

可类比应用框架提供路由/装配惯例，但浏览器首屏、SSR/payload和托管模式是Web独有边界，不照抄移动生命周期方案。

本点为概览与迁移观察，Nuxt实际构建/SSR/请求隔离由主综合项目与4.5运行报告证明。
