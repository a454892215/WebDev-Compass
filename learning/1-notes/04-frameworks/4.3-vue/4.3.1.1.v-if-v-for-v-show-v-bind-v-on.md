# 4.3.1.1 Vue模板与指令：渲染、事件、条件、列表和表单

## 前置与目标

先完成4.3.3.1 SFC；已会HTML表单和JS事件。

目标：能解释本节机制，运行对应实验，独立定位下述故障并说明边界。

## 解决什么问题与原理

模板将状态映射成DOM。双大括号插值按文本处理；v-bind（:）绑定属性，v-on（@）注册监听器。v-html会解释HTML，不能接不可信输入；框架不会让任意HTML自动安全。

v-if改变子树的创建/销毁；v-show切换display，实例与元素保留。选用取决于初始成本、切换频率和副作用，而不是哪一个绝对更快。条件和列表可先用computed筛选，避免把v-if与v-for竞争作用域混在同一元素。

v-for用稳定业务id作:key，支持插入/重排时维持正确实例身份；不要用随机数或在可编辑列表用位置替代业务身份。原生input的v-model连接value和input等适当事件，select/checkbox还有各自语义；不能据此省掉label或类型校验。

## 最小例子

```vue
<script setup lang="ts">
import { ref } from 'vue'
const title = ref('')
</script>
<template><label>标题<input v-model="title"></label><p>{{ title }}</p></template>
```

片段用于解释本节规则；标注为setup或模板的代码需放进对应SFC。完整导入、类型与运行入口见[示例操作卡](../../../2-examples/04-frameworks/4.3-vue/4.3.1.1.v-if-v-for-v-show-v-bind-v-on-demo.md)。

## 运行与观察

筛选标题改变computed列表；切换说明后v-show节点仍存在。输入<b>draft</b>只显示文字，没有b节点；真实模型更新改变插槽内容。

## 场景、边界与移动开发对照

与声明式列表及稳定key的身份问题类似；Vue事件仍遵循DOM传播，原生输入、焦点和表单行为不能按RN/Flutter控件假设。

本例v-model更新内存，不提交服务端；样式隐藏也不是访问权限控制。
