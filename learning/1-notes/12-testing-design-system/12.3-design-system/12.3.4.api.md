# 12.3.4 Vue组件API：原生语义、属性事件和slot组合

前置阶段4 Vue/Nuxt、6可访问性、3测试基础；先token→生成→stories→API/版本→主题，Web Components按需。目标是解释契约、运行可观察实验并评估新增成本。

## 问题与机制

先写调用方需要完成的任务，再设计最小稳定API。prop承载有限状态与数据，event表达意图，slot容纳内容组合；不要用几十个布尔值组合出无法定义的状态。封装button应保留type、disabled、可访问名称和键盘语义；默认type=button避免放入表单时意外提交。

## 最小例子与观察

共享UiButton的variant是primary/secondary，disabled/type有默认值，default slot提供可见名称，单原生button根节点承接class/aria属性及原生click。故事Primary验证type=button与点击，Disabled验证不能激活。slot不是任意HTML字符串；本例不使用v-html。

## 场景、边界与误区

Vue透传属性与显式emits会影响监听器落点，多根组件需明确绑定位置。不能把link与button混成靠颜色区分的万能组件；导航用a/NuxtLink。Compound组件适合确实共享上下文的结构，不要只因术语时髦拆出十个子组件；受控/非受控模式、focus与错误状态要写清。

## 移动开发对照

可类比Flutter props/callback/child或React Native children，但原生button/label/form语义、属性透传和浏览器默认提交行为没有一一对应关系。
