# 11.1.2 错误分级与告警路由：以用户影响决定响应

前置：阶段3工具/类型、4 Vue/Nuxt、5请求、9性能与10隐私安全；本组先11.1.1事件与版本，再11.1.2影响、11.1.3恢复，最后采样和操作上下文。

## 问题与机制

异常的技术类型或日志level不能直接决定事故优先级。一次TypeError可能只影响可重试的非关键图表，也可能阻断所有支付；反过来业务请求持续返回成功HTTP但没有完成业务，同样可能是高影响故障。先定义关键旅程、失败分母、影响窗口、覆盖比例、数据/安全后果和是否有恢复方法，再决定升级。

P0–P3没有跨组织统一含义。本课提供教学约定：P0是关键旅程大面积且无恢复；P1是关键旅程部分不可用；P2为非关键但不可恢复故障；P3为可恢复局部问题。生产应补充数据泄漏/破坏等优先升级条件，不能让简化比率函数替代事件指挥判断。错误事件数不是受影响用户数，重复重试会放大事件量，采样和拦截会缩小已观测量。

自动指派基于受维护的模块/服务owner映射并有未知owner兜底、值班交接和超时升级。告警应绑定行动：谁接、在多久内确认、先检查什么、何时kill switch或回滚。按环境/版本过滤、窗口/最少样本、抑制重复与恢复通知能减少噪声；调低错误采样却不改阈值会使告警失真。

## 最小上下文

```javascript
// error-lab/policy.mjs中的教学规则；并非平台默认级别。
priority({ criticalJourney: true, affectedRatio: 0.7, recoverable: false });
// P0：ratio必须是[0,1]内有限数；缺分母不能默认写0。
```

节选变量/依赖均由[error-lab完整工程](../../../2-examples/11-observability/11.1-error-monitoring/error-lab/README.md)提供；不要脱离import/初始化单独复制。

## 操作、预期与边界

运行Node第三组，分别观察关键旅程70%/2%、非关键不可恢复和可恢复返回P0/P1/P2/P3，NaN被拒绝。该规则是本地纯函数；Sentry官方告警界面用于读取触发器/环境过滤/通知/节流配置，不在本轮创建组织告警、发送消息或自动指派真实同事。

## 常见误区

P0不是“所有error日志”；事件数不是影响用户数；自动分派失败不能静默无人负责。少样本不能只用百分比，缺数据与零错误应区分。

## 移动开发对照

移动崩溃率与Web的关键旅程失败率类似地需要分母；Web可能只是一个模块失败而整页仍用，不能用App是否崩溃代替业务影响。
