# 11.1.4 错误采样与配额：先过滤和脱敏，再控制成本

前置：阶段3工具/类型、4 Vue/Nuxt、5请求、9性能与10隐私安全；本组先11.1.1事件与版本，再11.1.2影响、11.1.3恢复，最后采样和操作上下文。

## 问题与机制

错误事件、Tracing、Replay通常有独立采样参数与配额，不能把tracesSampleRate当错误事件率。Sentry sampleRate控制错误事件随机保留比例，beforeSend可在scope数据应用后修改或返回null；ignoreErrors/来源过滤等可先去明确噪声。不要只凭“Network Error”一类泛词全删，它也可能是真实核心故障。

先定义采集目的与字段允许列表，再在客户端/服务端各自可信边界脱敏，不依赖后台接收后才删除。Error.message、栈文件URL的query、user、request、extra、context和breadcrumbs都可能夹带秘密；删掉user.email并不足够。示例把原始异常消息替换固定代码，保留同次构建栈位置/版本，禁用默认自动集成，避免实验意外收集其他数据。生产需针对实际诊断需求与风险设计，而非盲删所有上下文。

采样降成本但不等于限流。每页本地最多2条不能阻止攻击者刷新或伪造直接请求，网络缓冲、接收端字节/速率限制、平台配额和预算告警仍需独立控制。样本丢弃、离线、广告拦截和传输失败都会产生观测盲区；sampleRate=0时零事件不表示零故障。不能不加假设地按1/rate还原影响用户数，概率抽样误差、相关重复和偏差要保留。

## 最小上下文

```javascript
// error-lab/app.mjs真实SDK配置节选，0与1用于确定性正反例。
sampleRate: new URL(location.href).searchParams.get('sample') === '0' ? 0 : 1,
beforeSend: createEventPolicy(2),
sendClientReports: false,
// createEventPolicy在policy.mjs：AbortError返回null；允许事件脱敏并最多2条。

```

节选变量/依赖均由[error-lab完整工程](../../../2-examples/11-observability/11.1-error-monitoring/error-lab/README.md)提供；不要脱离import/初始化单独复制。

## 操作、预期与边界

Node验证敏感字段/URL query删除、取消丢弃与配额；真实浏览器sample=1时连续三次仅2信封，AbortError不占允许配额；sample=0重载后手动捕获为0信封。没有随机0.1样本统计、远程429或平台月配额实验，不将确定性边界测试宣称已证明所有采样统计性质。

## 常见误区

本地限额不是抗滥用服务；beforeSend不影响已发出去的事件。移除客户端字段不能证明服务端/代理日志也没有秘密，scope中的秘密最好从一开始就不写入。

## 移动开发对照

类似移动监控采样和上报队列，但浏览器页面可频繁重载、受拦截/离开页生命周期影响，不能用单进程累计计数当整个用户或服务的硬配额。
