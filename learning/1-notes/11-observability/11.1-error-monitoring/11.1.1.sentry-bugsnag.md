# 11.1.1 Sentry/BugSnag集成：事件、Release与Source Map必须匹配

前置：阶段3工具/类型、4 Vue/Nuxt、5请求、9性能与10隐私安全；本组先11.1.1事件与版本，再11.1.2影响、11.1.3恢复，最后采样和操作上下文。

## 问题与机制

线上错误只有压缩文件行号时，很难定位到源码。监控SDK负责捕获异常并生成事件，传输层负责发出，平台负责分组、存储、映射和通知；不能把安装依赖当成闭环。浏览器与Nuxt服务端是不同运行环境，应选择各自集成并在服务端按请求管理上下文，不能共享“当前用户”全局scope。

Sentry使用release/environment等属性区分代码版本和环境；当前官方构建插件默认可注入Debug ID关联产物与map，不能只凭文件名相同假设可还原。无Debug ID的集成需按相应官方release/artifact规则配置。上传与部署应使用同一次构建，先产物/map核验并私密上传，再发布；重建后继续使用旧map可能得到“看似正常、实际错误”的行号。认证上传token属于CI服务端秘密，公开DSN不是上传token，也不是授权或配额防滥用手段。

BugSnag也有appVersion/releaseStage、onError、source map等对应机制，但配置名称和服务端协议不能混用。本节实际运行Sentry Browser 11.17.0，不同时安装多个SDK来重复上报。Nuxt生产接入应按Sentry Nuxt官方集成分开客户端/服务端及构建步骤，不把本lab的browser手动捕获当作Nuxt SSR自动监控。

## 最小上下文

```javascript
import * as Sentry from "@sentry/browser";
const captured = [];
Sentry.init({
  dsn: "https://public@example.invalid/1",
  release: "error-lab@1.0.0",
  environment: "local-fixture",
  defaultIntegrations: false,
  transport: () => ({
    send(envelope) {
      captured.push(envelope);
      return Promise.resolve({ statusCode: 200 });
    },
    flush() {
      return Promise.resolve(true);
    },
  }), // 仅内存，无网络
});
// sample、beforeSend、breadcrumbs与transport实现均见完整lab。
```

节选变量/依赖均由[error-lab完整工程](../../../2-examples/11-observability/11.1-error-monitoring/error-lab/README.md)提供；不要脱离import/初始化单独复制。

## 操作、预期与边界

运行error-lab的test/build/verify。真实Vite构建hidden map，浏览器抛出合成Error，由真实Sentry SDK形成信封；验证release/environment，取实际压缩栈行列用trace-mapping还原到app.mjs源码。浏览器列号转Source Map列号时减1，行号仍为1起。这里没有平台Debug ID上传、SaaS符号化或远程告警；map还原是本地消费同次构建产物的证据。hidden只是去掉sourceMappingURL，本lab静态服务仍能访问.map，不是权限隔离。

## 常见误区

SDK DSN、CI上传token与用户身份各有职责；隐藏map引用不等于禁止HTTP下载；保留release标签也不自动保证映射正确。

## 移动开发对照

与移动崩溃平台的版本/符号文件配对相似，但Web有HTML、CDN旧资源、多个浏览器和SSR双运行时，更新页面不代表所有标签页已经切换版本；不能照搬一个App进程的全局用户scope。
