# 11.1.5 Breadcrumbs：用有限语义事件还原操作顺序

前置：阶段3工具/类型、4 Vue/Nuxt、5请求、9性能与10隐私安全；本组先11.1.1事件与版本，再11.1.2影响、11.1.3恢复，最后采样和操作上下文。

## 问题与机制

错误栈告诉你失败位置，breadcrumbs帮助解释失败之前做过哪些操作。它是有界时间顺序记录，不是录屏、全量日志或完整业务审计。适合记录“打开面板、选过滤、提交、重试”这种语义动作与少量受控结果码；输入文本、完整URL、请求体、Cookie和身份token不应随手放进去。

SDK默认集成可能自动记录console、navigation、XHR/fetch和DOM点击，选择开关时应实看当前SDK文档与网络数据。本lab故意defaultIntegrations:false，只手动添加ui.action，beforeBreadcrumb检查动作allowlist后重建字段，maxBreadcrumbs:3保留最近3条。beforeSend再次过滤作为本例防线，不能据此声称任意未来自动集成都安全。给用户可见的错误ID也不要暴露带秘密的原始stack。

上下文生命周期尤其重要：浏览器单页可跨路由/换用户，服务端一个进程同时处理多个请求；跨会话共享breadcrumbs会泄露他人旅程，必须使用SDK支持的隔离scope并在登录切换/退出时清理适用上下文。事件记录可以有时间偏差、丢弃和重载中断，不能单凭两个breadcrumb断言业务操作已成功。应与后端trace/request与可信业务结果核对。

## 最小上下文

```javascript
// policy.mjs：丢弃未注册动作，并移除原data。
export function breadcrumbPolicy(crumb) {
  if (crumb.category !== "ui.action" || !actions.has(crumb.message))
    return null;
  return { category: "ui.action", message: crumb.message, level: "info" };
}
// actions完整定义及实际Sentry.addBreadcrumb见error-lab；不记录输入值。
```

节选变量/依赖均由[error-lab完整工程](../../../2-examples/11-observability/11.1-error-monitoring/error-lab/README.md)提供；不要脱离import/初始化单独复制。

## 操作、预期与边界

真实SDK加入四个允许动作加一个不允许文本，最终错误信封只有最近3条choose-filter/retry-panel/submit-fixture，没有data秘密和typed secret。每个独立浏览器context重载清空当前页内存实验，未验证生产登录切换或SSR SDK请求scope；后者在真实集成时必须专项检查。

## 常见误区

breadcrumb不是业务成功证据；beforeBreadcrumb应返回清理后的对象或null，不能忘记return而误丢所有记录；不靠正则遮盖任意复杂敏感文本。

## 移动开发对照

与移动埋点/崩溃面包屑相似，但Web有SPA路由、多标签和服务端共享进程，不能把进程级操作列表当每位用户的旅程。
