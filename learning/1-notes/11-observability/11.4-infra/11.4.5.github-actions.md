# 11.4.5 GitHub Actions矩阵、缓存与受保护部署

前置：阶段7部署/构建、阶段10安全；本章关注与平台协作，不要求所有项目安装所有基础设施。目标：解释职责、核对真实配置，并给出可验证交接。

## 机制与最小观察

矩阵把同一质量任务展开为多组环境；明确所需组合与成本，不把矩阵重复构建当发布多份不同产物。缓存是加速手段，命中后仍冻结安装与检查；key应包括OS/架构/运行时/锁文件。产物与依赖缓存是不同职责。

quality.yml.example定义2个OS×2个Node共4格质量，main push且needs质量成功才进入production environment。部署job仅打印说明，没有云动作；需在仓库设置required reviewers/分支规则，YAML中写environment不会自动创建审批制度。三个action SHA仍需核验替换。

## 场景、边界与误区

PR代码不拿生产secrets，避免pull_request_target检出并执行不可信分支。GITHUB_TOKEN最小权限，OIDC只在需要发布的job启用并由云端限定repo/ref/environment；id-token:write本身不是授权成功。平台secret遮罩不能保证所有变换都脱敏。部署concurrency/审批与回滚要另核。

## 移动开发对照

类似移动CI但Web部署还涉及运行环境、缓存、旧资源与远程配置；build通过不是用户已收到正确版本，也不是审批或生产健康通过。
