# 3.2.4 HMR：更新边界与状态保留

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 解决什么问题与前置

开发时改一段代码，为什么有时状态保留、有时整页刷新？

前置：模块图、事件监听、3.2.1与3.2.2。

## 原理与规则

1. dev server监视文件并通知客户端；变化在可接受的模块边界内由运行时应用，否则可能沿依赖图传播或回退全页刷新。HMR不是永不重载的承诺。

2. 框架模板通常由插件处理HMR；本实验用手工accept只为了观察依赖更新，不建议所有业务组件都重写这套机制。

3. 更新代码若重新注册监听/订阅需清理，资源生命周期仍重要。状态保留只说明本次边界生效，不表示生产性能或运行正确性。

## 最小例子

```javascript
if (import.meta.hot) {
  import.meta.hot.accept("./message", module => {
    const output = document.querySelector("#message");
    if (module && output) output.textContent = module.message;
  });
}
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.2-build-tools/3.2.4.hmr-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

与移动热重载/刷新可比较体验，但保存哪些状态、何时重启由各自工具决定，不依名称推导语义。

## 场景与误区

只看到文字变化不能证明是HMR；还要检查页面导航次数及未重载模块内状态。

## 实验与独立练习

vite-lab中点击计数至3，再修改message.ts。verify.mjs断言文字更新、计数仍3、无文档导航；测试后恢复源文件。

## 综合实践关联

在任务板开发时区分模块HMR与全页刷新，更新需保留状态时先理解边界，不把示例手工accept强塞到框架。

已有能力与副本扩展分开，按阶段综合项目的实际代码判断，不为覆盖知识点强加工具。
