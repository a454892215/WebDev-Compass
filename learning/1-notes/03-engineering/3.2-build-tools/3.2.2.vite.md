# 3.2.2 Vite：入口、配置、alias和公开环境变量

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 解决什么问题与前置

从最小Vite项目建立可运行入口，理解环境变量暴露边界。

前置：3.1与基础TS语法；暂不需要Vue。

## 原理与规则

1. create-vite可创建模板，也可用显式index.html与src/main.ts理解骨架；本实验保留可阅读的最小配置，避免把生成器当理解工程的替代品。

2. Vite配置负责解析别名与构建行为；TS paths帮助编译器解析类型，不会独自改写浏览器运行期URL，二者需一致或由适用插件处理。

3. import.meta.env下自定义VITE_值是客户端公开配置，通常为字符串并在构建时替换。非VITE_不自动暴露并不意味着可以把秘密导入客户端；生产需服务端秘密边界。修改.env后通常需重启dev server。

## 最小例子

```javascript
// vite.config.mjs
import { defineConfig } from "vite";
export default defineConfig({ build: { sourcemap: true } });
// 浏览器：import.meta.env.VITE_COURSE_LABEL（只能放公开文本）
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.2-build-tools/3.2.2.vite-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

类似区分构建配置与运行配置，但VITE_会进入公开客户端，不能类比移动本地配置就认为保密。

## 场景与误区

生产静态包生成后，不会因为服务器shell后来改一个env就自动改变已构建JS；具体SSR运行时配置另学Nuxt。

## 实验与独立练习

vite-lab从index.html加载main.ts，@lab别名导入util；复制.env.example为本地.env仅使用公开演示标签，重启再观察。
