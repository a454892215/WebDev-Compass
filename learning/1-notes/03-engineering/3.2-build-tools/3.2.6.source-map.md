# 3.2.6 Source Map：生成代码与源码的映射

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 解决什么问题与前置

生产压缩后怎样回到可理解的源码位置，同时控制源码公开范围？

前置：构建产物与浏览器Sources/断点基础。

## 原理与规则

1. Source Map把生成位置映射到原始源码位置，帮助调试和错误定位，不改变运行逻辑或自动修复错误。不同工具支持外部、内联、隐藏等策略，具体选项不是统一跨工具枚举。

2. Vite build.sourcemap:true生成独立map并关联；hidden通常不写消费方提示，但map文件仍存在，若上传到公开路径仍可能被下载。false关闭生成也不等于整个业务代码无法被理解。

3. 是否发布map要根据调试、错误平台、源码与隐私需求选择；不把含sourcesContent的产物无审查上传。工具能生成map不等于本轮已人工逐断点验证全部位置。

## 最小例子

```javascript
// vite.config.mjs
export default { build: { sourcemap: true } };
// 检查dist/assets中的.js.map、sources、mappings与JS尾部sourceMappingURL。
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.2-build-tools/3.2.6.source-map-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

可类比原生符号/映射文件辅助定位，但格式、上传路径和浏览器公开可见性不同。

## 场景与误区

hidden不是秘密保险箱；map是否暴露由部署访问与产物清单决定。

## 实验与独立练习

vite-lab build后check:output解析真实map并确认src来源；可在浏览器Sources手动定位TS，自动检查不冒充完整DevTools断点验收。
