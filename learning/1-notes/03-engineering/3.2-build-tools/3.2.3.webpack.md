# 3.2.3 Webpack核心概念：按需对照

## 解决什么问题与前置

能读旧项目Webpack配置，而不要求入门同时维护两套构建器。

前置：3.2.1模块图和产物。选读。

## 原理与规则

1. entry指定依赖图起点，output定义生成位置与文件名；loader转换匹配模块，plugin通过构建钩子处理更广的任务。它们职责不同。

2. HMR依赖运行时和更新边界，配置dev server不保证每种变化都无刷新。真实Webpack生态需相容的webpack/CLI/loader/plugin版本，不能拿几行配置当安装完成。

3. 本课默认Vite。Webpack配置仅作阅读与操作清单，本轮不安装或声称实际执行Webpack构建；已有旧项目才按其约束验证。

## 最小例子

```javascript
// webpack.config.cjs；独立Webpack项目阅读示例，不在本Vite实验执行
const path = require("node:path");
module.exports = { mode: "production", entry: "./src/main.js", output: { path: path.resolve(__dirname, "dist"), filename: "app.js" } };
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.2-build-tools/3.2.3.webpack-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

可对照构建任务图与资源转换器，但Gradle插件、Xcode build phase、Metro transform不是逐项等价API。

## 场景与误区

不要在Vite工程安装一个Webpack loader就期待它自动生效；工具配置边界要明确。

## 实验与独立练习

阅读webpack.config.cjs示例，标entry/output；解释为什么处理TS还要合适转换器、依赖和配置；不把静态阅读计为实际bundle。

若未来接手Webpack任务板，写入口/转换/产物迁移清单；当前工程继续Vite，不强引第二构建器。

## 官方依据
