# 3.2.5 生产构建：动态分块、Tree Shaking与压缩

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 解决什么问题与前置

如何证明构建确实拆分按需代码并去除了不用的纯导出？

前置：ESM、dynamic import、3.2.1。

## 原理与规则

1. 动态import提供按需加载边界，构建器可生成独立chunk；不是所有动态路径都能静态分析，也不能把更多chunk一概当更快。

2. Tree Shaking依赖可分析的模块与副作用判断。删除未使用纯导出不同于删除所有没显式调用的文件；模块初始化副作用和sideEffects声明需要谨慎。

3. 压缩缩短源码/标识符等，不等于类型检查或业务优化。Vite8具体打包实现按版本核对；部署路径、缓存与错误回退仍需验证。

## 最小例子

```javascript
const { summarize } = await import("./stats");
console.log(summarize([1, 2, 3]));
// util.ts导出一个未导入的纯函数，用唯一标记检查产物中确已去除。
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.2-build-tools/3.2.5.code-splitting-tree-shaking-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

可对照移动代码裁剪/延迟模块的目标，但Web分块是浏览器后续资源请求，不等同原生链接和安装包裁剪。

## 场景与误区

不要把.map中的原始源码文字误判为运行JS仍包含该导出；也不把一个产物正则当所有摇树情形都验证。

## 实验与独立练习

运行vite-lab build及check:output；检查至少两个JS资产，动态统计点击前后真实网络请求不同，唯一unused标记不在运行JS中。

## 综合实践关联

给任务板按需统计模块检查真实chunk与首次消费请求，并判断是否值得分割。

已有能力与副本扩展分开，按阶段综合项目的实际代码判断，不为覆盖知识点强加工具。
