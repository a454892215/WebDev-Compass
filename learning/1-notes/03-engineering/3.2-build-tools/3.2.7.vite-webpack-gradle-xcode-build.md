# 3.2.7 Web构建与移动构建：职责相似，机制不同

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 解决什么问题与前置

把多年移动经验迁移到Web工具链，又避免错误等价。

前置：3.1、3.2前六点；本节是总结对照。

## 原理与规则

1. 共同目标包括解析依赖、转换源码/资源、生成可运行产物和提供开发反馈。Webpack/Vite、Gradle、Xcode和Metro的职责范围并不一致，不能一对一替换。

2. Web产物通常由浏览器按URL加载；移动构建还涉及平台编译、链接、签名和安装等流程。开发服务器与生产托管也不同于安装一个APK。

3. 类型检查、打包、lint和测试在Web中往往是显式独立命令。Metro的模块/刷新行为与Vite不同，Flutter热重载也不能证明Web HMR的状态语义。

## 最小例子

```bash
pnpm typecheck  # 静态类型
pnpm build      # 本项目显式组合类型检查与浏览器产物
pnpm preview    # 本机预览产物，不是正式部署/签名/发布
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.2-build-tools/3.2.7.vite-webpack-gradle-xcode-build-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

本节按职责对照，不运行移动端框架或声称其具体线程/编译行为已验证。具体迁移仍读目标工具官方文档。

## 场景与误区

不要把Vite当完整Gradle替身，不把构建成功当部署、安全、权限或接口契约通过。

## 实验与独立练习

对同一个vite-lab分别执行typecheck/build/preview，列出输入、输出与未覆盖检查；不需要建立Android或Flutter工程。

## 综合实践关联

给任务板画四栏：类型/构建/质量/测试；用移动经验解释共同目标，并写出至少三项Web特有边界。

已有能力与副本扩展分开，按阶段综合项目的实际代码判断，不为覆盖知识点强加工具。

## 官方依据

核对日期：2026-11-24。先读[Modern Web Guidance Performance](https://developer.chrome.com/docs/modern-web-guidance/guides/performance/performance)，采用显式模块边界、按需加载与可验证资源；包管理/构建器细节没有覆盖全部的MWG专门条目，继续核对[对应官方正文](https://vite.dev/guide/)。Vite8/Node26等实际版本以实验manifest与运行报告为准，不把最新页面示例无条件套到旧版本。
