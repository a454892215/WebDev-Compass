# 3.3.5 泛型约束与常用工具类型

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 前置与目标

函数、对象、联合及可选结果。

## 原理与选择

泛型表达输入与输出之间的类型关系，不只是把any换成T。约束extends规定调用方至少满足哪些能力。

查询可能找不到时返回T|undefined，不用断言掩盖。readonly输入可以避免函数意外修改数组，但不是深冻结。

Partial/Pick/Omit/Record都是类型变换，不会在运行时补字段、删除字段或验证键。只为一次固定操作写清楚类型，避免无意义多层泛型。

## 最小例子

```typescript
function byId<T extends { id: string }>(items: readonly T[], id: string): T | undefined {
  return items.find(item => item.id === id);
}
const item = byId([{ id: "a", title: "课程" }], "a");
console.log(item?.title);
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.5.extends-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。

## 场景、边界与误区

当多个模型共享查询、映射关系时有价值；不为每个函数都设计“通用框架”。Partial也不能直接当未经验证的更新协议。

## 移动开发对照

可复用移动端泛型思路，但TS结构约束及类型擦除意味着T本身不提供运行时构造器。
