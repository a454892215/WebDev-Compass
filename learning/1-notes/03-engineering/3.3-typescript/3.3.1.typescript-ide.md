# 3.3.1 TypeScript解决什么问题与类型擦除

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 前置与目标

已有JS对象、函数、模块；无需先懂Vue。目标是区分开发期诊断与运行期数据校验。

## 原理与选择

TypeScript在JavaScript上增加静态类型检查，IDE补全、跳转和重构依赖同一份可分析契约；有类型并不自动证明业务正确。

类型注解、interface、type和多数断言在输出JS中消失；浏览器运行的是JS。Vite转译TS不等于执行完整类型检查，构建流程应另有tsc --noEmit。

any、断言、外部JS及不准确声明可绕开检查；网络/存储输入先作为unknown并验证，不能把“编译通过”当协议已可信。

## 最小例子

```typescript
const payload = JSON.parse('{"title":42}') as { title: string };
console.log(typeof payload.title); // number，断言没有转换或校验
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.1.typescript-ide-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。

## 场景、边界与误区

适合对项目模型、模块边界和协作接口建立反馈；不能替代运行期验证、权限和测试。启用strict后应逐步解释错误，不用any统一消音。

## 移动开发对照

像Dart/Kotlin编译期反馈的用途，但TS类型多数擦除；不能推导出Dart运行期类型检查在JS也存在。
