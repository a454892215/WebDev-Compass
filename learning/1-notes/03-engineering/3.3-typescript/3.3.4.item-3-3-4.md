# 3.3.4 联合、交叉与可辨识状态

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 前置与目标

对象类型、条件分支；never可参考3.3.2。

## 原理与选择

A|B表示值符合其中一种，未收窄前只能安全使用公共能力；统一kind字段可让分支关联到对应payload。

A&B要求同时满足两组约束，不是运行时合并对象。冲突字段可能收窄为never，不能把交叉当覆盖操作符。

用switch/default中的never检查遗漏分支；这只在检查器可见的封闭联合中有效，运行期输入仍可能非法。

## 最小例子

```typescript
type Load = { kind: "ok"; value: string } | { kind: "error"; reason: string };
function message(x: Load): string {
  return x.kind === "ok" ? x.value : x.reason;
}
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.4.item-3-3-4-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。

## 场景、边界与误区

用于加载/错误等互斥状态，优于多个可能互相矛盾的布尔值；不要求小页面过度状态机化。

## 移动开发对照

有判别字段的联合可对照sealed类的用途，但TS没有因此自动生成运行期类或反序列化校验。
