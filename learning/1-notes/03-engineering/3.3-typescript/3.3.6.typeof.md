# 3.3.6 断言、类型守卫与unknown数据入口

## 前置与目标

## 原理与选择

as和非空断言!改变编译器看法，不验证、转换或填充值。typeof、null检查、in、instanceof可依据真实运行条件收窄。

自定义value is T谓词是给编译器的承诺，检查体写错仍会撒谎；应逐个验证必须字段和类型，嵌套数据按实际schema继续解码。

instanceof适合真实类实例，JSON解析出的普通对象不自动成为类；跨realm等场景也需考虑构造器身份。DOM查询可先instanceof判断元素类型和缺失情况。

## 最小例子

```typescript
function isTitle(value: unknown): value is { title: string } {
  return typeof value === "object" && value !== null && "title" in value && typeof value.title === "string";
}
const input: unknown = JSON.parse('{"title":42}');
console.log(isTitle(input)); // false
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.6.typeof-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。

## 场景、边界与误区

网络、存储、文件都是边界。校验失败应返回可理解错误，不能靠as unknown as或!把错误变成调用栈更远处崩溃。
