# 3.3.12 TypeScript、Dart与Kotlin：可迁移经验和边界

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 前置与目标

基础类型、守卫、结构兼容和tsconfig。

## 原理与选择

可迁移经验包括类型契约、空值处理、泛型和IDE反馈；TS普通对象多按结构兼容，Dart/Kotlin的名义类型关系不能直接套用。

strictNullChecks改善静态空值检查，但any、断言、未检查外部JS及数组索引仍可能留下运行时缺失值；不把TS称为与Dart sound null safety完全等价。

TS类型主要擦除，运行平台仍是JS；外部JSON不会自动校验，类访问控制、泛型、枚举和平台API都要按目标工具链核对。Kotlin平台类型/!!等也有边界，不能反向宣称移动端绝无空值错误。

## 最小例子

```typescript
interface Named { title: string }
const bigger = { title: "结构兼容", id: "a" };
const named: Named = bigger;
const values: string[] = [];
console.log(named.title, values[0]); // JS仍可得到undefined
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.12.typescript-dart-kotlin-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。
