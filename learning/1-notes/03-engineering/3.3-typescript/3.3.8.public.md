# 3.3.8 类修饰符、readonly与#private的边界

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 前置与目标

阶段1 class与JS原型；先理解结构类型。

## 原理与选择

public是默认可访问性；protected允许子类访问，private限制TypeScript代码中的访问。初始化、继承和方法绑定仍按JavaScript执行。

TypeScript private通常保留普通JS属性，并非秘密存储；JS #private有运行时私有品牌检查。编译目标与工具支持必须核对，不能混用两者概念。

readonly阻止类型检查范围内的重新赋值，不等于Object.freeze或深不可变。受保护/私有成员还会影响类的类型兼容，不能把所有类都简化成任意结构一样即可。

## 最小例子

```typescript
class Counter {
  readonly id = "a";
  private cache = 1;
  #secret = 2;
  total() { return this.cache + this.#secret; }
}
const counter = new Counter();
console.log(Reflect.get(counter, "cache")); // 1，TS private不是运行期秘密
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.8.public-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。

## 场景、边界与误区

可用于实例状态，但不要求为了学修饰符把清晰纯函数重写成类。秘密不能只靠前端private字段保护，浏览器代码仍由用户掌控。

## 移动开发对照

与Dart/Kotlin访问控制的语法用途相似，不同语言的库边界、运行期和编译产物不能按关键词推断相同。
