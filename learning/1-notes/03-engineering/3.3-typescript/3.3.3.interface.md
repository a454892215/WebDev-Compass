# 3.3.3 interface与type：结构契约和声明合并

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 前置与目标

基础类型、对象属性、可选字段。

## 原理与选择

interface常用于对象契约，可extends并支持同名声明合并；type能命名对象、联合、元组等，不能依相同名字重复定义来合并。

多数对象兼容按结构判断：有需要字段即可，不要求显式implements。新鲜对象字面量的多余属性检查与变量赋值情形不同。

二者没有“interface一定更安全”的通用结论。对外契约保持清楚并避免无意全局合并；类型名在运行时不存在，不能instanceof一个interface。

## 最小例子

```typescript
interface Named { title: string }
type Id = string | number;
const full = { title: "课程", extra: true };
const named: Named = full; // 结构兼容，不会删除extra
console.log(named.title, "extra" in named);
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.3.interface-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。

## 场景、边界与误区

模型类型应表达业务字段，不能为了复用让一个巨型interface含所有可选属性。精确运行期JSON字段限制仍需解码器。

## 移动开发对照

Kotlin/Dart接口通常围绕名义声明关系；TS普通对象可以仅结构相符而赋值，不能机械类比。
