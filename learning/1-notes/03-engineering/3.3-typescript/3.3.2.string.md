# 3.3.2 基础类型、unknown、元组与enum

## 前置与目标

先学3.3.1，复用阶段1基本JS值与函数。

## 原理与选择

string/number/boolean、小写原始类型与数组描述值形状；元组固定位置的意义，readonly元组不等于运行期冻结。

unknown要求先收窄才访问；any主动退出大部分检查，错误可能一路传播。void表示调用方忽略返回结果的契约，never表示不应正常返回或不可达。

null/undefined在strictNullChecks下需要显式处理；数组越界需noUncheckedIndexedAccess或业务检查。enum一般生成运行期对象，不是全部TS语法都会擦除；某些仅剥离类型的执行器不支持enum。

## 最小例子

```typescript
const pair: readonly [string, number] = ["a", 1];
const incoming: unknown = { title: "课程" };
if (typeof incoming === "object" && incoming !== null && "title" in incoming) {
  console.log(incoming.title); // 此处仍需检查title的具体类型
}
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.2.string-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。
