# 3.3.9 ES模块、type-only import与声明文件

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 前置与目标

阶段1 ESM；3.2构建与包入口。

## 原理与选择

普通import/export组织运行时模块；import type只在类型系统中使用，编译后应擦除。Node、浏览器与打包器解析规则不同，示例明确NodeNext与.js后缀。

声明文件描述现有运行时API，不自动生成函数、变量或安装依赖。错误声明会让编译器相信不存在的事实。

包的types/exports与.d.ts需和实际产物一致；全局声明慎用，优先模块范围。运行时库缺失与类型声明缺失是两种错误，不能随手declare module any掩盖。

## 最小例子

```typescript
// contracts.ts
export interface Task { title: string }
// consumer.ts
import type { Task } from "./contracts.js";
const task: Task = { title: "模块" };
console.log(task.title);
```

此处是本节机制片段；完整可编译源和反例见[运行实验](../../../2-examples/03-engineering/3.3-typescript/3.3.9..d.ts-demo.md)。类型检查与运行输出分别观察，不能把注释当编译器证据。

## 场景、边界与误区

实验types/build-meta.d.ts声明BUILD_META；Node里typeof BUILD_META仍是undefined。真实代码直接读取未实现的变量会ReferenceError，类型检查通过不补运行时。

## 移动开发对照

可对照原生平台头文件/接口描述的部分作用，但TS声明不是二进制链接器，也不等于运行时实现存在。
