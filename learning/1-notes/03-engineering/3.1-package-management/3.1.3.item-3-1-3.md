# 3.1.3 SemVer：范围、零主版本与预发布

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 解决什么问题与前置

为什么同一依赖范围在不同时间可能得到不同版本？

前置：3.1.1，理解主/次/修订版本。

## 原理与规则

1. SemVer表达兼容承诺，不自动证明代码确实兼容。^1.2.3通常允许1.x范围；~1.2.3通常限1.2.x。精确版本只固定直接声明，完整依赖图仍由锁文件记录。

2. 零主版本的caret更窄：^0.2.3不接受0.3.0，^0.0.3不接受0.0.4；不能套用“caret永远允许所有次版本”口诀。

3. 预发布版本默认不随普通范围接受，除非范围明确包括相应预发布约束；用官方SemVer规则或实现验证边界。

## 最小例子

```javascript
import semver from "semver";
console.log(semver.satisfies("0.3.0", "^0.2.3")); // false
console.log(semver.satisfies("1.2.9", "~1.2.3")); // true
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.1-package-management/3.1.3.item-3-1-3-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

可对照移动依赖版本约束，但具体范围算法不同，不能把Dart/pub或Gradle动态版本语法直接搬来。

## 场景与误区

不是所有包严格遵守兼容承诺；锁版本和升级回归仍需要。
