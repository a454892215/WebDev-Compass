# 3.1.2 npm、Yarn、pnpm：安装、脚本与本地打包

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 解决什么问题与前置

理解命令职责，避免混用工具或把“打包”误当已发布。

前置：3.1.1与命令行；本库默认pnpm，npm/Yarn作为对照。

## 原理与规则

1. install安装依赖，run执行scripts，workspace相关命令定位子包；不同工具的锁文件、安装布局和命令参数不能简单互换。

2. pnpm --filter按包选择任务，npm可用--workspace定位；Yarn版本代际配置不同，按项目packageManager和官方文档选择。

3. publish是向注册表发布的外部写入；本课只做本地pack检查tarball，private或dry-run不等于完成发布。本轮不执行真实publish或全局安装。

本实验固定 pnpm 11：`.npmrc` 只用于认证/registry，`storeDir` 等专有配置写在 `pnpm-workspace.yaml`；本地缓存设为 `storeDir: node_modules/.pnpm-store`。可运行 `pnpm config get storeDir` 与 `pnpm store path` 核实，不能把 pnpm 10 配置习惯直接套用。

## 最小例子

```bash
pnpm install --frozen-lockfile
pnpm run check
pnpm --filter @compass/demo start
pnpm --filter @compass/math pack --pack-destination /tmp/stage3-pack
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.1-package-management/3.1.2.npm-yarn-pnpm-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

类似移动端依赖下载、任务执行与产物归档的分工；npm注册表发布不是生成APK或本地构建的同义词。

## 场景与误区

不要在同一包随意轮流install生成三种锁；先识别仓库约定，迁移包管理器需要审查依赖与CI。

## 实验与独立练习

在package-lab运行默认脚本、filter子包与本地pack；检查tarball清单。npm/Yarn只阅读对应命令映射，本轮不声称全部工具安装实测。

## 综合实践关联

用任务板既有pnpm脚本完成安装与检查；若评估发布，先以pack核对文件而不真实上传。

已有能力与副本扩展分开，按阶段综合项目的实际代码判断，不为覆盖知识点强加工具。
