# 3.1.1 package.json：依赖、脚本与运行环境

[章节目录](./README.md) · [知识地图](../../../../knowledge-map/02-engineering-stages-3-5.md)

## 解决什么问题与前置

一个工程怎样说明需要哪些包、可以运行什么命令、支持哪个Node环境？

前置：阶段0包管理与阶段2模块；先阅读manifest再执行命令。

## 原理与规则

1. dependencies用于包运行所需依赖，devDependencies用于开发、构建和测试工具；对于浏览器应用，最终哪些代码进入产物由导入与构建决定，不能把devDependencies等同“不会进入客户端”。

2. scripts定义可审核的命令，pnpm run使用本项目的可执行工具；engines声明环境范围，是否硬拒绝取决于工具与配置，不能替代实际运行记录。

3. private:true可防误发布本包；packageManager可固定团队工具选择，但不是自动安装所有环境的保证。版本与锁文件需要一起维护。

## 最小例子

```json
{"private":true,"scripts":{"check":"node scripts/check.mjs"},"engines":{"node":"^24.15.0 || >=26.0.0"},"devDependencies":{"semver":"7.8.6"}}
```

以上片段用于解释规则；运行上下文与源文件见[本点实验](../../../2-examples/03-engineering/3.1-package-management/3.1.1.package.json-demo.md)，不要把配置片段粘贴进错误工具或空白Node文件。

## 移动端经验对照

类似移动工程的依赖与任务清单，但package安装、浏览器打包与运行部署不是Gradle/pubspec逐字段等价。

## 场景与误区

不要靠移动依赖分类机械判断浏览器代码是否暴露；scripts可以执行任意本机命令，先读再跑。

进入package-lab，阅读根manifest及packages/app/package.json，再运行pnpm check与pnpm workspace；分别观察工具依赖和workspace运行依赖。
