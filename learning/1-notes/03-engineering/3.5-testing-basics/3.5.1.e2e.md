# 3.5.1 测试分层：单元、组件与端到端如何配合

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

单元测试隔离纯逻辑或少量依赖；组件测试验证渲染、交互与事件契约；端到端测试从用户入口贯穿浏览器流程。分层按风险和反馈速度选择，金字塔是经验模型，不是必须满足的数量比例。同一断言不必机械在所有层重复。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ts
// 纯函数边界
expect(() => addTask([], " ", 1)).toThrow()
// 用户流程则交给浏览器：填写标题 → 添加 → 完成 → 撤销
```

## 运行与观察

lab 的 domain/service 测试运行在 Vitest；Vue 组件 mount 在 jsdom；Playwright 在真实 Chrome 打开原生页面。三类证据各有范围：mock HTTP 没有验证真实服务器，jsdom 没有验证真实排版。

## 使用场景与误区

适合制定最小充分回归。导入解析的多种非法输入放单元；props/emits 放组件；表单可用和文本安全放关键 E2E。移动视口只验证布局尺寸，不能称手机真机或完整无障碍认证。

## 移动端经验对照

对应移动开发的单元/Widget或组件/集成测试分工；DOM模拟器与浏览器差异类似测试宿主与真实设备差异，但实现并非同一套。
