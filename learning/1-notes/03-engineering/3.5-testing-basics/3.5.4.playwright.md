# 3.5.4 Playwright：用可访问定位和条件等待验收用户流程

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

Playwright 在实际浏览器上下文操作页面。getByRole/getByLabel 优先表达用户可见语义；动作自动等待可操作条件，expect定位器断言等待目标状态。条件等待针对观察对象，固定 waitForTimeout 既慢又易在慢机失败。每个测试使用隔离上下文，自己创建所需数据。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ts
await page.getByLabel("任务标题").fill("阅读规范")
await page.getByRole("button", { name: "添加任务", exact: true }).click()
await expect(page.getByRole("button", { name: "完成：阅读规范", exact: true })).toBeVisible()
```

## 运行与观察

完整 e2e/tasks.spec.ts 以实际按钮名称/结构为准。Chrome 启动Vite后添加含HTML字符的标题、确认没有注入节点、完成和撤销；桌面1440×900与手机视口390×844各执行一次，并检查页面错误与横向溢出。

## 使用场景与误区

适合关键跨层流程；稳定选择器仍依赖正确标签和明确范围。两个视口不是所有浏览器和手机真机。现有Chrome路径仅为本机便利；其他机器用 CHROME_PATH 或按官方方式安装匹配浏览器，不能宣称零环境依赖。Cypress为选修对照。

## 移动端经验对照

类似移动集成测试的用户操作，但在隔离浏览器上下文执行；选择可访问名称比依赖DOM层级或像素坐标稳定。
