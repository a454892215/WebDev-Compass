# 3.5.3 Vue Test Utils：挂载 Vue 3 组件并验证 props/emits

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

本节主线用 Vue Test Utils v2 测 Vue 3；历史路径保留以保护链接，React Testing Library 为选修。组件细节在阶段4展开，这里只引入 defineComponent、h、props、emits 所需最小概念：父级传状态，子级发事件请求改变，测试不能假定子级自动拥有父状态。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ts
const wrapper = mount(TaskButton, {
  props: { task: { id: 1, title: "阅读", done: false } },
})
await wrapper.get("button").trigger("click")
expect(wrapper.emitted("toggle")).toEqual([[1]])
```

## 运行与观察

完整 component.test.ts 导入 mount/expect，enableAutoUnmount(afterEach) 清理挂载。点击后检查 emitted，再 setProps(done:true) 检查 aria-pressed；没有把 jsdom 挂载称为真实浏览器截图。

## 使用场景与误区

适合组件公开契约。await trigger/setProps 等待 Vue 更新；不要只断言内部实例私有变量。jsdom不提供可靠真实布局，ARIA属性存在也不证明屏幕阅读器全部通过。此例用h避开尚未学习的SFC编译配置。

## 移动端经验对照

类似 Widget 测试验证输入属性、点击与回调；Vue 的响应更新和 DOM 是自身机制，不能直接照抄 Flutter pump 语义。
