# 3.5.2 Vitest：边界断言、异步失败和依赖替身

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

Vitest 用 test/it 定义场景，expect 断言可观察结果。vi.fn 可替代依赖并检查调用。异步断言需要 await/return，否则测试可能在失败前结束。隔离并清理替身，避免前一个测试污染后一个。测试应围绕契约而非复制实现。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ts
const fetcher = vi.fn().mockResolvedValue({
  ok: false, status: 503, json: vi.fn(),
})
await expect(loadTasks(fetcher)).rejects.toThrow("503")
```

## 运行与观察

查看 service.test.ts 的完整 import 与 fixture：HTTP错误时不解析 JSON；还验证传输、JSON解析和协议失败。domain.test.ts 测空白、重复ID、非法 unknown 输入与不可变更新。verify:tools 的受控错误断言确实导致非零退出后清理。

## 使用场景与误区

适合快速业务边界回归。mock 成功只证明代码处理这个替身，不证明真实网络协议；外部响应仍要 runtime decode。Jest 可选对照，本课程主线不重复安装。

## 移动端经验对照

类似 Dart test + mock 注入，但 JS Promise 必须被测试等待；类型断言 as 不能验证网络数据。
