# 3.5.5 覆盖率与测试边界：用报告发现遗漏而非追逐数字

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

行、语句、函数和分支覆盖率是执行覆盖信号，不能证明断言正确。显式 coverage.include 把目标源码纳入分母，避免未import文件被遗漏。阈值是项目回归约束，不是跨项目通用质量等级；更不能为了通过随意排除未测业务文件。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ts
coverage: {
  provider: "v8",
  include: ["src/domain.ts", "src/service.ts", "src/TaskButton.ts"],
  reporter: ["text", "json-summary"],
}
```

## 运行与观察

pnpm coverage 实际执行14项测试，报告包含3个目标源码。本轮语句96.42%、分支93.33%、函数100%、行100%；数字只描述此fixture，此例防御分支仍有未执行路径。检查漏行要结合协议和可达性，不能制造无意义用例凑100%。

## 使用场景与误区

适合发现错误分支和未覆盖模块。报告 include 不含浏览器 main.ts；该UI流程另由Playwright验收，此测试报告不是全工程100%。生产服务、跨浏览器、安全攻防和真实学习掌握均未由这些数字证明。

## 移动端经验对照

类似 Dart 覆盖率但 provider和插桩不同；同样不能用高覆盖率代替断言质量与真实使用场景。
