# 3.4.6 Git ignore 与 npm 打包：分别核对跟踪范围和发布产物

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

.gitignore 控制未跟踪文件的忽略，不会取消已跟踪文件。git ls-files 查看索引，git check-ignore 观察匹配。npm 包的文件集合是另一套规则：有 .npmignore 时不会再把 .gitignore 当同等兜底；优先用 package.json files 明确允许分发文件，并核对实际清单。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```text
git ls-files
git check-ignore node_modules/demo.js
npm pack --dry-run --json --ignore-scripts
```

## 运行与观察

verify:tools 在临时仓库证明已跟踪 sample.js 后来被忽略仍留在索引；临时 npm 包用无敏感内容的 dummy-secret.txt 证明 .npmignore 与 .gitignore 的差异，补规则后 dry-run 清单不再包含它。没有发布任何包。

## 使用场景与误区

适合阻止产物和本地配置误入库/包；忽略不是加密或秘密防线。真实凭据泄漏须撤销/轮换，删除工作区文件不删除历史。git rm --cached 会修改索引，先核对目标，不在本课程主仓库批量执行。private:true 防误发布但不替代产物审查。

## 移动端经验对照

类似移动端排除 build、签名文件；npm 包发布清单与 Git 仓库可见性是不同维度。
