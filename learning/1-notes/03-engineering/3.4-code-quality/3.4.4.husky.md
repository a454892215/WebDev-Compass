# 3.4.4 Husky + lint-staged：在暂存文件上执行提交前检查

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

Git hooks 是 Git 生命周期中的本地脚本。Husky 配置仓库 hook 入口，lint-staged 获取暂存路径并把匹配文件交给工具。全项目类型检查不是简单给 tsc 追加暂存文件；涉及跨文件类型时仍跑项目脚本。先区分工作区、暂存区和提交。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ts
// lint-staged.config.mjs（示意；先在独立临时仓库）
export default {
  "*.{js,ts}": "eslint",
}
```

## 运行与观察

本例不在学习仓库运行 husky init/prepare。pnpm verify:tools 创建临时 Git 仓库、设置该临时仓库 .husky/_，暂存 debugger 并证明提交失败；修复、重新暂存后提交成功。临时仓库随后删除。

## 使用场景与误区

适合快速本地反馈；hook 可被跳过，不是服务端权限或安全边界。团队仍需独立自动化检查。husky init 会改 package.json 和仓库配置，不能未经判断在已有仓库执行；本例不提供真实主仓库 hook 安装。

## 移动端经验对照

类似提交前 analyzer 脚本，但 Git 暂存区是独立快照；只改工作区并不保证提交内容已修复。
