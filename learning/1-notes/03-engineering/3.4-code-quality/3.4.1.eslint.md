# 3.4.1 ESLint：用 flat config 检查代码质量

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

ESLint 解析源码并按规则报告问题。flat config 是配置对象数组；files 决定匹配范围，ignores 排除产物。typescript-eslint 使规则理解 TypeScript 语法；基础 recommended 不等于全部类型感知规则。tsc 负责类型检查，两者需要分别执行。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ts
import js from '@eslint/js'
import tseslint from 'typescript-eslint'
export default [js.configs.recommended, ...tseslint.configs.recommended]
```

## 运行与观察

运行 pnpm lint；再运行 pnpm verify:tools，临时 debugger 触发 no-debugger，进程返回非零。配置文件不会自己执行；编辑器诊断依赖对应插件和工作区设置，终端脚本才是可复现入口。

## 使用场景与误区

适合捕捉未使用变量、危险写法等。规则作用域必须匹配 ts 文件；不要用关闭全部规则解决误报。推荐集随版本变化，锁定依赖和锁文件。ESLint 不负责取代测试或统一所有排版。

## 移动端经验对照

类似 Dart analyzer 的部分职责，但 Dart 格式化、类型检查和 lint 在 Web 中通常是多个工具；没有装编辑器插件也应能运行 CLI。
