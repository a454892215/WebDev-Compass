# 3.4.3 EditorConfig：约定编辑器缩进、换行与编码

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

.editorconfig 是编辑器/工具可读取的文本约定。root=true 停止向父目录查找；section glob 选择文件，后匹配的属性可覆盖前面。indent_size、end_of_line 和 insert_final_newline 等不等同完整语法格式化。只有支持它的工具或插件会应用。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ini
root = true
[*]
charset = utf-8
indent_style = space
indent_size = 2
end_of_line = lf
insert_final_newline = true
```

## 运行与观察

verify:tools 在隔离目录把 indent_size 设成4，通过 Prettier.resolveConfig(...,{editorconfig:true}) 读到 tabWidth:4，并实际格式化出四空格。这证明支持工具的读取；没有冒充所有编辑器保存行为已测试。

## 使用场景与误区

适合跨编辑器基础约定。Prettier 显式配置可以覆盖其映射的 EditorConfig 属性；charset 不会替你把既有二进制或坏编码自动修好。Markdown 尾空格可能有意义，可单独设 trim_trailing_whitespace=false。

## 移动端经验对照

类似团队IDE代码样式约定，但它是工具无关的部分属性协议；不能像某个IDE配置一样假设人人自动启用。
