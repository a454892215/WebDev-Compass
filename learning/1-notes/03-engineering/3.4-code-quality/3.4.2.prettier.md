# 3.4.2 Prettier：统一排版并用 check 阻止漂移

前置：阶段2 JavaScript 与阶段3.1–3.3 包管理、脚本、TypeScript。目标：能解释本节机制、运行真实检查并定位一种失败。组件最小概念在3.5.3解释，完整 Vue 3 留到阶段4。

## 解决的问题与机制

Prettier 把源码解析后重新打印为统一风格；它关注排版。--write 改写文件，--check 比较结果并用退出码表示差异。ESLint 检查质量时避免再启用一套相互冲突的排版规则；此项目不需要把 Prettier 包成 ESLint 规则。

## 最小例子

以下片段对应完整共享实验工程；依赖、import 和脚本以其源文件为准，不作为脱离上下文的完整工程。

```ts
pnpm exec prettier --write src/domain.ts
pnpm format:check
```

## 运行与观察

实验配置使用 semi:false、singleQuote:true。verify:tools 对未排版 fixture 调用 --check，确认返回非零且文件未被重写；校验样本显式跳过 ignore 文件，避免误把“无匹配文件”当有效检查。

## 使用场景与误区

适合提交前和自动化检查中统一差异。格式正确不代表类型、业务逻辑或安全正确；--write 先看差异，避免对整个他人仓库做无关排版。配置必须由执行入口读取才生效。

## 移动端经验对照

类似 dart format；并非等同整个 analyzer。Web 多语言文件与忽略规则较多，要核对实际检查范围。
