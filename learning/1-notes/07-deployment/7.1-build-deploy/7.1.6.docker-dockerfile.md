# 7.1.6 Docker 多阶段构建：构建工具与 Node 运行镜像分离

前置：阶段3构建/类型/测试、阶段4 Nuxt与阶段6缓存/安全；本点聚焦首次生产交付。先说明产物/请求如何流转，再操作，不能把开发服务器当生产部署。

## 解决什么问题与原理

多阶段Dockerfile用构建阶段安装与编译，再将必要.output复制到运行阶段。运行镜像无需完整源码/开发依赖，但Nuxt server构建所需运行文件必须完整保留；只COPY public不能运行SSR。静态profile通常由静态服务器镜像提供，不需Node SSR进程。

## 选择、边界与误区

镜像tag、平台架构、libc、Node版本及原生依赖会影响可运行性；不盲目跨平台拷node_modules。用非root运行、明确工作目录和环境、通过exec形式CMD接收信号。秘密不放ARG/ENV构建层，.dockerignore排除.env/缓存/本机输出；生产按审核过digest固定镜像并更新。

## 最小观察

阅读release-lab/templates/Dockerfile.example和.dockerignore.example，按说明以主Nuxt目录为构建上下文。此轮只核对模板，不启动Docker daemon/Colima、不下载镜像、不宣称容器构建运行通过。

完整代码与命令见[发布lab](../../../2-examples/07-deployment/7.1-build-deploy/release-lab/README.md)。平台、Docker、远端CI明确为观察/模板；真正本地运行记录不替代它们。

## 移动开发对照

类似移动端构建包与发布渠道需要版本/恢复证据，但Web资源可能在页面生命周期中分批加载，HTML、JS、服务端和CDN可各自变更；回滚服务器不等于撤回已经执行的客户端或业务写入。不能直接套APK安装的原子包假设。
