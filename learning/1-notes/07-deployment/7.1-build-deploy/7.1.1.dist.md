# 7.1.1 Vite dist 与 Nuxt .output：识别可部署产物

前置：阶段3构建/类型/测试、阶段4 Nuxt与阶段6缓存/安全；本点聚焦首次生产交付。先说明产物/请求如何流转，再操作，不能把开发服务器当生产部署。

## 解决什么问题与原理

部署的输入是构建产物，而不是开发服务器或源码目录。Vite默认dist是静态文件；Nuxt Node SSR的.output包含server入口及public资源，只上传public会丢失请求渲染与API。Nuxt generate输出静态public目录，没有可执行的私有服务端；CSR和SSG都能静态托管，但原始HTML内容不同。

## 选择、边界与误区

资源hash用于内容寻址和缓存失效，不是版本号、加密或部署成功证明。发布应保存代码提交、锁文件、构建命令、Node/包管理器、profile及产物摘要。不要把打包后的JavaScript当秘密存储；Source Map控制发布可见性但不替代服务端权限。

## 最小观察

在综合目录执行pnpm build、pnpm build:ssg、pnpm build:csr（顺序执行），查看artifacts/ssr/server/index.mjs与artifacts/{ssg,csr}/public；对比SSG课程HTML与CSR壳。三个脚本真实存在，最终执行结果由主项目运行记录提供。

完整代码与命令见[发布lab](../../../2-examples/07-deployment/7.1-build-deploy/release-lab/README.md)。平台、Docker、远端CI明确为观察/模板；真正本地运行记录不替代它们。

## 移动开发对照

类似移动端构建包与发布渠道需要版本/恢复证据，但Web资源可能在页面生命周期中分批加载，HTML、JS、服务端和CDN可各自变更；回滚服务器不等于撤回已经执行的客户端或业务写入。不能直接套APK安装的原子包假设。
