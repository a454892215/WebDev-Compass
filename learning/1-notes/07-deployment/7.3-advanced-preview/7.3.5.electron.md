# 7.3.5 Electron/Tauri：桌面壳与原生权限边界

前置：阶段1原生HTML/JS、阶段3模块/测试、阶段4 Vue/Nuxt。业务选修，不阻塞首次交付；先读机制再按需实践。

## 解决什么问题与原理

Electron通常携带Chromium与Node运行环境，Tauri前端使用系统WebView并经IPC调用核心能力。应用体积、渲染一致性、系统依赖、插件、签名更新和团队经验需一起权衡，不能用一个安装包体积数字判定优劣。

浏览器DOM经验可复用，但桌面IPC扩大权限面。Electron应保持contextIsolation和沙箱等保护，不向renderer暴露任意文件/命令执行，只暴露小而明确的preload桥；校验来源、参数和返回数据。Tauri按capabilities/permissions限定WebView可调用能力，Rust核心/插件仍有系统权限，不能误认为配置自动约束所有核心逻辑。Nuxt SSR Node服务不能直接当静态WebView文件，需选择可打包前端和服务协议。

## 最小片段与上下文

```javascript
// 纯契约草案；没有加载Electron/Tauri SDK，不是已运行preload。
const desktopContract = {
  command: 'export-course-summary',
  input: { courseId: 'nuxt' },
  forbidden: ['arbitrary-shell', 'arbitrary-file-path'],
  result: { status: 'cancelled-or-saved' }
};
console.log(desktopContract.command);
```

## 应用与边界

类型：官方安全观察。阅读Electron checklist的上下文隔离/沙箱/IPC sender验证及Tauri trust boundaries/capabilities。为“导出课程摘要”画renderer→限定桥→系统保存对话框路径，加入用户取消和路径校验。没有安装、启动、签名或打包桌面壳；普通Chrome测试不覆盖桌面原生权限。

## 移动开发对照

熟悉Android平台通道或RN原生模块有助于理解IPC，但Electron/Tauri暴露的是桌面系统权限；浏览器页面输入需要在核心侧再次校验，桌面签名、更新和沙箱要分别验证。
