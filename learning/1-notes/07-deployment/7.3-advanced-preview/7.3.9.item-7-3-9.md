# 7.3.9 低代码原理：Schema白名单、渲染器与版本迁移

前置：阶段1原生HTML/JS、阶段3模块/测试、阶段4 Vue/Nuxt。业务选修，不阻塞首次交付；先读机制再按需实践。

## 解决什么问题与原理

低代码通常把受约束的页面/流程表示为schema，通过组件注册表和渲染器生成界面。可视化设计器只是输入方式，核心还包括schema版本、验证、数据绑定、权限和发布。适合稳定且可枚举的结构，不保证任意需求都能零代码实现。

本例只允许version:1和heading/text节点，验证完整输入后再创建DOM；文本走textContent，不使用eval、Function或任意组件名解析。拒绝未知字段/节点和过大输入是有意的范围控制。JSON Schema是通用验证标准，但本lab手写小型校验，不冒充实现整个标准。权限仍在服务端，隐藏组件不是授权；迁移/回滚需要旧渲染器能读哪个版本的契约。

## 最小片段与上下文

```javascript
// optional-lab/logic.mjs与app.mjs完整实现。
const schema = {version:1,nodes:[{kind:'text',text:'<b>这是文字</b>'}]};
// renderSchema先validateSchema，再createElement与textContent。
console.log(schema.version);
```

## 应用与边界

类型：真实白名单schema渲染。启动lab看标题/段落，点击未知script类型后显示拒绝且原内容保留；verify将恶意img字符串作为text节点渲染，确认无img节点/脚本执行。Node还拒绝未知字段、版本和超长文本。没有拖拽设计器、任意表达式或完整低代码平台。

## 移动开发对照

这与移动端动态页面/配置驱动UI有相似职责，但Web的危险HTML、URL、脚本和服务端授权边界必须单独约束；schema只描述允许界面，不能代替可信权限检查。
