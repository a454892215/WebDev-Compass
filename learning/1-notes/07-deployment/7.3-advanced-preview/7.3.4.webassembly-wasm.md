# 7.3.4 WebAssembly：二进制模块、i32与JS边界

前置：阶段1原生HTML/JS、阶段3模块/测试、阶段4 Vue/Nuxt。业务选修，不阻塞首次交付；先读机制再按需实践。

## 解决什么问题与原理

WebAssembly是可在宿主环境执行的低级二进制指令格式，适合复用计算密集代码或现有C/C++/Rust库。它不能直接取代DOM应用：DOM和资源能力由宿主导入/JS桥接提供。下载、编译、内存拷贝和调用边界都有成本，不是天然快于JS。

本lab内嵌可核对的add(i32,i32)模块字节，对应WAT注释放在logic.mjs；instantiate返回module/instance，再通过exports调用。i32加法按32位语义溢出；JS输入转换规则与任意精度运算不同。主线程调用重计算仍会阻塞，实际重任务可放Worker；共享内存/线程另需平台与隔离条件，本例没有这些。

## 最小片段与上下文

```javascript
// 可在optional-lab目录node运行；字节模块在logic.mjs。
import {wasmAdd} from './logic.mjs';
console.log(await wasmAdd(7,5)); // 12
console.log(await wasmAdd(2147483647,1)); // -2147483648
```

## 应用与边界

类型：真实Node和Chrome运行。node --test验证模块可编译、7+5=12、负数和i32溢出、截断二进制拒绝；浏览器点计算得到12。未安装Emscripten、未编译C/C++、未跑WASM性能基准。本例直接instantiate字节；若改instantiateStreaming需服务端application/wasm和正确错误回退。

## 移动开发对照

这与移动端复用C/C++计算库有相似动机，但WASM线性内存、导入函数与JS桥接不是直接调用平台ABI；浏览器主线程阻塞和传输成本仍须测量，不能只看算法内核。
