# 7.3.1 微前端与Module Federation：先确认独立发布边界

前置：阶段1原生HTML/JS、阶段3模块/测试、阶段4 Vue/Nuxt。业务选修，不阻塞首次交付；先读机制再按需实践。

## 解决什么问题与原理

微前端是按业务边界组织前端团队和交付的架构选择；Module Federation是运行时共享/加载其他构建模块的一种机制，两者不是同义词。普通Nuxt项目的模块、路由和懒加载通常已经足够。只有团队独立交付的收益超过依赖协调、首屏、故障和可访问性成本时，才评估微前端。

宿主与远端需约定模块名、输入/事件、版本兼容、共享依赖和失败UI。远端JS通常在宿主上下文执行，不因为来自另一团队就有权限沙箱。独立源iframe提供另一种隔离维度，但也带来通信、焦点、嵌入策略和身份边界。共享Vue单例可减少重复，却要求版本契约；不是把所有库都singleton就安全。

## 最小片段与上下文

```javascript
// 不依赖联邦工具的契约示例；不是可执行的Module Federation配置。
const widgetContract = {
  version: 1,
  input: { courseId: 'nuxt' },
  events: ['open-course'],
  unavailable: '显示本地课程链接，保持主目录可用'
};
console.log(widgetContract.version);
```

## 应用与边界

类型：官方文档与交付设计观察，不运行远程联邦构建。阅读webpack Module Federation中的container/exposes/remotes/shared概念，把主目录中的“课程推荐”假设为可选远端，画出一个宿主/一个远端和失败后的本地链接。核对宿主启动是否依赖远端、两端Vue版本与独立回滚；不要把普通动态import当作已经搭建联邦。

## 移动开发对照

移动端动态模块与微前端都可能服务组织独立交付，但Web远端模块是在浏览器运行时解析、缓存和执行；它不是Android进程隔离或商店分包。宿主与远端的版本故障需要独立回滚契约。
