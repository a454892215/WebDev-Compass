# 7.3.7 数据可视化：原生SVG基础与D3/ECharts/Chart.js取舍

前置：阶段1原生HTML/JS、阶段3模块/测试、阶段4 Vue/Nuxt。业务选修，不阻塞首次交付；先读机制再按需实践。

## 解决什么问题与原理

先确定数据问题、单位、排序、尺度和文字等价，再选图形库。D3是组合数据与图形的低级工具；ECharts侧重现成系列/交互配置；Chart.js以canvas图表为主。它们不等于自动产生正确或可访问的图。

少量数据可先用HTML表格和原生SVG，明确数据到宽度/位置的映射。Canvas需要额外名称、文字或表格等价；图例不能只靠颜色，缩放和实时更新也要检查可读性。框架中初始化需等容器存在，尺寸变化更新并在卸载释放实例/观察器。SSR先输出有意义的数据文字，不在Node模块顶层访问document。

## 最小片段与上下文

```javascript
// 主lab将0..100映射为0..300 SVG单位；数据已在validSeries校验。
const value = 30;
const width = value * 3;
console.log(width); // 90；不是90px物理屏幕长度
```

## 应用与边界

类型：真实原生SVG+表格，不安装三种库。启动lab查看构建30/验证50/发布20分钟，SVG三条与表格三行同源；390/1440视口不横溢出。verify核对条数、数值和非法数据拒绝。选择库是官方资料比较，没有虚报D3/ECharts/Chart.js实例实测。

## 移动开发对照

移动端Canvas/绘图库经验有助于理解坐标与重绘，但Web还要保留DOM中的文字等价、可缩放容器和SSR回退；图形画出来不代表屏幕阅读器已获得数据。
