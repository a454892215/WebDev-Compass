# 7.3.3 GraphQL客户端：查询、部分错误与身份缓存

前置：阶段1原生HTML/JS、阶段3模块/测试、阶段4 Vue/Nuxt。业务选修，不阻塞首次交付；先读机制再按需实践。

## 解决什么问题与原理

GraphQL用schema定义可查询字段，operation和variables描述读取/变更。它不是数据库，也不会替代后端逐资源授权。HTTP成功不代表每个字段成功；响应可以同时包含data与errors，客户端必须根据业务决定保留哪些部分并呈现错误。

Apollo Client、urql提供查询与缓存等能力，具体API/集成包需按选定版本和Vue适配核对；不要直接照搬React hook到Nuxt。归一化缓存按实体身份复用数据，分页合并、字段参数、登录切换和SSR每请求实例均影响隔离。不要在Node全局单例里保存带用户数据的客户端。简单REST契约已足够时，不必为选修改写阶段5API。

## 最小片段与上下文

```javascript
// 合成响应分析，不是网络GraphQL服务或Apollo接入。
const response = {
  data: { course: { id: 'nuxt', title: 'Nuxt' }, recommendations: null },
  errors: [{ message: '暂不可用', path: ['recommendations'] }]
};
console.log(response.data.course.title, response.errors[0].path);
```

## 应用与边界

类型：官方文档/合成响应观察。阅读GraphQL response与Apollo errorPolicy，比较none/all/ignore；为片段标注HTTP错误、请求验证错误、字段错误与正常空值。画出两个用户请求的两个独立客户端及注销后缓存清理。没有建立GraphQL服务，也没有安装Apollo/urql，不把JSON分析称接口实测。

## 移动开发对照

移动客户端也会处理GraphQL归一化缓存；Nuxt新增同一Node进程服务多个请求的维度，因此每请求客户端与缓存隔离不能用移动App的进程单例习惯替代。
