# 7.2.3 Nuxt生产部署：Node SSR、静态托管与身份缓存

前置：阶段3构建与测试、阶段4 Nuxt数据/状态、阶段5身份边界及阶段6质量检查。先读本章机制，再运行操作卡；7.2.2为选修观察，不阻塞Nuxt交付。

## 解决什么问题

开发服务器把许多职责一起提供，生产环境却需要明确交付目录、启动方式、环境变量和代理策略。能运行pnpm dev还不能证明生产产物可部署。

## 原理与选择

Node SSR构建交付完整.output，而不仅public；Node入口是.output/server/index.mjs，生产运行显式设置NODE_ENV=production和受控HOST/PORT。Node运行时可读取匹配NUXT_环境变量覆盖声明过的runtimeConfig；public会进入浏览器payload，private只允许留在server代码，返回到DTO仍会泄露。生产Node入口不会自动读取开发.env，秘密由运行环境安全提供，不能把真实密钥写进仓库或打进前端。

静态生成交付.output/public，不附带可运行server端点。构建时就捕获的公开配置/数据不能指望静态文件在启动时读取新的Node环境变量。静态托管仍须配置资源路径、MIME、缓存、深链和404；只上传目录不等于这些策略全部正确。

routeRules可以分路由配置prerender、ssr、cache/swr与headers；用精确敏感路径覆盖公开缓存规则，并真实核对最终响应。no-store约束HTTP存储，cache:false约束Nitro路由缓存，不自动完成身份认证/授权。Cookie或Authorization身份请求默认不应进入全站共享缓存，代理/CDN也应旁路；不能只在客户端清useFetch就称服务器隔离。

## 最小机制片段

```bash
# 完整Node产物构建后，在其项目目录执行：
NODE_ENV=production HOST=127.0.0.1 PORT=4507 node .output/server/index.mjs
# 这只是标准Node入口；综合项目的profile脚本见其README。
# 不在命令或日志中写真实密钥。
```

## 观察与适用边界

用综合项目SSR profile启动同一构建，改变公开runtime配置并检查原始响应；合成私有标记只在server使用，不进入HTML/payload/客户端资源。对公开和私有路径分别核对Cache-Control，再到SSG静态托管确认server-only端点不存在。

## 常见误区

不要上传.nuxt当生产产物；不要只传.output/public却期待SSR；不要将环境变量都放public；不要给/account或/api/private套公开swr。反向代理信任头与TLS另需部署配置，不因loopback演示就称生产认证完成。

## 移动开发对照

和APK构建配置类似，构建期注入会随产物固定；Nuxt Node另有运行期配置，静态站点则没有同样运行期。客户端拿到的配置始终不能当秘密。
