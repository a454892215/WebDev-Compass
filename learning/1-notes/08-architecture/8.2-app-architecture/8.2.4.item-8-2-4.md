# 8.2.4 模块化路由：URL归属与构建边界分别核对

前置：阶段3模块/测试、阶段4 Vue/Nuxt、阶段5–7身份/缓存/部署。先判断真实约束，再理解机制、做实验与变体；微前端按需，不是普通页面的门槛。

## 解决什么问题与原理

路由是用户可见地址与历史契约，功能域是业务代码边界，chunk是构建产物边界，三者不一一对应。Nuxt pages约定通常生成按需页面入口；公共依赖可能被提到共享chunk，同一功能也可能跨多个路由。不要因为目录放在feature就保证分包、懒加载或权限隔离。直接访问/刷新、参数变更、未知路由和资源404都需按托管能力实测。

## 最小机制片段

```javascript
// lab已有明确地址分配；不是Nuxt routes配置。
const owners = { '/catalog': 'catalog', '/reports': 'reports' };
console.log(owners['/catalog']);
```

片段的上下文由注释说明；标为契约草案的内容不是工具完整配置。完整可执行机制见操作卡，不能把示意代码当联邦/插件平台实装。

## 观察、使用场景与边界

lab点击目录/报表后reload，未知文档和missing.js都404。主项目页面构建由主代理另验；不把lab两段文字叫两个独立部署子应用。

先保持稳定URL，再优化加载；真实bundle边界须查构建，不用微前端解决普通路由组织。

## 移动开发对照

Android/Flutter的业务边界、接口与生命周期经验有助于判断职责；Web还涉及document、origin、URL、异步产物加载和每请求SSR。模块目录不是进程/权限沙箱，不能把移动端运行模型直接等同浏览器。
