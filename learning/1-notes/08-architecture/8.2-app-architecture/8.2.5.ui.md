# 8.2.5 配置驱动UI：受限schema、解释器与安全边界

前置：阶段3模块/测试、阶段4 Vue/Nuxt、阶段5–7身份/缓存/部署。先判断真实约束，再理解机制、做实验与变体；微前端按需，不是普通页面的门槛。

## 解决什么问题与原理

配置描述允许的UI结构，解释器把白名单节点映射到已审核组件。JSON Schema可以验证对象形状，但不会自动完成所有权限、URL安全、跨字段业务规则或渲染净化。需要版本、数量/文本长度限制、未知节点/属性策略和错误回退；先整体校验再修改DOM，避免半渲染。配置不是任意JavaScript，不用eval或配置里的组件路径加载任意代码。

## 最小机制片段

```javascript
// lab只实现有限field白名单，不是完整JSON Schema引擎。
const form = [{ id: 'title', label: '课程标题' }];
console.log(form[0].label);
```

片段的上下文由注释说明；标为契约草案的内容不是工具完整配置。完整可执行机制见操作卡，不能把示意代码当联邦/插件平台实装。

## 观察、使用场景与边界

lab用parseFields+renderForm渲染label/input；带onclick未知属性拒绝，恶意标签留为文本，原有效表单保持。

Schema约束不是安全沙箱；服务端还要核对调用者权限/数据规则，超复杂配置可能比普通组件更难维护。

## 移动开发对照

Android/Flutter的业务边界、接口与生命周期经验有助于判断职责；Web还涉及document、origin、URL、异步产物加载和每请求SSR。模块目录不是进程/权限沙箱，不能把移动端运行模型直接等同浏览器。
