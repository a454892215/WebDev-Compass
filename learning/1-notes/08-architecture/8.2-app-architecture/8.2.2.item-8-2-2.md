# 8.2.2 分层与依赖反转：调用方向不等于导入方向

前置：阶段3模块/测试、阶段4 Vue/Nuxt、阶段5–7身份/缓存/部署。先判断真实约束，再理解机制、做实验与变体；微前端按需，不是普通页面的门槛。

## 解决什么问题与原理

Presentation展示交互，Application编排用例，Domain表达稳定规则，Infrastructure实现网络/存储端口。运行时可能从页面调用应用再访问适配器；源码依赖不应机械形成Domain→Infrastructure。端口由内层定义或用最小结构类型描述，外层组合具体实现；依赖反转让应用可以用合成端口验证。不是每个小函数都要interface/class/四层目录；跨层DTO校验和权限仍需明确责任。

## 最小机制片段

```javascript
// application函数依赖port形状，不导入具体HTTP实现。
export async function listTitles(port) {
  const rows = await port.list();
  return rows.map(row => row.title);
}
```

片段的上下文由注释说明；标为契约草案的内容不是工具完整配置。完整可执行机制见操作卡，不能把示意代码当联邦/插件平台实装。

## 观察、使用场景与边界

在lab运行pnpm test，listTitles用异步合成port成功，坏DTO拒绝；再核读主项目端口注入与server/api组合位置，不把fixture调用写成真实远程HTTP。

不要把“少依赖”变成没有验证；DTO在边界校验，权限由真实服务端执行而非TypeScript类型决定。

## 移动开发对照

Android/Flutter的业务边界、接口与生命周期经验有助于判断职责；Web还涉及document、origin、URL、异步产物加载和每请求SSR。模块目录不是进程/权限沙箱，不能把移动端运行模型直接等同浏览器。
