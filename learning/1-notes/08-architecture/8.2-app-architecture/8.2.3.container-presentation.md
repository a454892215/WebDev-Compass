# 8.2.3 容器与展示组件：按变化原因分职责

前置：阶段3模块/测试、阶段4 Vue/Nuxt、阶段5–7身份/缓存/部署。先判断真实约束，再理解机制、做实验与变体；微前端按需，不是普通页面的门槛。

## 解决什么问题与原理

容器负责数据获取、URL/状态与失败分支；展示组件接收明确props并发出意图事件。分离的收益是可独立验证UI与复用，不是所有组件都必须成对命名Container/View。Vue props单向传递，但嵌套对象仍能被子组件间接修改，不能误认只读类型就是深不可变；用事件把所有权留给调用者。复杂编排常放composable而非再包三层组件。

## 最小机制片段

```typescript
// Vue展示组件上下文：不在此请求接口。
defineProps<{ title: string; selected: boolean }>();
defineEmits<{ select: [] }>();
```

片段的上下文由注释说明；标为契约草案的内容不是工具完整配置。完整可执行机制见操作卡，不能把示意代码当联邦/插件平台实装。

## 观察、使用场景与边界

核读主项目features/catalog/components与application，定位UI输入/输出、请求和过滤责任。lab插件只验证挂载/销毁，不冒称Vue组件测试。

按实际变更边界拆，不以文件数衡量架构；可读的小组件保留局部状态是合理的。

## 移动开发对照

Android/Flutter的业务边界、接口与生命周期经验有助于判断职责；Web还涉及document、origin、URL、异步产物加载和每请求SSR。模块目录不是进程/权限沙箱，不能把移动端运行模型直接等同浏览器。
