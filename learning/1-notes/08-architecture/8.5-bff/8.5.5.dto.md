# 8.5.5 DTO映射：运行校验、公开字段与时间/null契约

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 解决什么问题与原理

TypeScript接口不能验证网络字节。把上游unknown先校验结构/范围，再显式映射到内部/公开模型；驼峰转换不是权限过滤，也不能把原对象展开后只改几个key。区分字段缺失、null和0/空串，明确日期是瞬间、日历日期还是本地时间，货币金额不能仅靠显示格式解决精度。

只把UI需要的字段送出；内部备注、上游凭据与审计字段留在server。日期转换采用明确格式/时区，非法/溢出日期拒绝；需要完整多格式协议时用适合的校验器。本lab仅接受UTC秒精度ISO或null，不宣称支持全部ISO8601、时区或真实世界schema。

## 最小机制片段

```typescript
const dto = {id:raw.course_id,title:raw.display_name,updatedAt:raw.updated_at};
// 此片段须在raw通过运行校验后使用；完整校验见bff-lab/mapCatalog。
```

片段的Nuxt/校验上下文按注释使用；设计对象/伪码不冒充已运行框架工程。

## 观察、场景与误区

真实lab mapCatalog去除internal_note，保留null；数字标题、错类型id、非法日期与2026-02-30拒绝。必要上游DTO坏时BFF502，不伪造空成功。主Nuxt自己的契约与映射另读源码，不假设与本lab字段完全相同。

故障：return {...raw,courseId:raw.course_id}把internal_note带出。改显式白名单映射并断言序列化结果不含该字段，类型删字段不等于运行对象已删除。

## 移动开发对照

类似移动端JSON模型转换，但Web SSR还需审查HTML/payload和客户端bundle中的公开结果。
