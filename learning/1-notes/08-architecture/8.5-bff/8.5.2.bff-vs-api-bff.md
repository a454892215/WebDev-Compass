# 8.5.2 BFF还是直连API：用网络与职责收益抵偿运维成本

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 解决什么问题与原理

直连稳定后端契约可减少一个部署/跳转/故障层；当多个上游、客户端裁剪、保密服务凭据或不同终端适配带来真实重复时，再评估BFF。是否同一个域名、是否反代和是否BFF是不同维度；同源代理也不能自动修复后端权限或任意URL SSRF。

引入后需要责任人、版本契约、超时/限额、监控、缓存和回滚。BFF仅接受业务参数并映射到固定目标，不让请求参数决定协议/主机/端口；禁跳转并配网络出口规则，不能只用startswith校验URL。多端可共享核心业务服务，是否各建BFF看差异而非照抄PC/H5两个UI仓库。

## 观察、场景与误区

真实lab给/api/v1/workspace增加url=https://example.com输入，返回400且上游请求计数不变；所有真实请求只到本实验固定127.0.0.1端口。没有向外部或内网地址做攻击。主项目进程内adapter不是独立微服务。

故障：写/api/proxy?url=任意输入并自动跟随重定向。改固定服务映射、参数白名单和redirect:error，生产再核对DNS/网络出口；不要在真实私网演示。

## 移动开发对照

移动端拦截器能统一客户端错误，但不能承担服务器保密凭据与上游授权职责。
