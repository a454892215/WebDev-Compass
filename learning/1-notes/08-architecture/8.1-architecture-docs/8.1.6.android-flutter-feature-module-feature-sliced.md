# 8.1.6 移动端模块化与Vue/Nuxt：复用目标，区分运行约束

前置：阶段3类型/检查与阶段4–7 Vue/Nuxt、API、质量和部署。先明确约束，再读机制、观察和变体。

## 解决什么问题与机制

Android/Flutter业务模块与Web feature都希望局部变更、稳定接口、可替换依赖，但编译、运行、分发和状态生命周期不同。Web源码模块不是浏览器沙箱、独立部署或进程隔离；Nuxt模块顶层可变对象可能被多个请求共享。Flutter经验用于职责/契约/测试，不照搬全局容器或第三方框架。

## 最小项目观察

对照docs/ARCHITECTURE.md与代码：shared纯契约可两端编译，server端口只在服务端组装；useState在每次Nuxt应用内建立状态，收藏虽跨组件共享却不靠Node模块单例。当前scope为公开样例，不是登录隔离实现。

相关代码和完整运行条件见示例；这里的路径以综合项目根为基准。

## 使用场景、误区与移动端对照

基座复用规范与纯模块，宿主可保持不同UI；使用Web原生/框架适配的生命周期和状态管理。

移动经验可用于边界/契约与测试；Web仍需单独核对浏览器、SSR每请求与产物生命周期，不按目录或API相似推断能力。
