# 8.6.5 Offline-first：IndexedDB、幂等队列与显式恢复

前置：阶段2异步/存储、阶段4 Vue/Nuxt状态与数据、阶段5身份边界、阶段6缓存。先学8.6.1/2归属与key，再并发/过期/离线，最后按需选择协作模型。

## 解决的问题与机制

先明确断网时哪些读取/编辑仍应工作，再设计本地事实与同步协议。IndexedDB提供异步结构化存储和事务；request成功不等于整个事务完成，保存提示应等transaction.complete，并处理abort、配额、blocked、版本升级与存储驱逐。它不是原生安全存储，也不能承诺永久不丢。

离线写队列需要scope、稳定operation id、基准版本、去重与确认后删除；服务器也需持久幂等保证。navigator.onLine只是提示，不等于服务健康；显式请求失败才是本次证据。Background Sync依赖安全上下文/ServiceWorker和支持情况，调度不能保证按时执行，必须有前台显式重试。

本lab已有页面可断网写草稿和入队，真实IndexedDB刷新恢复；没有App Shell/SW离线导航，断网刷新页面仍可能打不开。服务端幂等表只在本进程，重启丢失；这不是完整离线PWA或生产同步后端。

## 最小片段与上下文

```javascript
import { openDB, saveDraft, enqueue } from './storage.mjs'
// 浏览器、state-lab的storage模块上下文：
const db = await openDB()
await saveDraft(db, 'alice', '离线草稿') // 等事务complete
await enqueue(db, {scope:'alice', id:'op-1', text:'离线草稿'})
// 只有匹配ack后removeQueued，不按navigator.onLine直接删。
```

## 观察、场景与误区

pnpm verify真正设置浏览器offline，确认HTTP重试失败但队列仍在；恢复网络后显式重试，只删匹配ack项。相同scope/id重复HTTP只应用一次，复用id改payload409；草稿按Alice/Bob分开，刷新恢复。

本地保存与服务器提交是两种成功；敏感数据最小化、保留期/退出清理/权限另设计。不要缓存所有私有响应解决离线。

## 移动开发对照

本地草稿、版本和生命周期的目标可类比移动端；Nuxt还有服务器进程与每请求应用、HTML/payload、浏览器存储和多层HTTP缓存，不能把Flutter进程单例或原生安全存储直接照搬。scope是公开fixture不是认证，生产权限和同步协议须独立设计。
