# 8.6.6 Local-first与CRDT：协作收敛不等于业务正确

前置：阶段2异步/存储、阶段4 Vue/Nuxt状态与数据、阶段5身份边界、阶段6缓存。先学8.6.1/2归属与key，再并发/过期/离线，最后按需选择协作模型。

## 解决的问题与机制

Local-first强调本地可用、数据所有权与同步协作，不只是给云应用加缓存。CRDT在指定数据类型与更新合并规则下支持并发副本最终收敛；仍需要传输、持久化、身份授权、文档生命周期和资源限制。Yjs/Automerge提供实现，不能用简单对象spread合并冒充CRDT。

收敛并不保证业务意图没有冲突：两人同时改价格、删除后编辑、库存约束仍需要产品规则。CRDT不是加密、权限系统或服务器事务替代品；撤销、版本迁移、离线大增量、恶意更新都要有协议。仅单人草稿通常用IndexedDB加明确同步就足够，不为时髦引入完整协作系统。

## 最小片段与上下文

```javascript
// 架构设计记录，不是CRDT算法或已运行Yjs：
const collaborationContract = {
  sharedType: 'collaborative text',
  identity: 'server verified document membership',
  unresolvedBusinessRule: '审批通过后是否仍允许编辑'
}
console.log(collaborationContract.sharedType)
```

## 观察、场景与误区

类型：官方观察。阅读Yjs shared types/updates与network agnostic说明，用两离线编辑者列增量传递、授权、持久化和业务限制。lab只运行本地草稿/队列，未装Yjs或Automerge，不把它们声称协作已实现。

没有协作需求时保持简单；跨端离线不天然等于Local-first，服务器也不因为网络无关而无需治理。

## 移动开发对照

本地草稿、版本和生命周期的目标可类比移动端；Nuxt还有服务器进程与每请求应用、HTML/payload、浏览器存储和多层HTTP缓存，不能把Flutter进程单例或原生安全存储直接照搬。scope是公开fixture不是认证，生产权限和同步协议须独立设计。
