# 8.6.1 状态归属：组件、URL、Nuxt共享状态与服务端数据

前置：阶段2异步/存储、阶段4 Vue/Nuxt状态与数据、阶段5身份边界、阶段6缓存。先学8.6.1/2归属与key，再并发/过期/离线，最后按需选择协作模型。

## 解决的问题与机制

先问谁是事实来源、谁需要共享、保留多久、由哪个作用域拥有，再选API。输入草稿/展开属于组件，能分享和刷新恢复的筛选属于URL，跨组件客户端偏好可用useState/Pinia，远程结果由useAsyncData/useFetch维护读取状态。不要把所有服务端DTO复制到一个永不过期的全局store，导致两份事实互相覆盖。

Nuxt useState在当前应用/SSR请求中共享，并把可序列化值放payload，不是服务器进程级单例。模块顶层export const x=ref(...)可能跨请求共享；普通只读常量与可变用户状态不同。Pinia也需要正确SSR实例生命周期，不因叫store就自动隔离。敏感值不能因放在useState就留在服务器。

const selected = useState<string[]>('public-selected', () => [])

## 观察、场景与误区

先列主工作台中草稿、scope/filter、列表结果、收藏的所有者；再运行state-lab观察草稿持久化是单独明确选择，而不是所有UI状态默认写入IndexedDB。主项目实际源码与SSR记录由集成验收核对。

把事实来源与缓存区分：useAsyncData不是数据库，URL不是所有数据的仓库，组件也无需为一个开关引入全局store。

## 移动开发对照

本地草稿、版本和生命周期的目标可类比移动端；Nuxt还有服务器进程与每请求应用、HTML/payload、浏览器存储和多层HTTP缓存，不能把Flutter进程单例或原生安全存储直接照搬。scope是公开fixture不是认证，生产权限和同步协议须独立设计。
