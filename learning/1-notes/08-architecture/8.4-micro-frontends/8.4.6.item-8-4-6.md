# 8.4.6 跨模块通信：版本事件与来源校验

前置：阶段3模块/测试、阶段4 Vue/Nuxt、阶段5–7身份/缓存/部署。先判断真实约束，再理解机制、做实验与变体；微前端按需，不是普通页面的门槛。

## 解决什么问题与原理

事件协议应小而稳定：版本、类型、允许载荷、数据最小化、发送者/接收者与释放时机。CustomEvent适合同document意图，composed控制是否跨Shadow；BroadcastChannel用于相同源且满足存储分区条件的上下文，不是跨源总线，也没有业务授权。postMessage可跨窗口/源，必须校验精确origin、event.source与数据形状，发送敏感数据指定targetOrigin。共享全局store容易绑定身份/版本/生命周期，不让事件携带原始token。

## 最小机制片段

```javascript
// 接收器上下文：expectedWindow来自已创建iframe，parseMessage为lab白名单。
if (event.origin === expectedOrigin && event.source === expectedWindow) {
  const message = parseMessage(event.data);
  console.log(message.slug);
}
```

片段的上下文由注释说明；标为契约草案的内容不是工具完整配置。完整可执行机制见操作卡，不能把示意代码当联邦/插件平台实装。

## 观察、使用场景与边界

lab真实4513↔4516跨源iframe：目标窗口合法v1接受；同源但非目标frame、错误origin、目标frame错误v2均拒绝。BroadcastChannel仅官方观察，未称已部署跨标签身份同步。

信任源不等于信任全部消息；先限制能力，再处理数据，不靠字符串反序列化获得安全性。

## 移动开发对照

Android/Flutter的业务边界、接口与生命周期经验有助于判断职责；Web还涉及document、origin、URL、异步产物加载和每请求SSR。模块目录不是进程/权限沙箱，不能把移动端运行模型直接等同浏览器。
