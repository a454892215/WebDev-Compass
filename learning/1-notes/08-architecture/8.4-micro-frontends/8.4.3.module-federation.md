# 8.4.3 Module Federation契约：remote、shared与版本

前置：阶段3模块/测试、阶段4 Vue/Nuxt、阶段5–7身份/缓存/部署。先判断真实约束，再理解机制、做实验与变体；微前端按需，不是普通页面的门槛。

## 解决什么问题与原理

container暴露模块、宿主异步取remote；模块加载和执行有失败与兼容边界。shared/singleton影响实例与版本协商，不保证任意版本兼容，也不是所有依赖都该singleton。Vue重复实例可能增加成本或造成上下文问题，但强制单例又会耦合升级；需固定可接受版本、初始化顺序、远端入口可达性及回退。remoteEntry与其chunk发布时序、旧资源保留、缓存和跨域路径要共同验证。

## 最小机制片段

```javascript
// 官方观察用的版本契约草案，非插件可运行配置。
const remoteContract = { exposes: './Recommendation', apiVersion: 1, fallback: 'local-link' };
console.log(remoteContract);
```

片段的上下文由注释说明；标为契约草案的内容不是工具完整配置。完整可执行机制见操作卡，不能把示意代码当联邦/插件平台实装。

## 观察、使用场景与边界

官方观察：沿webpack container/init/get与shared文档梳理一次宿主加载远端；本轮未安装Webpack联邦或启动真实remote，lab registry不替代版本协商。

固定入口和监测不能让不可信远端安全；同页远端仍是供应链与权限问题。

## 移动开发对照

Android/Flutter的业务边界、接口与生命周期经验有助于判断职责；Web还涉及document、origin、URL、异步产物加载和每请求SSR。模块目录不是进程/权限沙箱，不能把移动端运行模型直接等同浏览器。
