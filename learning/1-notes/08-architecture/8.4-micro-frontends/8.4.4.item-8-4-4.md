# 8.4.4 样式隔离：作用域与继承边界

前置：阶段3模块/测试、阶段4 Vue/Nuxt、阶段5–7身份/缓存/部署。先判断真实约束，再理解机制、做实验与变体；微前端按需，不是普通页面的门槛。

## 解决什么问题与原理

CSS Modules通过构建重命名降低类冲突；Vue scoped依赖选择器转换，两者不是运行权限隔离。ShadowDOM限制普通选择器跨树，但可继承属性、CSS自定义属性、slot与::part等有明确通道；closed也不是保密沙箱。CSS-in-JS库可能有全局reset、主题/顺序与运行成本，不能只看技术名保证隔离。要定义允许共享的design tokens、基线与主题，避免每子应用各自重置整个document。

## 最小机制片段

```javascript
// Shadow内部样式局部控制badge；宿主仍可通过约定token影响主题。
style.textContent = '.badge { color: rgb(15,76,129) }';
```

片段的上下文由注释说明；标为契约草案的内容不是工具完整配置。完整可执行机制见操作卡，不能把示意代码当联邦/插件平台实装。

## 观察、使用场景与边界

lab全局.badge红色，而shadow内同名.badge保持蓝色；读取computedStyle比较，两视口真实通过。这里只证实这个选择器案例，不认证所有CSS隔离。

隔离程度应服务产品一致性；不是禁止全部共享样式，也不是Shadow能拦截恶意JS。

## 移动开发对照

Android/Flutter的业务边界、接口与生命周期经验有助于判断职责；Web还涉及document、origin、URL、异步产物加载和每请求SSR。模块目录不是进程/权限沙箱，不能把移动端运行模型直接等同浏览器。
