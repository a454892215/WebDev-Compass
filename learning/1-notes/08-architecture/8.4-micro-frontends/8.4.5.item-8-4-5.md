# 8.4.5 路由协调：宿主地址所有权与子模块激活

前置：阶段3模块/测试、阶段4 Vue/Nuxt、阶段5–7身份/缓存/部署。先判断真实约束，再理解机制、做实验与变体；微前端按需，不是普通页面的门槛。

## 解决什么问题与原理

宿主统一决定根URL与激活条件，子模块在分配前缀内管理细节或仅发导航意图。需要约定push/replace/back、基路径、重复激活、卸载清理、权限失败与404；多个router各监听history容易产生不同步。服务端直接访问与客户端导航都要路由到相同模块，资源缺失不能混为子应用404。Nuxt单应用原生router通常足够，微前端编排是另加责任。

## 最小机制片段

```javascript
const owner = path => path === '/catalog' ? 'catalog' : path === '/reports' ? 'reports' : null;
console.log(owner('/unknown'));
```

片段的上下文由注释说明；标为契约草案的内容不是工具完整配置。完整可执行机制见操作卡，不能把示意代码当联邦/插件平台实装。

## 观察、使用场景与边界

lab由一个history owner处理/catalog.html、/reports.html和popstate，直接刷新报表可用，/unknown HTTP404且显示未知；不是完整子应用路由框架。

URL是对外契约；先约定归属和恢复，再选择路由编排工具。

## 移动开发对照

Android/Flutter的业务边界、接口与生命周期经验有助于判断职责；Web还涉及document、origin、URL、异步产物加载和每请求SSR。模块目录不是进程/权限沙箱，不能把移动端运行模型直接等同浏览器。
