# 8.3.2 React Server Components与Server Functions：可见输出与远程入口

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 解决什么问题与原理

RSC是React的服务端组件模型，不是SSR的别名。Server Component代码可在构建或请求阶段运行，不直接作为其客户端组件代码发送；输出、传给Client Component的props和序列化数据仍会被浏览器看见。Client Component也可能参与服务器初始HTML生成，use client不等于永远不在服务器执行。

Server Function/Action形成可被客户端调用的服务端入口，不是自动可信的本地函数。每次调用均需验证输入、身份/资源权限、CSRF或框架规定的来源保护；不可依赖UI隐藏、不可猜函数标识或闭包变量代替授权。框架/打包器支持随版本变化，Nuxt Vue方案不硬套React指令。

## 最小机制片段

```typescript
const publicCourseProps = { title: "Vue architecture" };
console.log(publicCourseProps); // 假设发送给客户端的DTO，绝不放secret
```

片段的Nuxt/校验上下文按注释使用；设计对象/伪码不冒充已运行框架工程。

## 观察、场景与误区

类型：React官方文档观察。分别读Server Components与use server，标出执行位置、发送数据和可调用边界；对主Nuxt把server/api、payload及Vue组件对应到职责而非API名字。不装Next/RSC，不声称编译通过。

故障：把数据库token作为Client Component prop，认为父组件在server所以保密。追踪输出/props，改为最小公开DTO；真正泄露过的token另需撤销/轮换，不能只删UI。

## 移动开发对照

类似移动端远程调用最终仍跨进程/网络信任边界；Server Action不是客户端可相信的私有函数调用。
