# ADR-001：先用模块化Nuxt单体与端口注入

状态：Accepted；2026-11-25；适用本教学工作台。

背景和候选见[RFC](./RFC.md)。决定：一个Nuxt Node SSR发布单元；catalog通过index.ts公开页面需要的接口，domain/application可独立单测；服务器application依赖domain端口，入口注入infra，不按调用流程误画import方向。

理由：当前没有多个自治团队或独立发布的强需求；能用最少运行单元演示请求、DTO和状态边界。微前端、Edge、CRDT保留选修，普通模块即可解决此处问题。

代价：分层与port有学习成本；单体发布/进程故障相关；不能把文件夹作为强权限隔离。代码约定用有限AST门禁和测试辅助，不代替人工审查、真实认证或生产性能评估。

后果与验证：按[NFR](./NFR.md)及主README检查。未来需要新模式时写新ADR说明supersedes ADR-001与迁移/回退，保留本记录，不静默改旧决策。
