# 阶段 0 综合观察任务

[说明](./README.md) · [共享资源目录实现](../01-web-fundamentals/index.html)

任务需按真实证据完成；资料关联不表示旧外网或协议演示已重新验证。

<a id="p-0-1-1"></a>

## 0.1.1 环境观察任务

启动本地 REST 示例，读取列表，再提交仅含虚构姓名与示例邮箱的创建请求；给两次请求分别画出浏览器、服务器和内存数据的流向。

- [ ] 记录读取与创建的 URL、方法、状态码、响应体，不用页面提示代替 Network 证据。
- [ ] 指出页面静态资源请求与用户操作产生的 API 请求至少各一例。
- [ ] 说明服务停止时前端能做什么，以及哪些数据只有服务器能返回。

<a id="p-0-1-2"></a>

## 0.1.2 环境观察任务

在示例中分别修改一个 DOM 文本、一条 CSS 规则和一个事件处理断点，记录三个修改对页面的影响；刷新后区分源文件与运行期 DOM。

- [ ] 提交 Elements 文本、Computed 样式与 Sources 断点各一项观察。
- [ ] 说明 DOM 检查器修改为何通常在刷新后消失。
- [ ] 区分 Node 终端和页面 Console 的 document 可用性。

<a id="p-0-1-3"></a>

## 0.1.3 环境观察任务

阅读旧 SPA/MPA 对照代码，标出真实导航、History 操作和纯文本模拟日志；再观察综合目录的锚点导航并分类，勿把它直接称为 SPA 路由。

- [ ] 记录一次真实文档导航与一次当前文档内变化的区别。
- [ ] 准确标明旧示例的 API 输出是模拟内容，不能充当抓包证据。
- [ ] 对资源目录提出需要深链接时的刷新/前进/后退验收项。

<a id="p-0-1-4"></a>

## 0.1.4 环境观察任务

列出本地目录页、REST 服务和假设的另一个端口的 origin；阅读双源示例实际请求地址，纠正“请求成功就是同源”的判断。无需主动请求外网。

- [ ] 对协议、主机、有效端口逐项比较三组 URL。
- [ ] 说明允许 CORS 的跨源成功请求仍然跨源。
- [ ] 区分浏览器拒绝读取响应、网络故障与服务返回 HTTP 错误的观察依据。

<a id="p-0-1-5"></a>

## 0.1.5 环境观察任务

围绕本地资源目录与 REST 服务，写一张 Android/Flutter 经验迁移清单：哪些协议概念可复用，哪些浏览器限制必须重新验证。

- [ ] 列出至少三项可复用概念和三项平台差异。
- [ ] 用同源策略与浏览器存储各举一个不能照搬原生端设计的例子。
- [ ] 说明桌面与手机可以共享业务约定而分别设计 UI。

<a id="p-0-2-1"></a>

## 0.2.1 环境观察任务

在示例副本中先检查 package.json 与锁文件，再记录 node/npm 版本并运行现有 info/start 脚本；依赖已就绪时不重复安装，需安装时按项目锁文件处理。

- [ ] 记录实际运行时版本、所选包管理器与对应脚本。
- [ ] 解释 npm 脚本如何调用 Node 以及浏览器为何无需运行这段 CLI。
- [ ] 指出依赖缺失与 Node 版本不符合要求的不同排查步骤。

<a id="p-0-2-2"></a>

## 0.2.2 环境观察任务

在练习副本中按配置说明启用格式化并检查 Problems；记录编辑器、CLI 和工作区设置分别承担的检查，不要求安装已删除的编辑器。

- [ ] 保存一个有缩进问题的 HTML 后对比格式化差异。
- [ ] 区分编辑器扩展提示与终端检查命令的实际结果。
- [ ] 确认团队配置与个人设置分离，不提交个人路径和凭据。

<a id="p-0-2-3"></a>

## 0.2.3 环境观察任务

在已有 DevTools 示例中完成一次事件断点、一次网络观察和一次布局检查；用操作步骤记录可复现的问题报告。

- [ ] 报告包含 URL、复现步骤、预期、实际和相关面板证据。
- [ ] 区分 Console 错误、HTTP 状态和 UI 结果。
- [ ] 窄视口检查有明确 CSS 像素宽度，且不称为真机测试。

<a id="p-0-2-4"></a>

## 0.2.4 环境观察任务

在单独的临时练习仓库中完成修改、diff、选择暂存与本地提交；不要在知识库或其他项目执行破坏性练习。

- [ ] 展示工作区、暂存区和提交记录各自的变化。
- [ ] 确认提交不包含 node_modules、凭据及无关文件。
- [ ] 能够解释本地提交与远程推送的差异，练习不要求推送。

<a id="p-0-2-5"></a>

## 0.2.5 环境观察任务

以 package-demo 为实际对象，把 manifest、lock、依赖目录、脚本与构建工具映射到熟悉的移动端概念，并注明相似范围。

- [ ] 指出 package.json、package-lock.json 与 node_modules 的分工。
- [ ] 说明 Node、npm、Vite 不属于同一层且示例未使用 Vite。
- [ ] 给出不混用多个锁文件的依赖变更与复现流程。

<a id="p-0-3-1"></a>

## 0.3.1 环境观察任务

用无凭据的 https://example.com:8443/resources?q=Vue%203&page=2#intro 解析 URL，增加同名查询参数，再比较默认端口的归一化。

- [ ] 正确标出 protocol、hostname、port、pathname、search 与 hash。
- [ ] 说明 URLSearchParams 对空格和重复参数的处理，以实际输出为证。
- [ ] 从本地目录的 Network 请求确认 fragment 不作为 HTTP 请求目标发送。

<a id="p-0-3-2"></a>

## 0.3.2 环境观察任务

在本地 REST 服务依次读取、新增虚构用户、请求不存在 id；制作方法、状态码、请求/响应头与正文对照表。

- [ ] 记录至少 200、201、404 的实际请求结果。
- [ ] 解释 fetch 遇到 HTTP 错误时为何仍需检查 response.ok。
- [ ] 记录 Content-Type 与 JSON 正文对应关系，排除真实凭据。

<a id="p-0-3-3"></a>

## 0.3.3 环境观察任务

按观察清单检查 Protocol 列，先记录本地服务，再选择自己获准访问的 HTTPS 站点；无法外网时只提交本地证据和版本机制分析。

- [ ] 记录实际观察的协议和观察日期，不预填 h2/h3。
- [ ] 说明本地 HTTP 服务不能证明生产 CDN 支持 HTTP/3。
- [ ] 分析多路复用与资源体积为何是两个不同优化问题。

<a id="p-0-3-4"></a>

## 0.3.4 环境观察任务

仅用 demo-theme 等无敏感测试值比较刷新、独立新标签和关闭标签后的存储变化；在 Application 中清理本次键。

- [ ] 分别记录 localStorage 与 sessionStorage 的观察条件和结果。
- [ ] 说明服务端 Session 与浏览器 sessionStorage 不同。
- [ ] 指出 JS Cookie 演示无法设置 HttpOnly，不声称已验证生产登录安全。

<a id="p-0-3-5"></a>

## 0.3.5 环境观察任务

按清单对获准公开域名记录一次 DNS 查询和浏览器 Timing；无法访问外网时解释预期链路并把实测字段标为未验证。

- [ ] 区分 DNS 解析、连接和请求等待所处阶段。
- [ ] 解释缓存命中时 DNS 耗时可能不出现，不能填造数值。
- [ ] 说明 CDN 缓存与 DNS 解析不是同一机制，不仅凭某个响应头断言命中。

<a id="p-0-3-6"></a>

## 0.3.6 环境观察任务

按清单观察获准 HTTPS 站点的证书域名、有效期和连接信息；对本地 HTTP 服务写出无法观察 TLS 的原因，不绕过证书警告。

- [ ] 记录证书观察对象和日期，不包含个人信息或凭据。
- [ ] 区分证书信任、传输加密和应用授权三个问题。
- [ ] 对 HTTP 页面与 HTTPS 页面的保护边界给出准确解释。

<a id="p-0-3-7"></a>

## 0.3.7 环境观察任务

在本地内存用户资源上完成列表、新增、部分修改、删除及不存在 id 的请求；记录服务器重启后数据状态。

- [ ] 记录 CRUD 对应方法、路径与实际状态码。
- [ ] 说明删除后的 204 响应无需强行解析 JSON。
- [ ] 明确内存示例无生产持久化和认证保障，不把重启丢失当数据库故障。

<a id="p-0-3-8"></a>

## 0.3.8 环境观察任务

启动教学 WS 服务并打开两个标签，以虚构消息观察广播；关闭自己启动的服务观察 close，再重启并手动重连。

- [ ] 记录 open、message、close 的实际触发条件。
- [ ] 区分握手与消息帧，不把帧数当 HTTP 请求次数。
- [ ] 说明极简服务的帧实现、鉴权和心跳边界，不复制为生产服务。

<a id="p-0-3-9"></a>

## 0.3.9 环境观察任务

把同一个本地用户资源契约映射为 fetch 与熟悉的 Retrofit/Dio 调用流程，用伪代码解释请求、状态校验、解析、错误和取消边界，不新增 axios 依赖。

- [ ] 区分传输异常、非成功 HTTP、JSON 解析异常和业务失败。
- [ ] 指出浏览器 CORS/凭据条件是原生客户端类比的额外边界。
- [ ] 说明 localStorage 与 SharedPreferences 类比不等于安全存储保证。
