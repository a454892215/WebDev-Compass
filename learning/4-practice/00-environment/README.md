# 阶段 0 综合实践：为学习资源目录建立环境与网络观察记录

## 目标与前置

你已经读过阶段 0 的 19 个知识点。本实践不另建框架，而是把它们应用到同一个[学习资源目录应用](../01-web-fundamentals/index.html)，并按需复用已有 HTTP、URL 和 WebSocket 教学示例，形成一份能够复查的环境与网络报告。阶段 1 综合目录负责界面与脚本练习；本页负责运行环境和网络观察，二者互补。

交付一份自己的 `environment-observations.md`，包含环境版本、启动命令、服务地址、请求证据、错误分类以及未验证边界。不要直接修改本知识库来记录个人路径、账号或其他隐私。

**状态边界**：本次补充了任务、练习与验收契约，没有重新运行阶段 0 的旧 REST/WS 服务，也没有完成全部旧正文技术复审。保留原有 G07 等复审条目的状态；完成练习不能自动把它们标为通过。观察清单、演示模拟和真实浏览器抓包是三种证据，必须分开。

只停止自己启动的进程。不要关闭浏览器安全策略、绕过证书警告、发送真实凭据或借练习进行远程写入。旧请求演示包含外部公共服务，旧 SPA 对照含模拟日志：可以阅读而不发起外网请求；请求/响应观察优先用本地 REST 服务，模拟日志不能证明真实请求。DNS、TLS 与公网协议观察需要获准的外部对象；无法访问时记录“未验证”，本地 HTTP 服务不能替代那些证据。

## 综合执行步骤

1. **建立环境记录**：记录操作系统、浏览器、Node 与包管理器实际版本；核对当前工作目录、项目脚本与锁文件。编辑器工具与命令行检查分开记录。在临时副本练习 Git，不在真实项目演练破坏性命令。
2. **建立运行链路**：按各对象说明分别启动必要服务；记录地址与端口。载入资源目录，在 Network 记录文档、脚本和其他资源；用 URL 解析器核对查询参数、有效端口与 fragment。
3. **建立 API 证据**：在本地 REST 教学服务记录成功读取、创建、删除空响应、不存在资源与服务停止后的连接失败。区分 HTTP 错误、传输异常、解析失败和 UI 反馈。创建用户仅用 Ada 与 ada@example.com 等演示数据。
4. **建立状态与实时观察**：使用存储演示的测试键比较刷新、独立标签及清理；再用两个 WS 标签记录握手、消息帧与关闭/重连。未实际运行的服务明确列在待执行区。
5. **建立边界分析**：比较资源目录、本地 API 和假设另一端口的 origin；说明跨源访问成功不等于同源。对 DNS/TLS/HTTP 版本分别标明实测、阅读分析或未验证，避免用本地 HTTP 页面断言生产网络能力。
6. **复查与清理**：清理本次测试键与虚构内存记录，关闭自己启动的服务。提交自己的报告前去除用户目录、真实账号、Cookie、Token 与其他敏感信息。

## 整体验收

- [ ] 19 个知识点均有对应练习记录或明确的未验证原因，报告不把待执行项算通过。
- [ ] 真实观察包含运行条件、操作、结果与解释；源码分析和模拟日志被明确标记。
- [ ] 资源目录与本地教学服务的证据分别标注，HTTP/WS/存储/协议能力没有互相冒充。
- [ ] 错误至少按 HTTP、传输、解析与 UI 表现分开排查；不通过关闭安全设置“修复”。
- [ ] 清理测试数据和自启服务，无真实凭据；本地证据不外推为真机或生产验证。
