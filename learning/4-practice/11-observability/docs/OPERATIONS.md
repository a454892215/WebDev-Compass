# 运行边界与诊断演练

## 实际数据与责任

| 数据/路径          | 来源与控制                                         | 本地保留/限制                                    |
| ------------------ | -------------------------------------------------- | ------------------------------------------------ |
| request trace/span | 每请求生成，严格00 header仅作关联；SSR内部显式传播 | 最近50日志，5分钟惰性清理；不作权限              |
| 固定event code     | 当前页主动开启；接收端字段允许列表/Origin/2048字节 | 最近50事件，5分钟惰性清理，无跨服务存储          |
| fixture分组        | 可改Cookie固定A/B，不验证身份                      | Cookie15分钟、可恢复guest；无真实账号            |
| release/kill       | 私有运行配置；响应只返回必要release/决策           | kill需配置并重启，不是远程实时开关               |
| 诊断快照           | 本地公开读取全部教学日志                           | 仅loopback；生产移除/另做认证授权                |
| SDK实验            | 各独立lab真实库/内存transport/exporter             | 不连接厂商SaaS/Collector，不自动等于生产隐私合规 |

字节读取设置2秒截止与8KiB大流停止，已测3000B真实chunked413；慢请求/巨大流断连接未全部测试，不承诺可达408或完整DoS防护。Origin不代替认证、也不阻止curl伪造；必须结合真实业务再做接收端滥用防护。环形保留避免无限内存，不保证攻击下所有证据都留存。

## 可复现闭环

1. 默认不勾选，发送按钮不产生浏览器事件；业务请求仍有独立运行日志，不能把“无可选事件”写成“完全没有遥测”。
2. 开启后发送固定事件，确认204与无敏感字段；触发模块渲染故障，局部fallback保留其他操作。修复后再清边界，避免立即再次抛错。
3. API503由catch处理，后端error日志带该次trace；全局错误另进error.vue，不能用局部边界承诺捕获所有异步错误。
4. 分组A刷新仍相同；HTTP对比workspace、SSR外层header/payload关联。主项目只实现最小00 trace链，真实OTel父子span导出在独立telemetry-lab。
5. 用独立新进程配置kill=true，确认可选面板不渲染；没有热更新、平台审批/审计。错误演示按钮独立，是为了比较错误范围，不属于被关闭的新功能。
6. 删缓存读取绕过与改Nginx return200两个隔离故障由infra-lab复现：分别HIT代替BYPASS、限流全200；恢复后正常实验通过。

## 实际验证与未测

主冻结离线安装（复用已存在本地pnpm缓存）、类型/ESLint/格式、4项单元、Nuxt生产构建、5项Playwright通过。两模拟视口1440/390覆盖最小采集/局部重试/SSR刷新/axe/键盘/无溢出与全局恢复；HTTP覆盖合法/非法trace、并发隔离、SSR显式关联、503日志、400/403/chunked413、kill新进程及SSR节点消失。运行证据由docs/audits的JSON记录，不把AI复审算第二轮测试。

初版发现AppFrame未挂载、status定位与Nuxt announcer冲突、只用afterResponse遗漏错误路径，已按实际失败修正；独立复审另发现flag仅文案及SSR关联未传递，修为实际v-if与显式header，受影响检查重跑。Nginx自定义NGINX_BIN的版本读取也统一并在无homebrew PATH下复验。

远程Sentry接收/map上传/通知/自动指派、真实RUM/SLO告警/Replay、Collector/OTLP、云预览/真实数据库回退、CDN/Purge/Geo/WAF、Docker/K8s/远程Actions均未运行。模板/官方观察是相应学习产出，使用者接平台后须获取自己的证据；本轮不声称生产事故响应能力已经具备。
