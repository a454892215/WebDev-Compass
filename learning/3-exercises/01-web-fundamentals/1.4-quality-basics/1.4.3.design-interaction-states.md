# 1.4.3 练习：为目录列表补齐设计稿没有的状态

[对应笔记](../../../1-notes/01-web-fundamentals/1.4-quality-basics/1.4.3.design-interaction-states.md) · [观察示例](../../../2-examples/01-web-fundamentals/1.4-quality-basics/1.4.3.design-interaction-states-demo.html) · [练习目录](./README.md)

先用演示数据完成自己的实现，再与示例比较。不要上传真实凭据；过程中的失败和修复同样需要保留说明。

## 动手任务

1. 列出初始、加载、成功、空、错误与重试的状态表。
2. 用真实长标题与窄视口检查层级、按钮和可恢复操作。

## 验收标准

- [ ] 状态文案、内容、按钮与aria-busy一致。
- [ ] 重试能恢复，不丢主要说明或用户当前操作位置。
- [ ] 能够解释桌面与手机可共享状态契约但采用不同UI。
- [ ] 能说明本次验证的浏览器/视口与未覆盖范围，不能以模拟冒充真机或正式服务。

## 排错任务

把所有没有数据的情况都显示为空，说明它如何掩盖正在加载或失败。

记录“复现步骤 → 观察证据 → 原因 → 修正 → 复验”，不要只写问题已经消失。

## 参考要点

- 先明确任务和内容优先级，再谈间距数值。
- 可运行的状态切换不等于真实API集成。

这部分提供判断方向，不替代自己的实现与排错。更完整机制和官方来源见对应笔记。
