## 动手任务

1. 比较 counter.read() 与提取后的函数调用；捕获错误。

2. 用 bind 修复，说明为什么它能保持接收者。

3. 项目应用：抽出综合项目筛选函数，明确参数、返回值及是否依赖this。 先写预期与边界，再修改自己的练习副本；不要只复制示例日志。

## 验收标准

- [ ] 纯筛选可脱离组件调用并测试。

- [ ] 对象方法传作回调不会因接收者丢失而报错。

- [ ] 能不用逐行提示说明原因，并在一个变体输入上重复验证。

- [ ] 记录一个正常输入与一个边界输入，以及实际结果；将机械通过与自己的机制解释分开。

## 排错任务

提取对象方法后独立调用，定位this丢失并提供两种修复。

复现后记录：现象、最小触发条件、错误发生的作用域/节点/异步阶段、修复与回归。错误示例必须捕获或隔离，不让课程页面产生未处理异常。

## 参考要点

- 使用返回值表达结果，避免让函数同时隐式修改过多外部状态。

- 箭头适合保留词法 this 的回调，不适合作为依赖动态接收者的方法。

先用配套笔记的“工作机制”解释结果，再检查源码。参考要点是提示，不是声称已完成练习；预期错误、网络模拟与真实环境结果必须区分。官方来源见配套笔记。
