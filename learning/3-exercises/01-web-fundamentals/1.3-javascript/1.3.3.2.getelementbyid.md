## 动手任务

1. 先查询两项列表再追加第三项，对比snapshot与live。

2. 故意查找不存在ID并写出可定位的错误提示。

3. 项目应用：限制综合项目选择器到当前区域，并检查缺失节点和动态节点集合。 先写预期与边界，再修改自己的练习副本；不要只复制示例日志。

## 验收标准

- [ ] 查询不到时有清楚诊断。

- [ ] 动态追加后静态集合的行为可解释。

- [ ] 能不用逐行提示说明原因，并在一个变体输入上重复验证。

- [ ] 记录一个正常输入与一个边界输入，以及实际结果；将机械通过与自己的机制解释分开。

## 排错任务

给静态NodeList追加项目后仍按旧length判断，解释快照行为。

复现后记录：现象、最小触发条件、错误发生的作用域/节点/异步阶段、修复与回归。错误示例必须捕获或隔离，不让课程页面产生未处理异常。

## 参考要点

- 优先在当前组件/区域根节点上查询，减少跨页面碰撞。

- 外部字符串进入CSS选择器前需转义或避免拼接；无效选择器会抛SyntaxError。

先用配套笔记的“工作机制”解释结果，再检查源码。参考要点是提示，不是声称已完成练习；预期错误、网络模拟与真实环境结果必须区分。官方来源见配套笔记。
