## 动手任务

1. 区分 null、数组、普通对象和函数。

2. 给一个带 Symbol.toStringTag 的对象改标签，解释为什么不能当作安全身份。

3. 项目应用：为综合项目接口解码器增加数组、null、普通对象与字段类型检查。 先写预期与边界，再修改自己的练习副本；不要只复制示例日志。

## 验收标准

- [ ] null或对象代替列表时给明确错误。

- [ ] 不能只靠instanceof业务类验证JSON。

- [ ] 能不用逐行提示说明原因，并在一个变体输入上重复验证。

- [ ] 记录一个正常输入与一个边界输入，以及实际结果；将机械通过与自己的机制解释分开。

## 排错任务

把typeof value === "object"直接当作可读字段保证，输入null复现并修正。

复现后记录：现象、最小触发条件、错误发生的作用域/节点/异步阶段、修复与回归。错误示例必须捕获或隔离，不让课程页面产生未处理异常。

## 参考要点

- Array.isArray 比 value instanceof Array 更适合跨 realm 数组。

- typeof x === "object" 仍需排除 null，不能据此直接读取属性。

先用配套笔记的“工作机制”解释结果，再检查源码。参考要点是提示，不是声称已完成练习；预期错误、网络模拟与真实环境结果必须区分。官方来源见配套笔记。
