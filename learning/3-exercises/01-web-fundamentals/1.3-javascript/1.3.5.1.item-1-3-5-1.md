# 1.3.5.1 独立练习

[配套笔记](../../../1-notes/01-web-fundamentals/1.3-javascript/1.3.5.1.item-1-3-5-1.md) · [配套实验](../../../2-examples/01-web-fundamentals/1.3-javascript/1.3.5.1.item-1-3-5-1-demo.html)

## 动手任务

1. 先预测同步map回调和setTimeout回调的先后。

2. 把两层依赖回调改成命名函数，画出错误分支和退出点。

3. 项目应用：重构综合项目中的嵌套回调，把请求、转换与渲染分离。 先写预期与边界，再修改自己的练习副本；不要只复制示例日志。

## 验收标准

- [ ] 成功与失败路径都可追踪。

- [ ] 不把同步回调误认为后台异步。

- [ ] 能不用逐行提示说明原因，并在一个变体输入上重复验证。

- [ ] 记录一个正常输入与一个边界输入，以及实际结果；将机械通过与自己的机制解释分开。

## 排错任务

把异步回调内错误交给外层同步try，说明跨调用栈的捕获问题。

复现后记录：现象、最小触发条件、错误发生的作用域/节点/异步阶段、修复与回归。错误示例必须捕获或隔离，不让课程页面产生未处理异常。

## 参考要点

- 给回调命名和定义输入输出，比盲目把所有函数套成async更重要。

- Node风格error-first与DOM事件回调不是同一种参数约定，需按API文档读取。

先用配套笔记的“工作机制”解释结果，再检查源码。参考要点是提示，不是声称已完成练习；预期错误、网络模拟与真实环境结果必须区分。官方来源见配套笔记。
