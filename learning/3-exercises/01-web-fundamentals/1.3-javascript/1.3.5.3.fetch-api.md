# 1.3.5.3 独立练习

[配套笔记](../../../1-notes/01-web-fundamentals/1.3-javascript/1.3.5.3.fetch-api.md) · [配套实验](../../../2-examples/01-web-fundamentals/1.3-javascript/1.3.5.3.fetch-api-demo.html)

## 动手任务

1. 比较成功JSON、HTTP404、正文非JSON三条真实本地请求。

2. 观察预取消请求的AbortError；用章节Node服务测试POST回显，再讨论服务端验证。

3. 项目应用：实现综合项目Fetch加载，覆盖HTTP错误、解析失败、取消和迟到响应。 先写预期与边界，再修改自己的练习副本；不要只复制示例日志。

## 验收标准

- [ ] 404与坏JSON得到不同诊断。

- [ ] 快速切换筛选条件时旧响应不能覆盖新条件。

- [ ] 能不用逐行提示说明原因，并在一个变体输入上重复验证。

- [ ] 记录一个正常输入与一个边界输入，以及实际结果；将机械通过与自己的机制解释分开。

## 排错任务

漏response.ok或未await response.json，分别复现HTTP和解析错误遗漏。

复现后记录：现象、最小触发条件、错误发生的作用域/节点/异步阶段、修复与回归。错误示例必须捕获或隔离，不让课程页面产生未处理异常。

## 参考要点

- 网络失败、主动取消、HTTP错误、JSON解析错误与业务错误应分别识别。

- POST JSON需序列化body并声明Content-Type；FormData则不要手写multipart boundary。

先用配套笔记的“工作机制”解释结果，再检查源码。参考要点是提示，不是声称已完成练习；预期错误、网络模拟与真实环境结果必须区分。官方来源见配套笔记。
