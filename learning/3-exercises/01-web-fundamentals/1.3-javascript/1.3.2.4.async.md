# 1.3.2.4 独立练习

[配套笔记](../../../1-notes/01-web-fundamentals/1.3-javascript/1.3.2.4.async.md) · [配套实验](../../../2-examples/01-web-fundamentals/1.3-javascript/1.3.2.4.async-demo.html)

## 动手任务

1. 同时启动两个带延迟任务，确认两项都开始后才完成。

2. 将其中任务改为拒绝，用try/catch观察结果并讨论取消。

3. 项目应用：在项目副本新增第二个本地只读数据源，再并发读取两个独立数据源，决定失败时整页失败还是部分显示。 先写预期与边界，再修改自己的练习副本；不要只复制示例日志。

## 验收标准

- [ ] 解释并发任务启动和等待顺序。

- [ ] 不声称Promise.all会自动取消其余请求。

- [ ] 能不用逐行提示说明原因，并在一个变体输入上重复验证。

- [ ] 记录一个正常输入与一个边界输入，以及实际结果；将机械通过与自己的机制解释分开。

## 排错任务

漏await一个拒绝Promise，解释为什么外层catch没有按期捕获。

复现后记录：现象、最小触发条件、错误发生的作用域/节点/异步阶段、修复与回归。错误示例必须捕获或隔离，不让课程页面产生未处理异常。

## 参考要点

- async返回普通值也会被包装成Promise。

- try/catch只能捕获作用域内实际await或同步抛出的错误，漏await可能产生未处理拒绝。

先用配套笔记的“工作机制”解释结果，再检查源码。参考要点是提示，不是声称已完成练习；预期错误、网络模拟与真实环境结果必须区分。官方来源见配套笔记。
