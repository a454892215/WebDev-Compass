## 排错任务

故意制造这个问题：双下划线会让浏览器自动隔离。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“给每一层DOM都创建长链名称，耦合页面结构。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- block表示独立组件，element常用双下划线表示内部部分，modifier常用双连字符表示变体。
- 状态可以由原生属性、aria或data表达；避免为了命名重复存多份同一业务状态。
- 类似组件文件/样式命名约定，不能替代Flutter组件作用域；CSS类仍可被全局选择器匹配。
- 这是维护/团队约定示例，不宣称BEM优于所有原生层叠或局部样式方案。

## 关联综合实践

给 .cards 组件列出block/element/modifier命名映射，评估是否需要BEM，不强制重写整个项目。

- [ ] 证明类名约定不会建立浏览器隔离
- [ ] 状态来源仍只有一份，不用多套class/data重复存业务状态
