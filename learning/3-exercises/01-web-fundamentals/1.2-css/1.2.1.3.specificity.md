# 1.2.1.3 练习：特异性：比较 ID、类与元素权重

## 动手任务

1. 初始比较 #target 与类选择器，预测颜色。
2. 切换后把低优先级样式改成 important，确认特异性不是第一步。
3. 在 Styles 中定位被划掉的声明。

在独立副本中修改目标规则，先写下预测，再运行和测量。不得仅复制切换后的CSS并宣布完成。

- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `color`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：认为十个 class 就能压过一个 ID。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“只记 important 最大，忽略过渡、用户重要样式和层次顺序。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- 一般选择器以 ID、类/属性/伪类、元素/伪元素三组权重逐组比较，不把三组当十进制相加。
- 避免用 ID、长祖先链和 !important 争抢样式；先定位所属层、来源和生效条件。
- 可类比多个配置同时匹配时的决策规则，但与 Theme 合并不同；层优先级先于选择器权重。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
