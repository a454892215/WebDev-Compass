# 1.2.1.3 练习：特异性：比较 ID、类与元素权重

## 动手任务

1. 初始比较 #target 与类选择器，预测颜色。
2. 切换后把低优先级样式改成 important，确认特异性不是第一步。
3. 在 Styles 中定位被划掉的声明。

独立实现：创建同一元素匹配ID、两个class及:where三组规则，手算三组权重并核对获胜声明。

从空白小页面或指定构建实验副本开始，先写预测再实现；观察示例是前置，不可只复制其切换结果。

## 排错任务

1. 故障注入：写一个ID颜色和十个连写class的冲突颜色，禁止!important，误以为class数量可进位。
2. 定位并修正：记录1-0-0与0-10-0，证实逐组比较而不是十进制相加；通过降低冲突规则耦合修复。
3. 保存故障前、修复后的代码差异与实际读数/行为；说明为什么这项修改解决原因。

## 思考题

分析下列误区：“只记 important 最大，忽略过渡、用户重要样式和层次顺序。”。写出错误假设、浏览器实际规则和一个反例；其中含修复建议时，说明建议为何有效。

## 参考要点

- 一般选择器以 ID、类/属性/伪类、元素/伪元素三组权重逐组比较，不把三组当十进制相加。
- 避免用 ID、长祖先链和 !important 争抢样式；先定位所属层、来源和生效条件。
- 可类比多个配置同时匹配时的决策规则，但与 Theme 合并不同；层优先级先于选择器权重。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
