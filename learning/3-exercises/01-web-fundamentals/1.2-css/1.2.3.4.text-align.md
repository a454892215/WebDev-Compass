## 动手任务

1. 初始允许长标识换行。
2. 切换为单行省略，确认white-space和text-overflow同时改变。
3. 观察完整文本仍存在DOM，思考用户如何获得完整内容。

独立实现：写一个长资源名称，提供自然换行与可展开完整值两种呈现，触控也可读取。

从空白小页面或指定构建实验副本开始，先写预测再实现；观察示例是前置，不可只复制其切换结果。

- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `whiteSpace`，解释原因，而非只复述输出。
- [ ] 组合实际约束并保留可展开完整内容；不能只用hover title作为唯一完整值路径。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

2. 定位并修正：组合实际约束并保留可展开完整内容；不能只用hover title作为唯一完整值路径。

## 思考题

分析下列误区：“对全部正文word-break:break-all，使普通单词难读。”。写出错误假设、浏览器实际规则和一个反例；其中含修复建议时，说明建议为何有效。

## 参考要点

- 用text-align:start/end适配书写方向；对齐与元素本身定位是两件事。
- 不要用连续br或空格制造布局；重要完整值应可查看，不能依赖触屏不存在的hover提示。
- 类似TextOverflow和maxLines，但Web受文档流和实际容器宽度影响，省略号不是内容删除策略。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
