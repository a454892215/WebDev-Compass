# 1.2.3.4 练习：文本对齐、换行、截断与内容保留

## 动手任务

1. 初始允许长标识换行。
2. 切换为单行省略，确认white-space和text-overflow同时改变。
3. 观察完整文本仍存在DOM，思考用户如何获得完整内容。

在独立副本中修改目标规则，先写下预测，再运行和测量。不得仅复制切换后的CSS并宣布完成。

## 验收标准

- [ ] 用自己的话解释：文字排版由行内空间和换行机会共同决定；截断只改变呈现，不应丢掉读者需要的信息。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `whiteSpace`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：只给文本写text-overflow却不限制盒子。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“对全部正文word-break:break-all，使普通单词难读。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- 用text-align:start/end适配书写方向；对齐与元素本身定位是两件事。
- 不要用连续br或空格制造布局；重要完整值应可查看，不能依赖触屏不存在的hover提示。
- 类似TextOverflow和maxLines，但Web受文档流和实际容器宽度影响，省略号不是内容删除策略。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
