## 动手任务

1. 观察正常流中三个子盒的排列。
2. 切换 display:flex，检查父元素 computed display。
3. 试用 none 隐藏一个子项并观察空间及 Tab 顺序。

在独立副本中修改目标规则，先写下预测，再运行和测量。不得仅复制切换后的CSS并宣布完成。

## 验收标准

- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `display`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：把所有布局都写 display:flex，包括正文段落。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“透明元素看不见但仍可点击/聚焦，误以为等同 none。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- block/inline 描述外部流；flex/grid 建立内部格式化上下文，不能只理解成“横向/纵向”。
- 切成 flex 不会自动把按钮、链接变得可访问；语义仍来自 HTML。
- Flex/Grid 与 Row/Column 目标相似，但 Web 的 DOM 源顺序、行内文字和盒生成行为需要单独理解。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
