- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：transform永远零成本，或所有动画都会自动GPU加速。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“全站will-change:transform导致内存和合成负担。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- 改变left/width等可能触发布局，颜色/阴影等通常涉及绘制；transform/opacity更有机会在合成阶段处理。
- 用Performance录制比较前后，关注长任务和帧稳定性，不拿一次视觉流畅感觉当性能证据。
- 与减少rebuild/repaint的目标相通，但Web还有布局、paint、composite和资源加载阶段，不能只套移动端帧数经验。
- 页面没有伪造FPS或基准结果；性能结论必须来自具体设备和录制。
