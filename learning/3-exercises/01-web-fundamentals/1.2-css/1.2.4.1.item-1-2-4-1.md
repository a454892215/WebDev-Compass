# 1.2.4.1 练习：媒体查询与内容驱动的断点

## 动手任务

1. 拖动窗口跨过800px，记录媒体条件是否匹配与computed列数。
2. 切换gap，观察媒体条件与布局参数相互独立。
3. 在中间宽度和大字号下复验。

独立实现：创建单列基础与宽屏多列布局，以长内容失效位置确定断点并记录390/700/1440px结果。

从空白小页面或指定构建实验副本开始，先写预测再实现；观察示例是前置，不可只复制其切换结果。

## 验收标准

- [ ] 用自己的话解释：媒体查询判断视口或环境条件，断点应来自内容无法合理排布的位置，而不是设备型号列表。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `gap`，解释原因，而非只复述输出。
- [ ] 使用内容约束选择媒体条件或内在网格，补测中间宽度；不根据宽度推断输入设备。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

1. 故障注入：只在390px与1440px做特例，在700px保留三个固定300px列，复现横溢。
2. 定位并修正：使用内容约束选择媒体条件或内在网格，补测中间宽度；不根据宽度推断输入设备。
3. 保存故障前、修复后的代码差异与实际读数/行为；说明为什么这项修改解决原因。

## 思考题

分析下列误区：“只测390和1440，忽略700px时的长标题。”。写出错误假设、浏览器实际规则和一个反例；其中含修复建议时，说明建议为何有效。

## 参考要点

- 移动优先通常先写单列基础，再用min-width增强宽布局；桌面优先用max-width收敛也可，需团队一致。
- 查询可以关注hover、pointer和用户偏好；不能把宽屏等同于鼠标，把窄屏等同于触控。
- 与LayoutBuilder断点布局相近；CSS视口、浏览器缩放与用户根字号会共同影响实际结果。
- 请用DevTools连续改变视口，不以当前设备外观替代断点验证。

## 关联综合实践

连续改变 .fields 和 .cards 的可用宽度，基于标题/输入框失效位置选择断点而非设备型号。

- [ ] 至少记录一处中间宽度结果
- [ ] 鼠标/触控能力不只按视口宽度推断
