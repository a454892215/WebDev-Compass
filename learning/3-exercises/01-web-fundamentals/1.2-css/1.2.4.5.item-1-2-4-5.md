# 1.2.4.5 练习：容器查询：组件根据可用空间变化

[返回理论](../../../1-notes/01-web-fundamentals/1.2-css/1.2.4.5.item-1-2-4-5.md) · [打开实验](../../../2-examples/01-web-fundamentals/1.2-css/1.2.4.5.item-1-2-4-5-demo.html)

## 动手任务

1. 同一浏览器视口中改变卡片祖先宽度。
2. 切换180px到280px，看子组件display改变。
3. 移除container-type，再观察查询为何失效。

独立实现：同一视口并排放窄侧栏和宽主体，两张卡片按各自祖先容器调整布局并保留基础样式。

从空白小页面或指定构建实验副本开始，先写预测再实现；观察示例是前置，不可只复制其切换结果。

## 验收标准

- [ ] 用自己的话解释：容器查询让组件根据祖先容器尺寸调整布局，而不只根据整个视口。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `display`，解释原因，而非只复述输出。
- [ ] 恢复正确祖先容器；固定视口只改变容器宽度也触发布局，不支持时基础内容仍可读。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

1. 故障注入：把container-type从祖先移到被查询卡片自己，同时移除其他命名容器，查询自身改变布局。
2. 定位并修正：恢复正确祖先容器；固定视口只改变容器宽度也触发布局，不支持时基础内容仍可读。
3. 保存故障前、修复后的代码差异与实际读数/行为；说明为什么这项修改解决原因。

## 思考题

分析下列误区：“为了启用size容器导致内容高度丢失。”。写出错误假设、浏览器实际规则和一个反例；其中含修复建议时，说明建议为何有效。

## 参考要点

- 尺寸查询需要在祖先声明container-type:inline-size或size，并可用container-name命名。
- 先提供可用基础布局，再用@supports/容器查询增强；组件在窄侧栏与宽主体应分别验证。
- 接近对局部LayoutBuilder constraints做响应，而非只看MediaQuery屏幕尺寸；查询对象必须正确选择祖先。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。

## 关联综合实践

让一个资源卡片根据自身容器而不是整页宽度改变封面/正文排列，对照窄侧栏与宽列表。

- [ ] 祖先声明inline-size容器而非错误地查询自身
- [ ] 基础布局可用，不支持查询时有合理回退
