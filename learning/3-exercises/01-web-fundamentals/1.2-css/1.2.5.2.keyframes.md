# 1.2.5.2 练习：keyframes 与 animation 生命周期

[返回理论](../../../1-notes/01-web-fundamentals/1.2-css/1.2.5.2.keyframes.md) · [打开实验](../../../2-examples/01-web-fundamentals/1.2-css/1.2.5.2.keyframes-demo.html)

## 动手任务

1. 初始暂停关键帧，观察animation-play-state。
2. 切换为播放并等待一次结束。
3. 模拟reduced-motion，确认内容仍完整可读。

独立实现：独立写一次性keyframes淡入，区分动画播放状态和真实请求成功/失败文本。

从空白小页面或指定构建实验副本开始，先写预测再实现；观察示例是前置，不可只复制其切换结果。

## 验收标准

- [ ] 用自己的话解释：关键帧定义样式随时间的序列，animation控制播放、次数、方向和填充。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `animationPlayState`，解释原因，而非只复述输出。
- [ ] 将真实状态更新与动画回调解耦；无动画、取消和失败时仍有确定文字反馈。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

1. 故障注入：让状态逻辑只在animationend里更新，再用reduce偏好关闭动画，观察业务反馈未出现。
2. 定位并修正：将真实状态更新与动画回调解耦；无动画、取消和失败时仍有确定文字反馈。
3. 保存故障前、修复后的代码差异与实际读数/行为；说明为什么这项修改解决原因。

## 思考题

分析下列误区：“无限闪烁内容且没有停止路径。”。写出错误假设、浏览器实际规则和一个反例；其中含修复建议时，说明建议为何有效。

## 参考要点

- @keyframes按百分比描述各阶段；animation-name绑定序列，duration与iteration-count控制时长和次数。
- 同一个元素的多个动画可能竞争同一属性；应简化合成关系并通过浏览器检查。
- 接近AnimationController/关键帧序列，但CSS填充模式不会替代Widget状态或业务事件。
- 减少动态效果环境下animation会禁用；此时应验证静态信息而非强制要求动画播放。

## 关联综合实践

为 #status 增加一次性、可关闭的请求结果淡入，加载/错误文字本身不依赖动画。

- [ ] 没有无限闪烁且不把动画结束当接口完成
- [ ] 取消或失败状态有真实文本，偏好reduce时保留结果
