## 排错任务

故意制造这个问题：所有margin都折叠或全部不折叠。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“为包含浮动顺手overflow:hidden，导致内容被裁。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- 正常流中块盒通常沿块轴依次排布，行内内容组成行盒；布局不是每个元素都需要绝对坐标。
- Flex/Grid内部的项目margin不按正常块流同样折叠；不要用固定高度掩盖因上下文产生的现象。
- Flutter的布局协议有约束向下/尺寸向上；CSS还包含文本正常流和margin折叠，不能只用Padding相加解释。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。

## 关联综合实践

比较综合页section内首段margin的正常流行为与flow-root边界；移除不必要固定高度。
