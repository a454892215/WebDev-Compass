## 验收标准

- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `borderTopStyle`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：把.scss当普通link样式直接加载。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“把Sass编译变量当可由浏览器style.setProperty修改的token。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- $变量和mixin在编译时展开，CSS自定义属性留在浏览器运行期，两者解决不同问题。
- 只有SCSS源码和浏览器成功展示不代表编译成功；必须运行选定编译器并比较产物。
- 与构建时代码生成相似；SCSS不是新的浏览器运行时，不能类比为实时修改Theme对象。
- 本页只验证已标注fixture的浏览器表现。源码/输出/复现命令在assets/source/README.md，未自动安装或运行Sass编译器。

## 关联综合实践
