## 排错任务

故意制造这个问题：把fr等同于屏幕百分比，忽略gap和内容约束。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“为数据表外观换成div，丢失行列表头关系。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- grid-template-columns/rows 定义显式轨道；额外内容会生成隐式轨道，grid-auto-* 控制其尺寸。
- 视觉跨列/重新定位不自动改变阅读和键盘顺序；表格数据仍使用 table 语义。
- 类似二维 GridView，但 CSS Grid 可以做跨行跨列和轨道对齐，不以滚动列表虚拟化为默认职责。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
