# 1.2.1.1 练习：CSS 的三种引入方式与来源顺序

## 动手任务

1. 初始检查目标颜色，预判内联声明是否获胜。
2. 点击切换移除内联 color，观察内部规则开始生效。
3. 在 Elements 恢复内联声明，再观察，而不是只读输出。

在独立副本中修改目标规则，先写下预测，再运行和测量。不得仅复制切换后的CSS并宣布完成。

## 排错任务

故意制造这个问题：认为内联、内部、外部是一条不变的三档顺序。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“为了压过一个规则不断追加 style；先用 DevTools 看最终获胜声明。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- link rel=stylesheet 加载独立资源，便于缓存和复用；style 适合页面级实验，style 属性只影响当前元素。
- HTML 先能表达内容，再把样式抽到独立文件；生产禁止把凭据塞进 style 或 CSS。
- 与 Android XML 样式或 Flutter Theme 的复用目标相似，但 CSS 不是简单的最后一次赋值：继承与层叠会共同选值。
- 本页外部 lab.css 提供公共样式；当前目标的内部规则与内联声明可在 Elements 核对。
