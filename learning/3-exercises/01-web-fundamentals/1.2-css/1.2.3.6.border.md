## 验收标准

- [ ] 用自己的话解释：边框参与盒尺寸，阴影通常不参与正常布局，圆角也不自动裁切所有后代。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `borderTopLeftRadius`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：阴影会自动撑开父元素和相邻间隔。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“把所有内容overflow:hidden来配合圆角，连焦点轮廓也被裁。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- border-width/style/color共同定义边框；只设置颜色不保证有可见边线，border-style初始为none。
- 不要只用阴影提示焦点或禁用状态；forced colors或打印时效果可能变化。
- 与BorderRadius/BoxShadow相似；Web中的绘制溢出与正常流尺寸要分开分析。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
