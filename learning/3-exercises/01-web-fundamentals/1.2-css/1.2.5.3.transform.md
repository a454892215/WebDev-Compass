## 验收标准

- [ ] 用自己的话解释：transform在布局之后改变绘制坐标，通常不会让正常流中的邻居为其新位置重新排布。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `transform`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：scale放大后相邻元素会自动让位。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“为了GPU加速到处添加translateZ(0)。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- translate、rotate、scale、skew可组合，组合顺序影响结果，不能任意交换。
- 放大视觉内容不改变其布局占位；需要确保焦点轮廓、点击目标和溢出仍正确。
- 与Transform组件相似；CSS同时影响层叠和定位上下文，不能只把它看成绘图矩阵。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
