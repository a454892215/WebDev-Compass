## 动手任务

1. 观察contain时插画的留空。
2. 切换cover并检查computed background-size。
3. 禁用背景图，确认目标文字仍表达含义。

在独立副本中修改目标规则，先写下预测，再运行和测量。不得仅复制切换后的CSS并宣布完成。

## 验收标准

- [ ] 用自己的话解释：background负责盒子背后的装饰；承载内容信息的图片通常仍应使用img及替代文本。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `backgroundSize`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：背景图片中的关键文案没有真实文字。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“用cover显示身份证件/图表，裁掉关键边缘。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- background-color在图像未加载时提供底色；多个背景层按列表前者在上叠放。
- CSS背景没有alt，关键信息不能只藏在背景；高对比/打印/加载失败也应可理解。
- 与BoxDecoration背景类似，但background-image参与资源下载，内容语义和alt不能靠装饰层补齐。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。

## 关联综合实践

为综合页header添加可选装饰背景，比较contain/cover；页面标题和用途保留真实文字。
