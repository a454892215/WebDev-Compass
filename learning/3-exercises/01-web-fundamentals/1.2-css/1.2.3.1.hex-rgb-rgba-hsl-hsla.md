## 动手任务

1. 观察相同颜色的不同语法计算值。
2. 切换为HSL表达，确认浏览器计算后颜色相同。
3. 把背景改为深色并重新评估文字可读性。

独立实现：为成功/错误提示设计等值HEX、RGB、HSL颜色，并记录文字与最终背景对比及文字状态。

从空白小页面或指定构建实验副本开始，先写预测再实现；观察示例是前置，不可只复制其切换结果。

## 验收标准

- [ ] 用自己的话解释：不同语法可以表达相同颜色；真正的UI决策还需考虑背景、对比和非颜色提示。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `color`，解释原因，而非只复述输出。
- [ ] 把透明度放到背景色alpha，保留文字不透明；对最终合成背景测对比，不能只做编码转换。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

1. 故障注入：用容器opacity:.3代替背景alpha，观察后代文字一起变淡。
2. 定位并修正：把透明度放到背景色alpha，保留文字不透明；对最终合成背景测对比，不能只做编码转换。
3. 保存故障前、修复后的代码差异与实际读数/行为；说明为什么这项修改解决原因。

## 思考题

分析下列误区：“把颜色编码转换当作无障碍对比验证。”。写出错误假设、浏览器实际规则和一个反例；其中含修复建议时，说明建议为何有效。

## 参考要点

- 命名色、HEX、rgb()/rgba()、hsl()/hsla() 都能表达颜色；现代rgb/hsl可用空格和斜线alpha语法。
- 状态不要只用红绿区分，还需文字/图标/结构说明；生产主题应验证文字与实际背景的对比。
- 与Color、ARGB颜色值相似；CSS alpha合成依赖底层背景，主题对比不能只看单一色值。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。

## 关联综合实践

- [ ] 颜色换语法不改变语义状态
