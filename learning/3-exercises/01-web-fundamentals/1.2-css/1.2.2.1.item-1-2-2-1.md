## 排错任务

故意制造这个问题：width:100% 再加 padding 导致溢出，却用 overflow:hidden 掩盖。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“认为 border-box 把 margin 也算进 width。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- content-box 的 width 只指定内容区；左右 padding/border 会加到外部宽度上，margin 仍在盒子之外。
- 调试时同时看 Computed 的盒模型、getBoundingClientRect 与父容器，不只看代码里的 width。
- Flutter 的约束与 Padding 同样影响最终尺寸，但 CSS 的 content-box 声明不是 Flutter tight constraints；要区分声明值和布局值。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
