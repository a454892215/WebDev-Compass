## 验收标准

- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：引入不存在的类就期待浏览器生成CSS。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“通过字符串拼接任意颜色类，构建结果却缺失。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- 原子类通常表达单一属性或职责，优点是组合与局部修改直观，代价是模板更长且需统一token。
- 语义HTML、无障碍、布局约束不会因换用工具类而自动解决；不把工具类系统当UI设计本身。
- 类似把常用Style token组合到Widget参数，但类扫描、响应式变体和CSS层叠是Web构建链特有问题。
- 为零依赖离线实验，本页显式使用lesson-*自有类，不冒充完整Tailwind输出；真实工具链接入留给工程阶段。
