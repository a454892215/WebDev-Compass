## 排错任务

故意制造这个问题：把 var 的回退当成条件分支或类型校验。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“所有值都定义全局变量，反而扩大耦合。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- --name 定义大小写敏感的自定义属性，var(--name, fallback) 在使用点替换值，普通双横线属性默认继承。
- Sass 变量在构建时求值，自定义属性在运行期存在；JS 可用 style.setProperty 修改后者。
- 类似 ThemeExtension/设计 token，但 CSS token 会参与级联和继承；不是强类型 Dart 对象，也不能装密钥。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
