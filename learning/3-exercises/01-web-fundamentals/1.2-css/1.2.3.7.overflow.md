## 动手任务

1. 观察一行长代码的溢出。
2. 切换overflow-x:auto并横向滚动。
3. Tab聚焦局部区域，用方向键确认内容可达。

在独立副本中修改目标规则，先写下预测，再运行和测量。不得仅复制切换后的CSS并宣布完成。

## 验收标准

- [ ] 用自己的话解释：溢出策略决定超出盒子的内容如何显示或访问，也可能改变定位与格式化行为。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `overflowX`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：全局overflow-x:hidden掩盖意外溢出。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“滚动面板没有焦点入口，键盘用户无法操作。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- visible显示溢出，hidden裁剪但可能仍可程序滚动，clip裁剪且不创建滚动容器，auto按需滚动。
- 窄屏优先修正布局，必要的代码/表格局部滚动须能键盘聚焦，并提供可访问名称。
- 类似ScrollView/裁剪设置，但Web滚动容器还影响sticky、滚轮传播和键盘可达性。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。

## 关联综合实践

给综合页增加一块可选长接口示例代码，让它局部滚动而非引起整页溢出。

- [ ] 滚动区有名称与Tab入口
- [ ] 长代码可达，正文不因全局overflow:hidden被裁
