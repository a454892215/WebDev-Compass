## 验收标准

- [ ] 用自己的话解释：溢出策略决定超出盒子的内容如何显示或访问，也可能改变定位与格式化行为。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `overflowX`，解释原因，而非只复述输出。
- [ ] 使用受限宽度和overflow:auto并提供可访问名称/焦点；箭头可滚动到尾部，整页不横溢。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

1. 故障注入：把代码区设overflow:clip并移除滚动入口，想通过方向键读出被裁尾部。
2. 定位并修正：使用受限宽度和overflow:auto并提供可访问名称/焦点；箭头可滚动到尾部，整页不横溢。
3. 保存故障前、修复后的代码差异与实际读数/行为；说明为什么这项修改解决原因。

## 思考题

分析下列误区：“滚动面板没有焦点入口，键盘用户无法操作。”。写出错误假设、浏览器实际规则和一个反例；其中含修复建议时，说明建议为何有效。

## 参考要点

- visible显示溢出，hidden裁剪但可能仍可程序滚动，clip裁剪且不创建滚动容器，auto按需滚动。
- 窄屏优先修正布局，必要的代码/表格局部滚动须能键盘聚焦，并提供可访问名称。
- 类似ScrollView/裁剪设置，但Web滚动容器还影响sticky、滚轮传播和键盘可达性。
- 验收记录需要实际修改与观测，不把一次自动检查等同于所有浏览器/辅助技术验收。
