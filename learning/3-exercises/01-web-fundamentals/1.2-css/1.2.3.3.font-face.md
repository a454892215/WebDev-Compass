## 排错任务

故意制造这个问题：computed font-family包含名字就断言该字体已实际成功显示。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“在生产用远程字体却只验证离线local来源。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- font-family是自定义家族名，src指向local或url来源；font-style/weight需要与真实字体文件能力匹配。
- 预加载仅用于首屏关键且确实会使用的字体；避免重复下载错误weight或预加载所有文件。
- 与Flutter字体资源声明目标类似，但Web有网络、缓存、CORS和回退交换过程；不能只验本机存在字体。
- 只验证本地声明与回退，不包含授权字体下载资源，不宣称已验收Web字体网络加载。
