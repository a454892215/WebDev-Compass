## 验收标准

- [ ] 用自己的话解释：viewport元信息让移动布局使用设备宽度的CSS视口；CSS像素不等于一个物理像素。
- [ ] 执行对照操作后，从目标元素的 Computed 面板读出 `fontSize`，解释原因，而非只复述输出。
- [ ] 完成一次与原例不同的条件变化，记录预期与实际结果；保留键盘焦点、可读文字与必要滚动。
- [ ] 能复现并修正本页下一节的排错任务；没有对应工具链或真机证据时不声称通过。

## 排错任务

故意制造这个问题：CSS width=390意味着物理屏幕390像素。

按“元素是否匹配 → 声明是否生效 → 参照/约束是否正确 → 最终尺寸/绘制”的顺序定位，截取或抄录关键计算值，并用最小修改修复。不要用全局important或overflow:hidden掩盖现象。

## 思考题

为什么“用maximum-scale=1掩盖页面在缩放后的布局缺陷。”会造成误判？它在综合项目中可能影响哪些内容或用户操作？

## 参考要点

- 常用meta viewport为width=device-width, initial-scale=1.0；不能用user-scalable=no阻止读者放大。
- Web页面应通过流动布局适配，而不是把整张固定设计稿按比例缩成不可读小字。
- 类似逻辑像素概念，但浏览器缩放、地址栏和visualViewport是移动App常规布局以外的边界。
- 本页始终允许缩放；字体切换只是观察入口，不修改设备缩放设置。

## 关联综合实践
