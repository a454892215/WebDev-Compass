# 7.1.6 Docker 多阶段构建：构建工具与 Node 运行镜像分离 — 独立练习

先按理论与操作卡理解机制，再关闭示例完成变体，不要求复制整套工程。

## 动手任务

为静态SSG改写最终阶段并写出与Node SSR镜像的区别；在有Docker环境且用户授权时运行构建、非root、停止信号和健康检查。

## 验收标准

- [ ] 构建上下文/锁文件/构建命令/输出匹配，最终镜像不含.env与开发缓存；静态和SSR入口不混。
- [ ] 运行用户、端口、启动环境、信号与检查步骤完整；未实际运行明确记录。

## 排错任务

COPY本机.output到不同平台后原生模块加载失败：定位Node/架构/libc与产物来源，在目标平台构建；不通过复制更多秘密文件解决。

保留失败请求/状态、具体原因、修正后同一输入结果，不用“检查配置”代替证据。

## 参考要点

多阶段Dockerfile用构建阶段安装与编译，再将必要.output复制到运行阶段。运行镜像无需完整源码/开发依赖，但Nuxt server构建所需运行文件必须完整保留；只COPY public不能运行SSR。静态profile通常由静态服务器镜像提供，不需Node SSR进程。

镜像tag、平台架构、libc、Node版本及原生依赖会影响可运行性；不盲目跨平台拷node_modules。用非root运行、明确工作目录和环境、通过exec形式CMD接收信号。秘密不放ARG/ENV构建层，.dockerignore排除.env/缓存/本机输出；生产按审核过digest固定镜像并更新。

综合应用：按主项目pnpm build和artifacts/ssr入口审查多阶段模板，真正容器执行属于可选扩展，不为入门重装本地虚拟化环境。
