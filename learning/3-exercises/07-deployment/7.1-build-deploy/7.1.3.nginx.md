# 7.1.3 Nginx 静态文件、反向代理与 gzip — 独立练习

先按理论与操作卡理解机制，再关闭示例完成变体，不要求复制整套工程。

## 动手任务

在副本增加/download/静态目录与/api/反代，观察proxy_pass有/无URI后后端实际收到的路径；为下载缺失保持404。

## 验收标准

- [ ] nginx -t成功，静态内容/代理JSON的Content-Type和路径正确；API失败不回HTML。
- [ ] 文本gzip协商有效且解码正文相同；HTML与hash资源缓存不同。

## 排错任务

把location /api/ proxy_pass改成带/的后端地址后/api/status变为/status，后端404：先记录上游路径，再按契约恢复，不把API404 fallback到index.html。

保留失败请求/状态、具体原因、修正后同一输入结果，不用“检查配置”代替证据。

## 参考要点

Nginx可按location提供文件，也可proxy_pass到Nitro。静态根目录与代理路径规则必须分开；proxy_pass是否带URI会改变转发路径，不能仅凭字符串相似判断。gzip是HTTP内容编码，与文件扩展名、HTTPS和HTTP/2不同。

location优先级、try_files最后参数与响应状态影响结果；API和缺失脚本不应被HTML fallback吞掉。长期immutable只适合URL随内容变化的公开资源；HTML要能更新，身份响应private/no-store并绕过共享缓存。生产代理还需超时、请求大小、可信转发头、TLS与日志隐私策略，实验配置不是生产配置全集。

综合应用：对主Nuxt明确静态profile与Node SSR需要的两套location；独立lab实际验证代理/压缩，不冒充公网TLS已经配置。
