# 7.1.7 GitHub Actions：验证门禁、产物和受控发布 — 独立练习

先按理论与操作卡理解机制，再关闭示例完成变体，不要求复制整套工程。

## 动手任务

在副本工作流加入一个故意失败的类型检查，保证不会走发布；为受保护生产environment写出审批/身份与并发策略，但不要把真实凭据写进教学仓库。

## 验收标准

- [ ] 失败停止推广，产物与提交/profile可追溯；缓存与产物职责分开。
- [ ] 权限最小、可信代码边界与固定Action SHA明确；未运行远端不记通过。

## 排错任务

工作流忽略测试退出码或使用continue-on-error后仍部署：删掉该旁路，用真实非零检查验证后续推广不执行；不可只在说明文档写“会阻止”。

保留失败请求/状态、具体原因、修正后同一输入结果，不用“检查配置”代替证据。

## 参考要点

CI在隔离runner重建并验证，CD将已验证产物推广到目标。先按锁文件安装、类型/规范/测试/构建，失败不发布。缓存依赖提升速度但不是可发布构建，不能用缓存命中替代校验。一次验证后的产物应有提交/摘要/profile，避免部署时悄悄重建不同内容。

工作流遵循最小权限、受保护环境和可信分支；不要给不可信PR代码生产凭据，尤其不把pull_request_target当普通PR构建。第三方Action固定完整审核SHA，定期升级；SHA固定降低漂移但不替代审阅。发布并发控制防止旧流水线覆盖新版本，失败有明确回滚入口。

综合应用：对主项目检查脚本和本地已验证profile制定CI门禁，阅读固定SHA模板；真实账户CD配置为明确后续扩展。
