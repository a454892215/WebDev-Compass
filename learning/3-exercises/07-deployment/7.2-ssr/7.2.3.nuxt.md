# 7.2.3 独立练习：Nuxt生产部署：Node SSR、静态托管与身份缓存

先阅读[理论](../../../1-notes/07-deployment/7.2-ssr/7.2.3.nuxt.md)，运行[操作卡](../../../2-examples/07-deployment/7.2-ssr/7.2.3.nuxt-demo.md)后关闭参考，在副本独立完成。只用合成数据，不在公网或真实账号上故意制造泄露。

## 动手任务

为同一公开站点分别写Node与静态交付清单；在副本新增一个公开站点名称配置和仅server使用的合成标记，验证两种profile何时读取。

## 验收标准

- [ ] Node交付入口、目录与运行环境明确，静态交付目录及无server能力明确。
- [ ] 私有标记未进入响应/payload/客户端包，身份路径有no-store且不落入公开整页缓存。

## 排错任务

将/api/private加入全站swr缓存，或将server标记移动到runtimeConfig.public；先在隔离副本用合成Alice/Bob/匿名请求检查重复读取与泄露，恢复精确规则/DTO后复验，不能对真实秘密实验。

## 参考要点

配置公开边界按“浏览器是否需要”判断；身份数据先授权再最小DTO，所有可能返回该内容的整页/API/代理缓存都应复核。主工程合成Cookie身份不是生产认证。

保存改动/命令、原始输出或官方观察摘录、原因与恢复证据；类型/文件存在不等于实际部署和掌握。
