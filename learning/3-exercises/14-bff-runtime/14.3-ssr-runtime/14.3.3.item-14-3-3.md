# 14.3.3 独立练习：SSR 数据获取：识别 waterfall 与安全并行

## 动手任务

把 aggregate 改为先 await profile 再启动 catalog，用闸门断言发现串行；恢复独立分支并行，再为必选身份和可选推荐模块画不同失败策略。

先预测结果，保存故障变体，再运行或进行明确标注的静态观察。不要修改预期来掩盖故障；主项目任务先阅读实际源码，未有的能力写成新增扩展。

## 验收标准

- [ ] 放行 gate 前两个独立 loader 已启动，返回 DTO 与输入一致。
- [ ] 依赖身份的请求仍在身份校验后执行；明确可选分支失败的 UI 和错误类型。

## 排错任务

故障：loader 内先 await loadProfile 再调用 loadCatalog，导致 catalog 在 profile gate 放行前没有开始。看 started 事件而非只看网络截图；恢复先发起再汇合。另解释 Promise.all 失败时其他请求为何可能仍在运行。

## 参考要点

优化是减少无必要依赖，而不是取消必要权限顺序；错误策略、取消与并发上限是独立设计。
