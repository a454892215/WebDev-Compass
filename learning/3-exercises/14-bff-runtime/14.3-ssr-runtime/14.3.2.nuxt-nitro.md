# 14.3.2 独立练习：Nuxt Nitro：请求生命周期、配置和用户隔离

## 动手任务

将 requestView 的局部 context 故意改为模块级 currentIdentity，并保持 A/B 闸门顺序，观察身份串线后恢复；再审查主 Nuxt 的事件上下文和配置输出。

先预测结果，保存故障变体，再运行或进行明确标注的静态观察。不要修改预期来掩盖故障；主项目任务先阅读实际源码，未有的能力写成新增扩展。

## 验收标准

- [ ] 故障变体确实让 A 错读 B；恢复局部 context 后同一断言通过。
- [ ] 记录主项目双用户响应各自的展示字段，并确认 HTML/payload 不包含会话凭据；不只检查浏览器按钮。

## 排错任务

故障：模块顶层 let currentUser，在 await 前赋值、await 后返回。使用可控 Promise 闸门稳定复现，不靠随机并发碰运气。定位共享变量作用域，修复为 event.context 或调用参数；模块级连接池不必一并删除。

## 参考要点

异步交错不等于多线程；同一进程共享模块实例已经足以串用户。
