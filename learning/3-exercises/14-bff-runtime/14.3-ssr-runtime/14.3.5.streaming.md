# 14.3.5 独立练习：HTTP Streaming：首块、已发送头、取消与恢复

## 动手任务

在现有Node实验新增一个故意把JSON行拆为两次write的路径，编写有半行缓冲的增量消费者；新增“未收到done就断线”的状态，不把200直接当成功。

先预测结果，保存故障变体，再运行或进行明确标注的静态观察。不要修改预期来掩盖故障；主项目任务先阅读实际源码，未有的能力写成新增扩展。

## 验收标准

- [ ] 拆行/合并chunk都能还原消息，partial错误不会显示成功；收到done才确认完成。
- [ ] 取消后服务器活动请求归零；解释503与200+协议error的不同恢复入口。

## 排错任务

故障：在 /partial 已 flushHeaders 后调用 setHeader 或 writeHead(500)，会违反已提交响应头状态。保留测试夹具的协议error分支；客户端把error显示成可重试失败。如果错误破坏字节流，应中断并呈现不完整状态，不能假补done。

## 参考要点

HTTP成功与业务流成功分开；浏览器恢复是新增扩展，lab仅实测传输与清理。
