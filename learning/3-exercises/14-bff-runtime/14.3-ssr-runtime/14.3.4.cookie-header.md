# 14.3.4 独立练习：SSR Cookie/Header：入站身份与上游转发白名单

## 动手任务

为上游转发列一个显式表：输入头、是否允许、由谁重建、测试证据；加入伪造cookie、authorization、Host和换行字符，保证结果只含白名单。

先预测结果，保存故障变体，再运行或进行明确标注的静态观察。不要修改预期来掩盖故障；主项目任务先阅读实际源码，未有的能力写成新增扩展。

## 验收标准

- [ ] 入站用户 cookie/authorization/代理声明不会原样出现在外部上游头；服务凭据来自服务器受信参数。
- [ ] 解释相对本地 API 与任意绝对外部 URL的区别，并给出 Session 丢失时的排查步骤。

## 排错任务

故障：把 upstreamHeaders 改成 {...requestHeaders, authorization: serviceToken}，用户 Cookie/代理声明也被带走。断言真实输出头发现额外字段，修复为逐字段允许；不要只把日志中 Cookie 隐去而保留实际转发。

## 参考要点

先认证再传播最小身份；服务端能读到一个头并不能证明它可信。
