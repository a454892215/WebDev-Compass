# 14.4.1 独立练习：Edge 与 Node：按平台、数据位置和 API 选运行时

前置：对应理论和edge-lab测试。先预测再操作，保存自己的变体及输出；以下任务是学习者新增扩展，不代表示例已实现。

## 动手任务

为一个依赖私网数据库的订单聚合接口写 Node/Workers 两种候选表，列关键 API、数据区域、CPU 与墙钟指标，选择最小可行方案。

## 验收标准

- [ ] 每个候选都标来源、核对日期和至少一个会改变决定的限制。
- [ ] 明确不把本地 Node 测试或隔离实例内存当生产持久化/跨区域证据。

## 排错任务

故障设定：团队声称“Request/Response 在 Node 跑过，所以 Workers 的 node:fs 持久上传也已验证”。检查 policy.mjs 的导入和平台绑定；修复判据是把本地契约与真实平台写入寿命分开，保存待验项，取消该上线结论。

## 参考要点

先问依赖与数据在哪里，再问运行时；兼容日期是部署契约的一部分，不能只记录包版本。
