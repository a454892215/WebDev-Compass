# 14.1.3 独立练习：Worker Threads：CPU卸载、输入上限与生命周期

先读理论并运行操作卡；保留原例，在副本完成变体。目标是能改变输入并解释机制，不只复制测试成功输出。

## 动手任务

在副本把求和改为有输入上限的质数计数，保留正确结果、非法输入、异常、超时四条路径；加一个有界队列方案草图，列满队列的拒绝策略。不要为了演示跑无限CPU循环。

## 验收标准

- [ ] 小输入与独立参考算法结果一致，超大/负数在创建线程前被拒绝。
- [ ] 异常与超时均拒绝且进程能自行退出，不留下worker；说明池化与一次性模型差异。

## 排错任务

删去cpu.mjs的error监听，运行crash变体，子进程会产生未处理worker错误；只监听message会把失败路径漏掉。恢复error/exit与单次结算，再验证hang能终止。故障应在隔离副本进程运行。

记录失败断言/日志、根因、修复和同输入复验。所有故障在隔离副本、固定输入范围内运行，不污染主教材或启动永久进程。

## 参考要点

同时看数据输入、消息序列化、容量和结束条件。message到达不代表可以忽略后续资源，exit不等于业务成功；用settled保护只完成一次。

完成后进入综合任务，将本点与实际Nuxt项目边界关联；只有自己实际执行的结果才能写为本轮实测。
