# 14.5.4 Prisma schema 与迁移：读懂约束，保护 API 兼容性：独立练习

## 动手任务

把新增字段email设置为可空并提出未来唯一约束计划，列出空值/重复数据/大小写规范化风险；设计兼容旧DTO到新DTO的发布顺序，为null/重复/旧记录写纯函数契约测试。

先不看参考实现，提交输入、输出和解释；变更仅在隔离副本。观察任务给出记录，代码任务给出可运行变体，不要求提供真实凭据。

## 验收标准

- [ ] 能说明主键、唯一、可空的不同约束及前端错误体验；字段类型不直接等同公开API。
- [ ] 计划先查数据再加约束并保留旧版本兼容窗口，指出删列回滚需数据恢复而非仅git revert。

## 排错任务

故障：先把前端name:string替换为displayName:string，数据库旧行仍为null，页面崩溃。用第六项失败输入定位后，先兼容旧字段/回填再收紧；不能用非空断言消除真实数据问题。

保存失败输入与现象，再修复并重跑受影响测试。不能删断言或把异常无条件吞掉作为修复。

## 参考要点

阅读实际迁移SQL及DTO契约；区分“schema能解析”“代码能编译”和“旧数据/旧客户端仍可运行”。在没有真实数据库证据时记录观察结论。

未安装Prisma CLI、未生成客户端、未执行SQL。数据库版本、锁表/大表性能、回填并发及生产恢复不在本轮实测范围。对外DTO变更仍需14.2.6契约测试和旧客户端兼容评审。
