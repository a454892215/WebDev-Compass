# 14.5.3 Redis 的协作边界：会话、TTL、原子限流与故障策略：独立练习

## 动手任务

为模型增加绝对会话寿命与闲置续期上限，使用可控时间测试边界；另写一份两副本交错执行INCR/EXPIRE失败的时间线和原子脚本伪码，明确哪些必须用真实Redis后续验证。

先不看参考实现，提交输入、输出和解释；变更仅在隔离副本。观察任务给出记录，代码任务给出可运行变体，不要求提供真实凭据。

## 验收标准

- [ ] 会话撤销立即不可用，闲置续期不突破绝对寿命；TTL边界不依赖真实等待。
- [ ] 限流key隔离tenant/主体，解释Redis不可用时不同接口降级策略；不把Map测试称Redis集成通过。

## 排错任务

故障：在每次请求新建Map限流器，计数永远为1；移到进程范围只能修复单副本。另遗漏首次计数TTL会永久拒绝，用固定时钟推进并检查过期字段定位，最终跨副本仍需共享原子存储。

保存失败输入与现象，再修复并重跑受影响测试。不能删断言或把异常无条件吞掉作为修复。

## 参考要点

分开验证业务策略、单进程模型和真实存储一致性。会话id不写URL/日志，生产cookie属性遵循前面安全阶段要求。

没有安装或连接Redis，不依赖Docker/Colima，不宣称跨进程限流实测。生产选型需要由维护服务的一方给出版本、集群和持久化/SLA，再运行集成/故障测试；这里只要求前端/BFF开发者能读懂角色和失效边界。
