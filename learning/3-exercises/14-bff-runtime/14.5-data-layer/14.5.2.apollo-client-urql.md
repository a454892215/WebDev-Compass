# 14.5.2 Apollo / urql：规范化缓存、SSR 隔离与登出清理：独立练习

## 动手任务

新增同一cache内A/B两个实体的identify断言，验证tenant+id确实生成不同key。再设计登出时取消旧请求、清空缓存、切换身份后重拉的顺序测试，用可控延迟复现旧响应晚到。

先不看参考实现，提交输入、输出和解释；变更仅在隔离副本。观察任务给出记录，代码任务给出可运行变体，不要求提供真实凭据。

## 验收标准

- [ ] 同id不同tenant的实体key不同，两个SSR请求快照不混入对方name或凭据。
- [ ] 明确区分network-only/no-cache与clearStore/resetStore；登出变体不让旧响应覆盖新身份状态。

## 排错任务

故障：两个SSR请求复用一个模块级cache，先写A再读B会读出A-private。通过extract定位ROOT_QUERY.viewer引用和实体key，改为每请求创建。仅增加tenant key不能清掉ROOT_QUERY上的旧viewer。

保存失败输入与现象，再修复并重跑受影响测试。不能删断言或把异常无条件吞掉作为修复。

## 参考要点

隔离client/cache解决生命周期问题，keyFields解决实体身份问题；两者需分别验证。主工程REST没有因此自动获得GraphQL缓存。

测试覆盖缓存核心和手工状态转移，不代表Apollo Vue / urql插件、HTML序列化、登录切换请求竞态已经集成完成。新项目先按现有REST与useFetch需求决定是否需要GraphQL客户端，避免为缓存概念重复引入库。
