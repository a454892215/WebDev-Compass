## 动手任务

不运行先写本例顺序，再把嵌套Promise移到另一个位置观察顺序。用有限循环比较同步工作和分批让出任务。

先写预期，再运行自己的实现；不要只复制演示输出。

## 验收标准

- [ ] 同步、直接微任务、嵌套微任务、timer的本例顺序可解释。
- [ ] 能说明微任务饥饿风险，不对RAF/timer或后台页面作绝对时序承诺。
- [ ] 保存一个变体输入的结果与因果解释，区分实测和推断。

## 排错任务

把处理10000项的每一小步都递归queueMicrotask，说明为什么仍可能长时间不响应；改成有界批次和任务让出，不运行无限循环。

记录触发条件、实际现象、定位依据、修复和复验；预期错误显式捕获，禁止无限循环或污染真实业务数据。

## 参考要点

先画当前栈，再按实际入队顺序展开微任务；网络、输入、渲染分别属于宿主调度，不从一个小例子归纳全部顺序。

参考用于核对自己的推理，不表示已替学习者完成练习。
