# 13.2.2 内部npm包交付：scope、registry、权限与可回退产物：独立练习

## 动手任务

只在模板中选定一套registry职责方案，核对scope路由与publishConfig一致，列安装和发布权限。检查本地归档不含源码秘密/缓存；如果没有已授权registry，只交官方观察和未测清单，不发送请求。

## 验收标准

- [ ] 区分pack成功与发布/安装授权成功，列明实际未运行Verdaccio/Artifactory/GitHub Packages。
- [ ] 为回退保留已知锁文件/版本/构建产物；不建议覆盖同一已发布版本或把unpublish当普通回退。

## 排错任务

配置推演：scope指向A源而publishConfig指向B源，或把具有发布权限的token供不可信PR安装。定位读取/写入目标和权限边界，改成一致的受控registry与最小权限；不要为演示真正泄露或试用凭据。

## 参考要点

registry负责包名/版本/元数据/归档分发，workspace只是本地依赖组织。Verdaccio可作私有代理缓存/发布源，Artifactory和GitHub Packages另有访问控制/认证约束；内部包未必必须自建registry。先确认组织scope、可见性、安装读权限、发布写权限及令牌用途，再配置具体工具。

GitHub Packages当前npm认证文档列PAT classic及Actions中GITHUB_TOKEN适用条件；npmjs trusted publishing/OIDC不能直接当作所有registry通用能力。读取别的私有repo还需授予包访问，安装token不应默认拥有发布权限。不要把.npmrc实际令牌、CI日志、缓存归档或tarball当秘密存储。

先独立记录输入、实际失败和恢复结果再看参考；只改隔离副本，不动旧阶段或真实registry。
