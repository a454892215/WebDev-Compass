# 13.3.2 Vite插件最小闭环：虚拟模块、构建钩子与公开Manifest：独立练习

## 动手任务

把label改成合法的release-fixture并重建，核浏览器和audit一致；再试非法含引号/尖括号label，确认在构建前拒绝而不是拼入可执行代码。

## 验收标准

- [ ] 真实build和页面显示相同公开label，audit包含JS产物，未知virtual id不被插件接管。
- [ ] 不透传环境秘密；说明generateBundle并非dev每请求hook，源码变换的map要求另列。

## 排错任务

删去resolveId对virtual id的返回值，再构建会发生解析失败；只改load而不完成解析不能修复。另一故障是把generateBundle产物当dev服务器已有路径，请求404时先核阶段。

## 参考要点

插件先定义输入/输出和适用阶段，再选择hook。resolveId把公开virtual:id映射到内部空字符前缀ID，load返回模块代码；transform处理已有源码时还要考虑过滤、source map和环境。generateBundle属于产物生成阶段，不能假设开发服务器每次请求都执行。

插件运行在构建机权限下，不可随意读取凭据/把process.env全部注入浏览器。此例返回新虚拟常量，无原始源码映射需要保留；改写真实TS/CSS的插件应提供正确map、限制id并考虑SSR/client差异。没有实现Webpack loader/plugin，二者扩展点不能直接复制接口。

先预测与操作，再对照参考；只改隔离副本，不污染主工程或旧阶段。
