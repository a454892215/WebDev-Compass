# 12.3.1 独立练习：Design Token分层：从视觉值到语义与组件契约

先读理论与操作卡，再在隔离副本改动，不能修改真实设计项目或发布账号。

## 动手任务

在隔离副本增加semantic color.focus，引用一个有明确对比要求的primitive，并给按钮focus-visible应用它；保留原action名。

## 验收标准

- [ ] 生成CSS/JS/.d.ts均包含新增语义，alias解析后值匹配预期，不能手改dist/tokens掩盖源缺失。
- [ ] 在明暗主题及键盘焦点分别核对可见性，说明token类型不能代替视觉/无障碍验收。

## 排错任务

把color.action的引用改为{missing.alias}，运行pnpm test中的未解析引用负例或独立构建；真实构建应拒绝。修正源引用再生成，不在产物补一个常量绕过。

## 参考要点

Token是对可复用设计决策命名，不只是给每个十六进制颜色起别名。先区分primitive（如navy）、semantic（如action/text/surface）和组件级（如button-background）职责；semantic引用primitive，使换品牌不必改所有调用处。Color、Spacing、Typography、Radius、Shadow需要类型、单位、用途、负责人及弃用策略，不能只维护一张色表。

名字是公开契约：删除/改语义可能影响依赖，即使CSS变量名仍在。类型化声明只校验引用形状，不证明对比度或语义正确；数值更新要在交互状态/主题中检查。不要把色值当交互状态唯一信息，不用未经净化的远端token片段拼CSS。
