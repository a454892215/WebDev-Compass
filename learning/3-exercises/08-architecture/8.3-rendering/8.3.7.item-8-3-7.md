# 8.3.7 渲染决策树：从身份、时效和托管约束给出可推翻决定：独立练习

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 动手任务

为课程目录新增“公开周更、无Node运维预算”和“每用户即时余额”两组互相不同需求，分别沿决策树走到结论并给替代方案。

## 验收标准

- [ ] 每条路径能回溯到明确需求与失败处理，至少两备选和后果。
- [ ] 写出验证与重新评估触发，不能把SSR/Edge/Islands当所有产品默认。

## 排错任务

故障：决定书以“SSR更先进”作为唯一理由。用内容时效/身份/部署能力重写，并注明未测预算；不编造性能数字填表。

## 参考要点

公共文档可SSG，个性化请求可SSR或静态壳+受保护API，封闭交互工具可CSR；混合模式需逐路由记录缓存、身份与更新机制。为候选写被否决原因、未知项、最小验证和重新评估触发，避免只给一个永远不变的框架答案。

先独立尝试，再对照操作卡；保存真实输入、结果、原因和恢复，不在公网/真实用户数据中故意制造泄露。
