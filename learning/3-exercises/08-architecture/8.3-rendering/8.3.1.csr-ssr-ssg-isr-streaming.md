# 8.3.1 CSR、SSR、SSG、ISR与Streaming：按约束比较而非排名：独立练习

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 动手任务

为公开周更文档、每秒行情、带身份工作台各选候选模式，给同一工作台两种方案并说明何时推翻决定。

## 验收标准

- [ ] 每个决定列内容新鲜度、身份、路由与托管约束，不以一个分数决定所有页面。
- [ ] 标明真实测量/历史证据/官方观察；Streaming与ISR未运行不记已通过。

## 排错任务

故障：方案把静态public上传后期待运行时Cookie聚合和SSR。先查看有无server入口，再选择Node/API或改变需求；恢复后直接访问详情并核对HTTP状态。

## 参考要点

ISR/后台再验证依框架和托管缓存能力，Nuxt Node swr与平台isr、浏览器HTTP缓存不同。Streaming提前发送壳或边界内容，不会自动缩短总数据时间；代理缓冲、错误状态何时已提交、CSP和接管策略也须验证。不要把TTFB小直接等于FCP/LCP好，更不能仅凭SSR承诺排名。

先独立尝试，再对照操作卡；保存真实输入、结果、原因和恢复，不在公网/真实用户数据中故意制造泄露。
