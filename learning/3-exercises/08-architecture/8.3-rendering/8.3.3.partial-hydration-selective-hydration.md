# 8.3.3 Islands、Partial与Selective Hydration：减少接管范围的不同机制：独立练习

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 动手任务

将公开介绍页设计成两个互不依赖交互区；再加入“结算需立即键盘使用”约束，修改触发与回退。

## 验收标准

- [ ] 静态内容与真实链接不因JS未就绪消失，关键操作有明确就绪/失败路径。
- [ ] 记录跨岛通信成本，不将所有部件都延后以追分。

## 排错任务

故障：关键按钮只在永远没进入视口的祖先事件后接管。用键盘路径推演并改为立即就绪或原生导航，不用spinner掩盖永久不可用。

## 参考要点

延迟接管减少立即工作，但交互前未就绪、布局变化、焦点/事件重放及跨岛状态都有成本。静态HTML仍需语义与可用链接，重要任务不能永远等不可达触发条件；普通动态import不是已经构建Islands系统。Nuxt特性应按当前版本和具体组件能力验证，不默认开启实验组件。

先独立尝试，再对照操作卡；保存真实输入、结果、原因和恢复，不在公网/真实用户数据中故意制造泄露。
