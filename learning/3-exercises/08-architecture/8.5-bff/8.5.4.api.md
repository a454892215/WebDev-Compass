# 8.5.4 API版本与废弃：并行兼容、Deprecation与Sunset：独立练习

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 动手任务

将v1字段title改为label制造旧客户端失败，再选择保留v1映射/v2并行或兼容字段迁移；写窗口和停止条件。

## 验收标准

- [ ] v1消费者原字段/类型/语义保持，v2有明确契约和回滚。
- [ ] Deprecation是@秒结构日期，Sunset是可解析HTTP-date；公告不等于自动关服。

## 排错任务

故障：返回Deprecation:true并次日直接删除v1。依据RFC修正格式，补真实消费者迁移/观察窗口；不能只改header掩盖破坏性下线。

## 参考要点

Deprecation按RFC9745使用Structured Field Date，如@unix-seconds，说明被弃用/生效日期；不是布尔true或HTTP-date。Sunset按其规范用HTTP-date说明预计停止服务日期，二者不自动执行下线，也不代替迁移说明。并行服务旧版直到约定窗口，记录兼容和回滚；不能让旧hash页面突然调用已删API。

先独立尝试，再对照操作卡；保存真实输入、结果、原因和恢复，不在公网/真实用户数据中故意制造泄露。
