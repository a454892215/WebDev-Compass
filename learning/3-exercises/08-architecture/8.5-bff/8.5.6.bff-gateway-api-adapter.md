# 8.5.6 BFF与移动Gateway/API Adapter：职责相似但信任位置不同：独立练习

前置：阶段3类型/构建、阶段4 Nuxt、阶段5API与阶段6–7质量/部署。先读机制，再运行/观察，独立变体后进入架构决策。

## 动手任务

为PC表格与手机摘要复用同一课程后端设计共享契约；列一个值得拆BFF的真实差异与一个不拆的理由。

## 验收标准

- [ ] 图中每个组件的运行位置与信任边界明确，客户端不含服务凭据。
- [ ] 不把UI独立等同业务/权限逻辑复制，明确fixture演示与真实认证差距。

## 排错任务

故障：把Android拦截器中的服务secret搬入Nuxt public配置，认为BFF相同架构。追踪浏览器payload，改在server持有受限凭据并最小化返回，真实泄露需轮换。

## 参考要点

PC/H5 UI独立不必自动产生两个BFF；同一业务服务可共享授权/领域规则，不同终端聚合需求若真实分化再拆。BFF无法消除上游权限、网络失败和版本成本，拆分要有所有者、契约、监测及恢复边界。教学scope只能选公开fixture，不代表已建立生产租户隔离或身份认证。

先独立尝试，再对照操作卡；保存真实输入、结果、原因和恢复，不在公网/真实用户数据中故意制造泄露。
