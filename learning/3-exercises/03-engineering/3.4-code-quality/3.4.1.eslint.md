# 3.4.1 独立练习：ESLint：用 flat config 检查代码质量

在实验副本或临时目录操作，先独立完成，再对照[示例](../../../2-examples/03-engineering/3.4-code-quality/3.4.1-eslint/README.md)。不改真实仓库全局配置，不使用真实凭据，不发布 npm 包。

## 动手任务

在实验副本添加 no-debugger:error，并创建含 debugger 的 ts 文件；记录失败，修复后重新检查。

## 验收标准

- [ ] pnpm lint 对 debugger 返回非零且指出规则名。
- [ ] 移除 debugger 后 lint 与 typecheck 均通过。

## 排错任务

把 files 误设成 **/*.js 后放入 bad.ts；观察该文件是否被规则检查。恢复 TypeScript 匹配范围，再比较输出；不能只看命令退出码而忽略 ignored 警告。

记录复现输入、实际错误、定位依据、修复与复验命令；只有结果可观察地恢复才关闭问题。

## 参考要点

先确认脚本工作目录、匹配范围和配置文件，再调整单条规则；不要把类型错误期待交给所有 ESLint recommended 规则。
