# 3.4.4 独立练习：Husky + lint-staged：在暂存文件上执行提交前检查

在实验副本或临时目录操作，先独立完成，再对照[示例](../../../2-examples/03-engineering/3.4-code-quality/3.4.4-husky/README.md)。不改真实仓库全局配置，不使用真实凭据，不发布 npm 包。

## 动手任务

阅读 verify-tools.mjs 的临时仓库段，在自己的临时副本把匹配范围改为 *.ts，添加 bad.ts 验证暂存检查。不要在真实宿主仓库安装 hook。

## 验收标准

- [ ] 坏暂存内容阻止提交且出现实际 ESLint 规则名。
- [ ] 修复并重新 git add 后成功；主仓库 hooksPath 未改变。

## 排错任务

修复文件但忘记 git add；比较 git diff 和 git diff --cached，再重新暂存验证。不要通过 --no-verify 掩盖失败。

记录复现输入、实际错误、定位依据、修复与复验命令；只有结果可观察地恢复才关闭问题。

## 参考要点

lint-staged 对部分暂存的处理依赖其版本；先读输出和差异。例子不把 hook 当不可绕过保证。
