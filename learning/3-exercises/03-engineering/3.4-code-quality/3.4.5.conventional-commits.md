# 3.4.5 独立练习：Conventional Commits：写清变更类型、范围与破坏性变化

在实验副本或临时目录操作，先独立完成，再对照[示例](../../../2-examples/03-engineering/3.4-code-quality/3.4.5-conventional-commits/README.md)。不改真实仓库全局配置，不使用真实凭据，不发布 npm 包。

## 动手任务

为“新增筛选”“修复标题解码”“改变导入字段导致旧文件不兼容”各写提交消息；最后一条写明迁移方法。

## 验收标准

- [ ] feat/fix 类型与实际变更一致，描述说明结果。
- [ ] 不兼容变更使用 ! 或 BREAKING CHANGE 并说明迁移。

## 排错任务

给纯排版提交写 feat: 新增功能；指出语义误导并改成团队认可的 style/chore 等类型，而不是只检查正则。

记录复现输入、实际错误、定位依据、修复与复验命令；只有结果可观察地恢复才关闭问题。

## 参考要点

先判断实际契约是否变化，再写类型；格式校验与审查目的不同。
