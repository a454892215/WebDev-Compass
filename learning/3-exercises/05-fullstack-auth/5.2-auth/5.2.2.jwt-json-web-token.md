# 5.2.2 独立练习：JWT：签名、claims与access/refresh职责

## 动手任务

在实验副本新增一个正确签名但aud错误的token，并说明为何“签名正确”仍不能授予访问；比较服务器会话退出与独立JWT到期。

先用自己的副本实现/记录，不使用真实账户凭据；先预测再运行。

## 验收标准

- [ ] 篡改payload或错误key被真实密码学验证拒绝，decode成功不算授权成功。
- [ ] 正确签名但错误用途/受众/时间被拒绝；说明退出后的access撤销取决于服务器策略。

## 排错任务

只用decodeJwt读取role=admin后放行；用实验现成篡改token重现解码可见而签验失败，恢复服务器固定验证策略，再验证合法token不受影响。

保留“输入→现象/状态码→原因→修正→复验”，不只写已解决。

## 参考要点

- token内容与传输方式分开；JWT放Cookie也仍有Cookie/CSRF边界。
- 不把用户敏感数据塞进可读payload，也不提交真实生产密钥。
