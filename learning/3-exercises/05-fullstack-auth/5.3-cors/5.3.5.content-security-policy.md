# 5.3.5 独立练习：HTTPS与安全响应头：按部署能力逐步收紧

## 动手任务

在副本增加一个合法脚本资源，先用报告模式分析策略，再根据来源/nonce设计允许方式；另写真实部署的证书和混合内容检查步骤。

先在副本实现，记录命令、请求/响应或连接状态；不要只复制预期答案。

## 验收标准

- [ ] 能实际证明本地内联脚本被阻止而允许脚本执行，且不以此声称没有XSS。
- [ ] TLS/HSTS步骤标明真实域名和恢复条件；不修改浏览器安全选项，不把本地HTTP称HTTPS通过。

## 排错任务

把Nuxt的内联接管脚本意外挡住，定位CSP控制台与响应头，而不是给script-src加入unsafe-inline草率放开。按框架nonce/可信哈希支持修正，并验证正常接管和拒绝非法脚本。

保留故障输入→实际现象→定位→修复→复验，不只写“已解决”。

## 参考要点

- 先盘点合法资源和部署能力，再逐步收紧；安全头各司其职。
- frame-ancestors放响应头；HSTS只在可靠HTTPS上部署。
