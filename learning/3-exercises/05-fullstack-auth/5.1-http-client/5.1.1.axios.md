# 5.1.1 独立练习：HTTP客户端选型：Fetch、Nuxt读取与统一错误边界

## 动手任务

在副本给一个真实列表读取保留四类错误，再将失败映射成页面提示；比较原生fetch与Nuxt读取生命周期，不同时引入多个HTTP库。

先在自己的副本动手，保留运行命令、预期/实际和修复记录，不以复制示例代替实现。

## 验收标准

- [ ] 404、坏JSON、错字段分别触发不同类别，失败不冒充空列表成功。
- [ ] 204不被强行解析JSON；成功DTO进入UI前已解码。

## 排错任务

将readJSON中的response.ok检查删去，再请求/missing，观察错误被误归为成功或结构失败。恢复HTTP分支，并保留原status供上层判断。

## 参考要点

- 统一的是应用错误契约，不是伪造所有库相同的异常。
- Nuxt SSR数据读取与事件提交的自动payload行为不同。
