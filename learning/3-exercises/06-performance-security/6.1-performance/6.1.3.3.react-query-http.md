# 6.1.3.3 独立练习：Nuxt数据缓存与HTTP响应缓存的失效

## 动手任务

给Nuxt副本一次筛选或更新定义数据身份/失效计划，分别检查payload重复请求、应用key与响应缓存。

先在副本实现/观察，保存自己的操作和结果，再核对参考。

## 验收标准

- [ ] 同key选项一致，身份/条件变化不复用错误用户或旧查询数据。
- [ ] 明确刷新/清理的是哪一层，不靠禁用所有缓存掩盖模型错误。

## 排错任务

把不同用户/不同查询硬塞同一个全局缓存对象，观察错数据；改作用域/数据身份与失效规则，再检查SSR与客户端。

记录具体输入、现象、原因、修复和复验，不只写“已解决”。

## 参考要点

- 公开目录与带身份API要采用不同策略。
- 缓存命中不是正确性证明，先保证数据边界。
