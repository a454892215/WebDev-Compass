先在副本实现/观察，保存自己的操作和结果，再核对参考。

## 验收标准

- [ ] 改造前后功能与依赖关系一致，没有因缓存漏依赖返回旧值。
- [ ] 解释为什么选择Vue机制，不把React的内联对象/memo规则当Vue强制规范。

## 排错任务

把带副作用的请求塞进computed以求“少执行”，重现重算/读取次数改变业务；派生保持纯，副作用改合适watch/事件/数据获取。

记录具体输入、现象、原因、修复和复验，不只写“已解决”。

## 参考要点

- 先证实热点再增加复杂度。
