# 6.1.1.2 独立练习：网络：压缩、请求成本与HTTP/2

## 动手任务

换一份业务形状的公开JSON，记录原始/编码字节、响应头与解码结果；另用官方HTTP/2清单分析目标托管，不凭文件数做结论。

先在副本实现/观察，保存自己的操作和结果，再核对参考。

## 验收标准

- [ ] 解码后与原文一致，Content-Encoding/Vary正确，区分Fetch解码长度和原始传输字节。
- [ ] 是否启用压缩/合包有具体资源和缓存依据，HTTP/2未测就标明。

## 排错任务

把gzip字节返回却漏Content-Encoding，或把已经解码的response.text长度写成压缩传输量；用原始http客户端与头定位并修正。

记录具体输入、现象、原因、修复和复验，不只写“已解决”。

## 参考要点

- 压缩比受内容/等级影响；本lab不测公网延迟。
- 生产编码协商应测试缓存变体，不只看Accept-Encoding是否存在。
