# 6.3.2 独立练习：语义HTML、无障碍树与读屏观察边界

## 动手任务

在Nuxt副本找到一个无语义可点击容器，改成原生button或正确链接；用键盘与role/name确认，不只看样式。

先在副本独立完成，保留自己的证据再对照参考。

## 验收标准

- [ ] 页面有明确主内容和标题层级，重复导航有合适名称。
- [ ] 新增操作能用键盘触发，工具识别正确角色/名称；未实测读屏时不写“读屏通过”。

## 排错任务

把button换成带click的div，观察Tab无法到达或Enter无效；恢复原生控件，重测交互和可访问名称。

记录输入/状态→现象→原因→修复→同条件复验，不只写“已解决”。

## 参考要点

- 原生header/nav/main/footer、h1–h6、ul/li、button与form提供语义。标题按内容层级组织，不能为字号跳级；多个同类导航应有可区分名称。装饰div不会因加点击事件自动成为可键盘按钮。
- 开发者工具/Playwright的role定位可辅助检查名称与角色，不等于已听过真实屏幕阅读器。应记录读屏器、浏览器、版本和实际播报/操作。
