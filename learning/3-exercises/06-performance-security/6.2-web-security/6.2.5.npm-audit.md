# 6.2.5 独立练习：依赖安全：审计快照、锁文件与升级判断

## 动手任务

读取一次自己副本的审计输出，为一个真实或明确标注的公告样本写受影响条件、依赖路径、升级/替代与验证计划，不要求制造真实漏洞包。

先在副本独立完成，保留命令、输入和实际结果，不逐行复制观察输出。

## 验收标准

- [ ] 记录审计日期、范围和服务是否成功；无法查询不伪报0。
- [ ] 处置解释修复版本/兼容风险和必要回归，不盲目强制升级或把锁文件当安全认证。

## 排错任务

把--prod快照当全工程安全结论；找出其排除的开发链，修正报告范围。若网络失败，保留错误并区分待查与已知安全。

记录故障输入→实际结果→原因→修复→复验，不能只写已解决。

## 参考要点

- audit退出非0可能是发现公告，也可能是工具/网络失败，要读结构。
- 不要向公共审计服务发送源码或凭据；依赖元数据仍需按组织政策处理。
