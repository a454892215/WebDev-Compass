# 11.4.5 GitHub Actions矩阵、缓存与受保护部署：独立练习与验收

## 动手任务

按模板算出4组合，评审缓存key和PR权限；设计一个只允许main环境发布的OIDC信任条件。将SHA占位换成你实际审过的官方提交后，在自己的仓库按需接入；本库不运行远程CI。

## 验收标准

- [ ] 逐项区分矩阵质量/依赖缓存/发布产物/环境审批，并指出该deploy骨架当前不会部署。
- [ ] 明确SHA与平台设置/云授信还缺什么；不向workflow注入真实secret进行教学。

## 排错任务

静态故障：把deploy触发改成pull_request_target并运行PR传入shell片段，标出不可信代码与高权限环境相交；恢复低权限PR质量与受保护main发布，输入以参数传递而非拼shell。不得真实执行恶意片段。

## 参考要点

矩阵把同一质量任务展开为多组环境；明确所需组合与成本，不把矩阵重复构建当发布多份不同产物。缓存是加速手段，命中后仍冻结安装与检查；key应包括OS/架构/运行时/锁文件。产物与依赖缓存是不同职责。

PR代码不拿生产secrets，避免pull_request_target检出并执行不可信分支。GITHUB_TOKEN最小权限，OIDC只在需要发布的job启用并由云端限定repo/ref/environment；id-token:write本身不是授权成功。平台secret遮罩不能保证所有变换都脱敏。部署concurrency/审批与回滚要另核。

不提前对照答案：先记录预测，再核操作/配置和实际证据。未运行的外部平台只能写推演。
