# 11.3.6 独立练习：事件响应：先恢复、再定位，形成可执行Runbook与复盘

先读[理论](../../../1-notes/11-observability/11.3-release-management/11.3.6.incident-response.md)，按[实验说明](../../../2-examples/11-observability/11.3-release-management/release-lab/README.md)在隔离副本操作；不要改真实生产资源。先独立完成，再看参考。

## 动手任务

给推演增加“kill服务不可用且新程序写入不兼容字段”分支，说明为何不能直接切旧程序；选择可恢复旧路径/暂停写入等方案并明确需要后端owner决策的边界。

## 验收标准

- [ ] 每次动作有触发、owner、预期、失败分支和复验；恢复以真实业务/版本指标而非告警静默判定。
- [ ] 复盘区分事实/推断/未确认，有不含敏感数据的证据以及可验收改进项。

## 排错任务

团队只把告警静音就宣布恢复，或先清空日志导致无法关联release。恢复业务检查/用户影响指标并保留最小必要证据，标注仍未知的原因，不能用猜测补齐。

## 参考要点

多人无记录同时改；先证明根因才止损；恢复后不核对业务；复盘只责备人；虚构“告警已通知值班人”。 保留前提、实际输入/输出和未测范围；不要只交一张“成功”截图。先读incident-drill.md，分别扮演指挥/操作/沟通，按检查点运行pnpm test和pnpm rollback，填自己实际开始/结束和输出。模板时间是相对推演节点，禁止填成真实事故已发生。
