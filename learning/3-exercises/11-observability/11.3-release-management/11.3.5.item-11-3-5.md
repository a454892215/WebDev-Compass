# 11.3.5 独立练习：回滚：不可变产物、旧资源保留与数据库兼容

先读[理论](../../../1-notes/11-observability/11.3-release-management/11.3.5.item-11-3-5.md)，按[实验说明](../../../2-examples/11-observability/11.3-release-management/release-lab/README.md)在隔离副本操作；不要改真实生产资源。先独立完成，再看参考。

## 动手任务

在隔离副本模拟删除stable hash后再回退，增加缺资源失败判据；设计新增字段→兼容部署→确认旧实例退场→收缩的两版本表。

## 验收标准

- [ ] 回退后manifest引用的旧hash真实存在，仍打开的新版本所需资源也保留。
- [ ] 明确应用/配置/数据库三层恢复条件；有破坏性迁移时不能宣布无条件回滚。

## 排错任务

把两版本脚本都写到同一个app.js，candidate覆盖stable后manifest切回也仍执行新代码。改内容hash命名并保留独立产物，验证restore读取stable内容。

## 参考要点

删除新hash造成仍开着页面404；回滚源码而没有保留旧产物；数据库down迁移当万能恢复；健康200却业务失败。 保留前提、实际输入/输出和未测范围；不要只交一张“成功”截图。运行pnpm rollback或第四组pnpm test；查看initial/candidate/restored和两hash保留/readable。临时目录finally清理。未进行CDN purge、真实SSR服务切换、数据库迁移或灾备恢复。
