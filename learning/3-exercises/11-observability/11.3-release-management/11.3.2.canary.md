# 11.3.2 独立练习：Canary灰度：稳定群组、分版本指标与停止条件

先读[理论](../../../1-notes/11-observability/11.3-release-management/11.3.2.canary.md)，按[实验说明](../../../2-examples/11-observability/11.3-release-management/release-lab/README.md)在隔离副本操作；不要改真实生产资源。先独立完成，再看参考。

## 动手任务

换一套group为reader-v2，保存三个fixture的桶值；分别设计1%→5%→25%的窗口、最小样本、版本标签及失败停止条件。

## 验收标准

- [ ] group不变时增大比例不移除旧成员；改变group明确视为重新分配。
- [ ] 监控比较按release拆分，零/少样本显示不足，不当作绿色放行。

## 排错任务

每次调用生成Math.random后再比较百分比；重复读取同一fixture会抖动。改回稳定hash并同时验证SSR与客户端复用结果，不能给测试固定随机数掩盖真实设计。

## 参考要点

只看全站平均；把2个请求的0错误叫验证通过；同时改salt又扩量却声称旧群组稳定；把匿名Cookie当真实权限。 保留前提、实际输入/输出和未测范围；不要只交一张“成功”截图。运行pnpm test第一组，逐个fixture扫0–100百分比，确认false只会变true、不逆转；0/100、区域、白名单、kill分别测试。三个fixture仅验证算法性质，不证明真实人口恰有25%或流量代表性。
