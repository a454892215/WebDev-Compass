## 动手任务

在React副本为同一阅读列表设计用户+筛选key和失败回滚计划；新增Mutation时用延迟失败fixture验证，不复制到Nuxt造成两套缓存真相。

先在自己的副本尝试，再查参考。保存改动、命令、预期和实际；选修对照不要求把React放进Nuxt主工程。

## 验收标准

- [ ] 查询输入变化映射到不同key。
- [ ] 失败回滚与最终重新校验可解释，不把本例等同完整并发乐观更新。

## 排错任务

列表A/B共用["tasks"]导致串数据；把筛选/用户放key，分别读取并断言缓存隔离。

记录具体输入→可观察故障→原因→修复→同条件复验。不要只写“修好了”，也不要删除规则掩盖问题。

## 参考要点

- 远程缓存和纯UI状态职责不同。
- 本例retry:false便于确定失败行为，不是所有生产场景推荐。
