# 15.6.3 OPFS：源私有草稿、配额和可恢复边界：独立练习

在隔离副本完成变体，运行入口见对应操作卡；先预测，保存失败与修复证据。以下为学习者新增任务，不声称主Nuxt已实现。

## 动手任务

新增可导出的版本化草稿格式，测试未知版本拒绝、正文读取失败和存储不可用回退；只清理由本练习创建的唯一文件。

## 验收标准

- [ ] close后才显示保存成功，读回正文与版本一致；失败有明确状态和导出恢复。
- [ ] 不清空整个源；区分配额/站点清理/权限/备份，未测的跨会话持久性不声称通过。

## 排错任务

故障：写后不await close就立即显示保存成功，错误晚到导致UI与实际内容不符；把成功状态移到完整close之后。若catch所有错误仍返回supported:true，应改为可见失败/显式回退，并保留旧草稿或导出入口。

记录目标浏览器、操作、实际状态和资源结束条件；不能改预期或吞异常伪造通过。

## 参考要点

真实Chrome执行getDirectory→唯一文件createWritable/write/close→getFile/text→finally removeEntry；返回合成正文且测试确认没有残留compass-fixture文件。强制缺失路径返回supported:false，不假称已持久化。 主项目扩展先核实际路由/状态owner与平台支持，再决定是否接入；观察或未测场景保持待验。
