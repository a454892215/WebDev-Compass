# 15.6.5 WebAuthn仪式、服务端验证与Payment Request边界：独立练习

先读机制和运行操作卡，在隔离副本完成变体；保留自己的输入、故障、修复与证据，不提交真实账号或支付信息。

## 动手任务

在隔离副本建立服务端验证责任表：challenge生成/存储/消费、RP/origin、UV、凭证归属、验签、业务会话。增加一个过期或已消费challenge的状态模型；Payment写取消与后端待确认的订单状态图，不接真实支付。

## 验收标准

- [ ] 责任表明确前端与服务端，重放/过期挑战拒绝，模型不能冒称密码学验证。
- [ ] 支付状态区分取消、授权结果和服务端确认；没有真实商户证据就不写支付成功。

## 排错任务

故障设定：把浏览器的challengeMatches:true直接当成“已登录”。通过当前serverVerified:false和缺失服务器验签定位信任边界；修复为只有服务端受验证结果才能建立会话。若扩展虚拟仪式，错误rpId应失败；不能以关闭校验或固定challenge解决。

## 参考要点

自动化verify.mjs先创建临时CDP虚拟认证器，点击生成本地合成凭证和发起断言；实际type为webauthn.create/get、origin为http://localhost:4576、challengeMatches为true，断言signatureBytes大于0，serverVerified始终false。Payment仅记录接口是否存在。测试结束移除认证器并关闭隔离浏览器上下文，不触碰用户真实passkey。 区分实际API返回、业务成功与部署条件；本机支持不等于其他浏览器或真实设备支持。
