# 15.6.2 Navigation API：拦截边界、历史与框架路由所有权：独立练习

在隔离副本完成变体，运行入口见对应操作卡；先预测，保存失败与修复证据。以下为学习者新增任务，不声称主Nuxt已实现。

## 动手任务

在原生lab新增/nav/three并为直接深链、后退、未知路径、锚点及下载列测试；对主Nuxt只写路由owner评审，不另装全局拦截器。

## 验收标准

- [ ] 同文档导航与普通链接回退均可到达新页面，标题/焦点与实际内容一致。
- [ ] 未知/跨源/表单/下载不被错误接管；说明主Nuxt已有路由owner和深链服务器责任。

## 排错任务

故障：只检查URL已到/nav/two就立即断言异步内容，会偶发看到旧标题；等待导航finished或页面完成标记。另一故障是无条件intercept把下载吞掉，恢复明确筛选并验证普通行为。

记录目标浏览器、操作、实际状态和资源结束条件；不能改预期或吞异常伪造通过。

## 参考要点

真实navigate拦截跳到/nav/two，保持window内同文档marker、更新标题，再后退回视图一。测试等待页面标题状态，不把goBack调用返回当渲染已完成；强制回退使用普通链接整页加载仍可用。 主项目扩展先核实际路由/状态owner与平台支持，再决定是否接入；观察或未测场景保持待验。
