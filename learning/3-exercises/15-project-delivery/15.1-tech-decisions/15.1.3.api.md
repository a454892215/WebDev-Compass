# 15.1.3 跨团队API契约：Mock先行、兼容窗口与联调：独立练习

先读对应理论与[操作卡](../../../2-examples/15-project-delivery/15.1-tech-decisions/15.1.3.api-demo.md)，在隔离副本完成变体；先预测再对照，不改共享生产环境。

## 动手任务

为主Nuxt目录记录一份请求/响应/错误契约，将一处字段改名作为隔离变体，验证旧消费者失败与适配恢复；真实接口联调列待验。

## 验收标准

- [ ] 正例、空/错或类型漂移负例及兼容适配都有实际证据；Mock和真实服务分清。
- [ ] 契约同时覆盖权限/错误/版本窗口，改名不直接删除旧消费者仍需的字段。

## 排错任务

把title改name却仅重生成TypeScript，旧消费者仍报CATALOG_CONTRACT。用固定输入复现，增加兼容适配与旧客户端测试，再决定移除窗口；不能用as断言掩盖。

保存输入、失败现象、根因与修复后复验。观察任务记录具体证据缺口及恢复条件，不用假日志补齐。

## 参考要点

六测中的两契约测试真实执行可选字段/私有字段投影、必需字段改名、类型漂移和兼容适配；无真实HTTP联调。 自动化仅验证对应模型/代码，人工协作效果与生产验收需自己的真实证据；没有同伴/环境时说明限制。
