# 15.2.1 代码评审：从用户行为到可复现缺陷：独立练习

先读理论和操作卡，在隔离副本完成；先预测、再修改/执行、最后保存输入与证据，不只复制成功输出。

## 动手任务

给商品行增加最大100字符标题与缺失title的变体，写两条blocking评审意见和一条明确可选的Nit；另按主Nuxt真实数据流选一个UI或SSR边界检查。

## 验收标准

- [ ] 坏输入实际被拒绝，正常398与公开字段不变；测试包含缺失、错误类型及长度边界。
- [ ] 意见包含触发输入、用户影响和复验方法，区分函数测试与真实UI/SSR证据。

## 排错任务

在副本把decodeLine改成Number(quantity)后校验，字符串2将被接受；现有字符串负例应失败。定位强制转换扩大输入契约，再恢复严格类型。不能把测试改成接受字符串来消除红灯。

保存失败输入、实际现象、定位依据、修复及同输入复验；静态推演与真实执行分开标注。

## 参考要点

先查输入契约再看实现，读负例是否真正调用目标分支。原始安全报告只验证纯函数和清单，不验证DOM、身份服务或性能。
