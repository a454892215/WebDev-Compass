# 15.2.3 技术债与Hotspot：历史线索、业务风险及偿还验证：独立练习

先读理论和操作卡，在隔离副本完成；先预测、再修改/执行、最后保存输入与证据，不只复制成功输出。

## 动手任务

在隔离历史fixture中给catalog增加一次真实提交，再分别报告touches与增删行数；新增一条低频但高安全影响的债务，写清为何不按教学乘积排序。

## 验收标准

- [ ] 真实历史计数由输出复算，生成文件/重命名/样本窗口等偏差有说明，不把人工权重称静态复杂度实测。
- [ ] 偿还条目包含用户影响、范围、最小变更、回归及复查条件，不用候选榜评价个人。

## 排错任务

故障设定：把generated.lock当业务模块、只按提交次数优先重构它，或把catalog人工权重冒称圈复杂度。用原始git log和权重来源核对；修复为过滤/分类并保留业务风险人工复核，不删除不利数据。

保存失败输入、实际现象、定位依据、修复及同输入复验；静态推演与真实执行分开标注。

## 参考要点

先确定要支持什么决定，再选窗口/指标。教学临时历史不是主项目真实债务证据，低频高风险项要独立评估。
