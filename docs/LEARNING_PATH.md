# Vue 3 + Nuxt 学习主线与阶段验收

这份文件定义如何使用[知识地图](../KNOWLEDGE_MAP.md)。默认以 Vue 3 + TypeScript + Nuxt 开发桌面和手机用户端 Web；React/Next 保留为选修。主线安排是结合本项目目标作出的教学判断，不代表所有 Web 项目都必须采用这一套框架。

## 优先级约定

| 类别 | 学习方式 | 是否阻塞首次 Vue/Nuxt 交付 |
| --- | --- | --- |
| 主线 | 原生基础、TS、Vue、Nuxt、API、必要质量与部署 | 相关前置及验收未满足时阻塞 |
| 贯穿要求 | 语义、无障碍、兼容、数据与安全边界、最小验证 | 从第一次实现开始执行 |
| 深化 | 渲染/缓存/性能/安全等已有能力的专项分析 | 按产品风险选择，不能跳过适用的安全要求 |
| 选修 | React/Next、特定 Web API、微前端、GraphQL、Edge、桌面壳等 | 不因未选技术而阻塞主线 |

同一章可能含不同优先级。知识库统计仍包括全部规划条目，含选修；全图覆盖率不作为主线通关分数。BFF/SSR 的状态隔离、授权和秘密边界只要用到就必须检查，不能借“高级阶段”延后。

## 默认学习与交付顺序

| 步骤 | 阅读范围与前置 | 实际产出 | 最小验收 |
| --- | --- | --- | --- |
| A 浏览器心智模型 | 阶段 0；已有移动开发经验可用实验复核代替重复阅读 | 一次页面与 API 请求的观察记录 | 解释 URL、源、状态码和资源失败；能用 DevTools 定位 |
| B 静态页面 | 1.1 结构/表单、1.2 CSS；1.4 从第一张页面贯穿 | 一个语义清楚、宽窄可用的用户端页面 | 标题/标签/替代文本、Tab/焦点、缩放与溢出；目标浏览器可用 |
| C 原生交互 | 1.3；选读 2.1 事件循环/资源清理、2.2 渲染/缓存、2.3 存储、2.4.7 History | 搜索列表或表单，含加载/空/错/重试 | 处理 HTTP 与解析失败、取消/迟到结果；输入不经 innerHTML 执行；解释存储边界 |
| D 工程与类型 | 阶段 3；知道 JS 模块和异步 | 用 Vite/TS 组织练习，具备脚本和最小测试 | 锁文件、类型/规范检查、生产构建；理解类型不校验网络数据 |
| E Vue 组件 | 4.1 → 4.3.3.1 SFC → 4.3.1 核心 → 4.3.2 路由/状态；按需 4.4 UI | Vue 组件化列表/详情/表单 | 解释响应式、Props/事件、composables 清理；验证路由与关键交互 |
| F Nuxt 应用 | 4.5；4.3.3.3 只作概览，不替代 4.5 | Nuxt 页面/布局、数据获取与配置示例 | 解释 CSR/SSR/SSG、payload、hydration、每请求状态、public 配置与服务端边界 |
| G 数据与认证 | 阶段 5，选取实际 API/会话契约 | 列表/详情/编辑与明确的会话流程 | unknown 数据解码、错误和查询竞态；服务端授权、CSRF/Cookie 或 Bearer 契约；mock 与真实服务结果分开 |
| H 首次交付 | 阶段 6 相关质量要求 → 7.1/7.2 与 7.4；7.3 可跳过 | 已构建、可部署且有恢复方法的一个宿主 | 静态/SSR 产物匹配托管、深链刷新、配置/秘密、错误恢复、关键回归、最小监测与回滚演练 |

两个独立 UI 宿主使用同一技术主线。先在一个宿主形成完整闭环，再在另一端验证公共能力、布局/交互和浏览器差异；不以复制目录或同时维护两套示例作为入门门槛。产品 UI 是否响应式与框架学习路线是不同决策。

## 主线之后的深化分支

| 实际问题或职责 | 对应内容 | 可复核产出 |
| --- | --- | --- |
| 模块边界、渲染与状态取舍 | 阶段 8 | 一份有备选方案、约束与风险的 RFC；能解释为何不采用更复杂架构 |
| 慢页面、交互卡顿或质量事故 | 阶段 9–11 | 性能测量/威胁模型/监控与恢复记录，按实际问题选择 |
| 组件复用、多人协作、版本治理 | 阶段 12–13 | 组件契约、测试策略或发布升级演练；单应用不强行引入 Monorepo/微前端 |
| 需要服务端聚合或运行时职责 | 阶段 14 | Nuxt/Nitro 或独立 BFF；明确授权、超时、用户隔离和个性化缓存 |
| 遗留改造与跨团队交付 | 阶段 15 | 迁移、回滚、可访问性或国际化专项方案与交付记录 |
| 需要另一个框架生态 | 4.2 与后续 React/Next 标注项 | 用已知 Vue/Nuxt 概念做对照；不重复当作全部基础必修 |

## 怎样判定掌握

安排学习时间可参考完成度表的小时区间，适用背景、选修与实践范围见[学习耗时说明](./LEARNING_TIME_ESTIMATES.md)；它不作为通关条件。

能够在不依赖逐行提示的情况下解释机制、做一个最小实现、复现错误并定位原因，最后说明方案的适用边界。AI 可以辅助检索、生成和审查；学习者仍应能核对来源、读懂改动、运行验证并独立做小范围排障。

每个正文沿用[内容规范](./AUTHORING.md)，并明确“需要知道什么、用在哪里、何时可跳过、怎样验证”。交付验收按当前风险选择最小充分证据，不要求所有练习都上真机或构建完整业务系统；模拟结果与真实环境结果分开。

## 顺序依据

核对日期：2026-11-24。MDN 核心课程把语义、布局、JavaScript、无障碍和开发者设计列为基础；Vue 官方要求基本 HTML/CSS/JS，Nuxt 官方将路由、数据获取、SSR 与运行配置作为应用能力。因此本路线先建立平台基础，再走 Vue/Nuxt，并将质量要求贯穿实现。
