# 分阶段实施与验收清单

返回[模块入口](./README.md)。下面保留 web-common 与宿主的完整目标验收清单。初始基座、模板和部分 CLI 已另行交付；没有专项证据的目标仍不勾选。清单的稳定 ID 可在新项目中沿用。

> 实施状态更新：独立基座和两端骨架已建立。本文中的完整契约与拟建命令包含未实现目标；实际能力、历史验证和差异见[交接记录](./07-implementation-status.md)，不要仅据本文勾选验收。

## 范围与依赖

~~~text
W0 环境与决策
  → W1 官方骨架与依赖结构
  → W2 公共运行能力
  → W3 质量与工作流
  → W4 桌面/手机模板
  → W5 打包与干净宿主接入
  → W6 复用、升级与发布候选
  → W7 首个真实宿主接入
~~~

W2 的模块测试与 W3 的规范实现可以在契约确认后并行。阶段集成、同一文件改动、暂存与提交由主代理协调串行。外部服务缺失时以本地 fixture 验证公共机制，实际认证和正式部署证据保留为对应条目的外部依赖。

- [ ] W1-01 用 create-nuxt 和官方 starter 初始化，记录 CLI 版本与模板 revision。
- [ ] W1-02 配置 pnpm workspace 和锁文件，按基座目录声明真实存在的工作包。

- [ ] W1-04 确认 core 无 Nuxt/Vue/UI 依赖，基座没有宿主反向依赖。
- [ ] W1-05 验证 Layer 在宿主解析路径、资产和依赖，保留 Nuxt 标准 TypeScript 工程配置。
- [ ] W1-06 干净安装后启动验证应用，独立运行类型检查和一次目标构建。

完成标准为官方骨架可运行、包边界可检查。创建目录本身不足以判定通过。

## W2 公共模块与运行契约

产物为请求工厂、错误类型、会话/配置/日志契约和 Nuxt 适配。

- [ ] W2-01 覆盖成功 JSON、空响应、非成功 HTTP 状态、业务失败、解析失败和网络失败。
- [ ] W2-02 覆盖超时、外部取消、重复查询、迟到响应及 loading 归属。
- [ ] W2-03 覆盖退出、账号切换、请求会话版本和可选刷新 single-flight。
- [ ] W2-04 同进程并发 SSR 用户 A/B，验证凭据、状态和缓存无跨用户泄漏。
- [ ] W2-05 验证 SSR 到 hydration 的数据衔接，确认页面初始请求未重复执行。
- [ ] W2-06 校验 runtimeConfig 的公开边界、静态产物配置与 .client 访问边界。
- [ ] W2-07 若启用 Cookie 刷新，验证多个 Set-Cookie 回写、属性和并发轮换策略。
- [ ] W2-08 验证日志脱敏、安全提示、存储解析失败和契约缺失诊断。

采用 Cookie/Bearer profile fixture 分别验证，条件不适用需记录依据。工具模拟通过与真实业务认证通过分别记录。

- [ ] W3-02 实现 format、lint、typecheck、structure、unit、workflow 的统一入口。
- [ ] W3-03 BASE-DEP-001 至 BASE-WORKFLOW-007 有正反 fixture、明确诊断与覆盖说明；样式约束按实际模板实现 BASE-STYLE-008。
- [ ] W3-04 验证显式导入、自动导入、别名、再导出、动态路径与合法页面取数的处理。
- [ ] W3-05 任务输入变化能使结果失效，清单写入不触发自身摘要变化，依赖环与缺失证据可定位。

- [ ] W4-04 公共业务 fixture 和适配契约共用，UI 代码各端独立，业务包与通用基座边界明确。
