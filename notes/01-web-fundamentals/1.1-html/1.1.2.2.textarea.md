# 1.1.2.2 textarea、select 与表单分组

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

原生输入控件同时提供值、键盘操作和可访问性语义；label 与分组让用户知道该填什么。

## 工作方式与使用规则

textarea 表示多行文本，初始值写在标签之间，运行时读写 `.value`。select 的 option.value 是协议值，用户看到的是选项文本；optgroup 提供长列表的分类。需要多个选择时可用 multiple，但移动端交互不同，少量多选常用 checkbox 更易理解。

每个输入应有可见 label，优先 `for="唯一 id"`；placeholder 不能替代标签。fieldset 将相关输入组成一组，legend 作为组名且放在首个子元素。不要为装饰卡片滥用 fieldset。

button 在 form 中默认可能提交，因此辅助操作显式写 `type="button"`，主操作写 `type="submit"`。reset 会恢复默认值，容易误清空，业务表单谨慎使用。DOM 顺序应与视觉顺序、Tab 顺序一致。

## 最小示例

```html
<label for="note">备注</label>
<textarea id="note" name="note" rows="3"></textarea>
<fieldset>
  <legend>联系时间</legend>
  <label><input name="period" type="radio" value="am" />上午</label>
  <label><input name="period" type="radio" value="pm" />下午</label>
</fieldset>
<button type="button">预览</button>
<button type="submit">提交</button>
```

## 📱 移动端对照

label 近似 TextField 的 label/语义说明；fieldset/legend 表达控件组，不能只靠 Flutter Column 或 Android LinearLayout 的视觉分组替代。

## 常见误区

- 给多个控件复用同一个 id：label 可能指向错误输入。
- 用 div onclick 模拟按钮：需要额外重做键盘、焦点和角色。
- 改 select 就自动提交：可能让键盘用户意外跳转，应有明确确认操作。
