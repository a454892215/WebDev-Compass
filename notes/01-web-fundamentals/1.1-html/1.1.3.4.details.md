# 1.1.3.4 原生折叠、对话框、进度与测量

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

优先使用已有语义和键盘行为的原生元素，再按目标浏览器支持范围渐进增强。

## 工作方式与使用规则

details 的首个 summary 是可操作标题，浏览器管理展开状态；open 是布尔属性。不要在 summary 内再放复杂按钮导致交互冲突。

模态 dialog 用 showModal() 打开：进入顶层、使背景不可交互，并提供焦点约束和 Esc 关闭。普通 show() 或 open 属性是非模态，不应伪装成阻塞弹窗。对话框通过 aria-labelledby 关联标题，提供可见关闭按钮；form method="dialog" 的按钮只关闭并设置 returnValue，不发起网络提交。

优先让浏览器管理焦点与 Esc；不要额外叠加一套焦点陷阱。示例把取消按钮 autofocus 作为安全的初始操作，关闭后检查触发按钮重新获得焦点。较新声明式命令与 closedby 需要单独核对兼容性，本例采用支持更广的 showModal，缺失时显示说明并禁用演示按钮，不提供不完整的模态替身。

progress 表示任务进度，省略 value 表示未知总进度；meter 表示已知范围内的量，如磁盘使用率，不能用来表达下载进度。两者都需名称和可见数值。

## 最小示例

```html
<details>
  <summary>查看说明</summary>
  <p>这里是补充信息。</p>
</details>
<button type="button" id="open">确认</button>
<dialog id="dialog" aria-labelledby="title">
  <h2 id="title">确认操作</h2>
  <form method="dialog"><button value="cancel" autofocus>取消</button></form>
</dialog>
<script>
  const dialog = document.querySelector("#dialog");
  if (typeof dialog.showModal === "function") {
    document.querySelector("#open").onclick = () => dialog.showModal();
  }
</script>
```

## 📱 移动端对照

dialog 类似系统 Dialog/Flutter showDialog，但浏览器原生元素还负责顶层和背景惰性。progress 近似确定/不确定进度控件；meter 是测量值，不等于进度条。

## 常见误区

- 给 dialog 加 open 就以为是模态：背景仍可操作。
- 为原生模态重复加角色、焦点陷阱和 Esc 逻辑：可能与平台冲突。
- progress/meter 无标签或只靠颜色表达状态：补充可见文字。
