# 1.1.1.7 表格：caption、thead、tbody、tr、th、td

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

table 表达行、列交叉的数据关系，caption 说明主题，th 与 scope 帮助识别数据所属表头。

## 核心机制与选择

| 元素                        | 职责                              |
| --------------------------- | --------------------------------- |
| `caption`                   | 表格主题或说明，通常放 table 开头 |
| `thead` / `tbody` / `tfoot` | 表头、主体及汇总行分组            |
| `tr`                        | 一行单元格                        |
| `th scope="col"`            | 当前列的表头                      |
| `th scope="row"`            | 当前行的表头                      |
| `td`                        | 普通数据单元格                    |

简单数据表优先明确行列头。复杂多层表头还需要审查关联，必要时使用 id/headers，或先把数据拆成更易理解的小表格。

## 最小示例

```html
<table>
  <caption>
    学习记录（分钟）
  </caption>
  <thead>
    <tr>
      <th scope="col">主题</th>
      <th scope="col">时长</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">HTML</th>
      <td>30</td>
    </tr>
    <tr>
      <th scope="row">CSS</th>
      <td>45</td>
    </tr>
  </tbody>
</table>
```

## 实际使用与边界

不要用 table 排页面布局，也不要只因设计稿看起来像两列就用表格。反过来，真实二维数据也不应仅为了手机样式就丢掉表头关系。

窄屏可给表格提供有名称、可键盘到达的局部横向滚动区域；避免整页横向溢出。该方案保留表格语义，但不是所有业务表格的最优移动交互，仍需结合列数和使用任务。

## 📱 移动端对照

表格可类比 Table/DataTable，而非通用 Row/Column；它同时表达跨行跨列的数据关系。移动端卡片化呈现需要把每个值的字段含义一起保留。

## 常见误区

- 只给第一行加粗，并不能建立表头关系。
- colspan/rowspan 的数量需与表格网格一致，不能随意凑版式。
- caption 不是任意放在表格外的装饰标题。

## 实践与验收

配套示例：[打开 1.1.1.7.table-demo.html](../../../examples/01-web-fundamentals/1.1-html/1.1.1.7.table-demo.html)。

1. 点击检查按钮，核对列头、行头与 caption。
2. 以 390px 视口查看表格，确认页面没有整体水平滚动。
3. 用键盘定位滚动区；需要时在区域内部滚动。
4. 使用屏幕阅读器检查表头关联属于进一步人工验证，不以视觉检查代替。
