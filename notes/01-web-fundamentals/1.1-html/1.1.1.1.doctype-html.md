# 1.1.1.1 文档结构：doctype、html、head、body

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

HTML 文档是一份可被浏览器解析为 DOM 的结构化文本；doctype 选择标准模式，head 描述文档，body 承载内容。

## 核心机制与选择

| 部分                  | 职责                           | 注意                           |
| --------------------- | ------------------------------ | ------------------------------ |
| `<!DOCTYPE html>`     | 让通常的 HTML 文档使用标准模式 | 它是声明，不是普通元素         |
| `<html lang="zh-CN">` | 文档根与主要语言               | 语言帮助朗读和翻译，不等于编码 |
| `<head>`              | 编码、标题、样式和其他元信息   | 不承载主要页面正文             |
| `<body>`              | 页面内容及其语义结构           | 只保留一个 body，主体放 main   |

浏览器解析器会修复部分省略或错误嵌套，因此 Elements 中的 DOM 不一定逐字等于服务器返回的源码。显式写清结构有助于排查问题。

## 最小示例

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>学习首页 · WebDev Compass</title>
  </head>
  <body>
    <main>
      <h1>学习首页</h1>
      <p>从原生 HTML 开始。</p>
    </main>
  </body>
</html>
```

## 实际使用与边界

在浏览器 Console 执行 `document.compatMode`，标准模式应为 `CSS1Compat`。`document.characterSet` 应为 `UTF-8`。字符编码声明尽量靠近文件开头，且完整位于前 1024 字节内；文件本身也要用 UTF-8 保存。

`viewport` 让移动浏览器按设备宽度设置布局视口，不会自动把任意桌面布局改成手机布局。不要限制用户缩放。

## 📱 移动端对照

HTML 文档近似“界面结构描述 + 页面元数据”，但不是 Flutter Widget 的运行时构建函数。浏览器先解析资源与 DOM，再结合 CSS 布局；Vue 的组件最终也落实到浏览器节点。

## 常见误区

- doctype 不是“下载 HTML5 引擎”，浏览器不根据这个声明联网下载实现。
- `lang` 不是中文乱码修复开关；编码问题需检查文件和响应头。
- 浏览器能够容错，不代表嵌套错误可长期保留。
