# 1.1.2.3 表单属性与约束

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

required、pattern 等表达输入契约；disabled 与 readonly 对交互、验证、提交的作用不同。

## 工作方式与使用规则

| 属性         | 主要作用                                                                   |
| ------------ | -------------------------------------------------------------------------- |
| required     | 支持的控件不能为空；一组 radio 可要求至少选一项                            |
| disabled     | 不能交互，通常不能聚焦，不参与提交和约束验证                               |
| readonly     | 适用的文本输入/textarea 不可编辑，仍可聚焦并提交；不适用于 select/checkbox |
| placeholder  | 短示例，输入后消失，不能代替 label 或持续说明                              |
| pattern      | 对适用文本控件匹配整个非空值，不写 `/.../`；空值还需要 required            |
| min/max/step | 对数值或日期等控件设范围与步长                                             |
| autocomplete | 帮助浏览器识别数据用途，不是校验器或安全开关                               |

布尔属性的“存在”表示真，`disabled="false"` 仍禁用。修改时用 `input.disabled = false` 或移除属性。

复杂字符集合的 pattern 随规范采用 Unicode 模式；初学先用简单明确字符类，并在目标浏览器验证。autocomplete 选用规范 token，例如 email、nickname、current-password。客户端限制都可绕过，服务端必须再次校验。

## 最小示例

```html
<label for="code">编号（3 位数字）</label>
<input
  id="code"
  name="code"
  required
  pattern="[0-9]{3}"
  inputmode="numeric"
  autocomplete="off"
/>
<input name="order" value="DEMO-42" readonly />
<input name="internal" value="not-sent" disabled />
```

## 📱 移动端对照

类似 Android/Flutter 表单的 enabled/readOnly/validator，但浏览器 disabled 还影响原生提交数据集。inputmode 主要影响软键盘，type/pattern/required 才分别提供相应输入语义与约束。

## 常见误区

- readonly 就可信：用户仍可在 DevTools 修改。
- disabled 字段会提交：FormData 默认不收集它。
- inputmode="numeric" 能禁止非数字：它只是键盘提示。
