# 1.1.1.8 元信息：meta、title、link 与 script

> [← 返回 HTML 目录](./README.md) · [知识地图](../../../knowledge-map/01-foundation-stages-0-2.md)

## 一句话理解

head 描述页面身份、编码、视口和资源关系；元信息不是页面正文，也不会自动保证搜索排名或分享展示。

## 核心机制与选择

| 写法                      | 职责                                              |
| ------------------------- | ------------------------------------------------- |
| `meta charset="utf-8"`    | 声明字符编码，与实际文件/响应一致                 |
| `meta name="viewport"`    | 移动布局视口；保留用户缩放                        |
| `title`                   | 标签页、历史记录等处的文档标题                    |
| `meta name="description"` | 页面摘要；搜索服务可能参考，也可能选择其他内容    |
| `meta property="og:*"`    | Open Graph 分享元数据；具体展示由平台抓取策略决定 |
| `link rel="stylesheet"`   | 声明外部样式资源关系                              |
| `script`                  | 引入或声明脚本，加载策略影响解析与执行顺序        |

生产环境的 og:url、og:image 应使用真实、可被目标平台访问的绝对 URL。不要把私有接口密钥写进 meta 或客户端脚本。

## 最小示例

```html
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>HTML 学习 · WebDev Compass</title>
  <meta name="description" content="理解文档结构、语义和原生 HTML。" />
  <meta property="og:title" content="HTML 学习" />
  <meta property="og:type" content="article" />
  <link rel="stylesheet" href="./styles.css" />
  <script src="./app.js" defer></script>
</head>
```

## 实际使用与边界

普通外部经典脚本的 defer 会并行获取，在文档解析后按顺序执行，并在 DOMContentLoaded 前执行；async 在资源就绪时执行，不保证多个脚本顺序。`type="module"` 默认具有延后执行行为，其依赖通过模块图加载。内联经典脚本的 defer 没有这种效果。

示例把监听器放进本地外部 defer 脚本，让它能访问已解析按钮。Open Graph 只给出本地演示的基本文字字段，未伪造正式分享 URL。

## 📱 移动端对照

title、description、分享元数据类似页面身份与平台外部展示配置，而 h1 属于当前文档内容。它们不能用一个 Text Widget 或一份路由标题配置完全等同。

## 常见误区

- title 不会自动创建页面上的 h1。
- 加 viewport 不等于已经实现响应式布局。
- 不加 user-scalable=no 或 maximum-scale=1 来掩盖手机排版问题。
- meta description 不保证成为搜索摘要，也不直接承诺排名。

配套示例：[打开 1.1.1.8.meta-demo.html](../../../examples/01-web-fundamentals/1.1-html/1.1.1.8.meta-demo.html)。
